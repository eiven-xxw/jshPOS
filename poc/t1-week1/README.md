# T1 Week 1 STATIC/FAKE 风险探针

本目录是与正式业务模块隔离的风险验证夹具。它只回答“契约是否自洽、故障是否可重复、门禁能否阻止证据混级”，不回答“设备是否兼容、支付是否可用、系统是否可商用”。

## 明确边界

- 所有租户、事件、支付请求、商品包和版本号均为虚构合成数据；
- 不访问网络，不包含支付 SDK、生产/沙箱密钥、真实终端或真实商户数据；
- 支付候选 `selectedForFake=true` 仅代表进入统一 Fake 语义验证，不代表已签约或接入；
- 实机、双打印、扫码、电子秤、钱箱、客显和支付沙箱 RTM 项继续为 `BLOCKED`；
- 不创建正式订单、支付、库存、促销领域表、接口或页面。

## 本周输入与输出

`fixtures/` 保存确定性输入，`src/t1_fake_harness.py` 执行纯内存模型，`tests/` 验证不变量。CI 输出：

- `static-evidence.json`：契约、资料、范围与安全静态检查；
- `fake-evidence.json`：七类风险的 Fake 故障执行结果；
- `evidence-manifest.json`：证据文件 SHA-256 清单。

所有证据只能标记为 `STATIC` 或 `FAKE`。
