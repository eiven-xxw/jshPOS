# T1 Week 3 内部 STATIC/FAKE 交叉故障探针

本目录是可以整体删除的风险验证模型，只对应 `T1-OFF-001`、`T1-SYN-001`、`T1-PAY-001`、`T1-DPK-001`、`T1-UPG-001`、`T1-SEC-001` 和 `T1-CI-001`。租户隔离使用 Week 2 探针原样回归，不在这里复制正式实现。

## 覆盖范围

- Outbox claim、服务端接收、ACK 丢失、本地提交、网络乱序和重启叠加下的最终收敛；
- 五家支付 Fake 的支付/退款 `UNKNOWN` 查询或回调收敛、回调幂等与合成对账差异；
- 合成包下载中断续传、切换 kill、旧包重放、跨租户拒绝和临时文件回收；
- 待同步状态下的兼容升级/不兼容阻断、迁移失败后的应用回退、兼容窗口和前向修复；
- Secret、合成 PII、依赖、安全、证据分级与失败 seed 机器门禁。

## 明确限制

- SQLite 关闭/重开和子进程 kill 只模拟进程故障，不等于 Android 实机物理断电。
- 支付探针不导入网络客户端、不读取凭据、不访问沙箱或生产环境。
- App、Schema、包、租户、支付与 PII 都是虚构合成数据；不存在可安装 APK 或真实商户资料。
- Fake 结果不能替代 `SANDBOX`、`REAL_DEVICE`、试点或商业验收。
- 本目录不创建正式订单、支付、退款、库存、促销表、迁移、API、SDK 或页面。
