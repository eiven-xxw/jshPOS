# 执行器规格、阈值与可比性

## 正式可比较执行器

正式墙钟基线绑定 GitHub 托管 `ubuntu-latest` x64 类别、Temurin 21、Python 3.12、MySQL 8.4.11、Redis 7.4.10、Flutter 3.47.0 和仓库锁定依赖。每次运行必须记录实际 OS/kernel、CPU 型号与逻辑核、内存、磁盘、JDK、容器镜像摘要和 commit。

Windows 与本地执行器只证明治理、契约、脚本和功能可复现，不与 Ubuntu 的 P50/P95/P99 或吞吐作横向判定。若执行器低于契约最小资源或指纹缺失，结论为不可比并失败，不自动换机重跑。

## 阈值原则

- 正确性、错误率、资源上限、积压恢复和样本完整性是硬门禁；
- 延迟阈值在负载执行前冻结，并保留相对 Gate 6H/Gate 8B 历史引用；
- P99 不得用平均值替代；冷启动必须从新进程开始；持续运行必须保存完整样本；
- 阈值只能通过后续独立 CR 调整，不能在失败提交中同时放宽；
- 所有阈值是内部退化护栏，严禁称为生产 SLO/SLA。

机器阈值以 `contracts/t2/gate8c-perf002/thresholds-v1.json` 为准。
