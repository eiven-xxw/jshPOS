# 正式栈容量、并发与持续运行模型

## 三个性能平面

| 平面 | 固定能力 | 主要量化项 | 正确性硬门禁 |
|---|---|---|---|
| 正式运行栈 | MySQL 8.4、Redis 7.4、完整 JAR、HTTP 认证与 Owner API | 冷启动、并发读写、持续运行、P50/P95/P99、吞吐、错误率、CPU/RSS/GC、连接与内存 | HTTP/业务码、幂等、租户、状态与历史保持 |
| Owner 容量 | 商品/价格、报表、迁移、开店、日结、异常、SaaS/SUB/SVC | 10k/100k/1m 合成规模、并发任务、重建和退化 | 数量金额守恒、摘要、检查点与无静默丢失 |
| POS 本地 | 扫码/计量、报价、现金结算、SQLite 事务、同步积压 | 1000 次扫描、200 次结算、10k Outbox、包安装与恢复 | 单事务、金额守恒、原幂等键、事件最终收敛 |

正式数据量、并发、预热和采样以 `contracts/t2/gate8c-perf002/workload-model-v1.json` 为唯一机器可读来源。负载先执行预热，测量阶段禁止改变 Schema、索引、JVM 参数或数据集。

## 并发与耐久

- HTTP 并发至少覆盖认证上下文读、SaaS 权益判定、Subscription 当前状态、Service 列表读取及受控写入幂等冲突；
- 持续窗口必须在同一应用进程内运行，记录全部原始延迟而非只记平均值；
- 队列/连接压力超过配置上限时必须有界拒绝、超时或背压，应用保持存活，恢复窗口内积压归零；
- 资源采样覆盖应用进程、MySQL 与 Redis，采样间隔固定，不得手工删除尖峰。

## 证据边界

100k/1m 只代表合成容量趋势；持续窗口为 CI 可重复窗口，不代表 7×24 稳定性。真实网络、真实终端、真实商户数据和生产拓扑均未覆盖。
