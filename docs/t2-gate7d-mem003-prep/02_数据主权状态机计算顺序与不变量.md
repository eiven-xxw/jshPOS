# T2-MEM-003 数据主权、状态机、计算顺序与不变量

## 1. 数据主权

| 事实 | 唯一写入 Owner | 允许读取方 | 写入规则 |
| --- | --- | --- | --- |
| 权益策略、版本、等级映射、门店范围 | Member | Pricing/Promotion/POS 包构建 | 批准后内容不可变 |
| 会员价簿/价格项/价格解析结果 | Pricing | Promotion/Order/POS 包构建 | 版本发布、未来生效 |
| 权益 Adjustment、叠加决策、解释链、分摊 | Promotion | Order/Refund/Reporting | 快照只追加 |
| 订单会员引用、权益/价格/报价摘要 | Order | Refund/Reporting | 成交后不可覆盖 |
| 退款分摊与恢复状态 | Refund/Promotion | Payment/Inventory/Reporting | 只读原成交快照 |
| 离线包清单、摘要、签名和安装状态 | DataPackage/POS | Sync/Operations | 原子切换 |

任何 Owner 不得通过 Mapper、原生 SQL 或表 Join 写入其他 Owner 私有事实。跨 Owner 使用进程内
窄端口、版本化事件、Inbox/Outbox 或明确只读投影。

## 2. 状态机

### 2.1 权益版本

`DRAFT → VALIDATING → VALIDATED → APPROVED → SCHEDULED → ACTIVE`

- `ACTIVE → PAUSED → ACTIVE`：只影响新报价；恢复仍使用同一不可变内容。
- `ACTIVE/PAUSED → RETIRED`：正常停止，不允许再用于新报价。
- `ACTIVE/PAUSED → REVOKED`：紧急撤回，递增撤回纪元并阻断旧离线包。
- 验证或发布失败进入 `VALIDATION_FAILED/PUBLISH_FAILED`，上一有效版本不受影响。
- APPROVED 之后任何内容变化必须新建版本，禁止原地编辑。

### 2.2 最小权益快照

`ISSUED → ACTIVE → EXPIRED | REVOKED | SUPERSEDED`

快照身份至少包含 tenant、store scope、member_ref_hash、level_history_id、benefit_version、
issued/effective/expires、revocation_epoch 和 content_sha256。同键异内容拒绝。

### 2.3 交易快照

报价为 `QUOTED → FROZEN → SETTLED`，或在冻结前 `EXPIRED/REJECTED`。`FROZEN` 后不可重算；
挂单取单、重启和同步恢复必须复用原报价 fingerprint、权益快照和幂等键。

## 3. 固定计算顺序

1. 从可信 POS/服务端上下文解析租户、门店、业务日和币种；
2. 验证最小会员权益快照的签名、摘要、门店范围、有效期和撤回纪元；
3. Pricing 解析普通基础/门店价候选；
4. Pricing 解析会员价候选，但不读取会员私有表；
5. Promotion 对普通候选执行已接受的普通促销链；
6. Promotion 对会员候选执行允许的基础会员权益 Adjustment；
7. 仅当会员权益版本和促销规则版本双方显式允许时叠加，否则互斥；
8. 在完整可解释的候选路径间执行 `BEST_PRICE`，选择应收更低者；金额相同按
   `NORMAL_PRICE_PROMOTION` 优先，保证稳定且避免无意义会员依赖；
9. 应用受权人工改价/整单折扣；
10. 应用抹零并执行金额守恒分摊；
11. 冻结 member/level/benefit/price/promotion/manual/rounding 引用、逐行结果和 fingerprint。

前端不得重算任何一步。Java 与 Dart 使用相同 JSON 固定向量、十进制规则和错误码。

## 4. 核心不变量

- `gross - discount + surcharge = receivable`，逐行合计等于订单头；
- 金额使用最小货币单位整数，数量/重量/换算使用精确 DECIMAL/BigDecimal，禁止浮点数；
- 同一调整不可在普通路径和会员路径重复应用；
- `BEST_PRICE` 比较的是完整候选路径最终应收，不是单独比较标签价；
- 会员价不会改写基础价、门店价或历史价格版本；
- 等级变化、权益撤回和价格发布不改变已冻结订单；
- 部分/最终退款累计不得超过原可退数量与金额，最后一次合法退款吸收舍入余数；
- 退款读取原会员权益、会员价、促销、人工优惠和抹零快照，不读取当前规则；
- tenant_id 只来自可信上下文；member_ref_hash 只能证明关联，不能替代身份授权；
- 离线失效时不得静默把会员报价当普通报价继续结算；必须显式重新报价并生成新 fingerprint；
- UNKNOWN 只观察原命令收敛，禁止重新生成订单、退款、积分或资金命令。

## 5. 幂等与事务边界

- 权益版本命令键：`tenant + policy + version + command_type`；
- 权益快照键：`tenant + member_ref_hash + level_history + store_scope + benefit_version + issued_at`；
- 报价键：既有 basket/quote 幂等键加 `benefit_snapshot_sha256`；
- 同键同内容返回原结果，同键异内容统一 `IDEMPOTENCY_CONTENT_MISMATCH`；
- POS 本地冻结购物篮、会员权益引用、报价、订单、现金事实和 Outbox 继续保持单 SQLite 事务；
- 服务端各 Owner 只在自己的事务内写事实与 Outbox，不构造跨 Owner 数据库大事务；
- 部分 Owner 失败使用稳定命令、Inbox/Outbox 和显式异常案件恢复。

## 6. 权限与审计

建议权限：`member:benefit:read/create/validate/approve/publish/pause/revoke`、
`pricing:member-price:read/publish`、`pos:member-benefit:quote`。创建/审批必须职责分离；发布、
暂停、撤回、门店范围变更、兼容豁免和重新报价均记录请求摘要、操作者、审批者、原因、版本、
关联标识和结果摘要，审计正文禁止 PII。
