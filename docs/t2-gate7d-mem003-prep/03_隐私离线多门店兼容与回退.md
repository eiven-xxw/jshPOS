# T2-MEM-003 隐私、离线、多门店、兼容与回退

## 1. 隐私和数据最小化

### 1.1 跨 Owner 白名单

允许：`member_ref_hash`、脱敏显示、`level_code/level_history_id`、权益版本、适用范围、权益标志、
摘要、签名密钥版本、issued/effective/expires、撤回纪元、订单绑定和关联标识。

禁止：姓名、手机号、证件、住址、生日、身份密文、令牌明文、原始授权材料、营销画像、支付
数据和可逆身份映射。禁止字段不得进入订单、价格、促销、离线包、日志、CI、普通 Artifact、
缓存键、导出和对象存储路径。

### 1.2 删除与撤回

同意撤回后停止新权益解析并吊销可逆身份令牌；隐私删除按既有 Member Owner 规则匿名化。财务、
订单、退款和审计法定事实保留不可逆引用和冻结权益摘要，不回写历史金额，也不能通过该引用恢复
身份。

## 2. 离线协议

权益/会员价包必须包含：tenant、store、package/schema/protocol version、source version、
issued/effective/expires、revocation_epoch、record count、payload SHA-256、签名算法、密钥版本、
兼容窗口和生成 commit。默认 TTL 不超过 24 小时，也不得晚于任何来源权益或等级的失效时间。

安装遵循下载到临时区、校验、SQLite 事务导入、投影校验、原子指针切换、旧包短期保留和过期
清理。旧包、损坏、签名失败、跨租户/门店、未知 Schema、过期、撤回纪元落后或摘要漂移一律
失败关闭，不覆盖上一有效包。

失效后的 UX：显示“会员权益暂不可用”以及原因，不默认套用优惠。操作员具备权限并获得顾客
确认后，可移除会员权益上下文并生成新的非会员报价；原报价、原因和操作者必须审计。

## 3. 业务日与时间

- 服务端和 POS 使用门店 IANA 时区与业务日起点；客户端系统时间不决定权益状态。
- 权益的时间窗口比较使用可信服务时间与上次同步时钟偏移保护；偏移超阈值失败关闭。
- 跨夜挂单在取单时若报价未冻结，必须重新验证并生成新报价；已冻结成交继续原快照。
- 夏令时重叠/缺失时段以带 offset 的瞬时点和业务日规则确定，不使用本地裸时间。

## 4. 多门店与加盟边界

- V1 只允许同租户权益，范围可以是租户内全门店、组织集合或门店白名单；范围版本化并纳入摘要。
- POS 终端必须由服务端登记并绑定门店，客户端自报 store/tenant 不构成权限。
- 同一会员在不同门店可以得到不同适用结果，但等级事实仍由 Member Owner 唯一持有。
- 优惠经营责任归销售门店，报表记录 member price discount 与 benefit adjustment；不生成跨门店
  应收应付、总部补贴、加盟商分摊或资金清算。

## 5. 兼容窗口

| 组合 | 策略 |
| --- | --- |
| 旧 POS + 新服务端 | 不下发新权益包，不展示会员权益，普通交易继续 |
| 新 POS + 旧服务端 | Capability 协商失败并隐藏入口，不使用本地硬编码权益 |
| 新 POS + 新服务端 | Schema/协议均在兼容窗口内才启用 |
| 旧权益包 + 新规则 | 版本/撤回纪元检查，失效则失败关闭 |

事件与 OpenAPI 版本向后兼容只允许新增可选字段；改变金额语义、状态、默认叠加行为或隐私字段
必须升主版本并独立评审。

## 6. 前向迁移与回退

准备阶段不创建任何迁移。正式实现只允许 MySQL/SQLite 前向迁移，不修改已发布文件。回退顺序：

1. 停止发布新权益版本并关闭门店 Capability；
2. 保持已成交快照和退款读取能力；
3. 未冻结购物篮显式转非会员重新报价；
4. POS 包回退只切换到仍有效、未撤回且兼容的上一版本；否则禁用权益；
5. 投影异常可丢弃重建，权威策略、快照、订单和审计不可删除；
6. Schema 不回退，使用安全前向修复；失败产生 Operations 异常案件。

## 7. 外部与证据边界

所有测试使用两个虚构租户、多门店、多终端和三业态合成数据。`T2-PAY-002/HWD-001/
PRN-001/PAR-001` 继续 BLOCKED；本能力不需要也不授权 Provider 网络、真实资金、真实终端、
伙伴现场、真实 PII、完整 Alpha 或生产执行。
