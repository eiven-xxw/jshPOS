# 数据主权、状态、冻结点、事务与不变量

## 1. Owner 主权

| Owner | 唯一可写事实 | 只读输入 | 禁止写入 |
|---|---|---|---|
| POS Local | 本地购物篮/成交/现金/班次/Outbox/幂等 | 已激活规则包与报价 | 服务端 Owner 表 |
| Promotion | 规则、报价、人工优惠、成交快照、退款分摊 | 订单/退款身份只读投影 | 订单、支付、库存 |
| Order/Refund | 订单、行、退货退款状态、快照引用 | Promotion 快照 | 促销、库存、支付事实 |
| Payment | Provider 无关支付/退款状态 | 已批准退款命令 | 订单、促销、库存 |
| Inventory | 不可变销售退货入库流水 | 已成功退款/退货事实 | 订单、退款、促销 |
| Return Orchestrator | Saga、Inbox/Outbox、步骤结果 | 各 Owner 版本化结果 | 任何 Owner 事实 |

## 2. POS 冻结点

结算开始前验证开放班次、可信 tenant/store/terminal/cashier、业务日、报价状态、规则包版本与指纹、人工审批引用及篮子内容摘要。进入 `BEGIN IMMEDIATE` 后冻结并一次性写入：

1. 结算请求事实及请求 SHA-256；
2. 成交促销快照与逐行/逐来源分摊；
3. 完成订单和订单行；
4. 现金收款、班次现金流水及理论现金；
5. 审计、幂等结果与 `order.completed.v2` Outbox。

任一检查点异常执行 ROLLBACK。重启只能以原幂等键恢复；同键异摘要返回 `IDEMPOTENCY_CONTENT_CONFLICT`。

## 3. 状态

- 本地结算：`PREPARED → COMMITTED`；事务失败不持久化 `PREPARED`，只允许重放原命令。
- 服务端订单：`RECEIVED → VERIFIED → COMPLETED`；快照不匹配进入 `REJECTED`，不得修补金额。
- 退货 Saga：`REQUESTED → PROMOTION_ALLOCATED → REFUND_PENDING/UNKNOWN → REFUND_SUCCEEDED → INVENTORY_APPLIED → COMPLETED`；任一步骤可 `RETRY_WAIT` 或 `MANUAL_REVIEW`，但不得倒退覆盖历史。

## 4. 金额与累计上限

- 每行：`line_gross - line_discount + line_surcharge = line_receivable`；
- 订单：`gross - discount + surcharge = receivable`；
- 订单头各金额等于逐行合计；现金 `tendered - change = receivable`；
- 退款累计数量不超过原行数量，累计退款不超过原快照可退金额；
- 非最终退货按原快照稳定比例/最大余数分配，最终合法退货吸收剩余尾差；
- 所有金额使用 int64 最小货币单位；数量禁止浮点数。
