# SQLite/MySQL 迁移、容量、兼容、回退与修复

## 1. 迁移计划

- SQLite V6 只追加促销结算事实、订单绑定与不可变触发器，不修改 V1—V5；数据库升级失败保留旧版本并禁止新能力。
- MySQL 后续在 ORD-003 准入后追加订单促销绑定迁移，不改已发布 V5；旧客户端 `order.completed.v1` 只允许零优惠兼容窗口，新 `v2` 才能携带促销快照。
- REF-002 准入后才追加 Saga/Inbox/Outbox 表；不预建绿色运行时。

## 2. 容量与限额

- 单订单最多 500 行、促销调整最多 2,000 条、人工审计引用最多 50 条；
- 本地单事件规范化 JSON 上限 1 MiB，超限失败关闭；
- Outbox 积压按终端告警，保持 Gate S3 的退避、死信和人工修复预算；
- 批量重放按 tenant/store/terminal 分片，不跨租户共享游标或缓存键。

## 3. 兼容与回退

应用先部署兼容读、再启用新写；旧端不认识促销成交时服务端拒绝含优惠旧事件。回退仅停止新写并恢复兼容应用；已提交事实不删除。迁移失败使用新版本前向修复，禁止修改已发布脚本与校验和。

## 4. 修复

摘要不一致、同键异内容、快照跨租户、游标损坏和无法解释的部分步骤进入隔离队列。人工修复只能重放原事件、补发 ACK 或追加补偿事实，不能编辑订单、快照、退款或库存历史。
