# T2-LBL-001 设计准入与验收冻结

## 1. 范围与非目标

实现价格发布/停用驱动的货架价签换签任务、版本化安全模板、服务端纯文本预览、受权人工换签确认、异常记录、
任务重放、失败关闭打印端口和 Vue 运营页面。真实打印机、厂商 SDK、USB/串口/蓝牙、电子价签、真实换签绩效和设备成功回执不在范围。

## 2. 数据主权与访问策略

| 表/能力 | Owner | 访问策略 | SQL 模式 | 说明 |
|---|---|---|---|---|
| `lbl_template` | ShelfLabel | CRUD_ENTITY | HYBRID | 草稿可编辑，发布后不可变 |
| `lbl_label_task` | ShelfLabel | CONTROLLED_WRITE | HYBRID | 只允许具名状态迁移与乐观锁 |
| `lbl_label_task_item` | ShelfLabel | CONTROLLED_WRITE | HYBRID | 冻结商品、条码、单位和价格快照；只允许换签状态迁移 |
| `lbl_task_event` | ShelfLabel | APPEND_ONLY | XML | 业务事件只追加，禁止更新/删除 |
| `lbl_task_exception` | ShelfLabel | APPEND_ONLY | XML | 异常及处置事实只追加 |

Pricing/Catalog 仍独占 `prc_*` 和 `cat_*`；Foundation 独占门店。ShelfLabel 通过只读端口取快照，禁止跨 Owner 写入。

## 3. 状态机与不变量

- 模板：`DRAFT → PUBLISHED → RETIRED`；发布内容由 SHA-256 固定，发布后不允许覆盖修改。
- 任务项：`PENDING → PREVIEW_READY → REPLACED_CONFIRMED`；预览失败进入 `EXCEPTION`，可重试回到 `PREVIEW_READY`；
  较新权威价格到达时，未完成旧项进入 `SUPERSEDED`。
- 任务投影：由任务项计算 `PENDING/PREVIEW_READY/IN_PROGRESS/COMPLETED/EXCEPTION/SUPERSEDED/DISPATCH_BLOCKED`。
- `REPLACED_CONFIRMED` 仅代表受权人员确认货架换签作业，不代表打印成功；所有确认必须保存操作者、时间、原因和关联标识。
- 来源键为 `price-book.{published|retired}.v1:{bookId}:{versionNo}:{storeId}`；同键同摘要幂等，同键异摘要返回 `LBL-IDEMPOTENCY-CONFLICT`。
- 迟到/乱序比较生效时间、门店覆盖优先级、价格版本和来源价格簿 ID；旧的未完成任务项只被标记为 `SUPERSEDED`，历史确认和事件不回写。

## 4. 模板与预览安全

模板最大 2,000 UTF-8 字符，渲染结果最大 8,000 字符。只允许 ADR-046 的批准字段；未知字段、HTML/脚本标签、
`javascript:`、路径穿越、控制字符、CSV/表格公式前缀和嵌套表达式失败关闭。预览返回结构化快照和纯文本；Web 禁止 `v-html`。

预览至少展示商品、SKU、条码、单位、原价、现价、币种、门店、价格版本、生效时间、任务状态和异常原因。
原价不可得时显示 `首次定价`，回退后无有效价时生成异常而不是伪造零价。

## 5. 权限、审计、API 与事件

- `catalog:label:template:manage`：模板草稿；`catalog:label:template:publish`：发布/停用。
- `catalog:label:task:read`：列表和预览；`catalog:label:task:confirm`：换签确认；
  `catalog:label:task:exception`：异常/重试；`catalog:label:task:dispatch`：只触发失败关闭端口。
- 所有任务查询同时校验可信 `tenant_id` 和门店数据范围；客户端 tenant/store 不作为授权依据。
- API、事件和错误码冻结在 `contracts/t2/gate7c-lbl001`；事件使用稳定 ID、Schema 版本、内容摘要和关联标识。

## 6. 事务、容量、恢复与前向修复

价格发布/停用、Catalog Outbox、价签来源幂等、任务/任务项、价签事件和审计在同一 MySQL 事务内提交；任一失败整体回滚。
预览、确认、异常和打印失败各自使用稳定幂等键。百万级趋势以分页、索引和固定合成计划验证，不把本地趋势写成生产 SLA。

迁移失败不修改既有 V1—V60；仅追加 V61。应用可关闭价签入口并重放稳定来源键恢复，历史任务和事件不得物理删除。
失败恢复覆盖事务中断、重启、重复、乱序、晚到、预览失败、打印不可用和安全前向修复。

## 7. 量化验收

- 两个虚构租户、至少三门店和便利店/零食折扣店/社区超市模板；固定故障向量不少于 16 个。
- 覆盖首次发布、未来生效、门店覆盖、批量调价、停用回退、重复/乱序/晚到、同键异内容、模板篡改、
  跨租户/门店、预览失败、重启恢复、百万级趋势和前向修复。
- MySQL 8.4 空库迁移、二次执行、租户约束、状态约束、唯一键、只追加事件触发器和权限全部通过。
- 服务端、Vue、完整既有 Gate、双平台 Flutter、Android/Kotlin、安全、SBOM、许可证与证据门禁全绿。
- P0/P1 为 0 后仅更新 `VERIFIED`，等待项目发起人确认；不得自动更新 `ACCEPTED`。
