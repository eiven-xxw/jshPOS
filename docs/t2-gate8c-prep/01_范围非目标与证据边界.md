# 范围、非目标与证据边界

## 目标

以 Gate 8B 封存提交 `68d94211b93156d0d87139e4ab5bef421802ad95` 为唯一仓库事实基线，对已接受的商业 V1 与 SaaS 运营代码做 P0/P1 安全、性能、可维护性和发布差距复核，并为后续逐项整改形成唯一 Requirement ID、Owner、证据、关闭标准和串行门禁。

## 允许范围

- Gate 8B 接受记录、RTM、ADR、CR、AGENTS 和目录索引一致性；
- 只读仓库扫描、静态规则、既有 CI/制品/报告复用；
- 发现台账、审计覆盖矩阵、整改依赖、测试与 CI 方案；
- 双平台治理和静态仓库审计。

## 非目标

- 不修改 Server、Web、Flutter、Kotlin/Android、MySQL/SQLite 运行时；
- 不新增或修改 Flyway/SQLite 迁移、依赖、业务 API、状态机、Owner、页面或后台任务；
- 不执行 Provider 网络、真实支付、设备/外设命令、伙伴联系、完整 Alpha 或生产部署；
- 不关闭 `T2-LIC-001`、外部四项、UAT 或发布需求；
- 不把现有内部候选升级为生产或商业证据。

## 证据等级

本阶段最高为 `STATIC_GOVERNANCE_AND_REPOSITORY_AUDIT`。Gate 8B 的正式 MySQL/Redis/HTTP 全量 CI 只作为未改运行时的封存基线复用；本阶段开放 P0/P1 表示审计发现真实存在，不表示门禁失败被忽略。

Gate 8C-Prep 的 `CONDITIONAL PASS` 只代表发现完整、证据可复核、顺序和关闭标准明确；Gate 8C 正式整改、完整 Alpha、生产和商业发布仍需独立确认。
