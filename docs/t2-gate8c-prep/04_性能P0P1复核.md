# 性能 P0/P1 复核

## 结论

未发现需要在准备阶段立即修改业务算法的性能 P0；发现两项 P1 证据差距。

- `G8C-PERF-P1-001`：`T2-PERF-001` 的 Gate 6H 基线早于 Gate 7 的交易运营、秤码、批次、补货、迁移、开店、日结、异常中心、会员权益和 Gate 8 SaaS/SUB/SVC 能力，不能代表当前完整代码面。
- `G8C-PERF-P1-002`：Gate 8B 的 55 次正式 API 顺序观察证明装配正确，不证明并发、尾延迟、持续运行、连接池耗尽、队列积压或资源上限。

## 后续基线维度

`T2-PERF-002` 至少覆盖：

- POS 冷启动、数据包安装、扫码、报价、现金结算、本地事务和同步积压；
- 商品/价格发布、报表、迁移、开店、日结、异常中心；
- SaaS 开户/权益、订阅调度、工单与附件元数据；
- MySQL/Redis 连接池、CPU、内存、GC、磁盘、网络、P50/P95/P99、错误率和背压；
- 固定数据量、并发模型、执行器、预热、采样、失败阈值和原始证据。

所有结果仍是内部合成趋势，不得形成 REAL_DEVICE、生产容量或商业 SLA。
