# 安全 P0/P1 复核

## 已守住的边界

- 47 个正式业务 Controller 均存在服务端权限注解；未发现 Controller 直接依赖 Mapper；
- `tenant_id` 可信上下文、Owner 状态机、金额库存不变量和 Gate 8B Secret/PII/依赖门禁仍有封存证据；
- 本轮未发现真实支付密钥、商户号、终端证书或真实 PII 新增进入仓库。

## P0

`G8C-SEC-P0-001`：`application-prod.yml` 仍包含静态默认凭据/令牌模式，且部分可选集成默认启用。它们不能被解释为真实生产 Secret，但生产配置若按默认值启动会产生可利用风险。关闭条件是：所有敏感值改为受控 Secret 引用，可选集成默认关闭，生产缺少必要 Secret 时启动失败，并由自动测试阻断默认凭据回归。

## P1

- `G8C-SEC-P1-002`：Actuator 使用全量暴露和固定健康详情；即使已有独立 Basic 鉴权，也应在生产缩为白名单并按授权显示详情。
- `G8C-SEC-P1-003`：服务附件业务上限是 10 MiB，但 Controller 在业务校验前调用整包 `getBytes()`，全局 multipart 上限为 64 MiB，存在并发内存放大风险。应先校验大小并采用受限流式处理。

## 下一阶段门禁

Gate 8C 首批只建议准入 `T2-SEC-002`。内部安全 P0 未关闭前，不准入可维护性、性能、内部发布候选、完整 Alpha 或生产。不得通过删除配置、关闭测试、日志掩盖或文档豁免关闭发现。
