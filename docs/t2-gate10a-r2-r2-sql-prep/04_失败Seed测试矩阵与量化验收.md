# 失败 Seed、测试矩阵与量化验收

## 红基线

- `SQL-PLAN-RED-001`：正式 Owner 测试中 EXPLAIN 回归文件为 0；
- `SQL-N1-RED-002`：报表导出查询数随门店数线性增长；
- `SQL-N1-RED-003`：支付对账引用查询数随账单条目增长；
- `SQL-N1-RED-004`：临期策略查询数随候选批次数增长；
- `SQL-PAGE-RED-005`：3 个交互报表查询没有显式分页契约。

`SQL-DIGEST-001` 与 `SQL-BOUNDARY-001` 是金标：12 条 SQL 摘要必须稳定，准备阶段运行时差异必须为 0。

## 正式执行矩阵

1. MySQL 8.4.11 空库迁移、重复执行、Flyway validate 与索引清单；
2. 12 条查询在 10k/100k 的 JSON/TREE 计划；1m 只用于获批趋势项；
3. 两租户相同自然键、门店越权、任务/导出范围攻击；
4. 稳定排序、分页边界、缺行/重行和 31 日边界；
5. 报表 1/10/50 门店、对账 1/100/1000 引用、临期 1/100/500 候选查询数；
6. FEFO/积分并发、锁等待、死锁、超时、回滚与原身份恢复；
7. 全量 Server、Gate 9C、安全、SBOM、许可证和证据门禁。

任何 P0/P1、租户越权、数据守恒变化、自动重跑或已发布迁移改写均为 `NO-GO`。
