# 影响分析、停止线与串行整改计划

## 影响分析

SQL 性能整改可能触及锁顺序、分页兼容、批量查询端口、索引、执行计划稳定性和内存上限。即使
结果集内容不变，也必须防止租户条件后移、排序漂移、分页漏重、锁范围扩大和 Outbox 事务退化。

## 停止线

- 新增或调整索引/数据库对象：停止，提交独立 CR 和前向迁移设计；
- 公共分页参数/响应、API 或错误码变化：停止，提交兼容性 CR 与 Requirement ID；
- 资金、库存、租户、支付、同步、幂等、事件或 Owner 语义变化：停止，独立业务 CR；
- MySQL 计划依赖不稳定参数、跨租户读取或只能通过放宽权限提速：`NO-GO`；
- R2-R3 资源整改继续禁止。

## 串行计划

1. **R2-R2-R1 执行基线**：仅添加测试夹具、合成种子、计划/查询数采集器和 CI；实际执行 12 条
   查询，保持生产 SQL 与索引不变；
2. **R2-R2-R2 锁定与单据查询**：在 R1 证据确认后处理 FEFO、积分、采购/调拨明细；需要索引先 CR；
3. **R2-R2-R3 查询放大**：分别处理报表导出、支付对账、临期策略三条 N+1；每条独立回归；
4. **R2-R2-R4 报表分页与大范围查询**：先确认 API 兼容 CR，再处理交互分页、数据包和对账范围；
5. **R2-R2-R5 总复验**：12 条计划、查询数、租户权限、Server/Gate 9C 和完整证据全绿后提交 Finding 验收。

每批独立 VERIFIED 并等待确认，不一次铺开。
