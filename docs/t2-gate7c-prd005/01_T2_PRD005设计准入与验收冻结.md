# T2-PRD-005 设计准入与验收冻结

## 1. 范围与非目标

实现 EAN-13 重量码、金额码模板的创建、发布、停用、签名包下发、本地确定性解析、
购物篮展示和成交计量快照。真实电子秤、厂商扫码 SDK、价签、补货、批次和新价格算法
不在范围。

## 2. Owner 与状态

- Catalog Owner：模板 `DRAFT → PUBLISHED → RETIRED`、摘要、事件、数据包。
- POS：只安装可信包并生成解析投影；不发布模板、不决定租户和门店权限。
- Order Owner：冻结原码和解析快照；成交后不可按新模板重算。
- 已发布内容不可变；更正创建新版本。重复命令返回原结果，同键异内容拒绝。

## 3. 模板与精度不变量

- EAN-13 固定 13 位且第 13 位校验；前缀 2—5 位，SKU 和数值段只占前 12 位且互不重叠。
- 字段位置为 1 基；SKU 段保持前导零并映射租户内启用 SKU code。
- `WEIGHT` 数值按 `10^-valueScale` 转为主单位数量；金额为数量乘冻结单价并
  `HALF_EVEN` 到分。
- `AMOUNT` 的 `valueScale=2`，编码值直接形成分；数量按主单位精度 `HALF_EVEN`
  反算，金额保持权威并记录 `roundingApplied/manualReviewRequired`。
- 单价必须为正、数量和金额必须为正；任何溢出、负数、零值和超精度均失败关闭。

## 4. 决策顺序、权限与审计

可信租户/门店来自服务端会话或终端绑定。候选按门店范围优先、前缀更长优先、显式
优先级更高优先；仍并列返回 `CAT-WBC-AMBIGUOUS`。发布前拒绝同范围重叠有效窗。
模板管理、发布、停用和解析预览分别使用独立权限并记录内容摘要、操作者和关联标识。

## 5. 迁移、离线与回退

MySQL 通过 `V202608220059` 新增模板和只追加发布历史，并通过 `V202608220060`
在不可变订单行冻结模板身份、解析摘要与完整计量快照；Catalog 包新增
`WEIGHT_BARCODE_TEMPLATE` 记录。`order.submitted.v2` 对标准商品保持原形状，对计量商品
增加可选且完整的 `measuredBarcodeSnapshot`，新服务端同时兼容旧客户端无快照事件。
SQLite v14 只前进新增本地模板和订单行解析快照列。旧客户端遇到要求新 Schema 的包失败关闭；
回退只停用入口或安装上一份已验证包，不删除已成交快照。
实时扫码只允许命中当前启用的商品、单位和有效模板；离线积压订单回传时则按成交时冻结的
SKU/单位身份、模板版本、有效窗和摘要验真，即使商品或模板后来停用也不得误拒绝历史事实。

## 6. 量化验收

- Java/Dart 共用重量码与金额码固定金标，逐字段数量、金额、摘要一致；故障向量不少于 12 个。
- 覆盖前导零、EAN 校验、重量/金额边界、舍入、重叠、未来/过期、旧包重放、挂单后
  模板变化、跨租户/门店、同键异内容、摘要篡改和迁移失败。
- MySQL 8.4 空库迁移、二次执行、发布不可变和权限通过；SQLite 原子安装/回退通过。
- P0/P1 为 0，完整 CI 全绿后只更新为 `VERIFIED`，等待项目发起人确认。
