## 3. 后续内部代码建议

当前没有开放的内部 P0/P1，因此不建议为了“继续开发”而制造新模块。若仍优先内部代码，
下一阶段只应选择以下二者之一：

- `Gate 9C 封板`：仅做证据固化、可重复构建和封板候选，不新增业务；
- `Gate 10A-Prep 内部 P2 债务评审`：只审计非阻断维护项，例如 GitHub Actions Node 20
  弃用提示、测试时长/制品体积和文档一致性；必须先建立缺陷 ID，不能改变业务事实。

不建议在外部 P0 长期保持阻断时继续无限增加商业 V1 功能，否则会扩大未经过真实环境验证的
代码面和后续集成风险。
