# G9A-R3 分批整改计划

## R3A：主路径、测试底座与组合支付可达性

范围：VUE-01/02/03/04、FLT-03/04/06。先冻结失败测试，再评审 Vue 挂载测试所需开发依赖，
收敛商品/组织页面状态和权限，补可信会话到组合支付的正式入口。不得改变支付金额、份额状态机
或电子支付失败关闭。

## R3B：Owner 运营页面

范围：VUE-05 至 VUE-15。复用统一受控操作状态，将 single-flight、原幂等键、错误码、关联标识、
空态和权限拒绝绑定到页面，并补组件交互测试。不得复制 Owner 算法或跨 Owner 查询。

## R3C：报表、终端、商业运营与 POS 辅助页

范围：VUE-16 至 VUE-20、FLT-01/02/05。补导出/终端/生命周期/附件权限与失败恢复测试，以及
POS 换货、退货、现金管理的离线和业务日向量。外部支付、硬件和外设继续失败关闭。

## R3D：26 页联合验收

使用两个虚构租户、三业态、多门店、多终端，逐页执行十二维矩阵；P0/P1 必须为 0，Linux/
Windows、Web/Flutter/Android、服务端权限与既有 Gate 全量回归必须全绿。只有此时才可形成
`G9A-UI-P1-001 VERIFIED_CLOSURE_CANDIDATE`，仍需项目发起人确认才能关闭。

四批严格串行，每批都须独立 `VERIFIED` 和项目发起人确认，不能一次铺开。
