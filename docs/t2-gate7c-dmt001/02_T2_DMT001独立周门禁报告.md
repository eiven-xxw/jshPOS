## 2. 已验证能力

- Migration Owner 独占文件登记、加密 staging、映射预检、双人审批、批次 Saga、
  Owner 检查点、对账、激活里程碑、审计、Outbox 和到期清理；不直接写其他 Owner
  私有表。
- Catalog、Procurement、Member 和 Inventory 分别通过正式应用端口接收商品/条码/
  单位/分类品牌、供应商、会员和期初库存事实；Owner 顺序冻结为
  `CATALOG → PROCUREMENT → MEMBER → INVENTORY`。
- 每个文件绑定可信租户、资料类型、Schema/映射版本、来源系统、原文件 SHA-256、
  字符集、行数、受控保管引用和上传人；租户不从文件内容获得。
- 原文件不持久化，staging 使用 AES-256-GCM；CSV 支持 UTF-8/GB18030，XLSX 执行
  公式、外链、压缩炸弹、重复扩展名、路径、列数、单元格长度和 64 MiB 上限检查。
- 状态覆盖 `UPLOADED/PREFLIGHTING/PREFLIGHT_FAILED/READY/APPROVED/IMPORTING/
  IMPORTED/RECONCILING/RECONCILED/ACTIVATION_PENDING/ACTIVATED/FAILED/
  COMPENSATION_REQUIRED/CLEANED`；非法迁移和摘要漂移失败关闭。
- 同幂等键同内容返回稳定原结果，同键异内容拒绝；跨 Owner 采用可恢复 Saga 和逐
  Owner 检查点，不伪造跨库大事务，部分失败通过检查点恢复、未激活版本、补偿命令
  或新调整事实收敛。
- 期初库存只允许引用同批次冻结商品，经 Inventory Owner 追加 `OPENING_IN` 事实；
  激活后只允许新库存流水修正，不物理删除或覆盖历史。
- 会员导入通过 Member Owner 的身份密文、令牌摘要与最小展示边界；原始身份信息、
  Secret 和文件内容不进入普通日志、Git、CI 或公共制品。
- 只有双人审批和所有必需 Owner 对账完成后才允许激活；P0/P1 差异、摘要漂移或审计
  缺失均为 `NO-GO`，且激活不会自动开店、发布价格、创建采购承诺或产生资金效果。
- Vue 迁移向导只调用正式 API，展示批次、预检错误、审批、Owner 检查点、对账、
  激活和清理状态；不跨 Owner 查询、不自报租户、不显示会员密文。
- MySQL V63—V65 只前进迁移包含中文 COMMENT、租户复合约束、只追加/受控更新
  保护、权限与索引；MyBatis 正式业务 SQL 全部位于 XML，未使用 SQL 注解。
- 39 个固定故障向量、两个虚构租户、多门店、多仓库和三业态合成数据已纳入回归；
  100k 正式预检与 1m 流式摘要仅形成内部趋势。

## 3. 失败与修复记录

首个实现候选 `77df61e165e32304f453af807a73564796dfdeb5` 的
[Run 32584943147](https://github.com/eiven-xxw/jshPOS/actions/runs/32584943147)
在 MySQL 8.4 执行 V64 时发现列名 `row_number` 为保留字，MySQL Job 失败；随后推送
修复时该候选 Run 按并发策略取消，其失败日志与 Run 均原样保留。

修复提交 `276d3489d77317badfa4a99e797a17f3fb87ad64` 在迁移尚未发布、需求尚未
`VERIFIED/ACCEPTED` 的开发候选阶段，将该列统一改为 `source_row_number`；同时发现
失败预检必须能登记空文件事实，因此把 `file_bytes` 约束从 `1..64MiB` 校正为
`0..64MiB`，并增加 MySQL 空文件失败事实防回归。没有修改任何已发布迁移，没有降低
约束或测试阈值，没有跳过失败测试或重跑单个失败 Job；新提交触发完整 Run
`32585460410`，九个 Job 全部重新执行并通过。
