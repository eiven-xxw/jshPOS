# T2-DMT-001 设计准入与验收冻结

## 1. 准入结论

`READY → IN_PROGRESS`。唯一范围是开业商品、供应商、期初库存和会员资料迁移。
工作基线为 `fdd2667e48ce4197907416b823ff6cb917a66d6b`；ONB、LOT、外部适配和生产执行
不在本准入范围。

## 2. 数据主权与访问策略

| 对象 | Owner | 写入方式 | 访问策略 / SQL |
| --- | --- | --- | --- |
| `mig_file/mig_batch` | Migration | Migration Repository | `CONTROLLED_WRITE / XML` |
| `mig_staging_row` | Migration | 加密暂存与受审计清理 | `CONTROLLED_WRITE / XML` |
| `mig_preflight_error/mig_approval/mig_state_event/mig_audit_event` | Migration | 只追加 | `APPEND_ONLY / XML` |
| `mig_owner_checkpoint/mig_reconciliation/mig_outbox` | Migration | 具名迁移或只追加 | `CONTROLLED_WRITE / XML` |
| `cat_*` | Catalog | `BusinessMigrationCatalogPort` | 端口写入，Migration 无 Mapper 权限 |
| `sup_*/pur_*` | Procurement | `BusinessMigrationSupplierPort` | 端口写入，Migration 无 Mapper 权限 |
| `inv_*` | Inventory | `BusinessMigrationInventoryPort` 追加 `OPENING_IN` | 端口写入，不更新余额历史 |
| `mem_*` | Member | `BusinessMigrationMemberPort` | 端口写入，身份密文最小展示 |

tenant_id 只来自可信上下文。文件内租户字段（若出现）属于未知字段并阻断预检。

## 3. 文件与隐私边界

- 支持 CSV 与无宏 XLSX；单文件默认上限 64 MiB、100,000 行、200 列和 4,096 字符/格。
- 文件名只保留安全逻辑名；拒绝绝对路径、`..`、NUL、重复扩展和不可识别类型。
- 上传时校验声明 SHA-256、字符集、压缩条目/解压体积/压缩比、重复/未知列、公式、
  外部链接、非法编码和危险首字符；任何错误不得写业务 Owner。
- 错误明细只保留稳定错误码和脱敏说明；批次详情最多带回首 500 条，完整结果必须经
  受权限保护的分页端点读取，每页不超过 500 条，不允许静默截断错误总数。
- 原始文件请求结束即丢弃；普通表只保存 SHA-256、行数、来源系统和受控保管引用。
- 规范化 staging 使用 AES-256-GCM；Secret 缺失、版本未知或解密失败均失败关闭。
  错误明细不得回显会员身份原文，日志、CI 和制品不得包含原始文件或真实 PII。

## 4. 状态机与冻结点

`UPLOADED → PREFLIGHTING → READY → APPROVED → IMPORTING → IMPORTED →
RECONCILING → RECONCILED → ACTIVATION_PENDING → ACTIVATED → CLEANED`。

失败分支为 `PREFLIGHT_FAILED/FAILED/COMPENSATION_REQUIRED`。状态只能具名条件迁移，
每次迁移追加状态事件和审计。冻结点：文件摘要在 UPLOADED 后不可变；映射和行摘要在
READY 后不可变；双人审批后不得替换文件；Owner 结果在检查点完成后不可覆盖；激活后
只能用新 Owner 事实修正。

`PREFLIGHT_FAILED` 为终态；修正文件必须建立新批次，禁止替换已登记原文件摘要，
也禁止把失败批次重新预检为绿色。

## 5. Saga、幂等与对账

- 批次幂等键作用域为可信租户；同键同请求返回原批次，同键异摘要拒绝。
- 同一资料类型的重复上传以原文件 SHA-256、映射、字符集、来源和保管引用共同核验；
  同内容返回原文件结果，任一元数据或内容变化均拒绝替换。审批同样执行同键同理由重放、
  同键异理由拒绝；Saga、对账、激活和清理对已达成状态返回原结果。
- 行幂等身份为 `batchId:dataType:rowNo`，预检冻结目标 ID 与内容摘要。
- 商业 V1 期初库存行必须引用同一迁移批次内已冻结的商品行，避免仅凭外部 SKU
  编码绑定旧商品。已有商品的单独期初库存导入不在本需求范围，如需开放必须先
  增加可审计的 Catalog 身份匹配规则并单独变更。
- Owner 顺序为 Catalog → Procurement → Member → Inventory；每一步只提交 Owner
  本地事务，随后写 Migration 检查点。崩溃缝隙依赖 Owner 稳定幂等返回原结果。
- 部分 Owner 成功后失败进入 `COMPENSATION_REQUIRED` 或可恢复 `FAILED`，禁止伪造回滚。
- 本需求中“断点续传”的验收语义是已登记文件的预检/Saga 检查点恢复，而不是
  HTTP 分片上传。进程重启必须沿原文件摘要、原行和原 Owner 命令继续；不得重传后
  替换原文件或生成新业务命令。HTTP 分片上传需要独立需求和对象存储安全设计。
- 对账摘要对完整有序检查点逐字段做长度前缀流式 SHA-256，禁止依赖会受长度限制的
  `GROUP_CONCAT`。对账至少校验文件/有效行/Owner 成功数、结果摘要、商品条码/单位唯一、供应商唯一、
  逐仓逐 SKU 期初量守恒及会员身份冲突。任一 P0/P1 差异禁止激活。
- 双人审批要求两个不同且具备数据迁移审批权限的操作者；自批、重复角色或越权失败。

## 6. API、事件与错误

正式 REST/OpenAPI 与事件 Schema 位于 `contracts/t2/gate7c-dmt001`。稳定错误前缀：
`DMT-FILE-*`、`DMT-MAPPING-*`、`DMT-PREFLIGHT-*`、`DMT-STATE-*`、
`DMT-APPROVAL-*`、`DMT-OWNER-*`、`DMT-RECONCILE-*`、`DMT-SECURITY-*`。
API 不接收 tenant_id，不返回 staging 明文；关联标识贯穿上传、Saga、Owner 命令与审计。

## 7. 迁移、容量与回退

新增 `cat_migration_product` 与 `mig_*` 表已逐表登记访问策略和 SQL 模式：绑定、文件、
错误、审批、检查点、对账、状态事件和审计采用 `APPEND_ONLY + XML`；批次、可清理加密
staging 与带投递状态的 Outbox 采用 `CONTROLLED_WRITE + XML`。正式业务 SQL 不使用注解，
应用层仅依赖持久化端口，不直接依赖基础设施 Mapper，也不暴露 BaseMapper 通用更新/删除。

仅新增独立前向 Flyway 迁移，不修改 V1—V62。所有表、字段、精度、索引与约束写中文
COMMENT；数量使用 `DECIMAL(19,6)`，金额/成本使用既有最小货币单位或明确
`DECIMAL/BigDecimal`，禁止浮点数。100k 是正式上传验收上限；1m 只运行流式合成趋势，
不构成生产 SLA。

回退通过关闭入口、恢复原检查点、保持未激活 Catalog 版本、追加补偿命令和安全前向
修复完成。不得修改已发布迁移、清空 Owner 历史或用直接 SQL 修复事实。

## 8. 量化验收

- 两虚构租户、多门店、多仓库、三业态；跨租户、跨仓库和文件替换全部失败关闭。
- 空文件、重复文件、映射冲突、重复条码/供应商、单位冲突、负/超精度库存、会员
  重复身份、同键异内容、进程重启、乱序、部分 Owner 失败、对账不平、激活中断、
  清理与迁移前向修复均有固定 seed。
- 文件级安全失败必须落入脱敏 `PREFLIGHT_FAILED` 事实，不能遗留在 `PREFLIGHTING`；
  超过 64 MiB 的 Multipart 在分配原文件字节前由容器/Controller 失败关闭。
- 100k 合成行在 180 秒 CI 内部预算内完成；1m 仅验证 60 秒内流式摘要趋势，
  不产生完整数据集内存副本，两者均不构成生产 SLA。
- 治理、Server、Web、MySQL、Flutter 双平台、SQLite、Android/Kotlin、安全、依赖、
  SBOM、许可证、覆盖率和既有 Gate 全量回归全部通过后，才可更新为 VERIFIED。
