# 测试矩阵、故障注入与量化验收

固定向量见 `contracts/t2/gate7b-s20b/test-vectors/s20b-fault-vectors.json`。

## 1. T2-EXG-001 独立验收

- 正常：部分/最终原单退货、新销售现金成交、跨业务日原单、计量数量与舍入边界。
- 幂等：重复提交返回同 exchange；同键异内容 100% 拒绝。
- 故障：退货成功后 ACK 丢失、退款 UNKNOWN、服务进程终止、新销售磁盘失败、
  新销售已收但客户端未知、乱序 Owner 事件和全量重放。
- 攻击：跨租户原单、跨门店关联、摘要/金额篡改、越权批准/恢复、缓存和导出污染。
- 守恒：每个 exchange 恰好引用一条退货腿和一条新销售腿；不得生成第三条净额资金/
  库存事实；退货数量/金额逐行不超过原上限。

## 2. T2-PAY-004 独立验收

- 正常：现金+合成电子两份、多个合成电子+现金、纯现金旧路径兼容。
- 不变量：2—8 份、现金最多一次且最后、总额逐分等于应收、成功金额不超额。
- 故障：电子 UNKNOWN、回调/查询乱序、ACK 丢失、进程终止、部分成功后现金写入失败、
  重启恢复、同键异内容、退款按原份额和最终余数。
- 阻断：未解阻时 Provider 入口/依赖/网络调用数量必须为 0，电子正式路径 100% 返回
  `PAYMENT_EXTERNAL_BLOCKED`，不得以 Fake 关闭 `T2-PAY-002`。
- 跨端：Java 与 Dart 对状态、错误码、份额、金额、摘要逐字段一致。

## 3. 量化门禁

| 指标 | 阈值 |
| --- | --- |
| 固定向量通过率 | 100%，失败 seed 全部入账 |
| 金额/数量守恒 | 100%，允许差异为 0 |
| 重复命令业务效果 | 恰好一次；原结果一致 |
| 同键异内容、跨租户、越权 | 100% 失败关闭并审计 |
| P0/P1 缺陷 | 0 / 0 才可 `VERIFIED` |
| 新核心 Java/Dart 作用域覆盖率 | 行/分支均不低于现有 90% 门禁 |
| MySQL/SQLite 迁移 | 空库、升级、中断、重复、前向修复全部通过 |
| 性能 | 本地计划操作 p95≤100ms；服务端无外部网络命令 p95≤300ms（内部合成环境） |
| 外部执行 | Provider/真实资金/设备/外设/伙伴/Alpha/生产全部为 0 |

## 4. 串行验收

先完成 EXG 的设计复核、运行时、迁移、Flutter、故障和全量 CI，独立 `VERIFIED` 并
封存证据；只有项目发起人确认该门禁后才准入 PAY。PAY 必须再次独立走完整门禁，
不得用 EXG 的绿色结果替代。任何 Flaky 必须固定 seed 和根因修复，禁止自动重跑掩盖。
