# 仓库事实审计与范围边界

## 1. 审计结论

第二批不是重建退货、销售或支付。仓库已具备原单退货退款 Saga、原促销快照恢复、
现金新销售、Provider 无关支付/退款核心和库存退货入库。确认的缺口只有：

| 能力 | 仓库事实 | 处理 |
| --- | --- | --- |
| 原单退货退款与库存回补 | `jshpos-returns` 的正式编排与 `ret_*` 前向迁移已存在 | 强制复用 |
| 新销售与全额现金结算 | Flutter checkout、Order/Shift 正式端口已存在 | 强制复用 |
| 换货关联与可恢复 Saga | 无正式 aggregate、表、应用服务和页面旅程 | `T2-EXG-001` 缺口 |
| Provider 无关支付核心 | Payment Owner 已有 intent/attempt/UNKNOWN/refund/reconciliation | 强制复用 |
| 多支付份额计划 | `pay_payment_intent` 当前一单一个，未发现 `pay_tender_*` | `T2-PAY-004` 缺口 |
| 部分现金份额 | `ord_cash_payment` 一单唯一且等于全额应收 | `T2-PAY-004` 缺口 |

机器可读事实见 `contracts/t2/gate7b-s20b/repository-findings.json`。

## 2. 禁止重复实现

- 禁止换货模块重算退款促销、价格、库存或成本；禁止新增“净额库存移动”。
- 禁止 Payment Owner 直接更新订单、班次或现金流水；禁止 Order Owner 复制电子支付状态机。
- 禁止 UI 通过两次独立按钮点击伪装原子换货或组合支付。
- 禁止跨 Owner Mapper、跨表 UPDATE、直接写其他 Owner 私有表或修改已发布迁移。
- 禁止用 `UNKNOWN` 的替代命令、自动二次扣款或重复退款完成恢复。

## 3. 准入和证据边界

- 当前只允许文档、OpenAPI、事件 Schema、迁移登记、固定合成向量和专用 CI。
- `T2-EXG-001`、`T2-PAY-004` 继续 `DRAFT`；运行时代码、迁移文件和页面均为 0。
- 外部支付、真实资金、真实设备/外设、伙伴、完整 Alpha 和生产均为 0。
- `T2-PAY-002` 未经独立解阻时，电子份额运行时只能失败关闭，不得模拟成功。
- 项目发起人确认后也必须严格串行：EXG 独立 `VERIFIED` 后才能准入 PAY。
