# T2 Gate 5A / Sprint S9 范围、非目标与顺序准入

> 状态：Accepted for implementation
> 分支起点：`63537b5cb7ceeb1fe6b04107b53e2e68941b25ad`

## 1. 获准范围

| 顺序 | Requirement ID | 正式范围 | 当前准入状态 |
|---:|---|---|---|
| 1 | `T2-PRM-001` | 规则身份、不可变版本、校验/发布/暂停、门店渠道商品作用域、确定性试算、解释、版本化离线规则包 | `VERIFIED`，独立提交与门禁已完成 |
| 2 | `T2-PRM-002` | 受权手工改价、整单固定/比例优惠、现金抹零、阈值、职责分离和只追加审计 | `VERIFIED`，独立实现与门禁已完成 |
| 3 | `T2-PRM-003` | 成交快照冻结、最大余数分摊、金额守恒、原单退款恢复与累计上限 | `VERIFIED`，独立实现与本地门禁已完成，等待总门禁 |

首版规则仅允许：`SPECIAL_PRICE`、`PERCENT_OFF`、`AMOUNT_OFF`、`NTH_ITEM_DISCOUNT`、`BUNDLE_PRICE`、`THRESHOLD_AMOUNT_OFF`、`THRESHOLD_QUANTITY_OFF`。作用域仅允许租户、门店、渠道、SKU、分类、品牌、业务日和有效时段；条件与结果均来自白名单结构化字段。

## 2. 强制顺序

1. PRM-001 完成正式服务端/Dart 引擎、规则包、同向量差分、租户和 MySQL 验证后，RTM 才可由 `IN_PROGRESS` 转为 `VERIFIED`，PRM-002 才可转为 `IN_PROGRESS`。
2. PRM-002 完成人工优惠权限、阈值、审批、审计和失败关闭验证后，PRM-003 才可转为 `IN_PROGRESS`。
3. PRM-003 完成快照、分摊、退款恢复、SQLite 原子冻结和跨端差分后，三项才可共同提交 Sprint 周门禁。
4. `VERIFIED` 不等于 `ACCEPTED`；只有项目发起人确认周门禁报告后才能更新为 `ACCEPTED`。

## 3. 非目标

- 优惠券、积分、储值、会员等级/标签、预算抢占、次数权益、拼团、秒杀、跨店累计、动态定价；
- 真实支付 Provider、真实会员或商户数据、生产密钥、生产签名私钥；
- 多承担方结算、供应商返利、应付、发票、税务总账和营销报表；
- 任意脚本、表达式语言、SQL 条件或外部实时网络查询；
- 管理后台完整运营 UI、实机性能、物理断电、设计伙伴试点与商业验收。

遇到未准入字段或算子必须返回 `PRM-CAPABILITY-UNSUPPORTED`，禁止忽略、猜测或按零优惠静默继续。会员、券和预算字段即使出现在输入中也必须失败关闭。

## 4. 证据边界

本 Sprint 只使用两个虚构租户、多门店、多终端、三业态合成商品与订单。最高证据等级预计为 `STATIC + UNIT + MYSQL_INTEGRATION + SQLITE_INTEGRATION + CROSS_RUNTIME_VECTOR`；`SANDBOX=0`、`REAL_DEVICE=0`、`PILOT=0`，不能据此宣称 Alpha、试点或商用。
