# Gate 5A 测试矩阵、CI 与证据规范

> 文档编号：JSH-POS-T2-G5A-005

## 1. 测试矩阵

| 维度 | 最低覆盖 |
|---|---|
| PRM-001 | 七类基础规则、有效期/业务日、优先级、互斥/叠加、解释码、幂等、能力拒绝、包摘要/签名/原子切换 |
| PRM-002 | 手工改价、固定/比例整单优惠、抹零、阈值、权限、职责分离、同键异内容、审计与回滚 |
| PRM-003 | 最大余数、稳定余数、零金额行、快照冻结、部分/最后一次退款、累计超限、并发和篡改拒绝 |
| 跨端 | Java 与 Dart 读取同一黄金 JSON，逐字段比较 gross、discount、rounding、payable、行结果、调整、解释和 fingerprint |
| 租户 | Mapper、XML、规则包、缓存、任务、导出、对象存储、快照、退款恢复共至少 18 个攻击面 |
| 数据库 | MySQL V1—V23、中文 COMMENT、复合租户 FK、不变触发器；SQLite V1→V5、损坏/中断/重复恢复 |
| 边界 | 0/1 分、最大 long 防溢出、数量 6 位、比例 8 位、午夜/时区、500 行、候选上限 |
| 故障 | 包下载损坏、签名错、切换 kill、迁移失败、并发发布、报价重复、快照重复、退款重复与乱序 |

黄金向量固定存放于 `contracts/t2/gate5a/test-vectors/promotion-golden-vectors-v1.json`，不得为修复单端实现而单独修改预期；语义变更必须提升引擎/Schema 版本并记录 ADR。

## 2. 顺序准入证据

- PRM-001：规则引擎、生命周期、包与跨端向量通过后，记录 `VERIFIED_PRM1` 证据，才允许 PRM-002 进入实现。
- PRM-002：人工优惠权限、阈值、审计与跨端向量通过后，记录 `VERIFIED_PRM2`，才允许 PRM-003 进入实现。
- PRM-003：快照、分摊、退款恢复、SQLite 事务与全量回归通过后，三项更新为 `VERIFIED`，等待项目发起人确认。

## 3. CI Jobs

`.github/workflows/t2-gate5a.yml` 至少包含：

1. governance：基线祖先、AGENTS、ADR、RTM 顺序、契约、策略登记和迁移摘要；
2. server：完整 Maven reactor、255+ 既有回归、新模块覆盖率与 Admin JAR；
3. mysql-migration：MySQL 8.4.6 V1—V23、注释、约束与触发器；
4. tenant-security：可信租户、权限和攻击矩阵；
5. cross-runtime-vectors：Java/Dart 同一黄金向量及语义摘要；
6. pos-linux：Flutter analyze/test/coverage、SQLite V5、Kotlin 与 debug APK；
7. pos-windows：独立 Windows Flutter 回归；
8. admin-web：audit/build/lint/typecheck/既有测试/许可证；
9. security-sbom-license：Secret、IaC、HIGH/CRITICAL、双 SBOM 与许可证；
10. evidence：九类制品、测试数、向量数、摘要、状态和 `paymentNetwork=0` 聚合。

不得使用 `continue-on-error`、自动重跑、跳过失败测试、降低覆盖率或绿色占位。Flaky 必须固定 seed、定位原因并完整重跑。

## 4. 量化门禁

- Promotion 核心 Java 行覆盖率 ≥ 90%、分支覆盖率 ≥ 85%；Flutter promotion 核心行覆盖率 ≥ 90%。
- 黄金向量 100% 通过且 Java/Dart 输出 SHA-256 一致；金额不变量属性测试至少 10,000 组固定 seed。
- 所有新表/字段中文注释非空；SQL 注解新增数为 0；应用/领域对 Mapper/MP Entity 依赖违规为 0。
- Provider 网络调用、生产密钥、真实数据、SANDBOX、REAL_DEVICE、PILOT 均为 0。

证据必须记录 commit SHA、run/job/artifact ID、digest、测试数、覆盖率、失败修复和未验证边界；Fake/合成结果不能升级为商业证据。
