# T2-INT-001 Owner 正式装配与内部集成设计准入

## 1. 组合根与数据主权

- 新增 `jshpos-integration` 作为模块化单体组合根，只声明和验证 Owner 能力，不保存业务事实、不执行金额、促销、库存或成本算法。
- 组合根在 Spring 单例初始化完成后验证 16 项正式能力各自唯一存在；缺失或重复以 `CORE-ASSEMBLY-001` 阻断启动。
- 各 Owner 继续只写自己的表和不可变事实；跨 Owner Mapper、跨 Owner Infrastructure、非组合根直接注入其他 Owner Application Service 均为 P0。

## 2. 正式协作边界

- Catalog 成交价通过 `OrderPriceResolutionPort.v1` 供 Order 只读校验，Order 不再直接依赖 Catalog 具体服务。
- Sync 消费 `order.completed.v2` 后通过 `PromotedOrderSubmissionPort.v2` 幂等进入 Order，不再注入 Order 具体服务。
- 既有 Inventory、Costing、Procurement、Transfer、Returns、Payment、Promotion、Terminal 与 Release 协作继续使用显式应用端口；Reporting 只消费版本化事实形成可重建投影。
- POS Outbox、服务端 Inbox、Owner 事实和 ACK 保持各自事务边界；至少一次传输以稳定 event ID、payload hash 和 Owner 幂等实现一次业务效果。

## 3. 失败关闭与恢复

- 同键同内容返回原结果，同键异内容拒绝；UNKNOWN 只能由原标识查询、回调或账单观察收敛，禁止重新生成业务命令。
- 重复、乱序、ACK 丢失、进程终止、磁盘失败、业务日切换、部分 Owner 失败和全量重放使用 12 个固定 seed 回归。
- 支付 Provider、真实硬件、伙伴、真实打印和鲸熵汇边界在组合根中继续显示 `BLOCKED/DEFERRED + UNAVAILABLE`；组合根不提供 Fake 成功适配器。

## 4. 装配与制品验证

- `ruoyi-admin`、父依赖管理和 reactor 均必须包含 `jshpos-integration`。
- 正式 Spring Boot JAR 必须同时包含 15 个 Owner 模块和 `jshpos-integration`，否则门禁失败。
- 关键 Owner 回归、装配缺失/重复、外部不可用状态均不得失败或跳过；新模块覆盖率最低为行 90%、分支 85%。

## 5. 证据边界

本准入只允许内部正式装配和软件故障验证。`T2-E2E-003` 在 INT 独立 CI 成功前继续 `DRAFT`；真实支付、真实设备、现场伙伴、完整 Alpha 和生产部署继续为 0。
