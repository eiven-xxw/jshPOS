## 3. 已修复问题

审计发现订单 Owner 与促销 Owner 曾由 Mapper 直接读取 `jsh_config_*` 私表。该实现违反 Owner 数据主权，且旧交班阈值 SQL未限定配置模板，存在读到错误配置值的风险。本次已完成：

1. Foundation Owner 新增 `PublishedConfigReadPort` 与可信实现，租户只来自认证上下文，门店覆盖租户的优先级固定；
2. Order Owner 通过 `ShiftDifferencePolicy` 读取 `SHIFT_CASH_DIFFERENCE`，缺少策略时按零阈值失败偏安全，畸形/负值拒绝；
3. Promotion Mapper 删除对 `jsh_config_*` 的 SQL，适配器改经 Foundation 只读端口读取 `PROMOTION_MANUAL_AUTHORITY`；
4. 增加可信租户、门店覆盖、未发布版本、策略解析与失败关闭单元测试；
5. Mapper 门禁改为明确禁止 `jsh_config_*` 出现在促销 XML。
6. POS 默认入口不再直接装配 `Locked*` 业务服务；新增会话绑定组合根，在可信终端和员工认证后才打开租户/门店/设备专属文件 SQLite，并安装签名商品与促销包。
7. 修正退货仓库 ID 与服务端 ULID 契约不一致的问题；服务端登录成功但本地运行时装配失败时，复用原关联标识撤销会话并保持页面锁定。

## 4. 允许保留的显式边界

- `PosLocalDatabase.inMemory`：只作为测试/合成执行的显式构造器；生产组合根使用路径数据库，不会自动选择内存库。
- `pos_device_adapter_platform_interface` 的未实现异常：真实硬件仍为 `BLOCKED` 时的插件平台失败关闭；不得作为真实设备成功证据。
- `LockedPosTerminalMaterialProvider`：HWD 未解阻时不从 `dart-define`、仓库或普通配置读取设备秘密，明确返回 `HWD_SECURE_CREDENTIAL_UNAVAILABLE`。业务服务本身已有正式组合根，不再以销售/退款空实现冒充生产装配。
