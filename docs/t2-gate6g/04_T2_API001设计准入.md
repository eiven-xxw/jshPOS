# T2-API-001 正式 API 与兼容契约设计准入

## 1. 数据主权与边界

- REST 只暴露 Owner 已接受的应用端口；Controller 负责认证、参数校验、协议转换和统一响应，不承载领域算法。
- `tenant_id` 只取自认证后的可信上下文。请求 DTO、路径、Header、分页条件或导出参数中的租户值均不得成为授权依据。
- Owner 间协作继续使用版本化事件、Inbox/Outbox 或明确只读端口，禁止跨 Owner Mapper 和私表访问。
- 支付 Provider、真实回调和硬件控制端点仍为零；外部边界只允许明确失败关闭。

## 2. 版本、错误与幂等

- 正式前缀冻结为 `/api/v1`、`/api/pos/v1`、`/api/admin/v1`；历史成本端点 `/api/inventory` 在 V1 内保持兼容，Gate 6H 只允许以新增版本路径实施迁移，不得静默改址。
- 统一响应使用 `R(code,msg,data)`，关联标识使用 `X-Correlation-Id` 返回；业务错误码遵守 `contracts/t2/gate6g/error-codes-v1.json`。
- 事实写入必须提供 `Idempotency-Key`/`X-Idempotency-Key`，或请求体内不可变 `commandId/eventId`。同键同摘要返回原结果，同键异摘要拒绝。
- UNKNOWN 只允许以原标识查询或观察收敛，禁止生成新资金或业务命令。

## 3. 分页、排序和容量

- 常规列表使用 `page/size`，`size` 上限 200；流水和同步使用 `cursor/afterSequence/limit`，`limit` 上限 1000。
- 排序字段由服务端白名单决定，不能接受任意列名或 SQL 片段。
- 所有查询、缓存、异步任务、导出、临时文件和对象存储都必须绑定可信租户和数据范围。

## 4. 兼容和回退

- V1 只允许向后兼容的可选字段、响应扩展和新增端点；删除字段、改变金额/状态语义或修改幂等结果必须发布新的主版本。
- Gate 2 POS 契约缺失的 `/api/v1/pos` server 前缀作为前向文档修正记录，不改变实际运行路径。
- Gate 6G overlay 只补齐已有运行时端点，不新增领域能力。回退时保留旧契约和旧客户端兼容窗口，服务端失败关闭。

## 5. 验收

`scripts/audit_t2_gate6g_api.py` 必须证明：Controller 与 OpenAPI 双向完全覆盖、`operationId` 唯一、权限无未解释缺口、请求 DTO 无租户覆写字段、错误码格式合法，且外部网络和真实回调准入仍为零。
