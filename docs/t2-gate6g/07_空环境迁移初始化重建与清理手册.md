# 空环境迁移、初始化、重建与安全清理手册

## 1. 空环境启动

1. 创建空 MySQL Schema 和最小权限迁移账号，不导入任何业务快照。
2. 对全量 Owner migration locations 执行 `flyway migrate`，随后执行 `flyway validate`；第二次 `migrate` 必须为 0。
3. 校验 `information_schema`：159 张正式表、主键、租户索引、中文表说明、唯一约束和金额数量精度。
4. 启动服务端并以正式健康检查确认应用版本、Schema 版本和依赖状态；外部支付和硬件适配器应明确返回 `BLOCKED/UNAVAILABLE`。
5. Flutter 首次打开创建 SQLite v1—v7，校验 7 条历史摘要、`quick_check=ok` 和可信设备绑定。

## 2. 虚构数据初始化

1. 只在非生产环境加载 `contracts/t2/gate6g/test-vectors/internal-seed-v1.json`。
2. 由平台管理员创建两个虚构租户的测试壳和受控管理员会话。
3. 严格按 `applicationSequence` 经正式 API 创建组织、门店、商品、价格、数据包和虚构终端；禁止数据库直写。
4. 完成后按 seed canonical SHA-256、租户数、门店数、终端数和三业态逐项核对。

## 3. 投影重建

1. 冻结目标租户写流量并记录 Owner 检查点。
2. 仅清空可丢弃投影，不触碰订单、支付退款、库存成本流水、促销快照、审计和 Inbox/Outbox 权威事实。
3. 按 Owner 顺序从不可变事实重放：Order/Shift → Promotion → Inventory → Costing → Member → Reporting。
4. 追平 Inbox/Outbox 与单调游标，执行逐租户、逐门店、逐业务日和逐字段守恒。
5. 任何同键异摘要、序号缺口或金额数量差异均失败关闭并进入人工修复。

## 4. 中断与前向修复

- MySQL 或 SQLite 迁移中断后先验证当前历史表和摘要；未完成事务必须回滚，完成版本不得重放为另一内容。
- 未知未来版本禁止降级打开。修复必须以更高版本追加，不得修改原迁移。
- 重建中断保留原检查点和幂等键；恢复后从同一事件继续，不生成新资金或业务命令。

## 5. 安全清理

- 仅凭 `seedId=GATE6G-SYNTHETIC-SEED-V1` 在隔离非生产环境执行；生产环境硬阻断。
- 先撤销会话和虚构终端，再清理临时对象、staging 和投影；权威事实只允许按测试环境销毁流程整体销毁 Schema，不执行选择性物理删除。
- 清理后检查对象存储、导出、临时目录、日志和 CI 制品无 Secret/PII，并保留清理审计和环境销毁证据。
