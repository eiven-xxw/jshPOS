# T2-CORE-001 生产代码完整性设计准入

## 1. 数据主权与装配

所有已接受 `jshpos-*` Owner 继续独占自己的事实表、状态与审计。`ruoyi-admin` 是 Spring Boot 组合根，只负责装配模块，不拥有领域事实；Web 与 Flutter 只调用正式 API/应用端口。

## 2. 审计分类

每个生产文件按以下类别扫描并人工复核：

- `FAKE/MOCK/STUB/IN_MEMORY`：测试实现不得被生产组合根注入；
- `LOCKED/UNAVAILABLE`：只有外部阻断适配器可保留，且每次调用必须显式失败并有错误码；
- `TODO/FIXME/EMPTY/UNSUPPORTED`：核心路径不得遗留；第三方上游和测试断言不计入，但必须在报告中区分；
- `STATIC_SYNTHETIC/HARDCODED_TENANT`：生产路径不得形成权威业务结果；
- `CONTROLLER_DOMAIN_LOGIC/CROSS_OWNER_MAPPER`：发现即 P0/P1 缺陷并修复。

## 3. 事务与失败关闭

- 写路径必须通过应用服务定义事务边界；账本、幂等结果、审计、Outbox 维持同事务不变量。
- Spring Bean 缺失、外部能力未解阻、租户上下文缺失、摘要冲突或依赖 Owner 失败时必须显式失败，禁止默认成功、空集合掩盖或写部分事实。
- Provider 无关 Payment 核心可以运行，但 Provider Adapter 只能返回 `PROVIDER_UNAVAILABLE/BLOCKED`；设备能力同理。

## 4. 准入验收

1. 生成覆盖全部 ACCEPTED T2 需求与正式 Owner 的机器矩阵；
2. 生产路径扫描项全部分类，P0/P1 为零；
3. 组合根包含全部正式模块且 Spring 上下文测试通过；
4. 所有保留外部失败适配器有可执行拒绝测试；
5. Maven 全量测试、Flutter/Web 既有回归和租户/Secret 门禁不退化。
