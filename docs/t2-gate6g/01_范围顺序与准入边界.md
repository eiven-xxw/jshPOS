# Gate 6G 范围、顺序与准入边界

## 1. 目标

把 Gate 0—6E 已接受能力从“模块内通过”收口为可启动、可联调、可恢复、可维护的内部商业 V1 核心候选。范围只包括内部正式代码和合成边界，不引入 Provider 或设备厂商实现。

## 2. 串行门禁

| 顺序 | Requirement | 本阶段职责 | 初始状态 |
|---:|---|---|---|
| 1 | T2-CORE-001 | 生产代码完整性、正式装配、事务和失败关闭 | `IN_PROGRESS` |
| 2 | T2-API-001 | REST/OpenAPI/事件/错误码/幂等和兼容 | `DRAFT` |
| 3 | T2-DAT-001 | MySQL/SQLite、初始化、重建、前向修复 | `DRAFT` |
| 4 | T2-INT-001 | 正式 Owner 应用编排和故障收敛 | `DRAFT` |
| 5 | T2-E2E-003 | 正式运行路径内部合成闭环 | `DRAFT` |

后一项只有在前一项完成独立 CI 并更新为 `VERIFIED` 后才能进入 `IN_PROGRESS`。设计夹具、文档或空测试不能改变状态。

## 3. 非目标

- 拉卡拉或其他 Provider SDK/HTTP、真实回调、账单下载和资金；
- 厂商打印、扫码、秤、钱箱、客显、APK 安装与终端命令；
- 伙伴联系、现场迁移、完整 Alpha、生产部署或商业 SLA；
- 优惠券、储值、发票、总账、复杂 WMS、鲸熵汇连接器；
- 修改已发布迁移、复制 Owner 算法或创建第二事实源。

## 4. 证据等级

单项可使用 STATIC、UNIT、COMPONENT、SOFTWARE_EXECUTION、SYNTHETIC_E2E；最终上限为 `INTERNAL_V1_CORE_CANDIDATE`。外部阻断仍只能由 SANDBOX、REAL_DEVICE、PARTNER_VERIFIED/PILOT 证据解除。
