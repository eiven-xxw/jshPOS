# T2-DAT-001 数据与环境一致性设计准入

## 1. 数据主权与迁移

- MySQL 以各 Owner 的 Flyway 迁移为唯一 Schema 来源；所有已发布迁移不可修改、移动或重命名，只能追加全局唯一版本的前向迁移。
- SQLite 以 `local_schema_history`、每版 SHA-256 和 `PRAGMA user_version` 共同校验；未知版本、摘要不一致、设备租户绑定不一致均失败关闭。
- 迁移中断必须依赖数据库事务整体回滚；再次启动只重试未完成的原迁移，不跳过版本，也不回写已发布脚本。

## 2. 表元数据与精度

- 159 张正式表必须有主键和中文表说明；含 `tenant_id` 的业务表必须把租户列纳入索引或唯一约束。
- 备份恢复的 5 张控制面表允许覆盖经授权的多个租户，因而使用不可变租户集合及 `tenant_scope_sha256`，这是显式例外而非租户缺口。
- 金额、成本、数量、比率不得使用 `FLOAT/DOUBLE`。最小货币单位金额使用整数，成本和中间值使用 `DECIMAL/BigDecimal`，数量使用 `DECIMAL(19,6)` 或冻结整数分数。

## 3. 初始化、重建和清理

- `internal-seed-v1.json` 只含两个虚构租户、四门店、四终端和三业态；不含 Secret、真实 PII、支付凭据或真实设备信息。
- 平台管理员建立非生产租户壳后，业务种子只能按清单经正式 API 写入，禁止直接写业务表或使用 E2E 后门。
- 投影允许丢弃并从 Owner 权威事实、不可变流水及 Inbox/Outbox 检查点重建；报表或 POS 本地库不得覆盖云端权威事实。
- 清理仅允许删除种子创建的临时文件、会话和可丢弃投影；权威业务事实不得物理删除。

## 4. 容量、归档和前向修复

- 继续沿用 10k/100k 商品、百万级报表事实和同步积压容量基线；最终生产容量需独立真实环境证据。
- 权威事实采用只追加归档批次，保留摘要、租户范围、Schema、时间点和审计；投影可重建，staging 与临时文件按运行手册限时清理。
- 迁移失败时停止流量并保留旧应用；只允许新迁移实施前向修复。不可逆迁移必须在发布前具备备份、兼容窗口和守恒校验。

## 5. 验收

静态审计、Flutter SQLite 故障测试、各 Owner MySQL Flyway 集成测试及全量 CI 必须共同通过；任一已发布迁移变化、表无主键/中文说明、租户索引缺失、浮点精度或非合成种子均为 P0。
