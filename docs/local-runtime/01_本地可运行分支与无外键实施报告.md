## 2. 数据库初始化和无外键结论

数据库初始化分为两个受控步骤：

1. `infra/local/mysql/jshpos-local-init.sql` 创建 `jshpos` 数据库并导入 RuoYi 基础表；
2. 商业 Server 以 `local` profile 启动，由 Flyway 从空库顺序执行全部业务迁移。

V1—V89 是不可修改的历史迁移。V90 只向前删除当前 200 张业务表上的 309 个物理
外键，不删除主键、唯一约束、CHECK、NOT NULL、不可变触发器或索引。引用完整性继续
由 Owner 应用端口、可信租户上下文、幂等、状态机、不变量和一致性巡检负责。

服务端 MySQL 的最终目标是 `information_schema.referential_constraints = 0`。后续新增
MySQL 迁移一律不得出现 `FOREIGN KEY` 或 `REFERENCES`，并由静态门禁和 MySQL 8.4
集成测试同时约束。

POS SQLite 不在本次批量去外键范围。它的少量域内外键用于本地原子结算、崩溃恢复和
Outbox 一致性；若后续确需删除，必须单独提交 CR、迁移和故障恢复证据，不能套用服务端
数据库规则直接删除。
