# ADR-032：Gate 6A 终端唯一事实源与恢复性边界

- 状态：Accepted
- 日期：2026-08-17
- 需求：`T2-TRM-001`、`T2-BAK-001`、`T2-UPG-001`

## 背景

Sprint S3 已用 `pos_sync_device` 建立正式同步设备绑定。如果 Gate 6A 再创建独立 `dev_terminal` 并复制租户、门店和状态，会形成两个可竞争终端事实源。与此同时，备份恢复需要覆盖所有权威 Owner，却不能获得修改这些 Owner 事实的权限。

## 决策

1. 逻辑领域名为 Terminal Registry，物理上复用并前向扩展 `pos_sync_device`；`jshpos-sync` 是终端登记、激活、状态、版本、能力和凭据摘要的唯一写入 Owner。
2. 激活授权、凭据版本、能力快照、命令结果和终端审计使用独立 `dev_*` 只追加或受状态约束表；不存明文激活码、刷新凭据、设备私钥或可逆硬件标识。
3. 激活码由后台受权创建并只展示一次；设备提交激活 ID 与秘密，服务端用外部 pepper 计算 HMAC。成功后返回一次性设备凭据，服务端只存 HMAC 摘要。
4. 同步、数据包、配置和后续升级只能从 Terminal Registry 获得可信 tenant/store/terminal、状态和兼容窗口；请求 Header/Body 仅作声明并必须与注册表一致。
5. BAK-001 获准后新增 `jshpos-resilience`。它编排备份清单、加密对象和恢复演练，但只通过受控快照/验证端口消费各 Owner；不得直接修改业务表或以备份投影覆盖权威事实。
6. 备份数据采用信封加密语义，数据密钥与恢复材料分开；仓库和 CI 只使用每次运行临时生成的合成密钥。
7. Gate 6A 的 RPO≤15分钟、RTO≤60分钟是 Alpha 候选内部目标。生产 KMS、跨账号不可变对象存储、跨区域切换和真实 APK 回退缺失时证据保持 `ASSUMPTION/BLOCKED`。
8. UPG-001 仅形成设计、契约与故障向量，不创建正式发布、升级命令或 APK 安装运行时。

## 后果

- 避免终端双写和状态漂移，同时保留 Sprint S3 数据兼容性。
- 激活无租户 Header 的入口是窄化认证根：只能通过高熵激活 ID+秘密查找并在成功后建立可信租户上下文，不能扩展为任意无租户查询。
- 备份恢复可以独立重放和审计，但不能绕过 Owner 不变量。
- 真实设备、生产密钥、云不可变保留与区域灾备仍需要外部解阻，内部 CI 不升级其证据等级。
