# ADR-035：Gate 6C 外部 P0 证据治理与 Alpha 准入

- 状态：Accepted
- 日期：2026-08-20
- 关联需求：T2-PAY-002、T2-HWD-001、T2-PAR-001、T2-UAT-001、T2-REL-001

## 上下文

T2 内部 Provider 无关核心、终端治理、恢复和发布治理已形成可重复的内部证据，但支付沙箱、真实硬件和设计伙伴仍缺外部证据。若把公开资料、模板、Fake、模拟器或合成数据当成外部验收，会错误放大资金、设备和试点结论并提前启动完整 Alpha。

## 决策

1. 三条外部轨使用独立证据包和独立解阻评审，不允许一条轨的结果替代另一条轨。
2. 外部证据必须登记来源、版本、取得时间、适用主体/设备/伙伴、保管人、分类、SHA-256、受控位置和验真状态；仓库只保存脱敏元数据与引用。
3. 证据状态按 `MISSING → RECEIVED_UNVERIFIED → VERIFIED_DOCUMENT → EXECUTED_EXTERNAL` 单向提升；支付、硬件、伙伴最终等级分别只能由授权沙箱、真实设备、可验证书面伙伴事实产生。
4. `T2-PAY-002/HWD-001/PAR-001` 只有在独立报告给出 `GO` 且项目发起人确认后才能解除 `BLOCKED`。准备报告、公开网页、内部测试或签字模板均不能改变 RTM 状态。
5. `T2-UAT-001/REL-001` 在三条外部 P0 任一未解除时保持 `DRAFT`，完整 Alpha 决策固定为 `NO-GO`；允许准备环境、RACI、证据目录和 Go/No-Go 模板。
6. 支付凭据、设备证书、真实 PII 和未脱敏商户样本不得进入 Git、CI、日志或普通制品；必须使用批准的 Secret/受控文档系统并执行最小权限、到期和删除证明。
7. Gate 6C-Prep 不创建 Provider/设备网络适配器，不执行网络、安装、固件、重启或真实 UAT，仅验证治理材料可收件、可追溯、可失败关闭。

## 后果

- Alpha 时间表必须服从真实证据，不以内部开发完成度推定外部可用性。
- 外部资料未齐时可以继续收件和离线验真，但不能形成绿色占位。
- 任一证据来源、范围、摘要或授权无法验证时，相关轨回退为 `BLOCKED` 并隔离材料。

## 验证

- Gate 6C-Prep 机器门禁检查 RTM 状态、允许路径、证据登记、禁止能力和必需签署角色。
- 三条报告逐项记录缺失证据，网络调用、真实设备命令和完整 Alpha 执行数必须为 0。
- 项目发起人确认前，任何脚本或文档都不得把三条外部需求改为 READY/VERIFIED/ACCEPTED。
