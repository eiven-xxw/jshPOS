# ADR-028：Gate 5A 确定性促销、跨端规则包与优惠分摊

- 状态：Accepted
- 日期：2026-08-17
- 决策范围：`T2-PRM-001`、`T2-PRM-002`、`T2-PRM-003`
- 技术基线：`t2-prep-baseline-2026-08-16`
- 工作分支起点：`63537b5cb7ceeb1fe6b04107b53e2e68941b25ad`

## 背景

详细设计 34 定义了完整促销、券、会员、预算和离线能力，而 Sprint S9 只获准基础促销、受权人工优惠、成交快照及退款恢复。Gate 4D 已冻结 `priority desc, rule_version_id asc` 和“基础/门店价→单品→组合/门槛→人工改价→整单折扣→抹零”的顺序；该已批准契约优先于详细设计 34 中较早的通用候选顺序，任何改变必须提升引擎与契约版本。

## 决策

1. 新建模块化单体 `jshpos-promotion`，作为规则版本、试算、解释、人工优惠、快照、分摊、退款恢复投影、审计与 Outbox 的唯一写入 Owner。
2. `T2-PRM-001`、`002`、`003` 必须顺序准入和实现；每项在下一项开始前形成独立提交、测试证据与 RTM 状态迁移。
3. 商业 V1 首版只实现白名单结构化算子，不执行 JavaScript、Groovy、SpEL、SQL 或租户代码。会员、券、积分、储值和预算条件一律返回能力不支持，不能绿色占位。
4. Java 为服务端参考实现，Dart 为 POS 离线实现；双方读取同一 JSON 黄金向量，金额、逐行调整、解释码、稳定排序、分摊与指纹逐字段一致。
5. 金额只使用最小货币单位整数。比例和数量采用精确十进制；百分比折扣中间值固定 `HALF_UP`，规则包与快照规范化摘要使用 SHA-256。
6. 订单级优惠采用最大余数法，余数按 `line_no、sku_id、line_id` 决胜。人工改价独立记录权限、阈值、原因、操作人与审批人，不伪装成普通促销。
7. 成交快照只追加且不可修改；退款恢复只读取原快照与累计已退账本，最后一次退货承接余数，禁止用当前规则重算。
8. POS 使用本地 SQLite 双槽规则包。下载内容先验证可信 tenant/store、Schema、兼容版本、有效期、SHA-256 和测试签名，再在事务内原子切换指针；失败保留上一有效槽但对已过期或不支持规则失败关闭。
9. 按 ADR-027，规则身份可用 `MP_ENTITY`，但版本、报价、调整、快照、分摊、审计、Outbox、幂等和退款恢复全部使用 `XML_ONLY`；应用层只依赖 Repository/端口，不直接依赖 Mapper。
10. 促销不得回写价格、订单历史、支付、库存和成本事实。订单 Owner 只冻结经摘要核验的结果；退款 Owner 通过只读端口获取原快照恢复上限。

## 非目标

- 优惠券、积分、储值、会员等级、预算抢占、跨店累计、拼团、秒杀和动态定价；
- 多币种、复杂税制、多承担方结算、品牌/供应商应付与会计总账；
- 真实支付、真实会员数据、生产密钥、实机或门店试点；
- 管理后台完整运营页面、营销报表和外部连接器促销网络调用。

## 后果与回退

- 优点：同一输入可重放、可解释、可审计，退款金额守恒，离线包损坏不会污染当前交易。
- 代价：Java/Dart 双实现必须维护同一黄金向量；规则范围严格小于详细设计 34 的完整 Backlog。
- 风险：规则组合爆炸通过候选数、行数和组合数上限控制；不支持能力失败关闭。
- 回退：停止新版本发布、切回上一已验证规则包和应用版本；已经发布的规则、快照、分摊与退款恢复流水不删除、不回写，Schema 修复只追加前向迁移。
