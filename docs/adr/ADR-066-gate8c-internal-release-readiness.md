# ADR-066：Gate 8C 内部发布准备、供应链证据与强制 NO-GO

- 状态：Accepted
- 日期：2026-08-24
- 关联：T2-RDY-001、T2-LIC-001、T2-UAT-001、T2-REL-001、CR-T2G8C-019

## 背景

Gate 6H 已形成内部发布候选，Gate 7/8 随后增加业务与 SaaS 运营能力，Gate 8C 又完成安全、可维护性和性能整改。当前仍缺少面向最新代码的统一发布物目录、来源与摘要、组件供应链清单、部署预检及机器可读 Go/No-Go。与此同时，三项商业许可证、四条外部 P0、完整 Alpha 和正式发布均未解阻。

## 决策

1. T2-RDY-001 只形成 `INTERNAL_RELEASE_READINESS_CANDIDATE`，不得产生生产或商业发布资格。
2. 内部制品包含服务端 JAR、Web 压缩包、明确标记为非生产的 Debug APK、部署配置包、组件 SBOM/许可证、迁移与运维证据；所有条目绑定 commit、Run、类型、大小和 SHA-256。
3. 发布清单由单次 CI 临时 Ed25519 密钥签署；私钥不得进入仓库、日志或 Artifact，公钥和验签结果随证据保存。该签名只证明同一 CI 内部清单完整性，不替代 APK 生产签名、KMS 或授权代码签名。
4. `G8C-REL-P0-001/P0-002/P1-003/P1-004` 保持其外部或商业阻断状态。内部完成项只记录为 `INTERNAL_CONTROL_VERIFIED`；Go/No-Go 必须同时输出内部准备结论与 Full Alpha、生产、商业三个 `NO_GO`。
5. 自有设备适配包使用明确的内部专有许可通知并维护变更日志；第三方 Aviator、simple-http、MySQL Connector/J 继续由 T2-LIC-001 独立关闭。
6. 部署预检只验证 Secret 引用、镜像摘要、兼容/迁移、健康、恢复和回退材料；不得连接未授权云资源、KMS、真实对象存储或终端。

## 后果

- 内部候选可重复构建、验签、审计和判定，不再依赖人工拼装；
- 任一制品、摘要、签名、SBOM、许可证或运维证据缺失都会失败关闭；
- 即使内部全部通过，只要外部 P0、商业许可证、UAT 或 REL 未关闭，商业结论仍固定 `NO_GO`；
- 不新增业务行为，不修改资金、库存、租户事实和已发布迁移。
