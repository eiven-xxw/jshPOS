# ADR-030：Gate 5C 会员隐私与权益账本边界

- 状态：Accepted
- 日期：2026-08-17
- 决策范围：`T2-MEM-001`、`T2-MEM-002`；`T2-RPT-001/002` 仅设计

## 决策

1. 新建模块化单体 `jshpos-member`，由 Member Owner 独占 `mbr_*` 写入权。其他 Owner 只经内部端口或版本化事件交互。
2. 会员主键使用 ULID；手机、卡号和外部身份均是可换凭证。精确检索使用版本化 HMAC，可逆值使用 AES-GCM 或 KMS 令牌引用，展示默认脱敏。
3. `T2-MEM-001` 先实现最小主体、身份绑定/解绑、可撤销合并关系、同意流水、隐私请求状态与审计。删除以去标识化/密钥销毁和用途限制表达，不删交易事实。
4. `T2-MEM-002` 只在 MEM-001 独立验证后准入。等级历史和积分流水只追加，余额/等级为可重建投影；积分使用按最早到期优先分配。
5. POS SQLite 仅缓存会员令牌、掩码、等级/权益快照版本、摘要和有效期；不缓存手机、证件、地址明文。积分抵扣不支持离线。
6. 新增会员表优先 `XML_ONLY`，因其含身份数据、状态条件、显式锁、只追加事实或幂等约束，不暴露通用更新/删除 CRUD。
7. Reporting 仅获得已脱敏且目的必要的事件字段；本 Sprint 不建 `rpt_*` 表或运行时。

## 不变量

- tenant_id 只来自可信上下文，请求中的 tenant 字段必须拒绝。
- 同一命令/事件 ID 不同摘要拒绝；重放只返回原结果。
- 同意、身份绑定、合并/拆分、等级和积分事实不物理删除。
- 积分余额必须等于有效流水重建值；退货冲正不得超过原事实的可冲正上限。
- 审计、日志、事件和导出不得含明文 PII 或密钥。

## 不采用

- 不以手机号作主键；不保存可检索明文；不用普通应用日志替代审计。
- 不让 Order/Return/Reporting 直接更新会员余额。
- 不在本 Sprint 实现优惠券、储值、短信、外部会员平台或报表运行时。
