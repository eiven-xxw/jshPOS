# ADR-041：Gate 6I 外部执行准入快照与完整 Alpha 冻结

## 状态

Accepted（2026-08-21，项目发起人按 `CONDITIONAL GO` 批准准备阶段）

## 上下文

Gate 6H 已形成 `INTERNAL_RELEASE_CANDIDATE`，但拉卡拉授权沙箱、真实 Android 主机与外设、设计伙伴和商业许可证均没有达到可执行或可发布证据等级。内部候选可以作为完整 Alpha 的软件输入，却不能证明 Provider、实机、伙伴现场和商业分发合规。

ADR-038 已定义外部材料的单向证据状态机。本阶段需要把 Gate 6H 的最终代码身份、四条外部/关闭轨的当前事实和完整 Alpha 的入口/退出规则冻结为同一份可机器核验快照，防止后续补件跨轨升级或自动解除阻断。

## 决策

1. Gate 6I-Prep 从 `e2bd699ad565845c363ffe478320eb2b3f9a0015` 建立独立治理分支，不修改正式运行时、迁移或外部适配器。
2. 继续使用 `MISSING → RECEIVED_UNVERIFIED → VERIFIED_DOCUMENT → EXECUTION_APPROVED → EXECUTED_EXTERNAL` 单向状态机；达到 `VERIFIED_DOCUMENT` 只允许提交该轨独立执行准入评审，不能自动进入网络、设备或现场执行。
3. 支付、硬件打印、伙伴和许可证使用四份独立快照、Owner、缺口与 Go/No-Go。硬件和打印属于同一实机执行窗口，但 `T2-HWD-001` 与 `T2-PRN-001` 分别保留需求状态和证据结论。
4. 完整 Alpha 的启动至少要求支付、硬件、打印和伙伴轨分别取得项目发起人的执行准入确认，并具备已授权环境、角色、数据清除和停止条件；许可证关闭不作为受控 Alpha 测试的替代证据，但继续作为任何生产/商业发布的强制阻断项。
5. 所有外部事实采用不透明引用和 SHA-256 登记；受控原文、Secret、真实商户/终端标识、设备证书、伙伴身份与联系方式不进入 Git、CI 或普通制品。
6. Gate 6I-Prep 只能得出 `PREPARED_NO_GO` 或逐轨补件结论。Provider 网络、真实设备命令、伙伴联系、现场试点、完整 Alpha 和生产发布保持为 0。

## 后果

- Gate 6H 的内部候选身份与外部证据不会混淆，后续每一轨可以独立补件、验真和评审。
- 缺件不会阻止继续维护内部候选，但会继续阻止完整 Alpha、现场试点和商业发布。
- 许可证可与外部执行并行关闭；即使 Alpha 通过，许可证未关闭仍必须发布 `NO-GO`。

## 验证

- Ubuntu 与 Windows 离线治理门禁核对 RTM 状态、四轨证据计数、UAT 冻结矩阵、禁止动作和零执行计数。
- 范围门禁拒绝服务端、Web、Flutter、设备插件、迁移、依赖和生产部署配置变更。
- 证据聚合器对所有治理结果生成 SHA-256 索引，并明确最高等级为 `STATIC_GOVERNANCE_FREEZE`。
