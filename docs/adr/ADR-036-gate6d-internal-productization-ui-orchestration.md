# ADR-036：Gate 6D 内部产品化 UI 编排与合成闭环边界

- 状态：Accepted
- 日期：2026-08-20
- 关联需求：T2-POS-007、T2-POS-008、T2-ADM-001、T2-E2E-001
- 决策人：项目发起人、产品负责人、架构负责人、POS 负责人、Web 负责人、QA 负责人

## 背景

Gate 0—6B 已形成租户、商品价格、POS 本地交易、同步、Provider 无关支付退款、库存成本、促销、会员、报表、终端和发布治理的正式内核，但 POS 仍停留在技术基线页，后台能力分散在工程型页面，尚没有可供内部人员连续操作的产品界面。直接让页面读写 SQLite、跨 Owner 查表或复制促销与金额算法，会制造第二套事实源并破坏此前门禁。

外部支付沙箱、实机和设计伙伴继续缺失，但其证据可与内部产品化并行；因此本决策只放行虚构终端、Fake Device、现金和合成数据的内部界面与闭环，不提升外部证据等级。

## 决策

1. Flutter 增加 POS 会话应用层和正式应用壳。UI 只向会话、目录、结算、同步和打印任务端口发命令，不持有数据库连接、不直接调用 `MethodChannel`、不构造领域事实。
2. 可信终端快照、员工认证、权限集合、门店、终端、班次和业务日形成一个不可由页面字段覆盖的 `PosSessionContext`。终端未登记、吊销、门店不匹配、权限不足、会话过期或业务日漂移时失败关闭并安全退出。
3. 收银工作台只编排既有 Catalog/Promotion/Checkout/Sync 应用能力。金额、优惠、现金订单和 Outbox 仍由既有 Owner 冻结；UI 只展示服务返回的不可变报价、成交结果和同步状态。
4. 打印采用 `PrintTaskRepository` 与 `PosDeviceGateway` 适配端口。Gate 6D 只生成任务、预览并允许 Fake 执行；真实打印能力必须继续由 `T2-HWD-001` 解阻。
5. Vue 增加经营工作台并复用 Foundation、RuoYi RBAC/System 与 Catalog 正式 API。前端组合查询结果，但不跨模块直连数据库、不复制状态机或领域算法；服务端权限仍是最终授权。
6. 内部 E2E 用版本化合成场景编排正式应用端口，证明从资料发布到现金交易、同步和权威投影对账的可重复流程。它不调用 Provider 网络、不控制真实设备、不接触真实 PII，也不等于完整 Alpha UAT。
7. 四项需求必须串行形成独立验证证据；后一项的运行时文件只有在前项标记 `VERIFIED` 后才允许创建。

## 结果

- 业务内核首次具备面向内部人员的连续操作入口，同时保持租户、资金、库存、成本和促销事实的单一数据主权。
- POS 与后台可以在合成环境验证页面状态、权限拒绝、断网、幂等、防重复点击和恢复路径。
- 支付沙箱、真实硬件、伙伴试点、完整 Alpha 与商业发布仍然独立阻断，Gate 6D 不能消除这些差距。

## 被否决方案

- 页面直接调用 SQLite 或 Mapper：绕过应用层不变量、权限、审计和幂等。
- 在 Flutter/Vue 内复制促销、金额、库存或成本计算：会造成跨端漂移和第二套事实源。
- 等全部外部资料齐备后再做任何 UI：会延迟可并行的内部可用性验证，但外部证据缺口仍可通过严格分级保留。
