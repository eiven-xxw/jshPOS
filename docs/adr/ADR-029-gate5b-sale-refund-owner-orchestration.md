# ADR-029：Gate 5B 促销成交、订单消费与退货退款 Owner 编排

- 状态：Accepted
- 日期：2026-08-17
- 决策范围：`T2-POS-006`、`T2-ORD-003`、`T2-REF-002`
- 技术基线：`t2-prep-baseline-2026-08-16`
- 工作分支起点：`e947a229782865f7759525cfa3e2e90819ebfba5`

## 背景

Gate 5A 已证明促销计算、人工优惠与分摊可确定重放，但尚未进入真实 POS 成交事务、服务端订单事实和跨 Owner 退货退款闭环。直接把促销算法复制到订单，或让退货模块跨表更新支付、库存和促销事实，会破坏数据主权、幂等与故障恢复。

## 决策

1. 严格按 POS 本地成交、服务端订单消费、退货退款编排三阶段交付；每阶段独立准入、实现、验证和 RTM 迁移。
2. POS 以 SQLite 单事务保存冻结输入引用、报价、人工审批引用、不可变促销快照、订单、现金、班次现金、审计、幂等结果和 Outbox。失败不留下部分事实。
3. 已提交命令的恢复以 `tenant + operation + idempotency_key` 和请求摘要为准。同键同内容返回原结果；同键异内容失败关闭；不得重新生成订单、退款或用新规则重算。
4. Promotion Owner 独占促销快照及退款分摊；Order Owner 通过只读端口验证快照身份、上下文、绑定和 SHA-256 后只保存引用；不得复制促销算法。
5. `gross - discount + surcharge = receivable` 同时应用于订单头和每行，且头部金额等于行合计。金额使用最小货币单位整数，数量使用精确十进制。
6. Return Orchestrator 只拥有编排状态、Inbox/Outbox、步骤结果和修复指令；Promotion、Refund/Payment、Inventory、Audit 各自事务只写自己的事实。跨 Owner 通过版本化事件和受控端口收敛。
7. 原单退货按成交快照和累计已退上限分配，最后一次合法退款吸收余数；UNKNOWN 保留原命令并查询/观察收敛，禁止发起第二业务命令。
8. 本 Sprint 不引入 Provider SDK 或网络适配器。现金闭环及 Provider 无关 Fake 只属于内部合成证据，不能解除 `T2-PAY-002`、`REAL_DEVICE` 或 `PILOT`。

## 持久化选择

- POS SQLite V6：`XML_ONLY` 不适用；采用显式 SQL、不可变触发器和事务门禁。
- 订单促销绑定、退货编排、Inbox/Outbox、幂等及审计：`XML_ONLY`，使用 Repository + Mapper XML，禁止通用更新/删除。
- 会员/报表仅契约准备：不得创建运行时表。

## 回退

停止新客户端/服务端发布并保持旧兼容窗口；已经写入的订单、促销快照、退款分摊、库存和现金事实不删除、不回写。SQLite/MySQL 失败迁移只允许前向修复；积压事件以固定幂等键重放，无法自动解释的同键异内容进入人工隔离。
