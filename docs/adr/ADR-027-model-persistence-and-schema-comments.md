# ADR-027：模型分型、持久化策略与 Schema 中文注释

- 状态：Accepted
- 日期：2026-08-17
- 持久化登记决策（第 3—4 项）：部分由 [ADR-033](ADR-033-persistence-access-strategy-and-sql-mode.md) 取代
- 决策范围：CR-DEV-003、全部新增或实质修改的服务端模型与数据库 Schema

## 背景

现有正式模块同时存在多种实现方式：foundation 建立普通持久化实体并使用 MyBatis-Plus，后续模块大量使用不可变 `record` 作为命令、投影和 Mapper 参数，并按资金、库存和账本风险使用专用 SQL。该方向保护了核心事实，但缺少明确模型分型和逐表策略登记，导致简单 CRUD 也可能退化为注解 SQL，应用服务直接依赖 Mapper，领域聚合、持久化实体与数据载体边界不清。

审计还确认，当前 19 个正式 Flyway 文件创建的 90 张业务表没有表/字段中文注释；7 个 MyBatis-Plus 持久化实体缺少中文类级和字段说明，大量 `record` 只有概括性容器注释而没有组件说明。现行规范表达了“简单用 MyBatis-Plus、复杂用 XML”和“核心代码使用中文注释”，但缺少可执行分类、数据库注释要求和自动门禁输入。

## 决策

1. 模型明确分为领域聚合/实体、持久化实体、DTO、Command/Query、值对象、只读投影和 Mapper 参数，各自保持分层与单一职责。
2. `record` 默认用于不可变数据载体、值对象和投影，不作为 MyBatis-Plus 持久化实体或有生命周期聚合的默认实现。普通持久化实体使用普通 Java 类；核心聚合使用能够集中维护不变量的领域模型或等价状态机对象。
3. 每张新增业务表在编码前登记 `MP_ENTITY`、`XML_ONLY` 或 `READ_PROJECTION`，同时记录 Owner、模型、Repository/Mapper、可信租户来源和更新/删除边界。
4. 简单单表 CRUD 默认使用普通持久化实体、`BaseMapper` 与 Lambda Wrapper；选择 XML 必须说明理由。不可变事实、状态条件更新、显式锁、复杂查询、账本、历史、审计、Outbox/Inbox 和幂等事实默认使用 Repository 与 Mapper XML，禁止危险通用 CRUD。
5. 正式业务模块原则上不新增 SQL 注解。Repository/查询端口位于内层，Mapper、Wrapper 和持久化实体位于基础设施层；应用和领域层不得依赖基础设施 Mapper。
6. 持久化实体必须具有中文类级与所有映射业务字段说明；`record` 必须具有中文类型说明和逐组件 `@param`。新业务表和每个字段必须具有有效中文数据库 `COMMENT`。
7. 已发布 Flyway 迁移不可修改。存量数据库注释通过独立前向迁移补齐，并验证列属性、元数据锁、兼容和失败恢复。
8. CI 后续增加策略登记、分层依赖、SQL 注解、实体/Record 注释和 `information_schema` Schema 注释门禁；存量整改使用独立 requirement_id 和模块化迁移，不在 Gate 4D 内自动展开。

## 备选方案

- 每张表生成普通实体并统一使用 MyBatis-Plus：拒绝。账本、历史、审计和幂等事实会因此暴露覆盖更新或删除风险，领域实体与表也不是一一对应。
- 全部保持 XML/注解 SQL、不建立持久化实体：拒绝。简单 CRUD 重复样板多、字段引用缺少类型安全，既有 MyBatis-Plus 基线得不到合理复用。
- 允许 `record` 统一承担 DTO、领域和持久化模型：拒绝。不同边界的变化原因、授权来源和更新语义不同，统一模型会造成耦合和受保护字段污染。
- 只在文档数据字典中维护中文说明：拒绝。数据库运维、排障和元数据工具无法直接获取 Schema 语义，且容易与迁移漂移。
- 直接修改历史 Flyway 增加注释：拒绝。会破坏迁移校验和、已发布基线和环境一致性。

## 后果

- 优点：Record、领域模型和持久化实体职责清晰；简单 CRUD 可复用 MyBatis-Plus；核心事实继续受专用 SQL 和 Repository 保护；数据库与 Java 语义可审计。
- 代价：新增表需要策略登记；实体和 Record 注释工作增加；存量 90 张表补注释需要多批前向迁移并评估元数据锁；Repository 边界整改需要回归测试。
- 风险控制：禁止一次性生成全表实体或修改历史迁移；先审计分类，再按模块和业务风险渐进整改；资金、库存、租户、幂等与审计行为必须以回归证据证明不变。
- 回退：本 ADR 的文档规则可以通过后续 CR/ADR 修订，但已经发布的 Schema 和业务事实不得删除或回写。注释迁移失败使用停止发布或前向修复，不得修改已封存迁移。
