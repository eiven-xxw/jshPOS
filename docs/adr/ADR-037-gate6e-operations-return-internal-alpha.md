# ADR-037：Gate 6E 后台运营、原单退货退款与内部 Alpha 候选边界

## 状态

Accepted（2026-08-20，项目发起人按 `CONDITIONAL GO` 批准）

## 决策

1. Gate 6E 从 `281e98a6b286f1343a012ed289cecb195858dcc7` 建立独立分支，只按 `T2-ADM-002 → T2-POS-009 → T2-E2E-002` 串行准入。
2. Vue 与 Flutter 均只做既有正式 Owner 能力的应用编排与状态呈现，不新增库存、采购、调拨、成本、促销、会员、报表、支付或退款算法。
3. 后台写操作必须显示服务端状态和版本、二次确认、稳定幂等键、权限、数据范围与审计引用；前端不得推演下一领域状态或计算权威数值。
4. 原单退货退款只通过 Return/Refund 编排端口读取原订单、原促销快照和累计已退上限。UI 不直接访问 SQLite、MethodChannel、Mapper 或任何 Owner 私表。
5. `T2-E2E-002` 的证据等级最高为 `INTERNAL_ALPHA_CANDIDATE`，只使用虚构租户、虚构终端、现金与合成包；它不改变 `T2-UAT-001/REL-001`。
6. Provider 网络、真实设备命令、现场试点和完整 Alpha UAT 保持 0；外部三项 P0 继续 `BLOCKED`。

## 后果

- 管理后台可以形成可操作但失败关闭的第二波正式界面，所有权威校验仍由服务端 Owner 完成。
- 现金退货退款可以先完成软件产品化和内部回归，电子支付 Provider 适配继续由独立沙箱解阻控制。
- 内部 Alpha 候选只用于发现集成缺陷和形成可重复证据，不得用于对外试点或商用声明。
