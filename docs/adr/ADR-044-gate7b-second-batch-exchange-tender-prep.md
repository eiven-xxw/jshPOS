# ADR-044：Gate 7B 第二批换货编排与组合支付准入准备

- 状态：Accepted
- 日期：2026-08-22
- 准备基线：`a9e368a2f09dcfb4565f4bc392e4f77d5c664805`
- 分支：`t2/gate7b-sprint20b-pos-operations`

## 背景

Gate 7A 确认换货关联与 Provider 无关组合支付是商业 V1 内部差距。仓库已有
原单退货退款 Saga、原促销快照恢复、新销售、现金收款和 Provider 无关支付
核心，但没有换货关联运行时，也没有 tender plan。现有 `pay_payment_intent`
和 `ord_cash_payment` 都是一单一笔/一次付清约束，不能由 UI 拼接成组合支付。

## 提议决策

1. `T2-EXG-001` 不创建新的资金、订单、退款或库存状态机；由 Return Owner
   持有换货编排与只追加关联事实，调用原退货退款和新销售的正式应用端口。
2. 换货金额不做净额覆盖：原单退货按原成交快照恢复，新销售按换货时有效价格、
   促销和受权人工优惠成交；差额等于新销售应收减已确认原单可退金额。
3. 跨 Owner 不追求分布式事务。换货使用可恢复 Saga、稳定命令 ID、Inbox/Outbox
   和显式 `MANUAL_RECOVERY_REQUIRED`；任何退款或支付 `UNKNOWN` 都阻断后续新命令。
4. `T2-PAY-004` 由 Payment Owner 持有版本化 tender plan、份额和支付进度；
   Order Owner 只消费“全部份额已权威成功”的结果，现金效果仍由 Order/Shift Owner 写入。
5. 支付计划冻结后，计划份额之和必须等于订单应收；现金最多一份且最后收取；
   电子份额顺序执行，存在 `PROCESSING/UNKNOWN` 时禁止新增或替换同额命令。
6. 通过独立前向迁移扩展组合支付，不改写已发布迁移。现有全现金和单电子路径
   保持兼容；新路径使用独立版本、摘要和明确兼容窗口。
7. `T2-PAY-002` 未解阻时，生产路径的电子份额固定失败关闭为
   `BLOCKED_EXTERNAL`；只允许合成测试观察验证状态机，不得伪造运行时成功。

## 状态与后果

项目发起人已于 2026-08-22 接受 CR-T2G7B-009，并仅授权 `T2-EXG-001` 独立
正式开发。当前严格按 `EXG-001 → PAY-004` 串行：先验证现金边界下的换货编排；
`T2-PAY-004` 继续 `DRAFT`，只有 EXG 独立 `VERIFIED` 且再次确认后才能准入。
电子支付、真实资金、外设和完整 Alpha 证据不因本决策改变。
