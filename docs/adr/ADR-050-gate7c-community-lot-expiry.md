# ADR-050：社区超市条件批次效期、FEFO 与库存账本扩展

- 状态：Accepted
- 日期：2026-08-23
- 决策范围：T2-LOT-001

## 决策

批次与效期作为现有库存数量事实的受控附加维度，不建立第二套商品、订单或成本
Owner。Catalog Owner 独占不可变的商品批次策略版本，策略包括适用门店、启用状态、
日期基准、保质期天数、临期阈值、FEFO 与过期禁售。Inventory Owner 独占批次身份、
批次命令、只追加批次流水、可重建批次余额、分配结果、临期投影、审计与 Outbox。

只有可信 Foundation 行业模板读端口确认门店当前绑定 `COMMUNITY_SUPERMARKET` 已发布
版本时，Catalog 才允许发布启用策略；便利店和零食折扣店默认关闭。客户端提交的
industry、tenant_id、过期状态或可用数量均不作为授权依据。

采购收货通过 Inventory 正式端口建立批次并追加 `PURCHASE_RECEIPT_IN`；销售按到期日、
收货日、批次 ID 的稳定顺序执行 FEFO 并冻结分配；原单退货优先引用原分配批次；采购
退货、盘点和调拨保留来源批次。每个批次效果与现有库存总账效果使用相同来源事件与
内容摘要对账，重复返回原结果，同键异内容、余额不足、过期、版本漂移和来源缺失均
失败关闭。Costing 继续消费仓级库存流水，不读取或写入批次成本。

POS 使用签名数据包中的策略和批次投影。SQLite 只前进迁移保存包版本、批次余额和
成交批次快照；成交快照、订单事实与 Outbox 必须在同一事务提交。恢复必须复用原命令、
原批次选择和原摘要，禁止按新的 FEFO 结果生成替代命令。

## 非目标与回退

- 不包含批次成本、库位、波次、越库、加工、序列号、冷链、质检、召回、自动报损和复杂 WMS。
- 服务端可通过停用新策略版本阻止新批次路径，但已形成的批次身份、流水和成交快照不得删除或覆盖。
- 投影损坏时从只追加批次流水重建；迁移失败使用前向修复，已发布迁移不得修改。
- Gate 7D、外部支付、真实设备/打印、伙伴现场、完整 Alpha 与生产不因本决策自动准入。
