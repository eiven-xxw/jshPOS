# ADR-048：Gate 7C 可恢复开业资料迁移与 Owner 写入边界

- 状态：Accepted
- 日期：2026-08-22
- 决策范围：T2-DMT-001

## 决策

建立独立 `jshpos-migration` 模块作为 Migration Owner，独占文件元数据、隔离加密
staging、映射版本、预检错误、批次状态、逐 Owner 检查点、双人审批、对账、审计和
清理。Migration Owner 不持有商品、供应商、库存或会员事实的写权限，不直接访问
其他 Owner 的 Mapper 或私有表。

跨 Owner 导入采用可恢复 Saga。每一行在预检阶段获得稳定目标标识、内容摘要和
Owner 幂等键；Catalog、Procurement、Inventory 与 Member 分别经正式应用端口写入
自己的事实并返回结果摘要。Migration Owner 只记录检查点和最终对账，不建立跨模块
数据库大事务。进程中断后沿原批次、原行、原命令恢复；同键异内容失败关闭。

商品在激活前保持不可销售的迁移版本，供应商和会员由各 Owner 的稳定幂等端口创建，
期初库存只通过 Inventory Owner 追加 `OPENING_IN` 账本。已被引用或已激活事实不得
删除或覆盖；错误通过补偿命令、新调整事实或 `COMPENSATION_REQUIRED` 人工处置表达。

原始文件仅在请求内执行安全检查和解析，普通持久化只保存摘要与受控保管引用；规范化
staging 使用 AES-GCM 加密，密钥由仓库外 Secret 提供。双人审批、所有必需 Owner
对账、摘要与审计完整是激活前置条件。

预检错误通过受权限保护的分页端点完整读取；大批量检查点摘要由应用层对稳定排序记录
逐字段做长度前缀流式 SHA-256，禁止使用存在长度截断风险的数据库 `GROUP_CONCAT`
充当事实摘要。文件、审批和状态推进都必须支持同请求重放，同键异内容失败关闭。

## 后果与回退

- 回退可以关闭上传/激活入口并继续恢复已开始批次，不能删除已产生的 Owner 事实。
- 迁移失败时保留检查点、摘要和审计；临时加密 staging 可在到期后受审计清理。
- 激活不自动开店、发布价格、创建采购承诺或产生资金效果。
- `T2-ONB-001/LOT-001`、外部支付、硬件打印与设计伙伴不因本决策获得准入。
