# ADR-067：Gate 8D 外部 P0、许可证、完整 Alpha 与发布准入复核

- 状态：Accepted
- 日期：2026-08-24
- 关联：T2-RDY-001、T2-PAY-002、T2-HWD-001、T2-PRN-001、T2-PAR-001、T2-LIC-001、T2-UAT-001、T2-REL-001
- 工作基线：`bd1dee42bacfb75874d601e16828c8f82720986b`

## 背景

T2-RDY-001 已被项目发起人接受为内部发布准备候选，但其临时签名、固定执行器和合成恢复
证据不能替代真实支付沙箱、真实设备与外设、设计伙伴、商业许可证关闭、完整 Alpha 或生产
发布。本仓库未出现可核验的新受控材料或书面法务关闭证据，因此 Gate 8D-Prep 必须复核而
不能自动继承历史准入结论。

## 决策

1. 四条外部 P0 各自拥有独立材料清单、证据等级和执行决定；一条轨的完整性不得补偿另一条。
2. 仓库只保存不透明材料引用、SHA-256、来源/授权/范围/版本/保管/生命周期等元数据；受控
   原文、Secret、商户/终端号、证书、真实 PII 和伙伴身份不得进入普通开发链路。
3. `VERIFIED_DOCUMENT` 只表示资料完整且离线验真通过，不等于执行批准；任何网络、资金、
   设备、外设或现场动作仍需项目发起人逐轨独立确认。
4. Aviator、simple-http、MySQL Connector/J 必须逐项以“替换并完整回归”或“适用于精确版本、
   地域和分发模式的书面法务批准”关闭。代码中未找到直接声明不能单独证明组件已从最终制品
   消失；最终 SBOM、许可证清单、NOTICE 和发布 BOM 是必要证据。
5. 完整 Alpha 的必要条件是四轨分别执行批准、隔离环境与具名 RACI 就绪、数据与 Secret 生命周期
   可审计且 P0/P1 为 0；发布的必要条件还包括 UAT 接受、许可证 3/3 关闭、真实签名/KMS、生产
   恢复/回退和联合签署。
6. 本阶段不修改运行时、迁移、依赖或外部适配器，所有外部执行、完整 Alpha、生产和商业声明计数为 0。

## 后果与验证

- `T2-RDY-001` 更新为 `ACCEPTED`，但证据上限保持内部候选；
- PAY/HWD/PRN/PAR 保持 `BLOCKED`，LIC/JSH 保持 `DEFERRED`，UAT/REL 保持 `DRAFT`；
- 专用双平台治理、状态守恒、受控元数据、Secret/PII、依赖差异和证据索引门禁必须全绿；
- 任一缺件、状态漂移、外部执行非零或把内部证据提升为外部结论时，Gate 8D-Prep 失败关闭。
