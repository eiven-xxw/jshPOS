# ADR-023：Gate 4A 不可变库存账本与版本化库存策略

状态：Accepted
日期：2026-08-16
需求：`T2-INV-001`、`T2-INV-002`、`T2-INV-004`

## 背景

Gate 2 已形成权威订单快照，Gate 3A 已形成权威原单退款快照。本阶段需要让销售完成和成功退货产生可审计库存效果，同时避免以余额覆盖、客户端自报数量或 Fake 证据形成不可解释库存。

## 决策

1. 新建模块化单体边界 `jshpos-inventory`，唯一拥有 `inv_*` 库存命令、流水、余额、策略版本、异常、审计和 Outbox；其他模块只能通过命令或事件访问。
2. `inv_stock_ledger` 是数量权威且只追加。`inv_stock_balance` 是按 `tenant + warehouse + sku + stock_status` 建立的受控投影，可由流水汇总校验或重建。
3. 销售出库只读取订单 Owner 提供的 `COMPLETED/PAID` 不可变订单和行快照；退货入库只读取支付 Owner 提供的 `SUCCEEDED` 原单退款行快照，再与订单行 SKU/单位交叉校验。REST 请求不得携带租户、SKU 或数量。
4. 来源事件 ID、来源聚合、来源行和移动类型共同提供稳定幂等语义。同事件同哈希返回原结果；同事件异哈希失败关闭；同一来源行重复业务效果由数据库唯一约束阻止。
5. 单个库存命令在同一 MySQL 事务内锁定维度余额，写不可变流水、更新余额、写命令结果、审计、异常和 Outbox；任何步骤失败则全部回滚。
6. 数量使用 `DECIMAL(19,6)` 与 `BigDecimal`，统一规范化到六位且禁止 `float/double`。`before + delta = after`、维度序号单调、delta 非零必须同时由领域规则和数据库约束保护。
7. 策略版本发布后不可修改。便利店默认 `DENY`；显式 `ALLOW_AND_ALERT` 可以形成负库存，但必须保存策略版本、产生异常和告警事件。`ALLOW_WITH_PERMISSION` 只保留契约，不在 Gate 4A 运行时开放。
8. POS 现货销售本阶段不预占。`on_hand`、`reserved`、`frozen`、`safety_stock` 分列保存，`available = on_hand - reserved - frozen - safety_stock`；Gate 4A 只允许 `reserved=0`，后续预占必须新需求准入。
9. MySQL 仅追加 V11/V12；旧应用可忽略新表。已发布迁移和库存流水不得回滚删除，只允许前向修复与受控投影重建。
10. `T2-INV-003`、`T2-PUR-001`、`T2-CST-001`、`T2-TRF-001` 只形成契约，不创建正式表、Controller 或运行时。

## 事务和并发

- 首次维度变动先以唯一键插入零余额，再 `SELECT ... FOR UPDATE`；并发插入冲突后重新锁定。
- 同一命令按稳定的 `sku_id` 顺序锁定多个维度，降低死锁；冲突不以自动重跑掩盖，调用方以相同事件 ID 重放。
- `DENY` 在锁内判断 `available_after >= 0`。允许负库存时仍记录真实负数、策略版本与异常，禁止把差异截断为零。
- 重建只聚合不可变流水并更新投影的数量、最后序号和版本；重建前后均保留审计，不修改流水。

## 后果与限制

- Gate 4A 能证明正式服务器端库存不变量、幂等、租户隔离、合成并发和迁移，但不能证明实机离线超卖、门店盘点、采购成本或试点运营。
- 成本、盘点、预占、采购和调拨必须沿用本账本扩展，禁止另建可覆盖库存事实。
