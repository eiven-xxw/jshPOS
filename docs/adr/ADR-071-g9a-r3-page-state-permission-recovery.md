# ADR-071：G9A-R3 页面状态、权限与可恢复交互边界

- 状态：Proposed
- 日期：2026-08-24
- 关联：`G9A-UI-P1-001`、`T2-UX-001`、`T2-ADM-001/002`、`T2-POS-007/008/009`

## 背景

Gate 9A 冻结了 20 个 Vue 页面/面板和 6 个 Flutter 页面。服务端 300 项 Controller 与
OpenAPI 已在 G9A-R1 对齐，商业默认装配已在 G9A-R2 收敛，但页面级交互证据仍不完整：
部分页面只有源码字符串断言，部分写操作没有把忙碌、错误码、关联标识和原幂等键恢复状态
完整呈现，组合支付页面还没有正式运行时入口。

## 建议决策

1. 页面统一使用具名状态表达 `INITIAL/LOADING/READY/EMPTY/SUBMITTING/FAILED/UNKNOWN` 中
   适用的子集；不要求所有页面机械包含全部状态，但每个 `N/A` 必须有范围理由。
2. 展示权限用于减少误操作，Controller 权限与可信租户/门店范围始终是最终授权；每个服务端
   写动作按钮必须使用与 Controller 对齐的最小权限，禁止依赖父弹窗入口或菜单隐藏代替授权。
3. 写操作必须单航班；失败重试复用原幂等键和内容摘要。资金或业务结果 `UNKNOWN` 只能查询、
   回调或观察原命令，不得重新生成命令。
4. 错误呈现使用安全消息、稳定错误码和关联标识，不展示响应体、Secret、PII 或内部堆栈；
   全局拦截器可以复用，但页面必须仍有可执行恢复入口和交互测试。
5. Flutter 页面只使用可信会话和冻结 Owner 快照决定门店、班次、业务日与离线事实；页面不得
   自行计算业务日或 tenant_id。业务日切换时旧页面必须失败关闭或恢复原上下文。
6. Vue 页面必须有挂载后的组件交互测试，Flutter 页面必须有 Widget 测试；源码字符串断言仅
   作为边界补充。依赖增加必须单独经过锁文件、SBOM、许可证和安全审查。

## 非目标

- 不改变任何 Owner 状态机、金额、库存、成本、促销、会员或租户事实；
- 不新增业务功能、API、数据库表或已发布迁移；
- 不解除支付、硬件、外设、伙伴、UAT、许可证或生产阻断。

## 生效条件

本 ADR 在 G9A-R3 正式整改获得项目发起人确认后才能更新为 `Accepted`。准备阶段保持
`Proposed`，不得据此修改页面运行时或依赖。
