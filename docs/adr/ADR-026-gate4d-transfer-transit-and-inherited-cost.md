# ADR-026：Gate 4D 调拨在途账与成本继承

- 状态：Accepted
- 日期：2026-08-17
- 决策范围：`T2-TRF-001`

## 背景

Gate 4A—4C 已建立库存数量 Owner、盘点/采购权威来源和仓级移动加权成本 Owner。基础调拨既不能使用一次跨仓余额覆盖伪造原子性，也不能让目的仓以当前平均成本重新估值。系统需要在发出成功、收货延迟、重复命令、部分收货、短少、拒收、跨业务日和进程故障下，持续解释来源仓、在途和目的仓的数量与成本去向。

## 决策

1. 新建模块化单体 `jshpos-transfer`，独占 `inv_transfer_*` 调拨单据、行、命令结果、发出/收货事实、在途流水、差异处置、审计和 Outbox。调拨模块不得直接写库存或成本表。
2. 发出与收货是两个独立幂等业务事实。发出先持久化权威调拨发出事实，再通过 `AuthoritativeInventoryMovementPort` 追加来源仓 `TRANSFER_OUT`；收货先持久化权威收货事实，再追加目的仓 `TRANSFER_IN`。每个本地命令只保证自身数据库事务原子，不承诺跨时间、跨仓的虚假原子提交。
3. 在途数量使用只追加 `inv_transfer_transit_ledger` 表达。发出增加在途，收货减少在途，获批短少/破损/拒收损失通过独立差异处置流水结清；余额投影可以重建，不得修改或删除历史在途流水。
4. `jshpos-transfer` 提供不含 `tenant_id` 和客户端成本的只读 `TransferCostSourcePort`。成本 Owner 对 `TRANSFER_OUT` 使用来源仓事务时平均成本并保存快照；对 `TRANSFER_IN` 必须查验收货行、原发出行和原发出成本流水，继承其单位成本后参与目的仓移动加权。
5. 目的仓累计收货不得超过已发出数量；来源仓与目的仓必须不同但属于同一可信租户。发出前可以取消且无库存效果；发出后原地取消失败关闭，只允许显式反向调拨或获批差异处置。
6. 商业 V1 准入整单一次发出、多次部分收货和最终短少处置；多发、无单收货、跨租户调拨、不同币种、多货主、批次、库位、越库、运输计费和复杂 WMS 后置。
7. 数量使用 `DECIMAL(19,6)`；成本金额和单位成本使用以最小货币单位计量的 `DECIMAL(25,6)`；舍入固定 `HALF_EVEN`。JSON 数值使用十进制字符串，禁止浮点数。
8. 所有状态命令携带稳定 `command_id` 与内容摘要。重复同摘要返回原结果；同键异摘要、非法状态、超收、越权仓库、未知来源发出成本和跨租户引用均失败关闭并记录审计。
9. 调拨单使用乐观版本控制，库存与成本维度继续使用各自 Owner 的行锁和序号。固定锁顺序为 SKU、来源行 ID；禁止由 Controller 或通用工具类编排 Mapper。
10. `T2-PRM-001..003` 本 Sprint 只保留设计契约并标记 `x-runtime-allowed=false`。支付 Provider 网络、会员、报表、应付、发票、总账、批次成本和后续 Gate 不进入本决策。

## 后果

- 优点：来源、在途、目的三段数量可对账；成本继承有权威链路；部分收货和差异不会篡改历史；各模块数据主权清晰。
- 代价：一次调拨需要多个可恢复状态和两次库存 Owner 调用；发出成功后不能通过简单取消回到审批态；差异需要人工审批闭环。
- 回退：关闭调拨入口并回退应用版本，但不得删除迁移、调拨事实、在途流水、库存或成本流水。失败迁移和投影异常只能新增前向修复；已发出未收货单据必须保留查询、收货、差异处置和人工 Runbook。
