# ADR-034：Gate 6B Provider 无关发布治理与真实设备边界

- 状态：Accepted
- 日期：2026-08-20
- 关联需求：T2-UPG-001、T2-TRM-001、T2-HWD-001、T2-UAT-001、T2-REL-001
- 决策人：项目发起人、架构负责人、发布负责人、安全负责人、SRE 负责人

## 背景

Gate 6A 已形成可信终端注册表和内部合成恢复基线，但只完成升级设计夹具。若把设计夹具直接转成生产表、把发布逻辑塞进 Sync Owner，或在没有真实厂商 SDK 的情况下发送安装/重启命令，会混淆发布治理、终端身份和硬件执行三类不同数据主权，并错误升级 `REAL_DEVICE` 证据。

## 决策

1. 新建模块化单体模块 `jshpos-release`，作为发布物、目标范围、灰度批次、终端软件任务、发布事件和审计的唯一写入 Owner。Sync Owner 继续独占终端登记、状态、版本和能力事实；Release Owner 只能通过只读端口查询。
2. 发布物类型统一为 `SERVER/WEB/MYSQL_SCHEMA/SQLITE_SCHEMA/TEMPLATE_PACKAGE/DATA_PACKAGE/APK`，每个发布绑定 release ID、版本、通道、租户/门店范围、对象键、SHA-256、Ed25519 签名、密钥版本、构建 commit、SBOM 摘要和兼容窗口。
3. 发布物状态、灰度批次状态和终端任务状态分离。控制记录使用 `CONTROLLED_WRITE + XML`；范围、命令结果、事件和审计使用 `APPEND_ONLY + XML`，数据库触发器禁止任意更新和删除。
4. 发布物验证读取受控对象和公钥注册表；仓库和运行时不保存签名私钥。对象存储、密钥注册表或多 Owner 营业保护探针未配置时必须返回 503 失败关闭。
5. 分配终端任务前，服务端必须从 Terminal Registry 读取可信 tenant、store、状态、版本与能力；从 Sync、Payment、Refund、Shift 和遥测 Owner 合并待同步、UNKNOWN、营业时段、存储和时钟快照。请求体不得声明这些安全事实。
6. MySQL/SQLite Schema 只前进。应用、Web 和 APK 健康失败可以进入受审计回退；Schema 迁移失败进入 `FORWARD_FIX_REQUIRED`，禁止用应用回退伪造数据库回滚。
7. 本 Sprint 的终端任务只是软件生成的发布执行事实，不发送真实安装、固件、重启或远程控制命令。主认证设备资料与实机升级证据继续由 `T2-HWD-001` 阻断。
8. `T2-PAY-002`、`T2-HWD-001`、`T2-PAR-001` 任一 P0 未解除时，`T2-UAT-001/REL-001` 不得进入完整 Alpha 验收。

## 结果

- 兼容决策、灰度扩散、失败暂停、回退和前向修复可在不依赖某家厂商 SDK 的情况下被测试和审计。
- 真实 APK 安装、静默升级、固件兼容、物理重启和实机回退仍为 `BLOCKED`，合成签名包不得提升证据等级。
- 真实对象存储、生产签名/KMS、生产发布节点和生产灰度仍需后续环境准入，当前实现不构成生产发布平台或商业 SLA。

## 被否决方案

- 直接扩展 `pos_sync_device` 保存发布和灰度状态：会让终端身份 Owner 同时拥有发布流程，职责和权限过宽。
- 将 Gate 6A YAML 夹具直接生成表：夹具缺少租户范围、幂等、乐观锁、只追加历史和可信端口，不能成为正式运行时。
- 将 APK/Schema 失败统一“回滚”：数据库迁移可能不可逆，必须区分应用回退和安全前向修复。
