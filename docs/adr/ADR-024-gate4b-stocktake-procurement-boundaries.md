# ADR-024：Gate 4B 动态盘点与采购库存边界

- 状态：Accepted
- 日期：2026-08-17
- 决策范围：`T2-INV-003`、`T2-PUR-001`

## 背景

Gate 4A 已建立不可变数量账本。Gate 4B 必须在不覆盖余额、不引入成本或调拨运行时的前提下完成盘点与采购购销闭环，并处理持续销售穿越盘点、分批收货、超收和重复退货等高风险场景。

## 决策

1. 动态盘点保存创建时 `snapshot_quantity/snapshot_ledger_sequence`；每次计数是不可变事实。提交时锁定余额，以当前 `cutoff_ledger_sequence` 得到校准账面量，`variance=counted-adjusted_book`。批准后以差异增量调用库存 Owner，业务穿越不会被覆盖。
2. 盘点采用 `COUNTING → RECOUNT_REQUIRED/PENDING_REVIEW → REVIEWED → POSTED`，取消仅允许入账前。创建/计数、复核、批准至少三类责任人分离；入账后只能建立后续纠正盘点。
3. 新建模块 `jshpos-procurement`，独占 `sup_*`、`pur_*`。采购订单不改变库存；已确认收货生成 `PURCHASE_RECEIPT_IN`，获批原收货退货生成 `PURCHASE_RETURN_OUT`。
4. 采购模块通过进程内 `AuthoritativeInventoryMovementPort` 提交已持久化 Owner 事实，外部 API 不能直接调用库存移动端口。采购单据与库存账本处于同一数据库事务，失败全部回滚。
5. 采购单位换算在订单批准前从商品 Owner 获取并冻结为整数分子/分母；基础数量使用六位精确小数。采购价格/税率只是采购商业快照，本阶段不生成成本余额、成本流水或移动平均成本。
6. 超收策略冻结在采购订单：默认 `DENY`；非零容差仅租户管理员可批准且最多 10%。采购退货必须引用原已确认收货行，累计退货不得超过累计实收。
7. `T2-CST-001`、`T2-TRF-001` 继续只做设计契约；支付网络调用保持 0。

## 后果

- 优点：盘点与并发销售可解释，采购单据和库存数量事实各有唯一 Owner，重试不会产生第二库存效果。
- 代价：动态盘点需要保存快照、计数、截止序号和调整引用；成本必须在后续 Gate 根据已冻结采购与库存流水实现。
- 回退：应用入口可停用，已落流水不得删除；迁移只允许新增前向修复。
