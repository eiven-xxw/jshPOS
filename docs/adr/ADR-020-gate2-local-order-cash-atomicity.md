# ADR-020：Gate 2 本地订单、现金与 Outbox 原子性

- 状态：Accepted
- 日期：2026-08-16
- 决策人：项目发起人（T2 Gate 2 / Sprint S2 限定准入指令）
- 影响需求：`T2-POS-001..005`、`T2-ORD-001..002`、`T2-OFF-001`、`T2-SYN-001`

## 上下文

POS 必须在断网时完成现金销售，同时保证订单、现金和待同步事件不会因进程终止或磁盘异常出现部分成功。T1 的 `syn_*` 表只验证风险模型，既没有正式领域语义，也不具备生产迁移承诺，不能直接转正。

## 决策

1. Flutter POS 重新建立 `local_*` SQLite Schema；禁止复制、重命名或迁移 T1 `syn_*` 表。
2. 订单、订单行、成交快照、现金 Payment、班次现金流水、打印任务、Outbox 和本地幂等结果在一个 `BEGIN IMMEDIATE` 事务内写入；任一步失败整体回滚。
3. 外设调用、打印执行和网络同步不得发生在数据库事务内；事务只创建打印任务和 Outbox 事实。
4. 离线新建的订单、班次、现金事实和事件使用跨端 ULID；Gate 0 门店等平台 `BIGINT` ID 在 JSON 中使用十进制字符串；金额为 CNY 最小货币单位整数，数量使用规范化十进制字符串并在 SQLite 以受约束文本保存。
5. 订单提交冻结商品、条码、单位、数量、单价、价格来源、门店、终端、班次、业务日和操作者快照；提交后不得覆盖行项目。
6. 现金成交写独立现金支付事实，分别保存应收、顾客交付和找零；现金净流入必须等于顾客交付减找零且等于订单应收。
7. `T2-SYN-001` 在 S2 只冻结事件信封、ACK/冲突语义和故障向量，不启用任何网络 Worker 或服务端 Sync Inbox。
8. SQLite 迁移只允许前向、幂等和 checksum 锁定；提交后的 Schema 不做破坏性逆迁移，应用回退必须落在兼容窗口内。

## 后果

- 现金成交的本地事实具备可证明的全有或全无语义，打印或网络失败不会回滚已经成功的现金事实。
- 数据库写入链路更长，需要控制事务耗时、磁盘空间和 WAL；实机物理断电仍需 `REAL_DEVICE` 证据，CI 不能替代。
- S2 不具备远程同步能力，本地 Outbox 只形成可持久化待发送事实，不得据此宣称云端已接收。

## 验证方式

- SQLite 实际迁移、外键、唯一键、金额 CHECK、`quick_check` 和重复迁移通过；
- 故障夹具在每个写入点注入失败后验证订单、现金、Outbox 和幂等结果均为 0；
- 相同幂等键与相同摘要返回原结果，不同摘要返回 `IDEMPOTENCY_KEY_REUSED`；
- 两个虚构租户的跨租户读取、挂单、成交、交班均不可见或失败关闭；
- Flutter 与服务端契约对状态、错误码、幂等键、金额和关联标识逐项一致；
- CI 明确验证 `T2-SYN-001` 运行时网络入口为 0，外部证据仍为 0。
