# ADR-062：Gate 8C 质量、性能、可维护性与发布差距复核

- 状态：Accepted
- 日期：2026-08-24
- 关联：T2-E2E-005、T2-SEC-002、T2-MTN-001、T2-PERF-002、T2-RDY-001、CR-T2G8C-001

## 背景

Gate 7E 已形成商业 V1 内部业务完整候选，Gate 8B 已形成商业 SaaS 运营内部候选，但两者都不代表完整 Alpha、生产或商业发布。项目发起人要求继续优先内部代码时，先对既有代码做 P0/P1 安全、性能、可维护性和发布差距复核，且任何新业务能力必须另行 CR 与 Requirement ID。

## 决策

1. Gate 8C-Prep 只做静态治理与仓库事实审计，不修改运行时和迁移；发现项以稳定 Finding ID、严重级别、阻断范围、Owner、证据和关闭标准登记。
2. 整改按 `T2-SEC-002 → T2-MTN-001 → T2-PERF-002 → T2-RDY-001` 串行；每项必须独立设计准入、实现、`VERIFIED` 和项目发起人确认，禁止一次铺开。
3. P0 表示可能导致越权、密钥暴露、事实损坏、无法安全发布或外部商业验收必然失败；P1 表示进入内部发布候选前必须关闭的高风险质量差距。外部阻断不因内部整改改变证据等级。
4. Gate 8B 封存全量 CI 可作为未改运行时的基线证据；Gate 8C-Prep 只新增双平台治理、仓库静态审计和不可变证据索引。正式整改阶段必须重新运行完整 Server、Web、Flutter、Android/Kotlin、MySQL、SQLite、安全、SBOM、许可证和既有 Gate 回归。
5. 不以重构名义新增业务状态机、Owner、表、API 或页面；确有新业务价值时必须先提交独立 CR 和 Requirement ID。

## 后果

- Gate 8C-Prep 可在存在开放 P0/P1 的情况下完成“发现与准入材料”验收，但不能据此形成代码通过或发布通过；
- 内部安全 P0 必须先于可维护性、性能和发布收口；
- `T2-LIC-001`、外部四项、完整 Alpha 与发布仍按原状态独立治理；
- 完整 Alpha、生产和商业发布继续 `NO-GO`。
