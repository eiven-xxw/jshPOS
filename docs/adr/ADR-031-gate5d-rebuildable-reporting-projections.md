# ADR-031：Gate 5D 可重建报表投影与安全导出边界

- 状态：Accepted
- 日期：2026-08-17
- 决策范围：`T2-RPT-001`、`T2-RPT-002`

## 决策

1. 新建模块化单体 `jshpos-reporting`，Reporting Owner 独占 `rpt_*` 投影、来源 Inbox、检查点、差异、导出请求及制品元数据写入权。
2. Reporting 只消费 Order、Shift、Promotion、Inventory、Costing、Payment、Refund、Member 的版本化事件或明确只读端口；禁止跨模块 Mapper 读取或写入其他 Owner 私有表。
3. 来源事件以可信租户上下文授权，冻结 `source_event_id + content_sha256 + schema_version + projection_version + business_date`。同事件同摘要幂等，同事件异摘要失败关闭；乱序、晚到和序列缺口进入显式状态，不静默丢弃。
4. 销售、收银、库存和成本投影只累加来源 Owner 冻结的增量；金额、数量、业务日、舍入和促销分摊不在报表层重算。投影可整体丢弃并从来源 Inbox 或权威事件重建。
5. `T2-RPT-001` 独立验证后才准入 `T2-RPT-002`。支付报表首版只消费已接受的 Provider 无关支付/退款事实与内部合成账单；真实渠道账单仍由 `T2-PAY-002` 阻断。
6. 来源 Inbox、检查点、差异、导出状态与审计使用 `XML_ONLY`；日汇总表使用 `READ_PROJECTION`，只提供明确查询和受控 upsert/rebuild，不暴露通用更新或删除。
7. 导出采用“请求—独立审批—生成—短期单次下载—过期清理”状态机。租户命名空间、门店范围、字段白名单、脱敏、水印、CSV 公式注入防护、行数/时间范围上限和审计缺一不可。

## 不变量

- 报表不能修改任何业务 Owner 的事实、余额、状态和历史；差异只能告警或建立受审计修复任务。
- 每个查询、任务、缓存键、临时路径、对象键和下载令牌必须绑定可信租户；门店范围由服务端数据权限决定。
- 报表逐日汇总必须与来源事件精确守恒；重复不重复计数，重建前后摘要一致。
- 金额为最小货币单位整数，数量与成本为精确十进制；禁止 `float/double`。
- 导出不得包含身份密文、HMAC/令牌摘要、支付敏感数据、生产密钥或不必要 PII。

## 不采用

- 不以 Redis、搜索、报表库或导出文件作为唯一事实源。
- 不允许任意 SQL、跨租户大盘、报表反向修正事实或 Controller 直连 Mapper。
- 不以内部合成账单、Fake 或 Provider 无关状态机解除支付沙箱阻断。
