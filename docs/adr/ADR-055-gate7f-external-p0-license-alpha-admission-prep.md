# ADR-055：Gate 7F 外部 P0、许可证与完整 Alpha 执行准入准备

- 状态：Accepted
- 日期：2026-08-23
- 决策范围：T2-PAY-002、T2-HWD-001、T2-PRN-001、T2-PAR-001、T2-LIC-001、T2-UAT-001、T2-REL-001
- 工作基线：`3aaa92e9c90d1db540cfb6b70cdf65058c6a118f`

## 背景

`T2-E2E-004` 已被项目发起人接受为内部商业 V1 业务完整候选，但该证据不包含授权支付
沙箱、真实 Android 主机、真实打印外设、设计伙伴或完整 Alpha。Gate 6I 已冻结初版准入
模板；当前仍未收到可核验的不透明材料 ID、资产/样机、书面伙伴意愿或三组件许可证关闭
证据，因此不能提升任何外部证据等级。

## 决策

1. Gate 7F-Prep 只拥有材料清单、离线元数据、摘要、保管与到期规则、准入判定和 UAT
   启动模板，不拥有支付、设备、伙伴或生产事实。
2. 支付、主机、外设、伙伴四轨相互独立。每轨只有完整材料达到 `VERIFIED_DOCUMENT` 后
   才能提交独立执行准入评审；材料验真本身不自动解除 `BLOCKED`。
3. 受控原文、Secret、商户号、终端号、证书、真实 PII 和伙伴身份不得进入 Git、普通
   日志、CI 或普通制品；仓库只保存不透明引用、SHA-256、范围、保管人与生命周期元数据。
4. 许可证关闭按组件独立判定：替换并完成回归与最终 SBOM，或取得适用于当前版本和分发
   模式的书面法务批准。三项未全部关闭时商业发布固定 `NO-GO`。
5. 完整 Alpha 只有在 PAY/HWD/PRN/PAR 四轨分别取得项目发起人执行批准、环境与 RACI
   就绪后才能启动；准备材料和内部候选不得替代 `SANDBOX/REAL_DEVICE/PILOT/FULL_ALPHA`。
6. 本阶段不修改运行时代码、数据库、依赖或外部适配器；所有网络、真实资金、设备/外设
   命令、伙伴联系、完整 Alpha、生产部署和商业声明计数必须为 0。

## 后果与验证

- `T2-E2E-004` 更新为 `ACCEPTED`，证据上限不变。
- `T2-PAY-002/HWD-001/PRN-001/PAR-001` 保持 `BLOCKED`；`T2-UAT-001/REL-001` 保持
  `DRAFT`；`T2-LIC-001/JSH-001` 保持 `DEFERRED`。
- 专用双平台治理、范围/Secret 和证据索引门禁必须证明没有运行时、依赖和外部执行扩张。
