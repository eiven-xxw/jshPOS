# ADR-040：Gate 6H 体验、性能、运维与内部发布候选

## 状态

Accepted（2026-08-21，项目发起人按 `CONDITIONAL GO` 批准）

## 上下文

Gate 6G 已证明商业 V1 内部核心代码可正式装配、启动、联调和恢复，但内部候选仍缺少三业态一致体验、可解释性能趋势、可执行运维入口和可追溯发布候选。外部支付、真实硬件、打印和设计伙伴仍未解阻。

## 决策

1. Gate 6H 串行顺序固定为体验、内部性能、内部运维和内部发布候选；每项独立 `VERIFIED` 后才准入下一项。
2. 三业态差异只进入版本化体验配置和行业模板，不复制 Owner 状态机、金额、促销、库存、成本或退款算法。
3. 性能证据分为硬正确性门禁和执行器相关趋势；合成负载不得推导真实终端、生产容量或商业 SLA。
4. 运维能力必须失败关闭、可审计、脱敏并可重复；诊断、备份和发布制品不得包含 Secret、真实 PII 或跨租户数据。
5. 内部 RC 必须绑定构建提交、摘要、合成签名、SBOM、许可证、迁移清单、变更说明和 Go/No-Go，不得解除外部 P0 或替代完整 Alpha UAT。

## 后果

- 便利店主路径可以作为默认体验，零食折扣店与社区超市通过同一产品壳表达必要差异。
- 性能与运维缺口在外部接入前可被重复发现和修复。
- 内部 RC 只是一组可追溯工程制品，仍不能生产部署或宣称可商用。

## 验证

- UX、PERF、OPS、RC 使用独立 Job 和独立机器证据，并以 `needs` 串行。
- 最终回归继续覆盖 Server、Web、Flutter Linux/Windows、Android/Kotlin、MySQL、SQLite、安全、SBOM、许可证和 Gate 0—6G。
