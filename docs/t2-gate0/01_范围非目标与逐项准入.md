# Gate 0 范围、非目标与逐项准入

## 1. 正式范围

| Requirement ID | 本 Sprint 可交付 | 编码前必须存在 | 量化准入 |
|---|---|---|---|
| `T2-IAM-001` | 可信租户/操作者上下文、缺失失败关闭、资源命名空间 | 数据 Owner、威胁模型、Mapper/SQL/任务/缓存/导出/存储测试 | 客户端租户输入参与授权次数为 0；两个租户泄漏为 0 |
| `T2-ORG-001` | 组织、门店、时区、营业日起点与业务日计算 | 层级/唯一约束/状态/权限/审计/Flyway | 跨租户父子引用为 0；DST/跨午夜向量全过 |
| `T2-RBAC-001` | 复用员工/角色/菜单权限，扩展业务组织与门店数据范围 | 权限动作矩阵、职责分离、服务端强制点 | 未授权 API/数据访问全部拒绝；UI 不作为授权依据 |
| `T2-CFG-001` | 行业配置模板草稿、发布、激活与回退版本治理 | Owner、状态机、JSON Schema 版本、审计与回退 | 已发布版本不可改写；激活/回退有审计且租户隔离 |
| `T2-AUD-001` | 追加式领域审计、关联标识、前后摘要与脱敏 | 必审动作、不可变约束、敏感字段策略 | 更新/删除审计 API 为 0；Secret/完整敏感值命中 0 |
| `T2-SEC-001` | Gate 0 认证、授权、输入、Secret/SCA/SBOM/许可证基线 | 威胁清单和 CI 阻断阈值 | HIGH/CRITICAL 未批准问题为 0；生产 Secret 为 0 |
| `T2-OBS-001` | `correlation_id`、租户/门店低基数标签、基础指标与诊断字段 | 日志字段、指标基数预算、脱敏清单 | 每个 Gate 0 API 返回关联标识；Secret/PII 标签为 0 |
| `T2-MIG-001` | Gate 0 Flyway 迁移、checksum 清单、兼容和前向修复手册 | Expand/Contract、容量、锁、回退决策 | 干净库迁移/重复迁移/旧库 baseline/失败恢复全过 |

只有当 `gate0-admission.json` 中相应项全部为 `true`，并由校验器确认来源、验收、Owner、依赖、设计和测试均存在后，RTM 才能从 `DRAFT` 转为 `READY`。实现开始时可转 `IN_PROGRESS`；本轮自动化全部通过后最多转 `VERIFIED`，`ACCEPTED` 必须等待发起人确认周门禁报告。

## 2. Gate 1 限定准备

`T2-PRD-001..004`、`T2-PRC-001..002`、`T2-DPK-001` 仅允许版本化 OpenAPI/JSON Schema、领域术语、数据主权、迁移草案、合成测试向量和验收用例。全部继续 `DRAFT`，且：

- 不创建商品、条码、单位、价格或数据包正式 Java/TypeScript 类；
- 不创建正式 Flyway 表或索引；
- 不把契约挂载到运行时 Controller、菜单或任务；
- 不将 T1 `syn_*` 探针复制为生产模型；
- 不用 10k/100k 合成结果宣称实机性能或商业验收。

## 3. 非目标

订单、班次、现金、支付、退款、对账、库存、采购、调拨、成本、促销、会员、报表、正式 POS 同步、硬件 SDK 和连接器均不在 Gate 0。真实支付、生产密钥、未脱敏商户数据、SANDBOX、REAL_DEVICE、物理断电、PILOT 与商业验收不在本轮证据范围。

## 4. 自动停止条件

- 发现客户端 `tenant_id`、Header 或 URL 参数直接参与授权；
- 发现业务逻辑进入 Controller、通用工具类或 `ruoyi-system`；
- Flyway 已发布脚本被改写，或迁移需要危险的回滚 DDL；
- 跨租户攻击、服务端权限、Secret、HIGH/CRITICAL 依赖或证据完整性门禁失败；
- 发现订单、支付、库存、促销或 Gate 1 正式实现；
- 测试通过依赖跳过、放宽阈值或无根因重跑。
