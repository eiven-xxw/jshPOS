# Gate 0 测试矩阵、CI 与证据规范

## 1. 两租户合成拓扑

固定 seed `gate0-two-tenant-v1`：

- `TENANT_A`：总部 A、区域 A1、门店 A101/A102；管理员、区域经理、店员；便利店模板。
- `TENANT_B`：总部 B、区域 B1、门店 B201/B202；管理员、区域经理、店员；社区超市模板。

名称、人员、门店、配置均为虚构；禁止引入真实手机号、支付标识、生产域名或商户号。

## 2. 攻击矩阵

| 面 | 攻击 | 预期 |
|---|---|---|
| API | Body/Header/Path 猜测另一 tenant 或对象 ID | tenant 输入不参与授权；返回拒绝/不可见 |
| Mapper | `selectById` 猜测 B 的 BIGINT | MyBatis tenant 条件使结果为空 |
| 原生 SQL | code/id 命中另一租户 | SQL 必含 trusted tenant 参数且 B 行为 0 |
| 任务 | 伪造 tenant 参数、上下文泄漏到下一任务 | 仅内部登记租户可运行；finally 清理上下文 |
| 缓存 | 相同 key 在 A/B 读写 | 命名空间不同；拒绝 `../`、分隔符注入 |
| 导出 | 文件名/查询条件跨租户 | 服务端生成 tenant scope，行泄漏 0 |
| 对象存储 | key 穿越或显式 B 前缀 | 规范化拒绝；只能生成当前 tenant 前缀 |
| 权限 | 仅有 UI 菜单、无服务端权限/范围 | API 拒绝，审计/指标记录拒绝 |

## 3. 功能与不变量测试

- 组织：唯一编码、父子租户、循环、层级 8、停用约束、乐观锁。
- 门店：唯一编码、组织归属、ZoneId、DST、跨午夜业务日、状态迁移。
- RBAC：角色功能权限与 TENANT/ORG_SUBTREE/STORE 数据范围组合、grant/revoke 职责分离。
- 配置：版本递增、发布不可改、hash、激活、回退、错误模板/Schema 拒绝。
- 审计：同事务、脱敏、关联标识、append-only、跨租户查询为 0。
- 迁移：空库、baseline、repeat、validate、约束和前向修复路径。

## 4. CI Jobs

| Job | 阻断内容 | 主要制品 |
|---|---|---|
| governance | 基线/tag/分支、ADR、RTM、范围、Gate1 DRAFT、禁区 | admission JSON |
| server-unit | Maven 编译、单元、架构边界、覆盖率 | Surefire/JaCoCo |
| mysql-migration | MySQL 8 Flyway/约束/跨租户原生 SQL | migration report |
| tenant-security | Mapper/API/任务/缓存/导出/存储与权限攻击 | attack matrix JSON |
| admin-web | lockfile、lint、typecheck、unit、prod build | Web report/license |
| security | Secret、SCA、SBOM、许可证、IaC，HIGH/CRITICAL 阻断 | SBOM/security JSON |
| evidence | SHA-256 索引、测试摘要、RTM 状态、证据等级 | 周门禁 evidence bundle |

不设置 `continue-on-error`，不以 `--skipTests`、排除失败用例或降低 HIGH/CRITICAL 阈值通过。Flaky 必须固定 seed、记录根因和修复提交；无根因重跑仍视为失败。

## 5. 覆盖与证据等级

- foundation 新/变更 Java 行覆盖率 ≥90%、分支覆盖率 ≥85%；安全上下文、状态机和业务日不变量用例 100%。
- Gate 0 最高证据等级为 `INTEGRATION`；GitHub 构建成功不替代 SANDBOX/REAL_DEVICE/PILOT。
- 自动化全过后 RTM 最多 `VERIFIED`，周门禁报告经发起人确认才可 `ACCEPTED`。
- 每个制品记录 workflow/run/job、commit SHA、生成时间、环境、证据等级和 SHA-256；摘要缺失或包内索引不一致即失败。
