# T2-EXG-001 正式实现准入与切面

## 1. 准入结论

项目发起人已接受 CR-T2G7B-009。`T2-EXG-001` 从 `DRAFT` 进入 `IN_PROGRESS`；
`T2-PAY-004` 继续 `DRAFT`。本实现只增加换货 Saga 和关联，不增加新的资金、库存、
订单、促销或成本算法。

## 2. 正式装配

- ReturnOrchestration Owner：`ret_exchange` 具名状态迁移、两条不可变腿、只追加事件、
  幂等、审计和 Outbox；
- 退货腿：复用 `ReturnOrchestrationService/ReturnSagaCoordinator`，始终使用原 returnId；
- 销售腿：POS 使用既有 Sale/Checkout 应用端口创建新销售，服务端通过 Order Owner
  只读端口观察原 newOrderId；不得由 Exchange Mapper 写订单表；
- Flutter：保存 Saga 恢复投影，组合 Return/Sale/Exchange 应用端口，不直接访问 SQLite；
- 外部电子支付：未准入，Provider 网络和真实资金仍为 0。

## 3. 冻结规则

- 同租户、同门店、CNY；原退货和新销售各自保持权威金额，展示差额不形成第三笔资金事实；
- DRAFT 冻结 returnId、newOrderId、两条命令 ID、预期金额、报价/订单摘要和可信终端上下文；
- 原退货完成金额必须等于预期退款；新销售完成金额和摘要必须等于冻结值；
- `UNKNOWN` 只观察原聚合；部分成功无法自动解释时进入 `MANUAL_RECOVERY_REQUIRED`；
- MySQL 和 SQLite 已发布迁移不改写，功能回退只关闭新入口并继续观察已创建 Saga。
