- 换货只表达为“原单退货退款 + 新销售 + 只追加关联”，没有建立第三套订单、
  支付、退款、库存、促销或成本算法。
- ReturnOrchestration Owner 只持有换货头、RETURN/SALE 两条冻结腿、稳定命令
  标识、Owner 聚合引用、摘要、检查点、只追加事件、审计和 Outbox。
- 原退货退款读取原订单、原促销快照和累计已退上限；新销售复用既有正式
  Checkout/Order 端口。Exchange Mapper 不跨 Owner 修改订单、资金、库存或促销表。
- `RETURN_UNKNOWN/SALE_UNKNOWN` 只能使用原 returnId、orderId、commandId 查询或
  观察；不得生成替代退款、扣款或销售命令。无法自动解释的部分成功进入
  `MANUAL_RECOVERY_REQUIRED`，审批和人工恢复均留存审计。
- MySQL V55/V56 与 SQLite V12 均为独立前向迁移；换货腿、事件和关联只追加，
  更新/删除由数据库保护失败关闭。空 MySQL 8.4 实际执行 30 个迁移并到达 V56，
  第二次迁移为 0。
- Flutter 页面通过 Exchange、Return、Sale 正式应用端口完成创建、审批、观察和
  恢复；不直接访问 SQLite、MethodChannel、Mapper，也不调用支付 Provider。
- 稳定幂等键、同键异内容拒绝、重复/乱序、ACK 丢失、进程终止、跨租户替换、
  摘要篡改和 20 个固定故障向量均进入自动化回归。
