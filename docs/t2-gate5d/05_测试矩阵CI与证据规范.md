# Reporting 测试矩阵、CI 与证据规范

## 1. RPT-001 准入测试

| 类别 | 必测场景 |
|---|---|
| 幂等/顺序 | 重复同摘要、同 ID 异摘要、乱序、晚到、序列缺口、部分 Owner 延迟、全量重放 |
| 守恒 | 订单金额、现金、退款、班次差异、库存数量、库存价值、COGS、采购/盘点/调拨逐日逐字段守恒 |
| 重建 | 空库重建、影子版本、增量追平、切换前 kill、摘要不一致拒绝、迁移失败前向修复 |
| 租户/权限 | 两租户、组织/门店越权、客户端 tenant、任务 tenant、缓存键、跨租户 source event、导出/下载越权 |
| 导出 | 独立审批、范围/行数/字段上限、脱敏、水印、CSV 公式注入、CRLF、对象键穿越、令牌过期/重放、临时文件清理 |
| 容量 | 10k/100k 功能回归、1,000,000 合成来源性能基线、并发查询与重建 |
| 兼容 | 未知 Schema、旧事件新投影、新服务旧活动版本、失败 DDL 和安全前向修复 |

RPT-001 独立验证必须包含模块单元/集成测试、MySQL 8.4 全迁移、治理检查、固定合成向量、攻击脚本和完整服务端回归。通过后才可更新为 `VERIFIED` 并准入 RPT-002。

## 2. RPT-002 后续测试

覆盖 Provider 无关成功/失败/UNKNOWN、退款、内部合成账单匹配、少账/多账/金额/币种/状态/日期差异、确定性优先级、重复/乱序/晚到、同键异摘要、处理人和只追加审计、全量重建、10万+10万容量、跨租户/跨门店、脱敏与安全导出。`sandbox=0` 必须保留，不能把合成账单标成渠道验收。

## 3. CI Job

1. `governance`：基线祖先、RTM 顺序、ADR/契约、迁移摘要、范围扫描、依赖差异。
2. `server`：`ruoyi-admin -am clean verify`、覆盖率和聚合 SBOM。
3. `mysql-migration`：MySQL 8.4 从 V1 到 Gate 5D 最新迁移，表注释、索引、权限和只追加/状态约束。
4. `tenant-export-security`：租户/门店/任务/缓存/导出/对象路径/下载令牌攻击。
5. `projection-vectors-performance`：固定向量、重建摘要和百万级合成性能基线。
6. `admin-web`：依赖审计、构建、Lint、类型、测试和许可证。
7. `pos-linux` / `pos-windows`：Flutter、SQLite、Kotlin、Android 既有回归，不新增报表 POS 运行时。
8. `security-sbom-license`：Secret、依赖漏洞、双 SBOM、许可证和 Workflow IaC。
9. `evidence`：单次聚合机器可读索引；生产者制品不重复上传。

## 4. 门禁阈值与证据

- Reporting 核心行覆盖率至少 90%，分支覆盖率至少 85%；全部测试 0 failure/error/skipped。
- 一百万合成事件必须全部被接受或按预期拒绝，重建摘要一致；性能数值只作为本提交回归基线，不宣称实机/生产 SLA。
- 每个制品包含 commit SHA、基线、需求状态、测试统计、覆盖率、攻击面、Provider 网络调用、真实 PII 数、SANDBOX/REAL_DEVICE/PILOT 等级和文件摘要。
- 禁止跳过、降低阈值、自动重跑掩盖 Flaky、修改已发布迁移或创建绿色占位。
