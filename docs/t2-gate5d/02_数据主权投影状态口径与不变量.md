# Reporting 数据主权、投影状态、口径与不变量

## 1. 数据主权

Reporting 只拥有 `rpt_*`。Order/Shift/Promotion/Inventory/Costing/Payment/Refund/Member 各自仍是事实 Owner。来源通过版本化事件或显式只读端口进入统一信封；任何 `rpt_*` 值都无权覆盖来源事实。

统一信封必须包含：`sourceEventId`、`sourceOwner`、`sourceAggregateId`、`sourceSequence`、`schemaVersion`、`projectionVersion`、`contentSha256`、`occurredAt`、`businessDate`、`orgId`、`storeId`、可选终端/收银员/仓库/SKU、币种与一种精确指标载荷。`tenantId` 不出现在客户端命令中，只由可信上下文注入。

## 2. RPT-001 来源与指标

| 来源 Owner | 允许载荷 | Reporting 行为 |
|---|---|---|
| Order / Promotion | 销售、取消、退货计数及冻结金额增量 | 按原最小货币单位整数累加，不重算促销 |
| Shift | 现金实收、现金退回、班次差异增量 | 绑定业务日、门店、终端、收银员 |
| Inventory | 在手/可用/预占及采购/盘点/调拨数量增量 | 使用 `DECIMAL(25,6)`，不计算库存规则 |
| Costing | 库存价值、COGS、采购/盘点/调拨成本增量 | 使用最小货币单位的 `DECIMAL(25,6)`，不重算移动平均 |

销售投影键为租户、业务日、组织、门店、终端、收银员、币种、投影版本；库存成本投影键为租户、业务日、组织、门店、仓库、SKU、币种、投影版本。

## 3. 事件与检查点状态

- Inbox：`RECEIVED → APPLIED`；校验失败不落业务效果；冲突写独立差异事实。
- 检查点：每个 `sourceOwner + partitionKey` 保存最大连续序号、最大已见序号和缺口数。
- 重复同摘要：返回原应用结果，不重复计数。
- 同 ID 异摘要：`409` 失败关闭并记录 `CONTENT_CONFLICT`。
- `sequence = contiguous + 1`：推进连续检查点。
- `sequence > contiguous + 1`：应用可交换的冻结增量，同时记录缺口并将投影标记 `INCOMPLETE`。
- 晚到缺口补齐：重新计算连续检查点；全部补齐后标记 `CURRENT`。
- 过旧但未见事件：按事件 ID 幂等后补算；禁止静默丢弃。

## 4. 守恒不变量

1. `gross_minor - discount_minor + surcharge_minor = receivable_minor` 对每个已完成订单事实成立；Reporting 只校验来源增量，不自行调整。
2. 日投影每个字段等于同租户、同维度、同业务日已 `APPLIED` 来源事件增量之和。
3. 订单头、行和促销分摊守恒由 Order/Promotion Owner 冻结；报表只记录内容摘要与金额。
4. 库存数量和成本按来源增量精确相加；禁止浮点数、隐式 scale 截断或报表层重新舍入。
5. 重建前后的 canonical digest 必须一致；不一致建立 `REBUILD_MISMATCH` 差异并停止切换。
6. 任何差异、重建和导出都不能修改来源 Owner 数据。

## 5. 重建与切换

重建生成新的 `projection_version`，从已校验来源 Inbox 以稳定顺序 `(business_date, source_owner, partition_key, source_sequence, source_event_id)` 重放到影子版本；完成逐日守恒、行数和摘要校验后原子切换活动版本。旧版本保留一个兼容窗口后再按审计策略清理。失败保留旧活动版本并以前向修复重试。

## 6. 会员与隐私边界

首版报表不保存会员身份、手机号、卡号、地址、身份密文、HMAC 或令牌摘要。允许的会员维度仅限匿名 `memberSegmentCode` 或等级代码，且必须满足最小聚合阈值；本 Sprint RPT-001 默认不出现在导出字段中。
