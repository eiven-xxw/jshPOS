# Reporting 迁移、容量、重建、兼容、回退与修复

## 1. Flyway 计划

- V32：RPT-001 来源 Inbox、检查点、销售投影、库存成本投影、差异、重建、导出请求与制品元数据；所有表/字段含中文 COMMENT。
- V33：RPT-001 菜单和权限，使用新保留 ID，不复用历史 ID。
- V34：RPT-002 Provider 无关支付/退款事实 Inbox、内部合成账单 Inbox、对账投影和只追加审计链；表和字段使用中文 COMMENT。
- V35：RPT-002 查询、导入和差异处理权限，使用新保留 ID。
- 已发布 V1—V31 不修改；DDL 失败修复只能新建前向迁移。

## 2. 索引与容量

- Inbox：唯一 `(tenant_id, source_event_id)`；重放索引 `(tenant_id, projection_version, business_date, source_owner, partition_key, source_sequence, source_event_id)`。
- 日销售：唯一维度键；查询索引 `(tenant_id, store_id, business_date)`。
- 库存成本：唯一维度键；查询索引 `(tenant_id, store_id, business_date, warehouse_id, sku_id)`。
- 导出：`(tenant_id, status, expires_at)`；差异：`(tenant_id, status, detected_at)`。
- 合成容量基线：1,000,000 条来源明细、两个租户、至少 12 个门店；测试记录吞吐、重建时间、投影行数和摘要，不作为生产承诺。
- RPT-002 另以 100,000 条 Provider 无关事实与 100,000 条内部合成账单验证幂等导入、匹配查询、差异分类和全量重建；仍不代表外部渠道 SLA。

Inbox 按业务日期具备未来分区/归档条件；首版不自动物理删除来源 Inbox。任何归档必须证明权威事实可重放并保存清单摘要。

## 3. 兼容

- Schema 只接受明确白名单版本；未知主版本失败关闭，兼容小版本忽略的字段不得影响摘要。
- 旧服务/新表：新增列提供安全默认值，不改变旧投影读取。
- 新服务/旧投影：活动投影版本指针未切换前继续服务旧版本；新功能失败关闭，不猜测缺失指标。
- 事件载荷只追加可选字段；删除、重命名或改变金额/数量单位必须发布新 Schema 主版本。

## 4. 重建与增量追平

1. 获取租户级重建互斥锁，记录旧活动版本和截止检查点。
2. 建立影子版本，稳定重放截止点前已 `APPLIED` Inbox。
3. 验证逐日字段守恒、投影行数、差异数和 canonical digest。
4. 追平重建期间到达的事件；再次验证后原子切换活动版本。
5. 失败时活动版本不变，重建标为 `FAILED`，保留证据并释放锁。

## 5. 回退和安全前向修复

- 代码回退只读旧活动版本；不删除新 Inbox，不逆向 DDL。
- 错误投影通过新投影版本重建修复，不直接手改汇总值。
- 错误来源摘要、跨租户事件、未知币种/scale 和同键异内容进入差异队列，禁止人工直接覆盖。
- 导出对象写入失败标记 `FAILED` 并清理临时文件；数据库状态与对象存储不宣称跨系统原子，依靠稳定对象键和幂等生成收敛。
- RPT-002 错误投影只允许清空并从两侧 Inbox 重建；晚到事实或账单以新只追加事实收敛。禁止手改匹配金额、删除冲突条目或把合成证据升级为 SANDBOX。
