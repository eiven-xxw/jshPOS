# T2-E2E-002 可重复运行手册

## 1. 适用范围

本手册只复现 `INTERNAL_ALPHA_CANDIDATE` 合成证据。它不调用 Provider 网络、不控制真实设备、不使用真实 PII、不开展现场试点，也不替代完整 Alpha UAT。

## 2. 源契约预检

在仓库根目录运行：

```text
python scripts/check_t0_structure.py
python scripts/check_rtm.py
python scripts/check_contracts.py
python scripts/check_t2_gate6e.py
python scripts/run_t2_gate6e_internal_alpha_candidate.py --output artifacts/t2/gate6e/local/internal-alpha-candidate-report.json --seed-ledger artifacts/t2/gate6e/local/failure-seed-ledger.json --defect-ledger artifacts/t2/gate6e/local/defect-ledger.json
```

源契约模式必须输出六条旅程、十二个固定 seed、外部执行为 0。该模式不组合 CI 生产者，因此不能单独形成 `VERIFIED`。

## 3. 正式 CI 复现

推送到 `t2/gate6e-sprint16-internal-alpha-candidate` 后，工作流必须先独立完成 governance、server、mysql、pos-linux、pos-windows 和 admin-web。`internal-alpha-candidate` 只下载同一 run 的上述制品并执行：

```text
python scripts/run_t2_gate6e_internal_alpha_candidate.py --bundle-dir artifacts/t2/gate6e/candidate-bundle --output artifacts/t2/gate6e/internal-alpha-candidate/internal-alpha-candidate-report.json --seed-ledger artifacts/t2/gate6e/internal-alpha-candidate/failure-seed-ledger.json --defect-ledger artifacts/t2/gate6e/internal-alpha-candidate/defect-ledger.json
```

随后 evidence Job 组合安全制品并生成最终索引。不得从其他 run 拼接制品，不得用本地报告替换缺失的 CI 生产者。

## 4. 必核结果

- `internal-alpha-candidate-report.json`：六旅程、三业态、两个虚构租户，金额/数量/库存/成本/报表/退款/班次全部守恒。
- `failure-seed-ledger.json`：十二个固定 seed 均有预期与观察结果，`failedSeeds` 为空。
- `defect-ledger.json`：`P0/P1` 均为空；否则内部决策必须为 `NO-GO`。
- `t2-gate6e-evidence-index.json`：包含候选报告与全部生产者文件 SHA-256。

## 5. 失败处理

任何失败必须保留原 run、日志、seed 和红色证据。修复后使用新提交完整重跑；禁止删除失败用例、跳过平台、自动重跑掩盖 Flaky、降低阈值或创建绿色占位。同一 seed 再现失败时不得改 seed 逃避。

## 6. 结论边界

全部通过时只允许结论 `CONDITIONAL_GO_INTERNAL_ONLY`。`T2-PAY-002/T2-HWD-001/T2-PAR-001` 仍为 `BLOCKED`，`T2-UAT-001/T2-REL-001` 仍为 `DRAFT`；完整 Alpha、试点、发布和商用结论仍禁止。
