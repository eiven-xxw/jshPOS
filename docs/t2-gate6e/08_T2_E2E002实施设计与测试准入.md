# T2-E2E-002 实施设计与测试准入

## 1. 目的与证据边界

本需求把 Gate 0—6E 已接受或已独立验证的正式 Owner 能力组合为可重复的内部候选闭环，用于发现跨模块契约、迁移、恢复和证据缺口。它不新增任何领域算法，不写 Owner 私表，不改变 `T2-UAT-001`，最高证据等级固定为 `INTERNAL_ALPHA_CANDIDATE`。

## 2. 数据主权和固定旅程

每个 Owner 继续只写自己的事实。候选执行器仅消费同提交的正式测试报告、公开应用端口结果和固定合成向量，不替代真实应用进程、真实设备或外部 Provider。六条固定旅程覆盖两个虚构租户各自的便利店、零食折扣店和社区超市：

后台初始化与价格/规则发布 → 虚构终端登录开班 → 扫码、促销、授权优惠、挂取单和现金成交 → 原 Outbox/Inbox/ACK 同步 → 服务端订单、库存、成本与报表守恒 → 原单部分退和最终退、现金退款及原优惠快照恢复 → 班次关闭 → 从空环境合成备份恢复 → 合成发布升级、健康失败回退与安全前向修复。

每条旅程绑定唯一租户、门店、终端、员工、业务日、订单、促销快照、同步事件、退货引用、备份集和 release ID。跨租户替换、同键异内容和摘要篡改必须失败关闭。

## 3. 状态、不变量和恢复

- 销售满足 `gross - discount + surcharge = receivable`；现金找零、班次理论现金与订单头行逐字段守恒。
- 部分及最终退款合计不得超过原成交可退额；最后一次合法退款吸收余数，退货数量和恢复优惠累计守恒。
- 销售出库与退货入库、销售成本与成本冲正、权威事实与报表投影逐业务日守恒。
- 重复、乱序、ACK 丢失、进程终止和客户端未知复用原幂等键、event ID、returnRef 与摘要；不得重建业务命令。
- 备份恢复从空环境校验清单、摘要、Schema、投影和游标；证据保持 `SYNTHETIC_RESTORE`。
- 合成升级校验签名、兼容窗口、待同步保护、健康检查、回退和安全前向修复；证据保持 `SOFTWARE_EXECUTION`。

## 4. 故障、缺陷与 Go/No-Go

固定 seed 至少覆盖跨租户/门店越权、重复乱序、ACK 丢失、进程终止、磁盘写入失败、业务日切换、订单/促销/退款摘要篡改、同键异内容、部分 Owner 失败、投影重建、备份缺片/错密钥、升级签名错误/健康失败和迁移前向修复。观察到的失败 seed 必须写入账本并永久加入回归，禁止删除或重跑掩盖。

`P0/P1` 缺陷账为空或全部关闭、六条旅程及全部固定 seed 单次通过、同提交正式 CI 生产者齐全且摘要可重现时，内部建议才可为 `CONDITIONAL GO`；任何 P0/P1 未关闭、事实不守恒、证据缺失或外部边界违规均为 `NO-GO/IN_PROGRESS`。

## 5. CI 与制品

新增独立 `internal-alpha-candidate` Job，必须下载同一 run 的治理、服务端、MySQL、Flutter Linux/Windows 和 Web 制品，拒绝失败、错误、跳过、重复或缺失报告；安全门禁继续独立执行。候选报告、失败 seed 总账、缺陷账、证据目录和运行手册进入 90 天封板制品，最终证据索引必须包含其 SHA-256。

## 6. 外部边界

`T2-PAY-002/T2-HWD-001/T2-PAR-001` 保持 `BLOCKED`，`T2-UAT-001/T2-REL-001` 保持 `DRAFT`，`T2-JSH-001/T2-LIC-001` 保持 `DEFERRED`。Provider 网络、真实终端命令、现场试点和完整 Alpha UAT 均为 0；不得把合成结果写成外部解阻或商用结论。
