# T2-ADM-002 实施设计与测试准入

## 1. 实现边界

- `admin-web/src/api/operations` 是后台第二波的唯一新网络适配层，统一使用仓库 `request`，禁止创建平行 Axios/Fetch 客户端。
- `views/operations/advanced` 只组合页面；Inventory、Costing、Procurement、Transfer、Promotion、Member、Reporting、Terminal、Release 各 Owner 仍是其事实与状态机唯一写入者。
- 本需求没有新增领域表或领域算法。唯一数据库变化是 V42 菜单前向迁移，只注册 `operations/advanced/index` 与 `operations:advanced:read`；按钮和 API 最终授权继续使用各 Owner 已发布权限。

## 2. 页面与应用状态

页面统一使用 `IDLE/LOADING/READY/CONFIRMING/SUBMITTING/SUCCEEDED/FAILED/STALE`。高风险写操作冻结对象、服务端当前状态、版本、动作、影响、原因与幂等键后才显示二次确认；提交期间单航班。409 进入 `STALE`，超时或失败保留原幂等键，禁止生成新业务命令掩盖未知结果。

## 3. 正式能力

1. 库存/成本：余额和不可变流水查询、受控投影重建；无历史编辑入口。
2. 盘点：创建、计数、提交、复核、审批；审批效果仍由 Inventory Owner 追加流水。
3. 采购：供应商状态、采购单、原单收货和采购退货；确认后由 Inventory/Costing Owner 处理数量与成本事实。
4. 调拨：创建、提交、审批、发出、收货和取消；禁止前端覆盖两仓余额。
5. 促销：白名单基础规则创建与版本生命周期；前端不实现促销计算器。
6. 会员：仅虚构会员码的创建/解析、同意、隐私请求、积分查询与双人审批调整；不持久化真实 PII。
7. 报表/终端：复用已接受正式页面。
8. 发布：合成包的清单、验签、灰度状态；真实 APK、厂商 SDK 和设备命令为 0。

## 4. 精度、租户与审计

- 数量以最多六位小数的字符串传输；前端不使用浮点数计算库存、成本或积分。
- BIGINT URL 标识以字符串校验后拼接；必须转成数字的列表限制在 JavaScript 安全整数范围。
- 请求守卫递归拒绝租户覆写和原型污染键；服务端可信租户、门店、仓库和终端范围仍是最终授权。
- UI 只显示服务端脱敏结果、状态、版本、摘要和关联标识；不得记录身份输入、令牌、密文或签名材料。

## 5. 迁移、兼容与回退

- 新迁移：`V202608200042__gate6e_advanced_operations_menu.sql`，只新增菜单记录；对保留 ID 发生碰撞时失败关闭。
- API 继续使用既有版本，不改变 Owner Schema。未知字段忽略，未知状态不自动猜测动作。
- UI 回退通过移除/隐藏菜单和回滚 Web 制品完成；已执行 V42 不删除，菜单停用使用后续前向迁移表达。

## 6. 固定向量与门禁

- 固定向量：`contracts/t2/gate6e/test-vectors/admin-operations-v2.json`，40 项，覆盖两虚构租户、三业态、Owner 成功路径、租户/权限攻击、重复、陈旧版本、未知结果、容量和兼容。
- Web：ESLint、TypeScript、35 项全量 Vitest、生产构建。
- MySQL：MySQL 8.4 空库从 V1 执行至 V42、二次 migrate 为 0、`validate`、菜单路由和权限核验。
- 全量：服务端、Flutter Linux/Windows、SQLite、Kotlin/Android、Secret、依赖、SBOM、许可证和 Gate 0—6D 回归不得降低。
- `T2-POS-009/T2-E2E-002` 继续 `DRAFT`；ADM-002 独立 CI 未全绿前不得创建其运行时。

## 7. 回退与故障处理手册

1. 前端失败先记录关联标识、对象状态/版本和原幂等键，不记录敏感输入。
2. 网络未知结果先重新查询 Owner；只有服务端确认未受理时才使用原幂等键重试。
3. `STALE` 必须重新读取服务端状态并重新走人工确认，禁止自动覆盖。
4. 投影差异只运行 Owner 受控重建并核对流水；不得以页面值覆盖事实。
5. 发布或菜单异常回退旧 Web 制品并隐藏新菜单；数据库只允许后续前向修复。
