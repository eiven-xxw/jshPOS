# T2-POS-009 实施设计与测试准入

## 1. 数据主权和旅程

Order Owner 提供原成交订单与行快照，Promotion Owner 提供原促销快照及累计恢复上限，Return/Refund Owner 独占申请和 Saga 检查点，Payment Owner 独占 Provider 无关退款状态，Inventory Owner 独占退货入库，Audit Owner 独占审计。页面只展示 `PosReturnApplicationService` 返回的组合只读视图。

用户旅程固定为：输入规范原单引用 → 加载原单及可退上限 → 选择本次数量 → Owner 重新预检并返回金额 → 选择原因并提交现金退货 → 若需职责分离则由正式应用服务处理受权审批 → 只读跟踪促销、现金退款、入库和完成检查点。Provider 无关 `UNKNOWN` 只查询原退款，不生成新命令。

## 2. 页面状态、权限和错误

- 页面状态：`IDLE/SEARCHING/READY/SUBMITTING/PENDING/UNKNOWN/COMPLETED/FAILED`；未知服务端状态映射为 `FAILED` 并要求升级。
- 权限：原单读取、退货申请、退货审批和退款状态读取分别校验；终端、租户、门店、班次与业务日来自既有可信会话。
- 稳定错误至少覆盖：原单非法/不可见、跨店、已取消、无可退量、数量超限、快照摘要冲突、同键异内容、审批分离、网络未知、状态未知和会话过期。
- 页面错误不得显示原始响应、凭据、PII、SQL、内部堆栈或支付敏感数据。

## 3. 应用边界与恢复

Flutter 新增 `features/return_refund`，只含领域只读模型、应用端口、页面 Controller、正式 UI 和默认失败关闭适配器。UI/Controller 禁止导入本地数据库、HTTP、设备适配器或其他 Owner 基础设施；稳定幂等键、命令、摘要、金额分摊和 Saga 推进由应用服务拥有。

断网可以查询已存在的安全缓存摘要，但不得离线创建云端退货事实。本次提交超时后页面进入 `UNKNOWN/PENDING`，只调用 `refreshReturnStatus(returnRef)`；进程重启由应用服务恢复原 `returnRef/idempotencyKey`。数据库与 Schema 不变，不新增 SQLite/Flyway 迁移；回退隐藏入口并恢复旧 APK，已提交事实继续由服务端收敛。

## 4. 精度、不变量和容量

数量使用最多六位小数的字符串，金额使用 CNY 最小货币单位整数。UI 不做金额或优惠计算；构造只读模型时校验 `gross - recoveredDiscount = refundable`、累计不得超过原上限、原促销摘要为 64 位十六进制。单次最多 500 行，搜索和提交采用单航班，按钮防重复点击。

## 5. 测试准入

固定向量覆盖两个虚构租户、多店、多终端、三业态以及部分/最终退款、最后余数、重复/乱序、ACK 丢失、进程终止、业务日切换、跨租户替换、摘要/金额篡改、职责分离、UNKNOWN 查询和 Provider 网络为零。单元测试覆盖模型与 Controller，Widget 测试覆盖触控/键盘、选择、确认、未知恢复和权限拒绝；之后必须重跑 Gate 6E 八路独立 CI。

`T2-E2E-002` 继续 `DRAFT`，POS-009 独立 `VERIFIED` 前不得创建内部 Alpha 候选运行时或绿色占位。

## 6. 本地实现证据

正式实现位于 `pos-flutter/lib/features/return_refund`，生产默认使用失败关闭组合根；会话首页只在同时具备读取、申请权限且班次开启时显示入口。`flutter analyze --fatal-infos`、112 项全量测试和新增范围 `192/212=90.57%` 行覆盖已通过。该结果仍为本地证据，POS-009 保持 `IN_PROGRESS`，等待 GitHub Ubuntu/Windows、Android/Kotlin/APK 和 Gate 0—6D 全量独立回归。
