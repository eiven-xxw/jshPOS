# T2-POS-011 设计准入

## 1. 结论

`PASSED_DESIGN_ENTRY / IN_PROGRESS`。允许实现成交时语义收据冻结、软件预览、补打请求与审计；`T2-PRN-001` 仍为 `BLOCKED`，真实打印命令和成功状态均禁止。

## 2. 用户旅程与数据主权

成交事务冻结收据语义内容和模板版本，生成原始打印任务；收银员可查看原始内容预览。具备 `pos:print:reprint` 权限的员工填写原因并确认后追加补打请求，界面必须显示“真实打印未接入”。Order/Checkout Owner 独占收据文档和打印请求事实，Device Owner 尚不产生真实执行观察。

## 3. 状态、冻结点与不变量

1. `ReceiptDocument` 在订单完成事务内进入 `FROZEN`，内容、模板、订单绑定和 SHA-256 永久不可更新或删除；
2. 原始打印请求与订单、订单行、现金、班次效果、收据和 Outbox 同一 SQLite 事务，任一失败整体回滚；打印执行失败不得反向撤销已完成交易；
3. 补打只读取原冻结语义内容，禁止按当前商品、价格或促销重算；每次追加原因、操作者、授权引用、次数、摘要、审计和 Outbox；
4. 补打序号为 1—999，同幂等键同内容返回原结果，同键异内容拒绝；请求与事件只追加；
5. 软件执行状态恒为 `BLOCKED_EXTERNAL`，适配器证据恒为 `BLOCKED_REAL_PRINTER`，不得写入 `PRINTED/SUCCEEDED`；
6. 同步端必须用可信设备上下文覆盖租户、门店、终端与员工声明，并验证语义 JSON 摘要、订单绑定和事件身份；
7. 兼容旧 SQLite 订单时没有冻结文档必须失败关闭为 `RECEIPT_NOT_FOUND`，不得临时重算伪造历史收据。

## 4. 权限、审计与错误码

- `pos:print:preview`：读取可信门店/终端范围内冻结收据；
- `pos:print:reprint`：追加补打请求，不能代表真实设备授权；
- 审计记录原因、操作者、授权引用、内容摘要、次数、命令与关联标识，不保存口令或设备 Secret；
- 稳定错误码：`PERMISSION_DENIED`、`RECEIPT_NOT_FOUND`、`RECEIPT_HASH_MISMATCH`、`RECEIPT_CONTEXT_MISMATCH`、`RECEIPT_REPRINT_INVALID`、`RECEIPT_REPRINT_LIMIT_REACHED`、`IDEMPOTENCY_KEY_REUSED`、`REAL_PRINTER_BLOCKED`。

## 5. API、事件与事务边界

POS 通过正式 `PosSaleApplicationService` 的 `loadPrintPreview/requestReceiptReprint` 使用本地能力，不直接访问 SQLite 或 MethodChannel。远端沿用已接受的同步 Push/Inbox 契约，新增 `receipt.document-frozen.v1` 与 `receipt.reprint-requested.v1`，Schema 见 `contracts/t2/gate7b/receipt-events-v1.schema.json`。服务端 Sync Dispatcher 只调用 Order Owner 端口，不跨 Owner Mapper。

## 6. 迁移、容量、兼容与回退

- SQLite 只追加 V10，MySQL 只追加 Flyway V53；已发布迁移不得修改；
- 单张收据最多 500 行、语义 JSON 最大 1 MiB，补打原因 256 字符，补打次数最多 999；
- 已成功 Schema 只前进；应用回退时旧版本忽略新表，新版本迁移失败整体回滚或安全前向修复；
- 原始语义内容使用规范 JSON 与 SHA-256 校验；服务端保存同步源事件并幂等拒绝同键异内容。

## 7. 测试准入

覆盖成交原子冻结、预览不重算、重复补打、同键异内容、补打上限、无权限、跨租户/门店/终端、内容/摘要篡改、磁盘及检查点失败、进程重启、Outbox/ACK 重放、迁移中断、旧单失败关闭和真实打印调用为零。量化要求为 P0/P1=0、Java/Dart 事件逐字段一致、既有覆盖率与安全门禁不降低。
