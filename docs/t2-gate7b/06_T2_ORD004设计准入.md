# T2-ORD-004 设计准入

## 1. 结论

`PASSED_DESIGN_ENTRY / IN_PROGRESS`。只允许实现成交前取消、未完成本地单作废、
服务端取消墓碑，以及成交后只追加反向处置路由。不得把已成交订单改回草稿或取消，
不得删除、覆盖或伪造支付、退款、库存、成本、促销和审计事实。

## 2. 用户旅程与数据主权

1. 当前购物篮取消：收银员二次确认原因，Checkout Owner 在本地保存取消订单、行快照、处置事实、状态历史、审计、幂等结果与 Outbox；页面随后创建全新购物篮。
2. 挂单取消：只允许当前可信租户、门店、终端、员工、班次和业务日内的 `DRAFT/SUSPENDED` 单；保留原挂单和行，不物理删除。
3. 未完成订单作废：仅 `DRAFT/PENDING_PAYMENT` 且不存在 `PROCESSING/UNKNOWN/SUCCEEDED` 资金、库存出库或确认事实时可迁移 `CANCELLED`。
4. 已完成订单处置：状态保持 `CONFIRMED/COMPLETED`，只追加 `RETURN_REFUND_REQUIRED`、`PAYMENT_REVERSAL_OBSERVATION_REQUIRED` 或 `EXPLICIT_COMPENSATION_REQUIRED` 路由；POS V1 正常入口只开放既有原单退货退款。
5. Order/Checkout Owner 独占订单状态、取消墓碑和处置路由；Return、Payment、Inventory、Costing 各自继续只写自身事实，禁止跨 Owner Mapper。

## 3. 状态机、冻结点与不变量

| 当前状态 | 命令 | 有效结果 | 守卫 |
| --- | --- | --- | --- |
| `DRAFT` | Cancel | `CANCELLED` | 未支付、未确认、无库存出库 |
| `PENDING_PAYMENT` | Cancel | `CANCELLED` | 没有活动、未知或成功资金尝试 |
| `CONFIRMED/COMPLETED` | RouteDisposition | 状态不变 | 只追加受控反向路径 |
| `CANCELLED/CLOSED` | 任意新处置 | 拒绝或原摘要幂等返回 | 禁止重开 |

- 取消事务必须原子保存订单/版本、状态历史、只追加处置、审计、Outbox 和幂等结果；故障整体回滚。
- 取消墓碑必须先于后到成交事实生效；相同 order ID 的后到成交必须失败关闭。成交已先成立时，后到取消必须冲突并转人工处置，不以到达顺序覆盖事实。
- `UNKNOWN` 只能查询、回调或对账收敛，禁止通过取消、重建订单或生成新资金命令消解。
- 同幂等键同摘要返回原结果，同键异内容返回 `IDEMPOTENCY_KEY_REUSED`；处置事实、状态历史与审计只追加。
- 业务日切换、班次关闭、跨租户/门店/终端/员工、版本竞态和摘要篡改均失败关闭。

## 4. 权限、审计与错误码

- 成交前取消使用 `pos:order:cancel`；跨业务日、异常关闭与显式补偿使用 `pos:order:dispose` 并要求非空授权引用；原单退货继续使用既有退款权限。
- 审计冻结 tenant/store/terminal/cashier/shift/businessDate、来源状态、有效状态、原因、授权引用、命令、幂等键摘要和关联标识，不记录口令或 Secret。
- 稳定错误码：`ORDER_STATE_CONFLICT`、`ORDER_VERSION_CONFLICT`、`ORDER_CANCELLATION_BLOCKED`、`PAYMENT_RESULT_UNKNOWN`、`ORDER_DISPOSITION_REQUIRED`、`ORDER_DISPOSITION_INVALID`、`RESOURCE_NOT_VISIBLE`、`PERMISSION_DENIED`、`IDEMPOTENCY_KEY_REUSED`。

## 5. API、事件与事务边界

Flutter 页面只调用 `PosSaleApplicationService` 的取消和处置路由操作，正式实现位于 Checkout/Order 应用层，不直连 SQLite。同步新增 `order.cancelled.v1` 与 `order.reversal-routed.v1`；服务端 Sync Dispatcher 通过 Order Owner 端口保存取消墓碑或处置路由。契约见 `order-disposition-events-v1.schema.json`，共享状态、错误码和摘要按 Java/Dart 固定向量逐字段一致。

## 6. 迁移、容量、兼容与回退

- SQLite 只追加 V11，MySQL 只追加 Flyway V54；不修改 V1—V10 或 V1—V53。
- 每单取消墓碑至多一个；反向路由按稳定处置 ID 只追加，原因最多 256 字符；所有查询显式租户和可信数据范围。
- 旧客户端不产生处置事件但可继续同步既有成交；新服务端必须拒绝与取消墓碑冲突的后到成交。新客户端/旧服务端收到不支持事件时保持 Outbox `FINAL_REJECTED` 并显示人工修复，不静默丢弃。
- 应用失败通过原命令重试或安全前向修复；禁止回滚已发布 Schema、删除墓碑或回写成交事实。

## 7. 测试准入

覆盖当前篮取消、空篮拒绝、挂单取消、重复与同键异内容、磁盘检查点失败、进程重启、ACK 丢失、取消先到/成交后到、成交先到/取消后到、完成单只路由、退款入口、UNKNOWN 阻断、跨租户/门店/终端、业务日切换、版本竞态、摘要篡改和全量重放。量化要求 P0/P1=0、Java/Dart 事件逐字段一致、既有覆盖率/安全/SBOM/许可证门禁不降低，外部执行仍为 0。
