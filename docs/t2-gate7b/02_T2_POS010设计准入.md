# T2-POS-010 设计准入

## 1. 结论

`PASSED_DESIGN_ENTRY / IN_PROGRESS`。本结论允许实现软件事实与 UI，不允许真实钱箱命令。

## 2. 用户旅程

已登录且开班的员工在“班次现金管理”中选择现金存入、现金取出或安全投库，输入正数金额和原因，二次确认后提交。具备独立权限的员工也可发起非销售开钱箱请求；系统只记录请求并明确显示“外设未执行”。

## 3. 数据主权和状态

- `local_shift_cash_movement/shf_cash_movement`：Checkout/Order Owner 只追加；
- `local_drawer_event/shf_drawer_event`：Checkout/Order Owner 保存业务请求；Device Owner 尚未产生真实执行结果；
- 班次必须为可信门店、终端和员工当前 `OPEN` 状态；
- 每次操作以 `expectedVersion` 条件推进班次版本，关闭班次后全部拒绝。

## 4. 不变量

1. 客户端只提交正数 `amountMinor`；Owner 将 `CASH_IN` 转为正数，将 `CASH_OUT/SAFE_DROP` 转为负数；
2. 现金移动、班次理论现金/版本、审计、幂等结果和 Outbox 同事务；任一失败整体回滚；
3. 钱箱请求金额恒为零，不改变理论现金；请求、班次版本、审计、幂等与 Outbox 同事务；
4. 钱箱设备执行状态固定为 `BLOCKED_EXTERNAL`，不得保存 `SUCCEEDED`；
5. 同幂等键同摘要返回原结果，同键异摘要拒绝；
6. 现金事实不可更新或删除，跨租户/门店/终端和关闭班次失败关闭；
7. 金额使用 CNY 最小货币单位整数并限制 JavaScript 安全整数上限。

## 5. 权限和审计

- `pos:shift:cash-manage`：记录非销售现金移动；
- `pos:drawer:no-sale`：记录非销售开钱箱请求；
- 本地权限来自已认证 `EmployeeSession`，服务端再次执行权限与门店数据范围校验；
- `authorizationRef` 只是已认证会话的不可逆引用，不代替服务端授权；
- 审计保存类型、金额、原因、操作者、命令、摘要、班次前后版本与关联标识，不保存口令。

## 6. API、事件和错误码

API 见 `contracts/t2/gate7b/openapi-pos-operations-v1.yaml`；事件为 `shift.cash-movement.recorded.v1` 和 `shift.drawer-requested.v1`。稳定错误码至少包括：`PERMISSION_DENIED`、`SHIFT_STATE_CONFLICT`、`SHIFT_VERSION_CONFLICT`、`SHIFT_CASH_OPERATION_INVALID`、`IDEMPOTENCY_CONFLICT`、`DRAWER_EXTERNAL_BLOCKED`。

## 7. 迁移、容量和回退

- SQLite 只追加 V9；MySQL 只追加 Flyway V52；已发布迁移不改写；
- 单班次非销售现金操作上限 5000 条；索引按租户、班次、时间；
- 部署回退只回退应用；Schema 保留且旧应用忽略新表；失败迁移整体回滚，已成功迁移仅前向修复。

## 8. 测试准入

覆盖三种移动、符号规则、钱箱零金额、重复/同键异内容、关闭班次、版本冲突、磁盘/检查点失败、跨租户、权限拒绝、业务日、迁移中断、Outbox 重放和真实设备执行为零。量化要求：Java/Dart 关键向量逐字段一致，P0/P1 为 0，既有覆盖率和安全门禁不降低。
