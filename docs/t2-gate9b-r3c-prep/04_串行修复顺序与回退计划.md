# 串行修复顺序与回退计划

## 顺序

1. `R3C-R0`：先冻结共享测试底座、具名页面状态、安全错误、单航班和原键语义；
2. `R3C-R1`：VUE-16 报表、导出和对账处置；
3. `R3C-R2`：VUE-18 服务工单与附件；
4. `R3C-R3`：VUE-20 终端和一次性秘密；
5. `R3C-R4`：VUE-17 SaaS 开户与权益；
6. `R3C-R5`：VUE-19 订阅生命周期；
7. `R3C-R6`：FLT-05 班次现金与钱箱；
8. `R3C-R7`：FLT-02 原单退货退款；
9. `R3C-R8`：FLT-01 基础换货；
10. `R3C-R9`：八页联合十二维验收和完整 CI。

前一步未独立 `VERIFIED`，后一步不得铺开。每一步先加入固定失败 seed，再做最小页面修复；
不得为页面整改修改 Controller/API、Owner 算法、依赖、数据库或迁移。

## 停点与回退

- 权限和正式 Controller 不一致：停止该页，记录差异；不得放宽服务端权限；
- 现有 API 无法支持原键恢复：停止并提交独立影响分析，不得在页面伪造成功；
- 资金、租户或库存事实解释出现歧义：保持缺陷 OPEN，提交决策；
- 页面修复破坏既有测试：回退该步最小提交，保留失败证据，不跳过用例；
- 外部 Provider/设备边界被触发：立即 NO-GO，并恢复为 `BLOCKED/UNAVAILABLE`；
- 本批全部页面变更均可通过独立 Git 提交回退；没有数据库迁移回退问题，因为本批禁止迁移。
