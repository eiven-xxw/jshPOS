# 既有环境前向清理运行手册

## 适用范围

本手册只用于已经执行过旧版 RuoYi 初始化 SQL 的既有环境，清理演示菜单、角色绑定和
`test_demo/test_tree` 测试表。新环境直接使用已收敛的 MySQL、Oracle、PostgreSQL 或
SQL Server 初始化源，不需要执行清理。

## 安全规则

1. 工具不连接数据库、不自动执行 SQL，只根据受控预检生成方言脚本；
2. 预检必须由受控环境使用 `JSH_G9A_R2_PREFLIGHT_HMAC` 完成 HMAC-SHA256 签名；
3. 预检有效期最长 30 分钟，菜单、角色绑定、表和自定义漂移计数必须与冻结策略完全一致；
4. 摘要错误、签名缺失、过期、计数漂移、客户自定义或未知方言必须失败关闭；
5. 清理只前进，不恢复演示表/菜单，不修改业务 Owner 表或已发布迁移；
6. 执行前必须备份并走生产变更审批。本阶段没有执行任何生产数据库写入。

## 离线生成步骤

1. 按 `contracts/t2/gate9b-r2/forward-cleanup-preflight.schema.json` 生成预检 JSON；
2. 由受控系统计算规范 JSON 的 HMAC-SHA256 并写入签名字段；
3. 在受控终端设置 Secret 环境变量，执行：

```powershell
$env:JSH_G9A_R2_PREFLIGHT_HMAC = '<受控Secret引用取得的临时值>'
python scripts/build_t2_g9a_r2_forward_cleanup.py --preflight <预检文件> --output-dir <受控输出目录>
```

4. 复核生成 SQL 与 admission digest；在目标环境的变更窗口由双人审批后人工执行；
5. 重新运行预检，确认目标对象为 0，并将结果、执行人、审批人、时间和摘要写入受控证据库；
6. 立即清除环境变量与临时文件，按保留策略归档或销毁。

## 回退

代码和 Web 删除可从 Git 历史恢复，但重新准入必须有新 CR、Requirement ID 和安全评审。
数据库不允许用恢复演示对象作为回退；误清理风险依赖执行前备份恢复，任何业务事实漂移必须
停止并升级人工处置。
