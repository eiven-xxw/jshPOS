## 2. 证据状态机

`MISSING → RECEIVED_UNVERIFIED → VERIFIED_DOCUMENT → EXECUTION_APPROVED → EXECUTED_EXTERNAL`

- `RECEIVED_UNVERIFIED`：仅登记不透明 ID、受控位置、收件时间和保管人；不得阅读 Secret。
- `VERIFIED_DOCUMENT`：来源、授权签署、适用产品/型号、版本、范围、SHA-256、保管、到期、
  轮换、删除和吊销全部可复核。
- `EXECUTION_APPROVED`：必须有该轨独立报告及项目发起人明确批准，不得自动晋级。
- `EXECUTED_EXTERNAL`：只能由批准执行产生，必须标明 SANDBOX、REAL_DEVICE、
  REAL_PERIPHERAL 或 PILOT，内部证据不得替代。

任何字段缺失、摘要漂移、过期、签署主体无权、产品/型号不适用或范围冲突都必须失败关闭。

## 3. 受控元数据最小集合

| 字段 | 约束 |
|---|---|
| material_id | 唯一不透明 ID，不含商户、设备、联系人或 PII |
| controlled_location | 只登记受控系统引用，不登记 Secret 值或可公开下载地址 |
| source | 厂商/机构/签署主体与取得渠道可验证 |
| authorization_signer | 身份、权限、签署时间与适用范围可验证 |
| product_model_version | 精确产品、型号、接口/SDK/固件版本 |
| scope | 环境、租户/门店/终端、允许动作、地域与时间窗 |
| sha256 | 对受控原文计算；仓库只保存摘要 |
| custodian | 具名责任角色、受控系统和最小访问权限 |
| lifecycle | 到期、轮换、删除、销毁证明和吊销规则 |

## 4. 保管与隐私

受控原文、Secret、商户号、终端号、证书私钥、真实支付报文、伙伴名称/地址/联系人和真实
PII 只能位于批准的 Secret、合同、CRM、设备资产或隐私受控系统。仓库、普通 CI、日志和
Artifact 只允许上述元数据及非敏感状态。下载、复制、预览、摘要和删除必须有审计。

## 5. 零执行与停止条件

Provider 网络、真实资金、APK 安装/重启、设备或外设命令、伙伴联系、现场试点、完整
Alpha、生产部署和商业声明全部为 0。发现疑似生产凭据、生产在用资产、未授权数据、范围
不清或摘要冲突时立即停止，隔离材料并通知安全/隐私 Owner。
