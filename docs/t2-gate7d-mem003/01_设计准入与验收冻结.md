# T2-MEM-003 设计准入与验收冻结

## 1. 数据主权和串行顺序

1. Member：不可变权益版本、等级映射、门店范围、发布/暂停/撤回、最小权益快照；
2. Pricing：会员价版本与 SKU 价格项，按 Member 快照解析候选；
3. Promotion：普通路径与会员路径、双向显式叠加、BEST_PRICE、解释和金额守恒；
4. Order/Refund：成交绑定只追加，退款只读原冻结快照；
5. DataPackage/POS/Vue：签名包、SQLite 原子切换、端侧旅程；
6. Java/Dart 向量和内部 E2E。

每个 Owner 只写自己的事实，不允许跨 Owner Mapper、表更新或复制状态机。

## 2. 状态与冻结点

- 权益/会员价版本：`DRAFT → VALIDATED → APPROVED → SCHEDULED → ACTIVE`，以及
  `ACTIVE ↔ PAUSED`、`ACTIVE/PAUSED → RETIRED/REVOKED`；批准后内容不可修改。
- 权益快照：`ISSUED → ACTIVE → EXPIRED/REVOKED/SUPERSEDED`；快照绑定 tenant、store、
  member_ref_hash、等级历史、权益版本、有效期、撤回纪元和摘要。
- 报价：`QUOTED → FROZEN → SETTLED`；冻结后等级、权益、价格或促销变化不得重算。

## 3. 计算和不变量

可信上下文 → 权益验签 → 普通价 → 会员价 → 普通促销路径 → 会员权益路径 → 双向叠加判断 →
BEST_PRICE → 人工优惠 → 抹零 → 冻结快照。平价选普通路径。

`gross - discount + surcharge = receivable`，行合计等于订单头；同一 Adjustment 不得重复；
退款累计数量/金额不超过原上限，最后一次合法退款吸收余数。

## 4. 权限、隐私和审计

权限冻结为 `member:benefit:create/validate/approve/publish/pause/revoke/read`、
`pricing:member-price:publish/read`、`pos:member-benefit:quote`。创建/审批职责分离；发布、暂停、
撤回、范围、报价降级和退款均记录摘要、原因、操作者、审批人和关联标识。

跨 Owner 只传不可逆会员引用、等级/权益/价格版本、门店范围、摘要和有效期；姓名、手机号、
证件、身份密文、令牌明文、支付敏感数据禁止进入价格、促销、订单、包、日志与制品。

## 5. 持久化与访问策略

正式登记见 `contracts/t2/gate7d-mem003/persistence-registry.csv`。MySQL 从 V75 起、SQLite 从
v16 起只前进；控制面使用 `CONTROLLED_WRITE + XML/HYBRID`，版本内容、快照、绑定、审计和
Outbox 使用 `APPEND_ONLY + XML`，复杂查询使用 `READ_PROJECTION + XML`。

## 6. 离线、兼容和回退

包绑定租户、门店、Schema/协议、版本、摘要、签名、有效期和撤回纪元。过期、撤回、旧包、
损坏、跨范围、未知 Schema 或时钟不可信均失败关闭；明确确认后只能生成新非会员报价。
回退关闭新入口和发布，不删除历史快照；Schema 使用安全前向修复。

## 7. 量化验收

- 40 个固定向量 Java/Dart 逐字段一致率 100%；
- 金额守恒、退款原快照、同键异内容、跨租户/门店、过期/撤回失败关闭通过率 100%；
- P0/P1 缺陷、Secret/PII 泄漏和 Flaky 均为 0；
- 完整 CI 覆盖治理、Server、Web、Flutter 双平台、Android/Kotlin、MySQL、SQLite、安全、
  SBOM、许可证、覆盖率和既有 Gate 回归；
- 外部执行和商业证据保持 0。
