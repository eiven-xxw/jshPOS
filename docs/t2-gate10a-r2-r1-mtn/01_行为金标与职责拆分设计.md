# 行为金标与职责拆分设计

## 金标顺序

1. 冻结五个服务的公开方法集合与 `@Transactional` 边界；
2. 冻结四个 Owner 应用服务目录的错误码多重集合摘要；
3. 复用并补强事务失败传播、同键异内容、审计/Outbox、Owner 调用顺序和金额数量守恒测试；
4. 启用 19 类只减不增、新类不超过 400 行、Owner 依赖环为 0 的门禁；
5. 原服务继续持有公开 API 与事务，抽取纯规则/验证/摘要协作者，不移动到 Controller、Mapper 或工具层。

## 风险顺序与职责

| 顺序 | 原服务 | 允许抽取的职责 | 禁止变化 |
|---:|---|---|---|
| 1 | ProcurementService | 命令校验、内容摘要、关联标识规则 | 采购状态、库存/批次Owner调用、事务 |
| 2 | LotInventoryService | 日期/批次/来源验证、规范化与摘要规则 | 批次账本、FEFO、Owner事实 |
| 3 | TransferService | 命令校验、单位换算、内容摘要规则 | 调拨状态、库存/成本事实、事件 |
| 4 | ReplenishmentService | 参数验证、分页、幂等摘要规则 | 建议计算、采购草稿与状态机 |
| 5 | ReturnOrchestrationService | 申请/审批/观察验证及摘要规则 | 退款Saga、UNKNOWN、原快照恢复 |

抽取类属于各自 Owner 的应用策略，不跨 Owner 写数据，不持有 Mapper，不开启新事务。
