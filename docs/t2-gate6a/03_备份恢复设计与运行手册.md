# T2-BAK-001 备份恢复设计与运行手册（准入前冻结）

> 当前状态：`DRAFT`。只有 T2-TRM-001 独立 VERIFIED 后才可实现。

## 1. 恢复集合

恢复点必须包含 MySQL 全量或 PITR 基线、对象存储业务对象、配置/行业模板、Flyway/SQLite 迁移清单、CI 封板证据与审计索引。Redis、搜索和报表投影不是唯一事实，可在权威事实恢复后重建。

清单字段：backup ID、环境、租户/数据范围、cutoff、Schema/应用版本、每个对象的逻辑路径、明文大小、明文 SHA-256、密文大小、加密算法、key version、nonce/tag、保留期、retention lock、创建者、状态与清单摘要。

## 2. 加密与权限

- 数据使用 AES-256-GCM 或等价 AEAD；每个对象独立随机 nonce 和数据密钥语义。
- 数据备份只保存 key version/引用，不保存解密密钥；恢复材料由独立 Secret/KMS 输入。
- 备份创建、保留、恢复、销毁权限分离；生产删除账号不得删除不可变恢复点。
- CI 只使用运行时随机合成密钥和临时目录，禁止写真实云资源。

## 3. 恢复顺序

1. 在空隔离环境载入独立恢复密钥；
2. 校验清单版本、范围、签名/摘要、保留状态和对象完整性；
3. 解密到受控临时区并复核明文摘要；
4. 恢复 MySQL 权威事实并执行 Flyway validate；
5. 恢复对象、配置、模板、迁移与证据；
6. 按 Owner 重建可丢弃投影；
7. 逐租户、逐门店、逐业务日核对订单/资金引用/库存/成本/会员/报表守恒；
8. 核对 Inbox/Outbox/游标与不可变审计；
9. 记录 RPO、RTO、差异、人工步骤和 Go/No-Go。

任何损坏、缺片、错密钥、跨租户对象、Schema 不兼容、恢复中断或守恒失败均为 `NO-GO`。禁止用报表投影或 POS 本地库覆盖云端事实。

## 4. Alpha 候选内部目标

- RPO：恢复点 cutoff 与最后纳入权威事实时间差 ≤15 分钟。
- RTO：从演练开始到完整校验与 Go 决策 ≤60 分钟。
- 0 个未解释差异、0 个跨租户对象、0 个缺失不可变事实。

该目标只在本 Gate 的合成隔离环境有效，不构成生产/跨区域或商业 SLA。
