# T2-BAK-001 备份恢复设计与运行手册

> 当前状态：`IN_PROGRESS`。T2-TRM-001 已由独立 CI 证据验证，BAK 已按顺序准入；本文描述的本地文件对象存储、软件生成密钥和空目标均为 `SYNTHETIC_RESTORE`，不能解除生产 KMS、真实对象存储、跨区域灾备和商业 SLA 阻断。

## 1. 恢复集合

恢复点必须包含 MySQL 全量或 PITR 基线、对象存储业务对象、配置/行业模板、Flyway/SQLite 迁移清单、CI 封板证据与审计索引。Redis、搜索和报表投影不是唯一事实，可在权威事实恢复后重建。

清单字段：backup ID、环境、租户/数据范围、cutoff、Schema/应用版本、每个对象的逻辑路径、明文大小、明文 SHA-256、密文大小、加密算法、key version、nonce/tag、保留期、retention lock、创建者、状态与清单摘要。

## 2. 加密与权限

- 数据使用 AES-256-GCM 或等价 AEAD；每个对象独立随机 nonce 和数据密钥语义。
- 数据备份只保存 key version/引用，不保存解密密钥；恢复材料由独立 Secret/KMS 输入。
- 备份创建、保留、恢复、销毁权限分离；生产删除账号不得删除不可变恢复点。
- CI 只使用运行时随机合成密钥和临时目录，禁止写真实云资源。

### 2.1 已实现边界

- `jshpos-resilience` 是恢复集合、加密对象目录和恢复演练的唯一写 Owner；其他 Owner 只通过 `Source`/`RestoreTarget` 端口参与。
- `BackupController` 不接收 `tenantIds`、密钥材料、对象正文或云凭据；租户集合只由 `AuthorizedScope` 可信适配器注入。
- 对象采用 AES-256-GCM，AAD 固定绑定 `backupId + tenantScopeSha256 + logicalName + plaintextSha256 + keyVersion`；nonce 随机且与密文同时校验。
- 对象键固定为 `backups/{tenantScopeSha256}/{backupId}/{ciphertextSha256}.aead`；本地适配器没有删除接口并使用 `CREATE_NEW` 拒绝覆盖。
- `bak_backup_object`、`bak_restore_check`、`bak_audit` 由 MySQL 触发器禁止更新/删除；备份与演练只允许具名状态迁移。
- 默认 Spring 适配器在缺少 Source、可信范围、独立密钥、空恢复目标或对象根目录时失败关闭，不生成绿色结果。

### 2.2 状态机和幂等

| 聚合 | 合法状态 | 合法迁移 | 幂等与冲突 |
|---|---|---|---|
| BackupSet | `CREATING/AVAILABLE/FAILED/EXPIRED` | `CREATING→AVAILABLE/FAILED`，`AVAILABLE→EXPIRED` | `backupId` 为键；同键同摘要返回原结果，同键异内容 `409` |
| RestoreDrill | `RUNNING/PASS/FAIL_CLOSED` | `RUNNING→PASS/FAIL_CLOSED` | `drillId` 为键；同键异内容 `409`；任一完整性或守恒错误写 `FAIL_CLOSED` |

备份失败不删除已写对象或目录，而是保留失败状态和去敏失败类型摘要，交由受审计运维流程隔离。恢复失败时必须调用目标 `abort`，不得将部分目标升级为可用环境。

## 3. 恢复顺序

1. 在空隔离环境载入独立恢复密钥；
2. 校验清单版本、范围、签名/摘要、保留状态和对象完整性；
3. 解密到受控临时区并复核明文摘要；
4. 恢复 MySQL 权威事实并执行 Flyway validate；
5. 恢复对象、配置、模板、迁移与证据；
6. 按 Owner 重建可丢弃投影；
7. 逐租户、逐门店、逐业务日核对订单/资金引用/库存/成本/会员/报表守恒；
8. 核对 Inbox/Outbox/游标与不可变审计；
9. 记录 RPO、RTO、差异、人工步骤和 Go/No-Go。

任何损坏、缺片、错密钥、跨租户对象、Schema 不兼容、恢复中断或守恒失败均为 `NO-GO`。禁止用报表投影或 POS 本地库覆盖云端事实。

## 4. Alpha 候选内部目标

- RPO：恢复点 cutoff 与最后纳入权威事实时间差 ≤15 分钟。
- RTO：从演练开始到完整校验与 Go 决策 ≤60 分钟。
- 0 个未解释差异、0 个跨租户对象、0 个缺失不可变事实。

该目标只在本 Gate 的合成隔离环境有效，不构成生产/跨区域或商业 SLA。

## 5. 标准运行手册

### 5.1 创建恢复集合

1. 值班 SRE 核验操作者具有 `backup:create`，并记录工单、恢复点、冻结 Schema/应用版本和保留截止。
2. 独立备份身份读取六类来源：`MYSQL/BUSINESS_OBJECT/CONFIG/TEMPLATE/MIGRATION/EVIDENCE`；缺少任何一类即失败关闭。
3. 可信范围适配器冻结租户集合，计算 `tenantScopeSha256`；来源对象声明的租户集合必须完全相同。
4. 目录先以 `CREATING` 登记；逐对象计算明文摘要、加密、写只追加对象、计算密文摘要并追加目录。
5. 生成字段顺序固定的清单，写 `manifestSha256` 后原子迁移到 `AVAILABLE`。
6. 核验对象数、六类覆盖、摘要、保留截止、审计和 RPO；不完整时保持 `FAILED/IN_PROGRESS`。

### 5.2 空环境恢复演练

1. 新建无业务数据的隔离目标；禁止指向生产库、既有业务库或 POS 本地库。
2. 读取目录并先校验租户范围、状态、Schema、清单摘要、对象密文摘要和 key version。
3. 由独立密钥提供者取解密密钥；密钥不得落入数据库、日志、报告或制品。
4. 解密后复核明文摘要，按数据类别恢复；任一对象缺片、损坏、错密钥或跨范围替换立即 `abort`。
5. 运行 Flyway validate、投影重建、逐租户/业务日守恒、Inbox/Outbox/游标和审计核对。
6. 自动记录开始、结束、RPO、RTO和九项校验；仅在全部为零差异且目标内时写 `PASS`。

### 5.3 故障与恢复决策

| 故障 | 系统行为 | Go/No-Go |
|---|---|---|
| 清单/密文/明文摘要不一致 | 停止恢复、隔离目标、写 `FAIL_CLOSED` | NO-GO |
| 错密钥或 nonce/AAD 不一致 | AEAD 验证失败，不输出明文 | NO-GO |
| 跨租户对象或恢复范围替换 | 权限错误并停止 | NO-GO/安全事件 |
| Flyway 或 Schema 不兼容 | 禁止跳过迁移，保留隔离目标调查 | NO-GO |
| 投影、业务日、游标或审计有未解释差异 | 禁止用投影覆盖权威事实 | NO-GO |
| RPO>900秒或RTO>3600秒 | 保存真实计时和差距，不改写证据 | NO-GO/保持 IN_PROGRESS |
| 演练进程中断 | 下次使用原 `drillId` 查询/恢复，不重新生成命令 | NO-GO直至受审计处置 |

## 6. 证据分级与当前阻断

- 当前可生成：`STATIC + UNIT + MYSQL8.4_SYNTHETIC + SYNTHETIC_RESTORE`；包括固定双租户、六类对象、百万合成事实摘要、自动 RPO/RTO 计时和九项核对。
- 当前不能证明：生产备份吞吐、真实 PITR 日志链、云对象保留锁、生产 KMS/密钥轮换、跨账号/跨区域恢复、真实删除身份隔离、真实灾备切换。
- 上述外部项保持 `ASSUMPTION/BLOCKED`；本地文件系统和软件密钥结果不得标记为 `CLOUD_DR/PRODUCTION/COMMERCIAL_SLA`。
