# T2-UPG-001 设计准备与实机阻断报告

> 文档编号：JSH-POS-T2-G6A-009
> 日期：2026-08-18
> Requirement：`T2-UPG-001`
> 当前状态：`DRAFT / DESIGN ONLY / REAL_DEVICE BLOCKED`
> 升级运行时：`0`
> 真实终端命令：`0`

## 1. 结论

本 Sprint 仅冻结服务端、Web、MySQL/SQLite Schema、模板/数据包和 APK 的版本契约、签名与摘要、兼容窗口、灰度状态机、营业时段保护、健康检查、回退及安全前向修复规则，并准备合成包和虚构终端故障向量。仓库没有创建升级 Controller、远程命令执行器、真实 APK 安装器或厂商静默升级适配器，`T2-UPG-001` 继续保持 `DRAFT`。

主认证 Android 厂商/型号/固件/SDK、静默安装权限、样机、Android Keystore/硬件证明、物理断电、存储压力、固件兼容与真实回退证据均缺失。因此任何合成包、Debug APK 构建或虚构终端状态不得标为 `REAL_DEVICE`，也不得解除 `T2-HWD-001`。

## 2. 已冻结设计

### 2.1 发布物身份

每个发布物必须包含：`release_id`、制品类型、语义版本、渠道、目标租户/门店范围、内容 SHA-256、签名算法与签名、签名密钥版本、构建 commit、SBOM 摘要、最低/最高应用版本、协议版本、Schema 版本、系统版本和发布时间窗。服务端不得信任终端自行声明的目标范围或能力。

### 2.2 发布与终端任务状态

- 发布：`DRAFT → SIGNED → STAGED → CANARY → ROLLING → COMPLETED`，异常分支为 `PAUSED | FAILED | REVOKED`。
- 终端任务：`PLANNED → DOWNLOADING → VERIFIED → INSTALLING → HEALTH_CHECK → SUCCEEDED`，异常分支为 `ROLLED_BACK | FORWARD_FIX_REQUIRED | FAILED_CLOSED`。
- 状态只能通过具名命令推进；同幂等键同内容重放，同键异内容拒绝；历史事件与审计只追加。

### 2.3 兼容和迁移

- 服务端至少兼容当前和上一批准 POS 主版本；兼容矩阵必须明确 API、事件、数据包和 Schema 读写窗口。
- MySQL 与 SQLite Schema 只前进，不回改已发布迁移；失败使用安全前向修复。
- 模板/规则包先校验签名、摘要、租户/门店、Schema 与兼容窗口，再进行原子切换；失败保留上一已验证版本。
- 服务端/Web 回退不得回退权威事实或数据库 Schema；代码回退必须通过当前 Schema 兼容检查。

### 2.4 营业保护与健康检查

出现班次开启、待同步 Outbox、支付/退款 `UNKNOWN`、磁盘或电量不足、设备时钟异常、关键营业时段、能力降级、终端已吊销或备份恢复演练未完成时，默认禁止自动安装。健康检查至少包含进程启动、数据库迁移、可信终端上下文、同步游标、规则/数据包摘要、外设能力快照和回退点完整性。

## 3. 已准备合成向量

已冻结的设计向量包括：摘要错误、签名错误、包截断、旧包重放、跨租户/跨门店包替换、版本跨度、下载中断、安装前进程终止、迁移失败、健康检查失败、待同步状态、营业时段保护、旧客户端/新服务端、新客户端/旧服务端、回退失败和安全前向修复。

这些向量只证明契约可测试，不证明厂商安装能力、固件兼容、物理断电恢复或真实终端回退。
