# Gate 6A 范围、非目标与顺序准入

## 1. 唯一边界

- 基线：`t2-prep-baseline-2026-08-16`。
- 分支起点：Gate 5D 封板提交 `1bd27f70d39dd2056ffecf3b25f07aa9c7953606`。
- 顺序：`T2-TRM-001 → T2-BAK-001`。
- `T2-UPG-001` 仅设计准备；`T2-UAT-001/T2-REL-001` 仅退出模板。

## 2. TRM-001 准入

允许：后台签发一次性激活授权、虚构 POS 激活、设备凭据摘要与轮换、终端阻断/吊销/退役、门店迁移受控重激活、版本和能力快照、可信上下文、审计、迁移、管理 API 和合成测试。

非目标：真实厂商 SDK、Android Keystore 实机证明、证书 CA/HSM、MDM、远程擦除、真实终端命令、固件管理、外设认证和商业设备 SLA。

TRM-001 进入编码前必须冻结 Owner、状态机、摘要算法、一次性展示、权限、审计、API/事件、V36 前向迁移、100k 终端容量、旧同步兼容与回退。全部已在本目录和契约中完成，故状态可进入 `IN_PROGRESS`。

## 3. BAK-001 准入

只有 TRM-001 独立达到 `VERIFIED` 后才允许将 BAK-001 从 `DRAFT` 更新为 `IN_PROGRESS`。其允许范围是 MySQL、对象、配置/模板、迁移与证据的合成加密备份，清单/摘要/保留锁，空隔离环境恢复、对账和 RPO/RTO 自动计时。

非目标：写入真实云资源、生产 KMS/Vault、真实 binlog 连续归档、跨账号/跨区域复制、生产 DNS/证书切换、勒索实战、商业 SLA 和完整 Alpha/UAT。

## 4. 一票否决

- 新增第二套终端事实源或让客户端 tenant/store 成为授权依据；
- 保存明文激活码、设备凭据、私钥、生产 secret 或真实 PII；
- 用备份、报表或 POS 本地库覆盖权威 Owner 事实；
- 用本地容器、模拟终端或合成密钥宣称 REAL_DEVICE、生产灾备或商业 SLA；
- Provider 网络调用、真实资金、后续 Gate 业务实现；
- 跳过测试、降低门禁、自动重跑掩盖 Flaky 或修改已发布迁移。
