# CR-T2G9R4-005：G9A-R4 关班后同步入口修复

## 1. 触发证据

- 候选提交：`be554b9a843f2bef21eacb6a98ef6ca9d1040304`
- GitHub Actions Run：`32886848376`
- 失败 Job：`formal-runtime`（`97931105591`）
- 稳定错误：`SHIFT_NOT_OPEN: 当前终端和员工没有唯一的进行中班次。`

## 2. 根因与产品影响

正式 `PosSyncCoordinator` 已装配在会话级业务运行时中，但此前唯一公开刷新入口属于销售工作区，执行同步后强制读取进行中班次。班次关闭后仍有关闭事实、审计和 Outbox 需要发送；把同步生命周期绑定到“必须存在进行中班次”会使关班事件无法通过正式运行时收敛。

## 3. 批准的最小修复

- `PosBusinessRuntime` 保留已经装配的正式 `PosSyncCoordinator`；
- `SessionBoundPosRuntime.synchronizeOnce()` 只委托既有协调器执行一次，不构造新命令、不改变协议和事实身份；
- G9A-R4 旅程在 ACK 丢失重启、成交和关班后通过该页面无关入口同步；
- 销售页面原 `refreshSyncStatus()` 行为不变，避免扩大本次整改范围。

该修复复用 `T2-SYN-001` 与 `T2-POS-005`，不新增业务能力、Requirement ID、服务端 API、数据库表或迁移。

## 4. 验收与证据边界

- Dart 格式、静态分析、会话运行时测试和正式旅程装载通过；
- 新提交从头执行完整 CI，且关班 Outbox 最终为 ACKED；
- 重启、重复和 ACK 丢失必须沿用原 event ID、payload hash 和幂等身份；
- 外部支付、真实设备/外设、伙伴现场、完整 Alpha 与生产执行继续为 0；
- `G9A-E2E-P1-001` 在最终报告获项目发起人确认前保持 `OPEN`。
