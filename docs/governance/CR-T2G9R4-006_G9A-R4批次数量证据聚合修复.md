# CR-T2G9R4-006：G9A-R4 批次数量证据聚合修复

## 1. 触发证据

- 候选提交：`3ca9930ddee120ae2ddfde5548481c276f32abfb`
- GitHub Actions Run：`32888065404`
- 失败 Job：`formal-runtime`（`97934078211`）
- 稳定错误：只读证据 SQL 查询 `local_order_lot_allocation.base_quantity` 时返回 `no such column`。

## 2. 根因

正式 SQLite 表按 `T2-LOT-001` 把冻结数量保存为 canonical decimal 文本字段 `quantity_decimal`，以避免浮点误差。G9A-R4 新增证据汇总误用了服务端语义名称 `base_quantity`，没有遵循实际 SQLite 契约。

## 3. 批准的最小修复

- 只读查询改为读取 `quantity_decimal`；
- 在 Dart 证据层以六位定点整数精确求和，再输出 canonical decimal；
- 增加 `0.1 + 0.2 + 1.000000 = 1.3`、空集合为 `0`、超精度失败关闭回归；
- 禁止 SQLite 隐式浮点聚合，也不修改表、迁移、批次分配或 FEFO 算法。

## 4. 验收边界

新提交必须从头执行全部 G9A-R4 门禁。`G9A-E2E-P1-001` 在正式栈、12 个故障 seed、安全和证据聚合全部通过且项目发起人确认前继续保持 `OPEN`；所有外部阻断和零执行边界不变。
