# CR-T2G9R4-009：G9A-R4 会员身份密钥运行时装配修复

## 1. 触发证据

- 候选提交：`cbb8c9989f41856f0855c5611171108ef8ec80db`
- GitHub Actions Run：`32890648094`
- 失败 Job：`formal-runtime`（`97942547887`）
- 稳定错误：`r4-community-member-create: HTTP=200, code=503, msg=MEM-CRYPTO-004: 会员身份密钥未由安全环境提供`。

该候选已完成三业态 Flutter 正式旅程并越过同步关班断言，证明 CR-T2G9R4-008 有效；失败发生于随后通过正式 API 执行 Member Owner 后置检查时。

## 2. 根因与安全影响

商业 JAR 正确使用 `RejectingMemberIdentityProtector` 在外部密钥缺失时失败关闭。G9A-R4 正式栈启动脚本已经临时生成数据包签名密钥，却没有为会员身份精确检索 HMAC 与 AES-GCM 信封加密注入本次运行专用密钥，导致 Member Owner 无法进入正式加密路径。

这不是允许默认密钥或降低安全配置的理由。固定测试密钥、仓库内明文、普通制品或日志泄露均不允许。

## 3. 批准的最小修复

- 在正式栈 Job 中使用 OpenSSL 为每个 Run 独立生成 32 字节 HMAC 检索密钥与 32 字节 AES-GCM 加密密钥；
- 立即通过 GitHub masking 隐藏两个值，仅导出到当前 Job/JAR 进程环境；
- 同一运行窗口内 JAR 重启继续使用同一临时密钥，以验证重启后既有密文仍可读取；
- Run 结束后由临时执行器销毁，不写入 Git、普通日志、数据库、Artifact 或静态默认配置；
- 保留生产缺密钥时 `MEM-CRYPTO-004` 失败关闭行为，不修改 Member 领域代码、API、数据库或迁移。

该修复复用 `T2-MEM-001`、`T2-SEC-002`、`T2-INT-001`，不新增业务能力或 Requirement ID。

## 4. 回归与证据边界

- G9A-R4 治理脚本强制检查两份临时外部密钥与版本已经注入；
- 新候选必须从头运行完整 CI，并通过 Member 创建、重启后查询与 Secret 扫描；
- 临时 CI 密钥不等于生产 KMS、密钥轮换或商业安全验收；
- 外部支付、真实设备/外设、伙伴现场、完整 Alpha 与生产执行继续为 0；
- `G9A-E2E-P1-001` 在完整门禁和项目发起人确认前保持 `OPEN`。
