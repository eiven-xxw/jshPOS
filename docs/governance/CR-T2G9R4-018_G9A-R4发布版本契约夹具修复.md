# CR-T2G9R4-018：G9A-R4 发布版本契约夹具修复

## 1. 触发证据

- 候选提交：`0a3baba6e4f791f195301c0ece0886fd9a2a5d6d`
- GitHub Actions Run：`32913581542`
- 失败 Job：`formal-runtime`（`98013212392`）
- 失败位置：`r4-community-release-create`
- 服务端结果：HTTP `200`、业务码 `400`、`UPG-COMP-004: 发布版本格式无效`

该候选已经通过治理双平台、Server、Web、Flutter 双平台和 Android/Database 门禁，
并越过此前 Reporting 小数摘要失败点。失败发生在 G9A-R4 后置旅程调用正式 Release
Owner API 创建合成发布物时。

## 2. 已确认根因

Release Owner 已接受契约要求版本匹配
`^[0-9]+(?:\.[0-9]+){0,3}(?:[-+][A-Za-z0-9.-]+)?$`。G9A-R4 编排器却生成
`R4-community`，后续故障夹具还潜伏着 `R4-IDEMP-*`，两者均未以数字版本段开头。
服务端按既有规则失败关闭是正确行为，缺陷只位于内部合成旅程夹具。

## 3. 最小修复

1. 先增加可执行失败回归，证明当前夹具没有符合 Release Owner 契约的稳定版本生成器；
2. 统一生成 `0.0.0-r4.<purpose>.<journey>` 形式的确定性合成版本；
3. 正式后置旅程和固定故障 seed 共用该生成器，保证重复/恢复时复用原版本身份；
4. 不修改 Release Java 状态机、API、OpenAPI、事件、数据表、已发布迁移或发布事实；
5. 不重跑失败 Job，提交新 commit 后从头运行完整 G9A-R4 CI。
