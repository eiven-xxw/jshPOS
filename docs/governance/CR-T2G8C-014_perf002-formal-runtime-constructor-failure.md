# CR-T2G8C-014：PERF-002 正式运行栈构造注入失败

## 事实

修复提交 `ef7bd619175dafce88f370e2721501938a9b160f` 的 GitHub Run `32702135141` 中，Owner/MySQL 容量已通过首次失败位置。正式 JAR 启动时，Spring 无法实例化 `RuoYiServiceAttachmentStorageAdapter`：该类同时具有配置字符串构造器与包级测试构造器，但未显式标记容器应使用的构造器，因而错误寻找不存在的无参构造器。

## 根因与处置

这是 T2-SEC-002 流式附件适配器的正式运行时装配缺陷。仅给配置构造器增加显式 `@Autowired`，并增加“恰好一个 Spring 注入构造器”的回归测试。附件大小、流式缓冲、摘要、临时清理、对象存储失败关闭和 Owner 契约不变。

## 边界

- Run `32702135141` 及其失败 Artifact 保留，不重跑失败 Job；
- 生产运行时只改变一处依赖注入元数据，不新增业务能力，不改变 API、资金、库存、租户或历史事实；
- 数据库迁移、依赖和既定性能阈值变化均为 0；
- 修复提交必须从治理起执行新的完整工作流；`T2-RDY-001` 继续 `DRAFT`。
