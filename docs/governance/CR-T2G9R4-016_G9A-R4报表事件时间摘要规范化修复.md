# CR-T2G9R4-016：G9A-R4 报表事件时间摘要规范化修复

## 1. 触发证据

- 候选提交：`745342e4a9d5cde806c5a34bd48237fd8956398a`
- GitHub Actions Run：`32911764475`
- 失败 Job：`formal-runtime`（`98007864310`）
- 原始失败：社区超市旅程向 Reporting Owner 提交库存/成本来源事件时，服务端以
  `RPT-G5D-055` 拒绝内容摘要；同一 Run 的治理双平台、Server、Web、Flutter
  双平台和 Android/MySQL 8.4 均已通过。

## 2. 根因

G9A-R4 Python 编排器使用微秒精度 ISO-8601 文本参与来源事件 SHA-256。Java
`Instant` 会对同一时刻的尾随零进行规范化，个别微秒值因此在反序列化后形成不同文本，
使测试编排器摘要与 Reporting Owner 的权威 canonical 摘要不一致。该问题位于内部 E2E
夹具，不是 Reporting 领域算法、API 或持久化语义缺陷。

## 3. 最小修复

1. G9A-R4 来源事件统一使用无小数的 UTC 秒级 ISO-8601 文本，保证 Python 与 Java
   `Instant` 无损往返；
2. 在 G9A-R4 范围检查中固定该规范化约束；
3. 不修改 Reporting Java、事件 Schema、金额/库存/成本事实、API 或数据库迁移；
4. 不重跑失败 Job，提交新 commit 后从头运行完整 G9A-R4 CI。

## 4. 状态与边界

- `G9A-E2E-P1-001`：继续 `OPEN`，等待完整 CI 与项目发起人最终确认；
- 外部 PAY/HWD/PRN/PAR、UAT/REL、LIC/JSH 和零执行边界保持不变；
- 本修复不形成 SANDBOX、REAL_DEVICE、FULL_ALPHA、PRODUCTION 或商业证据。
