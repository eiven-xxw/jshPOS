# CR-T2G7B-009：商业 V1 换货编排准入

- 状态：`PROPOSED_CONDITIONAL_GO_AWAITING_SPONSOR`
- Requirement：`T2-EXG-001`
- 基线：`a9e368a2f09dcfb4565f4bc392e4f77d5c664805`
- 日期：2026-08-22
- 证据等级：`STATIC_DESIGN_AND_REPOSITORY_AUDIT`

## 1. 决策请求

批准在 Gate 7B 第二批正式开发中，以“原单退货退款 + 新销售 + 只追加换货关联”
实现基础换货；不批准新建独立资金、库存、价格、促销、订单或退款算法。确认前
`T2-EXG-001` 保持 `DRAFT`，本 CR 不授权运行时代码或数据库迁移。

## 2. 业务价值与适用范围

- 便利店：减少先退货、再重新扫码、人工解释差额的操作时间与差错。
- 零食折扣店：保留原促销退款恢复与新交易当前促销快照，避免差额口径争议。
- 社区超市：支持计量商品的原单数量上限校验，但不新增批次成本或复杂 WMS。
- 财务与客服：以一个关联 ID 查询退货、退款、新销售、支付和库存各自权威事实。

商业 V1 仅支持同租户、同门店的原单换货；原订单可属于历史业务日，新销售使用
当前业务日与当前冻结报价。V1 不支持无原单换货、跨门店换货、跨币种净额结算、
以新商品直接覆盖旧订单行或批次/序列号换货。

## 3. 方案比较

| 方案 | 优点 | 主要风险 | 决策 |
| --- | --- | --- | --- |
| A. 继续由操作员分别退货和销售 | 无新增开发 | 无换货关联、恢复困难、审计和客服体验差 | 不推荐 |
| B. 新建独立换货资金/库存状态机 | 表面流程集中 | 复制 Owner 规则，易双退、双扣和库存不一致 | 拒绝 |
| C. 可恢复 Saga + 两条权威业务腿 + 只追加关联 | 复用已接受能力，事实边界清晰，可追踪恢复 | 需要显式处理中间态和人工修复 | 推荐 |

## 4. 影响分析

### 4.1 需求和架构

- 复用 `T2-REF-002` 的原单退货退款编排、`T2-POS-006/ORD-003` 的新销售，
  以及 Inventory、Promotion、Payment 各 Owner 的正式端口。
- ReturnOrchestration Owner 新增换货 Saga 与关联事实；每个 Owner 仍只写自己的表。
- `T2-PAY-004` 是差额组合支付的后续依赖，不是现金边界换货的前置依赖；
  电子差额继续受 `T2-PAY-002` 阻断。

### 4.2 数据和兼容

- 计划新增 `ret_exchange`、`ret_exchange_leg`、`ret_exchange_event` 及 POS 本地恢复投影，
  均必须使用新版本前向迁移，不修改已发布迁移。
- 旧客户端不显示换货入口；旧退货、新销售、现金支付路径继续工作。
- 换货事实不物理删除；停用功能只能关闭新入口，并观察既有 Saga 收敛。

### 4.3 资金、数量与促销

- 退货数量/退款上限沿用原订单及原成交优惠快照；新销售按当前冻结报价独立成交。
- `展示差额 = 新销售应收 - 已确认原单退款金额`，只作操作提示，禁止用它替代两条资金事实。
- 任一资金状态为 `UNKNOWN` 时，只能查询或观察原命令；禁止创建替代退款或扣款。

### 4.4 安全、权限与运维

- `tenant_id`、门店、终端、员工和业务日来自可信上下文；请求体不得成为授权依据。
- 建议权限：`pos:exchange:preview/create/approve/read/recover`；恢复需受权、原因和完整审计。
- 部分成功不能靠删除事实回滚；进入 `MANUAL_RECOVERY_REQUIRED`，以原命令身份恢复。

### 4.5 成本、排期与风险

- 预计为一个独立串行开发包：设计准入复核、MySQL/SQLite 前向迁移、服务端 Saga、
  Flutter 页面、故障注入与全量回归。
- P0 风险：重复退款、成功退货后新销售命令丢失、跨租户关联、按新促销重算退款。
- P1 风险：历史业务日展示、失败恢复操作复杂、旧客户端兼容与容量告警。

## 5. Go / No-Go

`CONDITIONAL GO` 建议必须同时满足：

1. 项目发起人明确接受本 CR；
2. ADR-044 转为 `Accepted`，`T2-EXG-001` 才可由 `DRAFT` 进入准入检查；
3. 状态机、Owner、API/事件、迁移、权限、审计、故障向量全部冻结；
4. 禁止引入独立资金/库存算法、分布式事务、自动重试 `UNKNOWN` 或外部 Provider 调用；
5. `T2-EXG-001` 独立 `VERIFIED` 后，才允许准入 `T2-PAY-004`。

任一条件不满足均为 `NO-GO`。本 CR 不改变 `T2-PAY-002`、真实设备、真实外设、
设计伙伴、完整 Alpha、生产与商业验收状态。
