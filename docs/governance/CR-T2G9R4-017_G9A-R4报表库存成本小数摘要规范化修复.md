# CR-T2G9R4-017：G9A-R4 报表库存成本小数摘要规范化修复

## 1. 触发证据

- 候选提交：`ba471019c5865d7ada5cd625763cb99092a9944c`
- GitHub Actions Run：`32912736282`
- 失败 Job：`formal-runtime`（`98010592331`）
- Artifact：`t2-g9a-r4-formal-runtime`（`9587183817`），SHA-256
  `cb756aebdf09dae0b0af0c2b0324a55d0fdc700dbbf17d7e80d15b9ffb8ad65a`

## 2. 已确认根因

Artifact 内的 `server.log` 证明社区超市第一条库存报表来源事件把 12 个
库存/成本字段以字符串 `"0"` 发送并按该文本计算 SHA-256。Reporting Owner 按已接受
规则先把每项规范为 `DECIMAL(25,6)`，权威 canonical 因而使用 `0.000000`，随后正确以
`RPT-G5D-055` 失败关闭。该差异属于 G9A-R4 测试编排器，没有改变业务事实。

## 3. 最小修复

1. 编排器对库存/成本字段执行与服务端一致的 `DECIMAL(25,6)` 精度和 scale 校验；
2. 同一份六位小数文本同时用于 JSON 载荷和 SHA-256 canonical；
3. 增加 `"0" -> "0.000000"` 可执行范围回归；
4. 不修改 Reporting Java、OpenAPI/事件 Schema、金额/库存/成本事实或数据库迁移；
5. 不重跑失败 Job，新提交从头运行完整 G9A-R4 CI。
