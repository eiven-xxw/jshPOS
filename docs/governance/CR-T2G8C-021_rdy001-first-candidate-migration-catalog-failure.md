# CR-T2G8C-021：RDY001 首轮候选全 Owner 迁移目录失配

## 结论

候选提交 `932a56e0f05271713be2978e70d9f0beea412ab9` 的 GitHub Actions Run
`32712716043` 保留为失败证据。治理双平台、Web 与 Flutter 双平台已通过；
`mysql-operations` 在 MySQL 8.4.11 空库成功应用 71 项可见迁移后，由
`ReleaseMigrationMySqlIT` 的旧固定目录断言 `expected: 56 / actual: 71` 失败。

## 根因

发布验收仍使用 Gate 7B 时期的模块依赖闭包和 V56 固定目录。后续已接受 Owner 的
V57—V86 前向迁移没有被统一纳入这一发布级测试，因此合法演进首先表现为旧数量断言失败，
而不是迁移 SQL 或 Flyway 执行失败。

## 最小修复

1. 仅在发布验收测试中从仓库 21 个正式 Owner 版本迁移目录及 1 个集成回调目录聚合资源；
2. 固定当前 86 项版本、最高版本 V202608240086 和 287 张正式业务表元数据；
3. 工作流输出同步登记 `migrationCount=86` 与最高版本；
4. 不修改任何已发布迁移、生产代码、运行时依赖、业务事实或质量阈值；
5. 不重跑失败 Job，修复提交必须从头执行完整工作流。

## 状态与边界

T2-RDY-001 继续为 `VERIFIED` 候选。该失败不改变 T2-LIC-001、PAY/HWD/PRN/PAR、
UAT/REL 或零外部执行边界，也不形成 Alpha、生产或商业结论。
