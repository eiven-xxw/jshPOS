## 2. 已验证能力

- Catalog Owner 独占只追加批次/效期策略版本；只有可信 Foundation 行业读端口
  确认当前门店绑定已发布 `COMMUNITY_SUPERMARKET` 模板时才允许启用。
- Inventory Owner 独占批次身份、命令、只追加数量流水、可重建余额、FEFO 分配、
  临期投影、审计、Outbox 和独立批次数据包；没有引入批次成本或第二套库存算法。
- 采购收货建批、销售 FEFO、原单退货归原批、采购退货、盘点和调拨均经既有
  Owner 的具名端口提交；批次数量合计与基础库存流水按同一来源事件守恒。
- FEFO 稳定排序冻结为 `expiry_date, received_date, lot_id`；数量使用
  `DECIMAL(19,6)/BigDecimal`，批次临期阈值、到期日和策略版本在建批时冻结。
- 过期、余额不足、未知批次、重复同键异内容、跨租户/仓库/批次和来源摘要漂移
  均失败关闭；投影可从只追加流水重建，历史事实不可覆盖。
- Foundation 行业模板切换引入批次事实守卫；门店存在任何批次事实后，切回
  无批次业态必须拒绝，防止退货和账本路径分叉。
- MySQL V68—V70 只前进迁移建立批次策略、十张 Inventory 表、租户复合约束、
  不可变触发器、索引、中文 COMMENT 和细粒度权限；复杂 SQL 位于 Mapper XML。
- SQLite v15 保存签名包槽、策略、批次余额/流水/分配与成交快照；包的摘要、
  Ed25519 签名、租户/门店/时区/模板/单调版本均校验，旧包和损坏包拒收。
- Flutter POS 在同一 SQLite 事务中冻结 FEFO 分配、批次快照、订单、现金、
  批次流水和 Outbox；任一写入失败整体回滚，重启后复用原幂等键。
- Vue 批次效期页只调用正式 API，支持策略发布、批次查询、到期/临期查询，
  不在前端重算库存、效期或 FEFO。

   `Flyway validate` 和 MySQL 不可变约束验证。修复后从新提交启动完整 Run，
   未重跑单个失败 Job，未跳过测试或降低门禁。
