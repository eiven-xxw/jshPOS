# T2-LOT-001 设计准入与验收冻结

## 1. 范围与证据等级

- Requirement：`T2-LOT-001`
- 状态：`VERIFIED / AWAITING SPONSOR CONFIRMATION`
- 适用模板：仅 `COMMUNITY_SUPERMARKET`；其他两业态服务端、包和 POS 三层关闭。
- 证据等级：`INTERNAL_SOFTWARE_EXECUTION / SYNTHETIC_DATA`。
- 非目标：批次成本、库位、波次、越库、加工、序列号、冷链、质检、召回、自动报损、复杂 WMS。

## 2. 数据主权与事实模型

Catalog Owner 写商品批次策略版本；Foundation 只读端口提供可信门店行业模板绑定。
Inventory Owner 写批次身份、命令、只追加流水、余额投影、分配、临期投影、审计和
Outbox。Procurement、Order、Returns、Stocktake、Transfer 只能通过版本化正式端口提交
已经持久化并验证的来源事实；不得跨 Owner Mapper 或直接更新批次余额。

| 表 | Owner | 访问策略 | SQL 模式 | 不变量 |
| --- | --- | --- | --- | --- |
| `cat_lot_policy_version` | Catalog | APPEND_ONLY | XML | 发布版本不可修改，只有社区超市可启用 |
| `inv_lot_identity` | Inventory | APPEND_ONLY | XML | 租户/仓/SKU/来源/批号/日期身份冻结 |
| `inv_lot_command` | Inventory | CONTROLLED_WRITE | XML | 原事件与摘要幂等，状态具名迁移 |
| `inv_lot_ledger` | Inventory | APPEND_ONLY | XML | 数量流水只追加、精确六位、来源可追溯 |
| `inv_lot_balance` | Inventory | READ_PROJECTION | XML | 可从流水重建，不是唯一事实来源 |
| `inv_lot_allocation` | Inventory | APPEND_ONLY | XML | FEFO/退货分配冻结且金额成本无关 |
| `inv_lot_expiry_projection` | Inventory | READ_PROJECTION | XML | 由批次余额和策略版本重建 |
| `inv_lot_audit_event` | Inventory | APPEND_ONLY | XML | 权限、拒绝与修复全记录 |
| `inv_lot_outbox` | Inventory | CONTROLLED_WRITE | XML | 载荷不可变，投递状态受控 |

## 3. 状态、排序与日期规则

策略版本只保存不可变的 `PUBLISHED` 事实；停用通过发布 `enabled=false` 的新版本表达，
不原地修改旧版本；商业 V1 一旦存在批次身份或可退历史事实即禁止停用，避免切回无批次
路径造成账实分叉，需通过商品退市或后续受控迁移 CR 处理。批次状态由投影计算为
`AVAILABLE/NEAR_EXPIRY/EXPIRED/DEPLETED/BLOCKED`，客户端不得自报。FEFO 稳定顺序为
`expiry_date ASC, received_date ASC, lot_id ASC`；无生产日期允许，但到期日必须能由
冻结策略或可信收货事实唯一确定。日期使用门店 IANA 时区和业务日，按自然日计算，
覆盖闰年、跨月与夏令时边界；临期包含阈值日，过期批次禁止销售。

## 4. 数量、事务、幂等与恢复

数量统一 `DECIMAL(19,6)/BigDecimal`，禁止浮点数。入库、销售、退货、盘点和调拨
分别追加具名流水；批次行合计必须与同来源基础库存效果守恒。命令使用来源 event ID
和内容 SHA-256；重复同摘要返回原结果，同键异内容拒绝。批次流水、余额投影、分配、
审计与 Outbox 在 Inventory 单库事务内提交，失败整体回滚。跨 Owner 使用可恢复事件，
UNKNOWN 只能观察原命令，不得重新生成销售或库存命令。

## 5. API、事件、权限与离线

OpenAPI 不接收 tenant_id、行业、过期状态或成本。发布策略要求租户管理员与门店范围；
批次查询与预警按仓库/门店范围；重建和受控调整使用独立权限并完整审计。事件使用
`catalog.lot-policy.published.v1`、`inventory.lot.received.v1`、
`inventory.lot.allocated.v1`、`inventory.lot.returned.v1`、
`inventory.lot.transfer-received.v1`、`inventory.lot.rebuilt.v1` 与
`inventory.lot.package-published.v1`。临期状态是可重建投影，不发布虚构的独立事实事件。

门店一旦存在任意批次身份或可退历史事实，Foundation 激活新的行业模板前必须调用
Inventory 只读守卫；从 `COMMUNITY_SUPERMARKET` 切换到非批次业态必须失败关闭。社区
超市模板版本升级可以继续，但已建立批次冻结的策略版本、临期阈值和到期日不得改写。

SQLite v15 只前进迁移保存签名包槽、策略、批次余额、成交分配快照与本地只追加事件。
包必须绑定可信 tenant/store、模板、版本和 SHA-256；旧包、损坏包、跨租户包、未知
批次、过期、余额不足和摘要漂移失败关闭。成交时批次快照与订单、现金事实和 Outbox
在同一事务提交，重启复用原快照。

## 6. 容量、兼容与回退

- 单命令最多 500 行、单行最多 100 个批次分配；包最多 100000 个可售批次投影。
- 旧客户端遇到启用批次策略的 SKU 必须拒售并提示升级，不能退化为无批次销售。
- 新客户端在非社区超市模板或策略关闭时走既有无批次路径。
- MySQL V68—V70、SQLite v15 只前进；投影可丢弃重建，历史事实不可修改。

## 7. 量化验收

固定故障向量不少于 48 个，覆盖三业态关闭、FEFO、过期禁售、临期、采购/销售/退货、
盘点/调拨、重复乱序晚到、同键异内容、跨租户、旧包损坏包、离线重启、迁移中断和
前向修复。Java 与 Dart 对日期状态、FEFO 顺序和六位数量金标逐字段一致。完整 CI 必须
覆盖治理、Server、Web、Flutter Linux/Windows、MySQL、SQLite、Android/Kotlin、租户
权限、Secret/PII、依赖、SBOM、许可证、覆盖率和既有 Gate 回归。
