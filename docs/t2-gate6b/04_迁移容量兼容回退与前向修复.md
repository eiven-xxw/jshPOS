# Gate 6B 迁移、容量、兼容、回退与前向修复

## 1. Flyway

- V40 新建 `upg_release/upg_target_scope/upg_rollout/upg_terminal_task/upg_command_result/upg_release_event/upg_audit`。
- V41 新建冻结身份、合法状态和只追加触发器及权限菜单。
- 全部是新表/新菜单，不修改 V1—V39；失败采用 V42+ 前向修复，禁止修改已发布脚本。
- 空库、从全历史升级、二次执行 0、Flyway validate、触发器和中文 COMMENT 元数据进入 MySQL 8.4 CI。

## 2. 容量

| 对象 | Alpha 候选内部基线 | 索引/清理 |
|---|---:|---|
| 单发布门店范围 | ≤10,000 | tenant+aggregate+store 唯一 |
| 单批次终端任务 | ≤100,000 合成 | tenant+rollout+state+updated_at |
| 命令结果/事件/审计 | 只追加 | tenant+aggregate+occurred_at；后续分区需独立 ADR |
| 合成对象校验 | ≤64 MiB 内存夹具 | 生产大对象改流式校验，当前不得据此承诺 APK 上限 |

## 3. 兼容

- 兼容窗口同时包含 app、protocol、Schema、system 及可选 capability SHA。
- 服务端必须兼容当前和上一受支持 POS 主版本；破坏性字段变更先扩展、双读写、迁移，再在后续版本收缩。
- 系统版本目前未进入 Gate 6A 注册表，默认真实适配器返回空并失败关闭；HWD 解阻后通过前向迁移或厂商可信适配器补齐。

## 4. 回退与前向修复

- Server/Web/APK：只有旧版本仍在兼容窗口、旧制品摘要/签名有效、Schema 未越过不可逆边界时才可创建显式回退发布；禁止修改原任务结果。
- MySQL/SQLite Schema：只允许安全前向修复；应用回退必须继续兼容新 Schema。
- Template/Data package：使用既有双槽/原子指针；损坏包不切换，保留上一有效槽。
- 灰度健康失败立即暂停扩散，记录失败种子和证据；人工恢复必须使用新幂等命令和审计原因。
