# Gate 4C / Sprint S7 范围、非目标与逐项准入

## 1. 正式准入

| Requirement | 正式能力 | 准入结果 |
|---|---|---|
| `T2-CST-001` | 不可变成本流水、仓级移动加权平均、出库快照、原成本退货、负库存差异和可重建投影 | READY → IN_PROGRESS |

准入已经覆盖数据主权、输入事实、状态与顺序、不变量、权限、审计、API、事件、Flyway、容量、回退、固定向量和 CI。实现只能位于 `jshpos-costing` 以及库存/采购 Owner 的最小内部端口适配。

## 2. 仅设计准备

`T2-TRF-001` 只冻结申请、审批、发出、在途、收货、差异、取消、幂等和成本继承契约；`x-runtime-allowed=false`，不创建调拨表、服务、Controller、任务或库存移动。

## 3. 非目标

支付 Provider 网络、生产密钥、真实资金、未脱敏数据、应付、发票、总账、税务会计、供应商返利、运费分摊运行时、批次/FIFO、生产加工成本、调拨、促销和后续 Gate 均不在本 Sprint。`T2-PAY-002` 继续 `BLOCKED`；`SANDBOX/REAL_DEVICE/PILOT` 证据均为 0。

## 4. 准入门禁

- 基线 tag 与 Gate 4B 最终提交必须是分支祖先。
- `T2-INV-003`、`T2-PUR-001` 必须为 `ACCEPTED`；`T2-CST-001` 只可为 `IN_PROGRESS/VERIFIED`；`T2-TRF-001` 必须保持 `DRAFT`。
- 成本端口不得接收 tenant_id、客户端单位成本或资金状态；可信租户、门店范围和操作者必须由服务端上下文提供。
- 所有成本 SQL 显式使用 tenant_id、显式列、稳定锁顺序和禁止 `SELECT *`；复杂 SQL 必须位于 Mapper XML。
- CI 不得包含 `continue-on-error`、自动 retry、测试跳过、阈值降低或外部证据绿色占位。
