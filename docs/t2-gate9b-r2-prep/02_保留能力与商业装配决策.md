# 保留能力与商业装配决策

## 推荐边界

| 能力 | 商业默认装配 | 源码处置 | 重新启用条件 |
|---|---|---|---|
| `ruoyi-demo` | 完全移除 | 活动源码删除，Git 基线可恢复 | 不建议重新启用 |
| `ruoyi-generator` | JAR/Web/菜单/SBOM 均排除 | 服务端源码可留在默认 reactor 外 | 独立 CR、安全评审、专用研发环境 |
| `ruoyi-workflow` | JAR/Web/菜单/SBOM 均排除 | 服务端源码可留在默认 reactor 外 | 新 Requirement ID，证明不复制 Owner 状态机 |
| `ruoyi-job` | JAR/菜单/SBOM 均排除 | 服务端源码可留在默认 reactor 外 | 新 Requirement ID，删除模拟账单执行器并重做安全评审 |
| 纯测试夹具 | 不进制品 | `src/test` 保留 | 继续受测试范围和 Secret 门禁约束 |

商业装配是默认且唯一可发布路径。开发源码“仍在仓库”不等于可以被默认 reactor、
Spring 扫描、Vite glob、初始化脚本、容器镜像、SBOM 或发布清单发现。

## 禁止的折中

- 只删除菜单但保留 Controller；
- 只从 `ruoyi-admin` 删除依赖但仍让根 reactor/SBOM 聚合模块；
- 依赖前端隐藏或权限按钮掩盖后端端点；
- 以 `enabled=false` 代替移除演示模块；
- 把 generator/workflow/job 宣称为商业 V1 已交付能力；
- 删除测试夹具来伪造生产目录无 demo 文本。

## 决策状态

以上是 ADR-070 的 `Proposed` 建议。项目发起人确认正式整改前，不执行任何 POM、源码、
页面、配置或 SQL 变更。
