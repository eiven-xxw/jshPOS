# 生产装配与演示面基线审计

## 结论

`G9A-ASM-P1-001` 已由静态扫描和本地正式构建确认，不是误报。当前商业构建不能仅靠
菜单权限隔离演示能力，因为服务端依赖、Spring 路由、Web 懒加载块、初始化数据和 SBOM
都已经包含相关实现。

## 服务端装配

| 检查面 | 当前事实 | 风险 |
|---|---:|---|
| `ruoyi-admin` 直接依赖 | demo/job/generator/workflow 共 4 个 | 全部进入启动类路径 |
| `ruoyi-demo` | 19 Controller、44 Java、6 资源文件 | 暴露缓存、锁、队列、邮件、短信、Excel、加密等示例入口 |
| Springdoc | `org.dromara.demo` 单独分组 | 演示接口被主动发布到文档 |
| WarmFlow | enabled=true、ui=true | 未准入平台能力默认开启 |
| 当前 JAR | 含 4 个对应嵌套 JAR | 隐藏菜单仍不能移除路由 |
| 22 Owner 引用 | 对 generator/workflow/job 为 0 | 排除不会切断已接受 Owner 依赖 |

`ruoyi-job` 还包含支付宝与微信固定金额模拟账单执行器。它们未进行网络调用，但名称、
执行器注册和固定资金样例不应进入商业运行时，也不能被解释为 T2-PAY-002 的任何证据。

## Web 与路由

- `admin-web/src/views/demo` 有 2 个页面，`admin-web/src/api/demo` 有 4 个 API 文件；
- `import.meta.glob('./../../views/**/*.vue')` 会发现所有页面，而不是只构建服务端返回的菜单；
- 当前生产 dist 至少 3 个 JS 文件含 `/demo/demo`、`/demo/tree` 或演示权限信号；
- 代码生成有 5 个页面，工作流有 12 个页面，同样位于商业视图扫描范围。

因此正式整改必须以编译产物为准，不能只检查 `router/index.ts` 是否有静态路由。

## 初始化与供应链

MySQL、Oracle、PostgreSQL、SQL Server 四份初始化脚本每份均包含：

- 13 条演示菜单/权限记录（父菜单加 12 项页面/按钮）；
- 24 条演示角色菜单绑定；
- `test_demo`、`test_tree` 两张测试表及样例数据。

当前聚合 CycloneDX SBOM 有 435 个组件，并明确包含 demo、job、generator、workflow。
根聚合 BOM 以默认 reactor 为输入，仅从 `ruoyi-admin` 删除依赖仍不足以让 SBOM 收敛；
必须同步调整默认 reactor 或改为对商业装配图生成权威 SBOM。

## 不属于本缺陷的同名内容

- `src/test` 下 `DemoUnitTest` 是测试夹具，不进入 JAR，不按名字删除；
- SaaS 内部合成旅程中的“虚构演示商户”不是 RuoYi demo 模块，由 G9A-R3 页面证据复核；
- CSS 类名含 `demo`、上传组件示例属性等非运行时能力不计入本缺陷。
