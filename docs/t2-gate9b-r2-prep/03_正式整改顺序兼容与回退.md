# 正式整改顺序、兼容与回退

## 串行实施顺序

1. 先增加失败回归，固定当前 JAR、Web、SQL、SBOM 中的演示信号和正式 300 API/22 Owner；
2. 将 ADR-070 更新为 Accepted，冻结默认商业 profile 与非 V1 模块清单；
3. 从 `ruoyi-admin`、默认 reactor、dependencyManagement 和 flatten 产物移除 `ruoyi-demo`，
   同步移除 Springdoc 演示分组；
4. 删除演示 Web 页面/API，并让生产构建不再发现 generator/workflow 页面；
5. 将 generator/workflow/job 排除于商业 JAR、Web、菜单和 SBOM，WarmFlow 默认关闭；
6. 同步清理四方言新装初始化源中的菜单、角色绑定、测试表与样例数据；
7. 对已初始化环境提供带签名预检、稳定摘要和审计的前向清理方案，不改已发布迁移；
8. 重新构建 JAR/Web/SBOM，执行启动、API、租户、安全和既有 Gate 全量回归。

前一项未验证，后一项不得开始。任何正式 API、Owner、权限或业务旅程减少都必须 NO-GO，
不能以“清理演示”作为删除正式能力的理由。

## 兼容策略

- 对外当前 OpenAPI 仍保持 300 项，不把 demo/generator/workflow/job 计入正式 API；
- 已接受 Owner 不依赖四个被排除模块，运行时依赖图应只减少非 V1 边；
- 新装数据库不再生成演示菜单/表；既有环境清理只匹配冻结 ID、权限串和内容摘要，
  发现客户自定义或摘要漂移必须停止并进入人工评审；
- 不修改任何已发布 MySQL/SQLite Flyway 文件，只允许新的前向处理和安全检查。

## 回退

- 代码与制品：回退到完整、已验签的上一内部候选，不进行单文件回拷；
- 配置：恢复上一版本配置清单，但禁止重新开启 demo 或未准入平台端点；
- 数据库：清理演示菜单/表属于前向处置，不通过重新插入演示数据回退。若预检失败则不执行；
- 业务事实：本批不得触碰资金、库存、订单、租户和审计事实，无业务数据回滚路径；
- 发现正式 300 API、22 Owner、启动或供应链门禁回归失败时整体 NO-GO。
