# 发布物清单、签名与供应链设计

## 发布物

同一 GitHub Run 生成服务端 JAR、Web 确定性压缩包、明确标记非生产的 Debug APK、部署配置包、Server/Flutter SBOM、Web 许可证清单、迁移和运维证据、发布说明。每项都保存稳定 artifact ID、路径、类型、大小、SHA-256、commit、Run 和 `productionEligible=false`。

## 清单与签名

构建器先生成 canonical manifest 和 release BOM，再由 CI 内临时 Ed25519 密钥签署。私钥只存在于临时文件并在上传前删除；公钥、签名和独立验签结果进入 Artifact。扫描到任何私钥 PEM 标记必须失败。

该签名仅证明内部候选清单在同一 Run 内未被替换，不等于 Android APK 生产签名、代码签名、KMS 或商业授权。APK 保持 Debug 身份并显式禁止生产。

## 供应链

- Server：聚合 CycloneDX JSON/XML、精确许可证策略、漏洞扫描；
- Flutter：锁文件、CycloneDX、许可证文本摘要、禁止强 Copyleft；
- Web：冻结锁文件、许可证清单、审计结果和锁文件摘要；
- Release BOM：引用全部组件清单和发布物摘要，不复制或覆盖上游结论；
- T2-LIC-001 的 Aviator、simple-http、MySQL Connector/J 继续 OPEN 0/3，商业决策固定 NO-GO。
