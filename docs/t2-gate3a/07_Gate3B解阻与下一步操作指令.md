# Gate 3B 解阻与下一步操作指令

> 文档编号：JSH-POS-T2-G3A-NEXT-007
> 日期：2026-08-16
> 当前状态：`PREPARED / NOT ADMITTED`

## 1. 推荐路线

Gate 3A 通过后，推荐采用双轨但不混合准入：

1. **外部轨：Gate 3B-Prep。** 保持 `T2-PAY-002=BLOCKED`，只收集并核验一家首接 Provider 的授权沙箱、产品/接入模式、测试终端、正式文档、回调网络、账单样例和技术联系人；未经独立解阻评审不得网络调用。
2. **内部轨：Gate 4A。** Gate 4 直接依赖已接受的 Gate 2，可先逐项准入 `T2-INV-001`、`T2-INV-002`、`T2-INV-004`，建立不可变库存流水、销售出入库和版本化库存策略。`T2-INV-003`、`T2-PUR-001`、`T2-CST-001`、`T2-TRF-001` 只允许契约准备。

这样可以继续内部开发，又不会用 Fake 冒充支付沙箱。两条轨道必须使用独立 Requirement 状态、CI 证据和周门禁报告。

## 2. Gate 3B 独立解阻包

至少提供：

- 唯一首接 Provider、具体产品、主扫/被扫/聚合码/银行卡等准入子集；
- 授权非生产商户、门店、终端标识及有效期，凭据只进入 Secret Store；
- 官方接口目录和版本：下单、查询、关闭/撤销、回调、退款、退款查询、账单、错误码、限流；
- 签名/验签、证书、nonce、时间窗、重放、TLS/mTLS、IP 白名单与时钟要求；
- 独立 HTTPS 回调域名、证书、网关/WAF、超时、请求体大小和 Provider 重试规则；
- 成功、失败、处理中、超时未知、重复乱序回调、全/部分退款、退款未知、账单的触发方法；
- 沙箱/脱敏账单样例与字段字典；
- Provider 技术联系人、工单渠道、响应 SLA，以及商务/财务负责人。

缺任一关键项时只允许标记 `BLOCKED_WITH_PROGRESS`，不得改为 `READY`。
