# T2 Gate 2 范围、决策与逐项准入

## 1. 范围结论

Gate 2 / Sprint S2 形成便利店主样板的本地现金交易闭环，零食折扣店和社区超市只作为合成数据配置差异，不复制交易状态机。准入范围为开班、购物篮、现金成交、挂单/取单、交班、本地订单快照、幂等 Outbox 和正式 SQLite 模型。

明确非目标：第三方支付、支付沙箱、退款/退货、库存命令、采购、成本、促销、会员、真实打印/开钱箱、正式 Push/Pull/Ack、服务端 Sync Inbox、主数据增量安装、生产密钥、真实数据和试点。

## 2. 冻结决策

| 决策 | 本 Gate 结论 |
|---|---|
| DEC-01 首批聚合 | `Shift`、`Basket/SalesOrder`、`CashPayment`、`CashLedger`、`PrintJob`、`LocalOutbox`、`LocalIdempotency` |
| DEC-02 标识 | 离线新建的订单、班次、支付、事件使用跨端 ULID；Gate 0 门店等平台 `BIGINT` ID 在 JSON 中使用十进制字符串；租户仍为可信上下文 `VARCHAR(20)` |
| DEC-03 业务日 | 开班时按门店时区计算并冻结 `business_date`；跨午夜不自动换日；时区配置变化只影响新班次 |
| DEC-04 售后 | S2 不实现任何退货退款；后续只允许先准入原单售后 |
| DEC-05 高风险阈值 | 交班差异阈值来自版本化配置；超阈值必须主管批准且批准人与收银员不同；无服务端批准能力时保持 `APPROVAL_REQUIRED` |
| DEC-11 本地模型 | 新建正式 `local_*` Schema，不复制、不引用、不迁移 T1 `syn_*` 表 |

## 3. 逐项准入

| Requirement ID | 数据主权 | 状态/不变量 | 权限/审计 | API/事件 | 迁移/容量/回退 | 测试准入 | 结论 |
|---|---|---|---|---|---|---|---|
| T2-POS-001 | Shift | 每终端/员工最多一个 OPEN；业务日冻结 | `pos:shift:open`；开班审计 | `shift.opened.v1` | SQLite/服务端均有唯一约束；失败全回滚 | 重复、跨租户、跨午夜 | READY |
| T2-POS-002 | POS Basket；提交后 Order 接管 | 数量精确、行金额确定；只修改 DRAFT | `pos:basket:operate` | 本地命令模型；不产生云端调用 | 草稿前向迁移；恢复不改变成交事实 | 数量边界、金额篡改、重启 | READY |
| T2-POS-003 | Order 的现金事实与 Shift 现金流水各自唯一写入 | 应收=实交-找零；现金 Payment 直接 SUCCEEDED | `pos:cash:collect`；金额审计 | `cash.received.v1`、`order.completed.v1` | 与订单/Outbox 同事务 | 原子失败点、重复命令、找零边界 | READY |
| T2-POS-004 | DRAFT Order | `ACTIVE↔SUSPENDED`；成交订单不可挂取 | `pos:order:suspend` | `order.suspended.v1`/`resumed.v1` 仅本地 Outbox | 乐观版本；冲突不覆盖 | 重复挂取、终端/门店范围 | READY |
| T2-POS-005 | Shift | `OPEN→CLOSING→CLOSED`；理论现金可由流水重算 | `pos:shift:close`；差异审批审计 | `shift.closed.v1` | 关闭与汇总/Outbox 原子；禁止删除流水 | 差异阈值、并发关闭、重算 | READY |
| T2-ORD-001 | SalesOrder | DRAFT 提交冻结快照；金额守恒；成交事实不可覆盖 | `pos:order:submit` | `order.submitted.v1`、`order.completed.v1` | 服务端 Flyway + SQLite；仅前向修复 | 状态矩阵、属性测试、历史快照 | READY |
| T2-ORD-002 | Order command + Outbox | 相同键/摘要返回原结果；同键异摘要拒绝 | 与订单命令相同并记录 actor | REST 命令和同事务 Outbox | 唯一键、条件更新、无第二业务效果 | 并发/重复/进程终止 | READY |
| T2-OFF-001 | POS Local Store | 订单、现金、班次流水、打印任务、Outbox、幂等同事务 | 设备会话冻结租户/门店/终端 | 只落本地事件；不传输 | WAL、FK、FULL/NORMAL 策略、quick_check、前向迁移 | 写点故障、磁盘异常、kill/reopen | READY；物理断电仍 BLOCKED |

上述 `READY` 是设计准入结论；只有机器校验确认全部文档与契约完整后，RTM 才更新为 `IN_PROGRESS` 并进入实现。

## 4. T2-SYN-001 设计准入但不实现

- 允许：信封字段、payload hash、ACK 结果、重复/乱序/缺口/冲突矩阵、固定 seed、SENDING 恢复与运行手册。
- 禁止：HTTP/WebSocket 客户端、定时同步 Worker、Push/Pull/Ack 调用、服务端 Sync Inbox/游标表、网络重试运行时、用 T1 Fake 作为正式实现。
- RTM 状态保持 `DRAFT`，证据等级只到 `STATIC/UNIT-CONTRACT`，不得改为 `VERIFIED`。

## 5. 外部阻断

`T2-HWD-001`、`T2-PAY-002`、`T2-PAR-001` 保持 `BLOCKED`；`T2-JSH-001`、`T2-LIC-001` 保持 `DEFERRED`。真实扫码、打印、钱箱、客显、物理断电、支付沙箱和试点均不以本 Gate 内部证据关闭。
