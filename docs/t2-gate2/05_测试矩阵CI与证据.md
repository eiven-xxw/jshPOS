# Gate 2 测试矩阵、CI 与证据

## 1. 测试矩阵

| 层级 | 必测内容 | 量化门槛 |
|---|---|---|
| Dart 单元 | 精确数量、金额舍入、ULID、业务日、状态机、幂等 hash | 全部状态/金额不变量用例化；0 skipped |
| SQLite 集成 | V1/重复迁移、FK/唯一/CHECK、WAL、quick_check、原子成交、挂取/交班 | 每个写点故障；事务部分事实 0；0 skipped |
| Flutter | 开班→购物篮→现金→挂取→交班应用服务，不接设备/网络 | Linux/Windows 干净执行器；format/analyze/test/build APK |
| Java 单元/属性 | 订单、现金、班次状态与幂等 | 新核心行≥90%、分支≥85%；状态/资金不变量 100% 用例化 |
| Flutter/SQLite 单元与故障 | 本地事务、挂取单、审批、SQLITE_FULL | Gate 2 核心行覆盖率≥90%；失败事务零部分事实 |
| MySQL 集成 | Gate 0—2 六版 Flyway、重复 migrate、租户复合约束、Outbox 同事务 | MySQL 8.4；0 failure/skipped |
| 契约 | Flutter/Java 状态、错误码、字段、Schema、请求 hash 向量 | 同一 golden vector 字节/摘要一致 |
| 租户/权限 | 两租户、多门店、Mapper/SQL/API/本地绑定/导出缺省关闭 | 越权成功数 0 |
| 故障 | 重复提交、磁盘失败、进程终止、跨午夜、金额篡改 | 固定 seed 可复现；无静默丢失 |
| 安全/供应链 | Secret、依赖、SBOM、许可证、IaC、网络入口扫描 | HIGH/CRITICAL 0；未批准许可证 0；Sync 网络运行时 0 |

真实扫码、打印、钱箱、客显、物理断电、支付沙箱和 PILOT 明确不在绿色门禁中。

## 2. 合成场景

- `TENANT_A`：便利店，上海时区，门店 A1/A2，终端 A-T1/A-T2；
- `TENANT_B`：零食折扣/社区超市组合，北京时区，门店 B1/B2，终端 B-T1；
- 员工包含收银员、主管、财务，审批人与被审批人必须不同；
- Linux 与 Windows 独立进程终止夹具分别验证 `COMMIT` 前回滚和 `COMMIT` 后持久；该证据等级为 `INTEGRATION`，不替代实机物理断电。
- 服务端与 Flutter 分别生成 CycloneDX/依赖许可证清单；HIGH/CRITICAL 依赖、Secret、IaC 和强 copyleft 策略失败即阻断。
- 数据只使用虚构 SKU、商品名、条码、金额和 ULID；禁止任何真实商户或个人数据。

固定向量覆盖：前导零条码、多单位 0.125/1.000000、半分舍入、0 元与最大安全金额边界、现金不足、找零、重复命令同/异 hash、跨租户订单 ID、跨午夜、差异阈值边界。

## 3. CI Job

| Job | 内容 | 制品 |
|---|---|---|
| governance | 基线祖先、RTM、ADR、准入、禁入范围、迁移 checksum、JSON Schema/OpenAPI | governance JSON、dependency diff |
| server | RuoYi reactor、Order 模块测试与 JaCoCo | JUnit、JaCoCo、JAR、SBOM |
| mysql-migration | MySQL 8.4 六版迁移、repeat/validate、租户/事务约束 | JUnit XML |
| pos-linux | analyze、SQLite 故障、覆盖率、kill/reopen、Kotlin、Android debug APK、SBOM/许可证 | machine test、coverage、APK、SBOM、licenses |
| pos-windows | Windows 干净执行器 analyze、SQLite 测试与 kill/reopen | machine test、进程终止摘要 |
| tenant-security | 本地/服务端租户、可信操作者、主管审批与 Mapper 攻击矩阵 | JUnit、attack JSON |
| admin-web | audit、build、lint、typecheck、Gate 1 回归与许可证 | JUnit、dist、licenses |
| security-sbom-license | HIGH/CRITICAL、Secret、IaC、服务端/Flutter SBOM 与许可证 | 安全摘要/SBOM |
| evidence | 校验所有上游制品、测试、覆盖率、状态和 SHA-256 | Gate 2 evidence bundle |

禁止 `continue-on-error`、自动 retry、测试跳过、覆盖率降低或绿色占位。Flaky 必须登记固定 seed 和根因。

## 4. 退出标准

- 八项准入需求均达到 `VERIFIED`，但在项目发起人确认前不改为 `ACCEPTED`；
- `T2-SYN-001` 继续 `DRAFT` 且正式网络运行时为 0；
- Gate 0/1 需求继续 `ACCEPTED`；外部 `BLOCKED/DEFERRED` 不变化；
- GitHub 全部 Gate 2 Job 在同一候选 SHA 上通过并形成证据包；
- P0/P1 开放缺陷为 0；P2 有 Owner、截止点和回退；
- 不宣称 Alpha、可试点或可商用。

## 5. 证据等级与限制

本 Sprint 最高证据等级为 `UNIT+INTEGRATION+MYSQL+SQLITE+ANDROID_BUILD`。Android APK 编译不等于 `REAL_DEVICE`；桌面 kill/reopen 不等于物理断电；本地 Outbox 不等于服务器已同步；现金闭环不等于第三方支付完成。
