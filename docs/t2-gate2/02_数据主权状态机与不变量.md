# Gate 2 数据主权、状态机与不变量

## 1. 唯一数据主权

| 事实 | Owner | 只读消费者 | 禁止写入方 |
|---|---|---|---|
| 门店时区、终端授权、员工范围 | Foundation | POS/Order | 客户端参数 |
| 商品、条码、单位、价格版本 | Catalog | POS/Order 快照 | Basket/Order |
| 活动班次与交班结果 | Shift | Order、报表 | Payment/设备 |
| 订单、行和成交快照 | Order | Cash、后续库存/报表 | Catalog/设备/同步 |
| 现金支付事实 | Gate 2 Cash 子域 | Order 摘要、Shift | 后续渠道支付 |
| 现金流水 | Shift | 财务汇总 | Order 直接覆盖 |
| 本地幂等与 Outbox | POS Local Store | 后续 Sync Worker | UI/网络层 |

客户端不得提交 `tenant_id` 作为授权依据。本地数据库在激活时只绑定一个可信租户/门店/终端，仓储层每次事务都交叉校验该绑定；服务端租户只来自 `TrustedTenantContext`。

## 2. 状态机

### 2.1 班次

```text
不存在 --OpenShift--> OPEN --BeginClose--> CLOSING --ConfirmClose--> CLOSED
                              CLOSING --AbortClose--> OPEN
```

- 同一租户、门店、终端、收银员只允许一个 `OPEN/CLOSING` 班次。
- 开班冻结门店时区、业务日、期初备用金、操作者和配置版本。
- 关闭冻结理论现金、实盘现金、差异、批准人和原因；`CLOSED` 不可重开。
- 理论现金=`opening_cash_minor + Σ cash_ledger.signed_amount_minor`，汇总必须可从不可变流水重算。

### 2.2 购物篮与订单

主状态遵循详细设计 32：

```text
DRAFT --Submit--> PENDING_PAYMENT --RecordCashSucceeded--> CONFIRMED --CreateRequiredTasks--> COMPLETED
DRAFT --Cancel--> CANCELLED
```

挂单是 DRAFT 的正交 `draft_disposition=ACTIVE|SUSPENDED`，不新增与文档 32 冲突的订单主状态。只有 `DRAFT/ACTIVE` 可编辑；`DRAFT/SUSPENDED` 只允许授权取单或取消。

现金结算在同一个 SQLite 事务内依次记录提交、现金成功、确认和必要任务创建，状态历史保留全部迁移；最终对 UI 原子可见为 `COMPLETED`。任何数据库写入失败均不留下中间可见事实。

### 2.3 现金事实

现金 Payment 只允许：

```text
不存在 --RecordCashPayment--> SUCCEEDED
```

S2 不实现撤销或退款。重复相同命令返回原成功结果；不得创建第二 Payment 或第二现金流水。

## 3. 冻结点

订单 Submit 时冻结：SKU/SPU/条码、商品名、单位、精确数量、目录与价格版本、单价、原价、行总额、应收、币种、门店、终端、班次、员工、业务日、门店时区、行业模板版本和 Schema 版本。

冻结后 Catalog 的商品改名、停售或价格变化不得修改历史订单。S2 不准入促销和税计算，`discount_amount_minor=0`、`surcharge_amount_minor=0`、`tax_amount_minor=0`，这些字段仍保留以维持契约兼容。

## 4. 金额与数量不变量

对每一行：

```text
line_gross_minor = exactRound(unit_price_decimal × quantity_decimal)
line_payable_minor = line_gross_minor - line_discount_minor + line_surcharge_minor
```

对订单：

```text
gross_minor = Σ line_gross_minor
receivable_minor = gross_minor - discount_minor + surcharge_minor
discount_minor = 0, surcharge_minor = 0（S2）
receivable_minor >= 0
currency = CNY
```

现金：

```text
tendered_minor >= receivable_minor
change_minor = tendered_minor - receivable_minor
cash_net_minor = tendered_minor - change_minor = receivable_minor
```

所有最终金额使用 64 位整数。Dart/Java 不使用 `double/float`；数量用最多 6 位小数的规范字符串/`BigDecimal`，本地计算转为缩放整数后进行乘除和明确的 `HALF_UP` 舍入。

## 5. 幂等与并发

- `command_id`、`idempotency_key`、事件 ID 使用 ULID；相同业务意图必须复用。
- 本地唯一键为 `(tenant_id, command_type, idempotency_key)`；保存规范化请求 SHA-256 与完整结果摘要。
- 同键同摘要返回原 `order_id/payment_id/outbox_event_id`；同键异摘要返回 `IDEMPOTENCY_KEY_REUSED` 并记录安全审计。
- 订单/班次更新带 `record_version`；影响行数为 0 时重新读取并返回 `VERSION_CONFLICT` 或原结果，禁止最后写入者获胜。
- 进程终止后只从已提交事务恢复；不得凭 UI 状态猜测交易结果。
- 超阈值差异审批必须绑定 `shift_id + theoretical_cash_minor + actual_cash_minor + difference_minor + expected_shift_version`；主管可信认证证明只保存不含凭据的引用，收银员不得自批，任一金额或版本变化均须重新审批。

## 6. 业务日边界

- 业务日由开班时的门店时区与营业日切换配置计算，并随班次冻结。
- 跨午夜仍归属原班次业务日；新班次使用当时有效配置。
- 运行中修改门店时区或切日点不改写已有班次与订单。
- 终端本地时间仅作为 `occurred_at`，同时保存 `clock_offset_estimate`；服务端接收时间由后续同步阶段补充。
