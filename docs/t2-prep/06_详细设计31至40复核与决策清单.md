# 详细设计 31—40 复核与编码前决策清单

## 1. 复核结论

详细设计 31—40 已覆盖商业 Alpha 所需的领域模型、状态机、库存、促销、离线、设备、连接器、开放平台、安全与验收框架，可以作为 T2 需求权威。T2-Prep 不改写这些权威文档，只将强制不变量映射到原子需求并标记仍需业务确认或外部证据的项。

复核结果为：`10/10 已评审；0 个权威文档缺失；12 个编码前决策项；外部 BLOCKED/DEFERRED 不变`。

## 2. 文档 31：领域模型与数据库

### 强制继承

- RuoYi 平台主键 `BIGINT`，离线可创建业务实体使用 ULID；业务 `tenant_id VARCHAR(20)`；
- UTC 时刻与门店业务日期分离，金额使用最小货币单位整数，中间价格/成本/税率用 `DECIMAL/BigDecimal`；
- 聚合内本地事务，跨聚合 Outbox/Inbox；事实、账本和审计不得物理删除；
- 订单、支付、库存、促销、同步各有唯一数据 Owner；
- Flyway 只前进，Expand/Migrate/Contract，多版本兼容窗口和前向修复。

### T2 映射

`T2-IAM-001`、`T2-ORG-001`、`T2-PRD-*`、`T2-ORD-*`、`T2-PAY-*`、`T2-INV-*`、`T2-MIG-001`。

### 编码前缺口

- `DEC-01`：冻结商业 V1 首批表/聚合与模块前缀，禁止直接照抄示例 DDL；
- `DEC-02`：冻结 ULID 二进制/字符存储、排序和跨端生成测试向量；
- `DEC-03`：明确门店业务日跨午夜、时区变更和交班归属口径。

## 3. 文档 32：订单、支付与退款状态机

### 强制继承

- 订单、支付摘要、退款摘要正交，禁止万能状态；
- 提交点冻结商品、价格、促销、税和收银上下文快照；
- 支付尝试与支付聚合分离；`UNKNOWN` 只能查询、回调或对账收敛，禁止自动二次扣款；
- 回调和查询以业务优先级合并，幂等结果持久化；
- 退款额度、退货数量、原优惠分摊和支付通道可退额度分别校验；
- 资金事实只前进，异常通过冲正/补偿和审计修复。

### T2 映射

`T2-ORD-001/002`、`T2-PAY-001..005`、`T2-REF-001`、`T2-UAT-001`。

### 编码前缺口

- `DEC-04`：T2 是否只准入原单退货，建议无原单退款和换货后置；
- `DEC-05`：现金差异、改价和退款的角色/金额阈值；
- `EXT-PAY`：主支付沙箱、终端和文档未提供，电子支付实现保持 `BLOCKED`。

## 4. 文档 33：库存、预占与成本

### 强制继承

- 库存以不可变流水为权威，余额可重算；维度键必须包含租户/组织/仓店/SKU 及启用的批次等维度；
- 在手、预占、可用和在途口径分离；流水与余额原子更新；
- 幂等来源单据和行号唯一，重复消费不得产生第二条业务效果；
- 负库存是版本化策略，不得靠数据库允许负数隐式实现；
- 移动加权成本采用 DECIMAL，销售出库沿用出库时成本快照，调整用新流水；
- 盘点差异经审批后生成调整流水，不覆盖历史。

### T2 映射

`T2-INV-001..004`、`T2-PUR-001`、`T2-CST-001`、`T2-TRF-001`。

### 编码前缺口

- `DEC-06`：便利店默认负库存策略与离线售卖风险限额；
- `DEC-07`：T2 是否实现预占；建议 POS 现货销售不预占，外部订单预占后置，仍保留契约；
- `DEC-08`：批次/效期只作为社区超市条件能力，不进入便利店主闭环。

## 5. 文档 34：促销与优惠分摊

### 强制继承

- 规则输入、候选、互斥、叠加、执行顺序和舍入必须确定；
- 总优惠与行分摊金额严格守恒，余数使用稳定顺序分配；
- 成交订单保存规则版本、命中解释和行级分摊；
- 退款按成交快照和已退额度还原，禁止用当前促销重算；
- POS/服务端使用同一测试向量，规则发布版本化并可回滚。

### T2 映射

`T2-PRM-001..003`、`T2-ORD-001`、`T2-REF-001`。

### 编码前缺口

- `DEC-09`：T2 冻结为手工改价、整单折扣、抹零；单品/组合/券规则不在首波；
- `DEC-10`：统一余数分摊稳定排序键，建议 `order_line_no + sku_id`。

## 6. 文档 35：POS 离线同步

### 强制继承

- 本地交易事实、支付意图和 Outbox 同一 SQLite 事务；
- ULID、事件 ID、幂等键、设备序列和游标分别承担不同职责；
- Inbox/Outbox 至少一次投递、幂等消费，允许重复、乱序、ACK 丢失和重启；
- 数据包先验签/摘要/租户/版本校验，再原子切换；
- 冲突按数据所有权解决，服务器事实不能被客户端最后写入覆盖；
- 客户端/Schema 有明确兼容窗口，失败使用应用回退和数据前向修复。

### T2 映射

`T2-OFF-001`、`T2-SYN-001`、`T2-DPK-001`、`T2-UPG-001`。

### 编码前缺口

- `DEC-11`：冻结 POS 本地正式表与服务端命令/事件版本；不得复用 T1 `syn_*` 表；
- 物理断电、真实闪存和厂商进程策略仍为 `REAL_DEVICE BLOCKED`。

## 7. 文档 36：Android 设备与认证

### 强制继承

- Flutter UI/业务层只依赖统一设备契约，Kotlin 插件承接厂商 SDK；
- 能力探测、错误码、超时、取消、恢复和诊断必须标准化；
- L0 模拟、L1 实验室、L2 认证、L3 灰度、L4 商业白名单证据不可跨级替代；
- 打印队列与业务成功分离，重复打印有副本标识和审计；
- 认证覆盖打印、扫码、秤、钱箱、客显、升级、长稳和 RMA。

### T2 映射

`T2-TRM-001`、`T2-PRN-001`、`T2-HWD-001`、`T2-UPG-001`。

### 外部阻断

主机厂商/型号/SDK、两条打印链路、扫码、电子秤、钱箱和客显仍未落实。T2 只能先实现厂商无关契约；实机验收继续 `BLOCKED`。

## 8. 文档 37：连接器 SDK 与标准契约

### 强制继承

- 连接器 Manifest、能力协商、标准对象、映射、幂等、重试、死信、限流、监控和审计统一；
- 渠道扩展字段不得污染核心对象；核心系统不得按鲸熵汇/渠道写特殊分支；
- 数据主权、版本和回放边界明确；沙箱/生产配置严格隔离。

### T2 映射

T2 只保留连接器 Runtime/契约准入，不猜测鲸熵汇：`T2-JSH-001 DEFERRED`。真实最小闭环待收银主体和外部资料齐备后单独准入。

## 9. 文档 38：开放平台 API 与 Webhook

### 强制继承

- OpenAPI 优先，版本、认证、授权、幂等、分页、错误和限流一致；
- Webhook 签名、时间窗、防重放、重试、禁用、回放和审计完整；
- OAuth/客户端凭据和租户授权范围分离；密钥只进入 Secret 管理。

### T2 处理

完整开放平台不进入 T2 Alpha；内部 API/事件仍采用相同版本、幂等和错误规范。后续外部 API 必须新建独立 RTM 需求，不以内部 Controller 直接暴露。

## 10. 文档 39：安全、隐私、等保与灾备

### 强制继承

- 可信租户上下文、服务端授权、最小权限、职责分离和高风险动作复核；
- Secret/密钥轮换、TLS、存储加密、展示脱敏和诊断包最小化；
- POS 本地敏感数据、日志、备份和远程支持均有保留/销毁边界；
- SAST/SCA/SBOM/Secret/IaC/镜像和渗透门禁；
- 备份恢复验证、RPO/RTO、同区高可用、灾难恢复顺序和事件响应。

### T2 映射

`T2-SEC-001`、`T2-OBS-001`、`T2-BAK-001`、`T2-REL-001`。

### 编码前缺口

- `DEC-12`：Alpha 环境 RPO/RTO 建议值和恢复演练频率；正式 SLA 在 T3/T5 再批准；
- 等保定级、测评和隐私影响评估不以 T2 内部扫描替代。

## 11. 文档 40：商业 V1 验收

### 强制继承

- RTM 100% 追踪、P0/P1 缺陷门槛、职责分离和证据保留；
- 租户、资金、库存、促销、离线、硬件、安全、性能、迁移和灾备均有独立验收域；
- 商业退出必须包含真实支付、实机、72 小时长稳、门店影子运行/试营业和 Go/No-Go 联合签署。

### T2 Alpha 裁剪

T2 只执行实验室 Alpha 子集：核心闭环、状态机/不变量、合成容量、故障恢复、租户攻击、迁移和安全基线。`REAL_DEVICE/SANDBOX/PILOT/商业验收` 不得因 Alpha 通过而变绿。
