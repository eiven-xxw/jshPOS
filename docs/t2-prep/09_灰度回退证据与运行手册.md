# T2 灰度、回退、证据与运行手册

## 1. 目标

T2 Alpha 仍是实验室阶段，但所有实现必须从第一天具备可部署、可观察、可停止、可前向修复和可追溯证据。不能把回退推迟到试点前补做。

## 2. 发布单元

| 单元 | 版本标识 | 独立回退 | 数据兼容要求 |
|---|---|---|---|
| Server | Git SHA + SemVer + Flyway version | 回退应用镜像 | 新旧应用跨一个 Schema 窗口 |
| Admin Web | Git SHA + 静态资源摘要 | 切换前一制品 | API 向后兼容 |
| Flutter POS | versionName/versionCode + Git SHA | 回退兼容 APK | SQLite 已提交迁移必须前向兼容 |
| 设备插件 | plugin/vendor/SDK/firmware 版本 | 按白名单回退 | 能力协商而非假定存在 |
| 配置/行业模板 | template version | 激活前一版本 | 不修改历史订单/规则快照 |
| 数据包 | tenant/store/version/digest | 原子指针切回兼容包 | 禁止旧包覆盖新事实 |

## 3. 灰度阶梯

T2 Alpha 只执行前三级：

1. CI 合成环境；
2. DEV-INTEGRATION 双虚构租户；
3. DEVICE-LAB/支付 SANDBOX（解阻后）；
4. STAGING 影子数据；
5. PILOT 单店影子运行；
6. 受控门店切换；
7. 商业分批发布。

每一级必须有观察窗口、错误预算、人工停止开关和回退 Owner。低级通过不能跳过更高级。

## 4. 回退触发

- 租户越权、资金重复/丢失、库存不可重算、优惠不守恒：立即停止并 `NO-GO`；
- Schema 迁移失败、App 健康失败、同步积压无法收敛：停止流量/升级并执行兼容应用回退或前向修复；
- 支付 UNKNOWN 比例、回调积压、对账差异超过批准阈值：停止新电子支付，不自动重扣；
- POS 崩溃、打印/设备故障超过错误预算：回退 APK/插件或降级到批准能力；
- 安全 HIGH/CRITICAL、Secret 泄漏或依赖来源异常：撤销制品并轮换凭据。

## 5. 数据修复

- 禁止直接 UPDATE/DELETE 抹去订单、支付、退款、库存、积分事实；
- 修复使用幂等命令、冲正流水或前向迁移；
- 修复前生成影响范围、租户/门店、原值摘要、预期不变量和回滚不可行说明；
- 执行由业务 Owner、SRE/DBA、QA 会签，完成后自动对账并保留审计。

## 6. 最小 Runbook

每个模块必须提供：

1. 服务/版本/依赖和 Owner；
2. 健康指标、仪表盘和告警阈值；
3. 常见失败定位顺序；
4. 停止、隔离、降级、回退和前向修复步骤；
5. 数据一致性检查和对账命令；
6. Secret/PII 安全注意事项；
7. 证据收集和事件升级联系人；
8. 恢复完成判据和复盘模板。

## 7. 证据包

每个 Gate/Sprint 证据包含：

- baseline/tag/commit/branch、工具链和环境；
- Requirement ID→实现→测试→制品的 RTM 快照；
- 原始测试、覆盖率、迁移、性能、安全、SBOM 和许可证结果；
- 固定 seed、故障脚本和失败总账；
- APK/JAR/Web/Schema/镜像摘要；
- 已验证、未验证、证据等级和限制；
- 风险、缺陷、Owner、截止日和 Go/No-Go 签署。

制品至少保留 90 天；试点/商业证据按文档 39/40 和合同要求执行。报告不得只链接会过期的 CI，关键摘要需回填仓库治理文档。

## 8. T2-Prep 重现

本地执行：

```powershell
python scripts/check_t0_structure.py
python scripts/check_rtm.py
python scripts/check_contracts.py
python scripts/check_t1_prep.py
python scripts/check_t1_week4.py
python scripts/check_t2_prep.py
git diff --check
```

当前阶段不得执行 tag 命令。CI 全绿后，由评审报告记录候选 tag、目标 SHA 和制品摘要，等待项目发起人确认。
