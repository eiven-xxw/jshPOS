# 三类业态边界与商业 V1 冻结清单

## 1. 主样板决策

便利店是商业 V1 主样板；零食折扣店和社区超市是兼容性对照样板。三类业态共用同一租户、商品、订单、支付、库存和促销内核，差异通过版本化模板与能力开关实现。

## 2. 共同核心

| 能力 | 共同口径 |
|---|---|
| 组织 | 1—30 店，租户→组织→门店→终端；可信上下文注入 `tenant_id` |
| 商品 | SKU、条码、多单位、启停、门店范围、基础导入 |
| 价格 | 基础价/门店价、版本发布、改价权限和成交快照 |
| 交易 | 开班、销售、现金/主支付、原单退款、交班、小票 |
| 离线 | 本地事实+意图+Outbox 同事务，幂等同步和恢复 |
| 库存 | 不可变流水、销售出库、采购收货、盘点、基础成本 |
| 促销 | 高频确定性规则、金额守恒、退款按成交快照还原 |
| 管理 | 员工权限、配置、审计、基础报表、监控和备份 |

## 3. 差异矩阵

| 维度 | 便利店（主样板） | 零食折扣店（对照） | 社区超市（条件对照） |
|---|---|---|---|
| 商品结构 | 标准条码、单件/整箱 | 高 SKU、快速建档、件/包/箱 | 标准条码+称重商品+短保属性 |
| 价格 | 基础价、门店价 | 高频调价、价签、折扣模板 | 门店价、称重计价、可选批次价 |
| 收银 | 扫码为主 | 高吞吐扫码、整箱换算 | 扫码+秤码/电子秤（实机阻断） |
| 库存 | 单位库存、基础盘点 | 多单位换算、快速盘点 | 可选批次/效期、称重数量精度 |
| 促销 | 改价、整单折扣、抹零 | 单品/整单折扣模板（T2 后波次） | 基础促销；生鲜复杂规则后置 |
| 采购 | 供应商、采购、收货 | 高频补货但智能补货后置 | 采购、收货、短保提示后续增强 |
| 硬件 | 扫码、打印、钱箱、客显 | 同便利店，可增强标签打印 | 增加电子秤；未认证前不能承诺 |

## 4. 行业模板治理

模板对象包含 `template_code`、`template_version`、适用范围、默认参数、能力开关、迁移说明和 Owner。模板只允许配置：

- 商品必填属性、单位/条码规则和导入模板；
- 价格/促销默认策略；
- 负库存、改价、退款、现金差异等审批阈值；
- 设备能力要求和报表默认视图；
- 开班/交班、采购/盘点的步骤开关。

模板禁止定义独立订单状态、支付状态、库存流水类型、金额算法或租户隔离规则。需要新增核心语义时必须新建 Requirement ID 和 ADR。

## 5. 商业 V1 冻结清单

### 必须交付

1. 标准 SaaS 开户、套餐授权、员工权限、配置模板、门店克隆、终端管理；
2. 商品、条码、单位、价格、导入与发布；
3. Flutter Android POS、开班、销售、现金、一个主支付、退款、交班、小票、离线同步；
4. 采购、入库、库存流水、盘点和基础移动加权成本；
5. 基础连锁下发、高频促销、会员档案；
6. 销售、收银、库存和支付对账报表；
7. 审计、风控事件、监控、备份、灰度、诊断、工单和实施工具；
8. 鲸熵汇订单/库存/退款/对账最小闭环；
9. 商业订阅、到期提醒、客户健康度和基础服务成本归集。

### T2 Alpha 允许简化

- 仅便利店标准模板进入主闭环；另两模板验证数据结构和配置兼容，不承诺实店可用；
- 先形成现金实验室闭环；主支付必须在沙箱解阻后完成 Alpha 电子支付闭环；
- 会员以档案和识别为主，等级/积分按独立波次准入；
- 促销只做手工改价、整单折扣、抹零及守恒分摊；
- 轻连锁只做总部模板、商品/价格下发和基础调拨；
- 鲸熵汇在资料提供前继续 `DEFERRED`。

### 明确后置

完整 WMS、储值、复杂券、CDP、自助收银、AI、Windows 正式版、私有化、多外卖/即时零售渠道、联营代销、复杂财务和大型集团能力。

## 6. 冻结后的变更门槛

新增能力须同时回答：谁付费、合同价值、复用率、交付工时、质量风险、替代方案、是否影响三类业态共核。缺少任一项不得进入商业 V1。
