# T2 环境、数据库迁移、测试与 CI 门禁

## 1. 环境分层

| 环境 | 数据 | 外部连接 | 用途 | 禁止 |
|---|---|---|---|---|
| LOCAL | 合成 | Fake | 单元、契约、开发 | 真实凭据/商户数据 |
| CI | 固定合成 seed | 禁止出站业务调用 | 构建、测试、安全、证据 | 沙箱/生产 Secret |
| DEV-INTEGRATION | 合成/授权脱敏 | Fake；白名单沙箱按需 | 跨模块集成 | 真实资金 |
| SANDBOX | 合作方测试数据 | 仅授权支付/连接器 | 外部联调 | 生产密钥/真实交易 |
| DEVICE-LAB | 合成 | 白名单测试服务 | Android/外设/断电/升级 | 未登记设备 |
| STAGING | 合成+批准脱敏迁移样本 | 生产等价但测试终端 | T3/T4 前验证 | 未脱敏数据 |
| PILOT/PROD | 后续独立授权 | 生产 | 不属于 T2-Prep | 当前阶段禁止 |

环境配置必须外置，Secret 由受控存储注入；测试代码不得通过默认值连接生产域名。

## 2. 迁移规范

### 服务端 Flyway

- 目录按业务模块管理，但版本在仓库级唯一且不可重写；
- 采用 Expand→双写/回填→读切换→Contract，破坏性 Contract 至少跨一个兼容窗口；
- 每个迁移记录预估行数、锁风险、索引方式、执行时长、监控和前向修复；
- 已发布迁移禁止删除/改 hash，失败优先前向修复；
- 所有业务表和关键索引包含租户/门店访问维度并有攻击测试。

### POS SQLite

- `PRAGMA user_version`/自有 schema version 与 App 兼容矩阵并存；
- 本地事实、支付意图和 Outbox 事务边界不可拆；
- 迁移前检查磁盘、备份/快照策略和待同步队列；
- 数据迁移提交后 App 健康失败只回退应用兼容版本，不逆向破坏已提交 Schema；
- 需要使用前向修复和幂等迁移，正式表不得使用 T1 `syn_*` 名称。

## 3. 测试矩阵

| 层级 | 最低范围 | 强制失败场景 |
|---|---|---|
| 单元/属性 | 金额、数量、状态机、分摊、成本 | 边界、舍入、非法迁移、重复命令 |
| 数据库集成 | Mapper、SQL、唯一约束、事务、Flyway | 并发、锁、回滚、跨租户、重复幂等键 |
| API/契约 | OpenAPI、事件、Schema、兼容 | 认证、授权、限流、旧客户端、未知字段 |
| POS 集成 | SQLite、Outbox/Inbox、数据包 | kill、ACK 丢失、乱序、损坏、磁盘不足 |
| E2E | 开班→销售→现金/支付→库存→交班→报表 | 部分失败、重试、退款、恢复、对账差异 |
| 安全 | SAST/SCA/Secret/IaC/租户攻击 | IDOR、SQL 越权、缓存/任务/导出/对象存储 |
| 性能 | 10k/100k 商品、交易峰值、同步积压 | 冷启动、弱机、长事务、回填和大导出 |
| 外部实证 | SANDBOX/REAL_DEVICE/PILOT | 只在资料解阻后执行，不得绿色占位 |

## 4. 覆盖与缺陷门槛

- 新/变更核心领域行覆盖率候选门槛 ≥90%，分支覆盖率 ≥85%；整体覆盖率只能持平或提升；
- 所有状态迁移、资金/库存/优惠不变量必须 100% 用例化，不以覆盖率百分比替代；
- P0/P1 未关闭为 `NO-GO`；P2 必须有 Owner、截止日和回退；
- Flaky 测试不得简单重跑变绿，必须隔离、登记根因并在约定时限修复；
- 固定 seed 失败必须进入总账；新随机测试必须输出可复现 seed。

## 5. T2 CI 质量门禁

| Job | 内容 | 阻断条件 | 制品 |
|---|---|---|---|
| governance | AGENTS、ADR、RTM、范围/链接/状态 | 唯一 ID、T1 状态、T2 边界或文档缺失 | governance JSON |
| boundary | 相对 `962c4ed…` 的目录差异 | 出现正式业务代码、迁移、PoC 改写或 tag | boundary JSON |
| contracts | OpenAPI/JSON Schema/事件兼容 | 破坏性变更或校验失败 | 契约报告 |
| server | Maven 格式/编译/单元/集成/Flyway | 任一失败、迁移 checksum 变化 | 测试、覆盖、迁移报告 |
| web | lockfile、lint、typecheck、test、build | 浮动依赖或失败 | Web 制品/许可证 |
| pos | format/analyze/test/build | 插件越层、SQLite 迁移或测试失败 | APK/测试/SBOM |
| security | 依赖差异、SBOM、许可证、Secret、IaC/镜像 | HIGH/CRITICAL 或未批准许可证 | SBOM/安全摘要 |
| evidence | 汇总 SHA-256、RTM、环境/等级 | 证据缺失、等级污染 | 阶段证据包 |

T2-Prep 当前只启用 governance、boundary、contracts 和 security/static；业务构建门禁沿用 T0 并在正式编码首波启用，不创建假绿色 Job。

## 6. 证据等级

`STATIC < UNIT < INTEGRATION < E2E < SANDBOX < REAL_DEVICE < PILOT < COMMERCIAL_ACCEPTANCE`。

高等级门禁只能由同等级或更高证据关闭。CI 成功不能替代外部沙箱、实机、物理断电或试点。

- `server/admin-web/pos-flutter/packages/pos_device_adapter/infra` 相对 Week 4 基线变化 0；
- Secret/PII/生产端点/真实凭据命中 0。
