# T2 迭代计划与 RACI

## 1. 计划假设

- 日历：7 个双周 Sprint，共 14 周；
- 团队：产品/领域 2、架构 1、后端 4—6、POS/设备 2—3、Web 2、QA 2—3、DevOps/安全 1—2；
- 每个 Sprint 只允许已批准 Gate 中的 `READY` 需求；
- 支付和实机工作受外部解阻约束，延迟时不得伪造通过或把风险塞入最后一个 Sprint。

## 2. 迭代路线

| Sprint | Gate/目标 | 候选交付 | 退出门槛 |
|---|---|---|---|
| S0（1—2周） | Gate 0 平台安全基座 | 租户/组织/门店、权限、配置、审计、基础迁移与两租户攻击测试 | P0 设计项清零；租户越权 0；迁移回退演练通过 |
| S1（3—4周） | Gate 1 商品价格 | SKU/条码/单位/导入、基础价/门店价、版本发布/数据包 | 数据质量、版本兼容、10k/100k 合成数据门禁通过 |
| S2（5—6周） | Gate 2 交易本地闭环 | 开班、购物篮、订单快照、现金、挂单、交班、SQLite 正式模型 | 订单/现金不变量和本地原子性通过 |
| S3（7—8周） | Gate 2/3 同步与支付 | Inbox/Outbox、恢复、小票契约；支付沙箱若解阻则进入主支付 | 重复/乱序/崩溃收敛；无沙箱则支付保持 BLOCKED |
| S4（9—10周） | Gate 3/4 售后和库存 | 原单退款、库存流水、销售出库、采购收货 | 退款额度和库存余额可重算；并发无双效果 |
| S5（11—12周） | Gate 4/5 成本促销会员报表 | 盘点、移动加权成本、基础促销、会员档案、基础报表 | 成本/优惠守恒、退款还原、报表对账通过 |
| S6（13—14周） | Alpha 集成退出 | 端到端、故障、安全、迁移、备份恢复、证据包 | 实验室 Alpha 门禁通过；外部项仍按证据等级独立判定 |

## 3. 每个 Sprint 固定节奏

1. Day -2：准入评审，RTM 从 `DRAFT` 转 `READY`；
2. Day 1：契约、迁移和测试先行；
3. Day 2—7：小批量实现，PR 不跨未经批准 Gate；
4. Day 8：集成、故障、租户和回退验证；
5. Day 9：安全/依赖/证据审计；
6. Day 10：演示、RTM 回填和 `GO/CONDITIONAL GO/NO-GO`；
7. 未达门槛的需求不自动滚为“完成”，保持真实状态并重排。

## 5. 职责分离

- 编码者不能独立接受自己的资金、库存、权限或迁移需求；
- 支付 Provider 实现与对账验收至少由两个角色复核；
- 生产/试点密钥操作与业务开发分离；
- 数据修复脚本由业务 Owner、DBA/SRE、QA 三方批准；
- AI 生成代码必须由人类 Owner 评审状态机、不变量、迁移和测试。

## 6. 容量与降范围规则

若稳定投入少于 10 人，优先保留 Gate 0—2、现金、库存基础和质量门禁，后置会员、促销增强、调拨和移动端；不得削减租户隔离、金额/库存不变量、离线恢复、安全或测试来赶日期。
