# Gate 1 数据主权、状态与不变量

## 1. 数据主权

| 聚合 | 权威事实 | 允许依赖 | 禁止写入 |
|---|---|---|---|
| Catalog | SPU、SKU、分类、品牌、单位、条码、销售属性 | Foundation 可信租户/审计 | 价格、订单、库存 |
| ProductImport | 源摘要、staging、错误、激活版本、幂等结果 | Catalog 命令端口 | 活动商品的直接覆盖 |
| Pricing | 价格簿、价格项、发布版本、有效区间 | Catalog SKU/单位只读引用 | 商品身份、订单成交价 |
| DataPackage | Manifest、内容摘要、签名元数据、可用状态 | Catalog/Pricing 发布快照 | POS 本地 active slot |

所有表包含 `tenant_id VARCHAR(20) NOT NULL`，唯一键和子表外键包含 tenant_id。可信值来自 `TrustedTenantContext`；请求、导入行、任务参数、缓存键、导出路径和包 Manifest 的 tenant 值只能做一致性校验，不能成为授权来源。

## 2. 状态机

- SPU/SKU：`DRAFT -> ACTIVE -> INACTIVE`，`INACTIVE -> ACTIVE` 必须递增 recordVersion 并审计；禁止物理删除；
- 分类/品牌/单位：`ACTIVE <-> INACTIVE`，被活动 SKU 引用时不得失效；
- 导入：`PRECHECKED -> PUBLISHED -> ROLLED_BACK`；校验错误直接形成 `REJECTED` 批次；发布通过 `cat_catalog_binding` 单行活动指针原子切换，不得形成半可见版本；
- 价格簿：`DRAFT -> PUBLISHED -> RETIRED`；PUBLISHED 内容不可改；未来生效由价格项有效区间表达；
- 数据包：生成、canonical 编码、摘要、签名和对象写入任一步失败均不落库；成功后一次登记为 `AVAILABLE`，内容、摘要和签名不可改。

## 3. 不变量

1. `(tenant_id, spu_code)`、`(tenant_id, sku_code)`、`(tenant_id, category_code)`、`(tenant_id, brand_code)` 和 `(tenant_id, unit_code)` 唯一；
2. `(tenant_id, barcode)` 唯一，条码为 1—64 位可打印 ASCII 字符且保留前导零；
3. 每个 SKU 恰有一个活动主单位，换算分子、分母均为正整数且最大公约数为 1；
4. 扩展属性 JSON 必须声明 schemaVersion（缺省归一为 `1.0`），最多 50 个键、单键最长 64 字符、canonical UTF-8 最大 16 KiB，并拒绝 password/secret/token 类凭据键；
5. 同一导入幂等键只能对应一个 source SHA-256；相同键/相同摘要返回原结果，不同摘要冲突；
6. 任何预检错误都使活动商品写入数为 0；staging 只有在完整校验和租户复核后才可激活；
7. 价格 amountMinor 非负、currency 只能为 CNY、effectiveUntil 必须晚于 effectiveFrom；
8. 单一价格簿内同 SKU/unit 的区间不得重叠；跨已发布版本按 `STORE > TENANT_BASE`、`version_no`、生效起点、priceItemId 的稳定顺序解析，使未来版本可在到点后覆盖且退役时安全回落；
9. 发布和包内容的 canonical SHA-256 可重复；失败发布不改变上一活动版本；
10. 包的 tenant、store、schema、version、content SHA-256、签名算法、key ID 和签名缺一不可；错租户、错门店、旧版本重放、损坏或不兼容一律拒绝。
11. 当前活动导入批次的 canonical 商品记录必须进入正式商品价格数据包；回退活动指针后，新数据包必须读取恢复后的批次。
12. 单店数据包版本从 1 开始严格递增 1，`previousVersion` 必须等于数据库当前最新版本；旧版重放或跳号在签名、对象写入之前拒绝。

## 4. 数据类型

- API 金额使用 64 位整数语义；Web 只展示格式化结果，不做最终结算计算；
- Java 数量和校验使用 `BigDecimal`，数据库数量为 `DECIMAL(19,6)`；单位换算使用 `BIGINT numerator/denominator`；
- 时间使用 UTC `DATETIME(6)` 和 ISO 8601；客户端时间不决定发布顺序；
- 状态为稳定字符串代码；一经发布不得重解释。
