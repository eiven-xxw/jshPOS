# 失败测试、影响分析与验收矩阵

## 先红后绿清单

准备阶段冻结 12 个失败 seed，当前只记录可执行红基线和未来通过条件，不修改生产代码。核心红线为：

- 三项交互查询各自返回 48,000 行；
- 三组旅程查询数分别为 150、501、501；
- 跨租户/门店、游标篡改、同键异内容、锁顺序漂移、导出 ACK 丢失必须失败关闭；
- 10k/100k 当前与候选计划必须使用同一数据、参数、统计和 MySQL 8.4.11 比较。

完整 seed 定义见 `contracts/t2/gate10a-r2-r2-r2-sql-remediation-prep/failure-tests-v1.json`。

## 影响范围

| 维度 | 候选影响 | 当前阶段 |
|---|---|---|
| OpenAPI/Vue | 三项报表可能新增版本化分页/导出入口 | 只提 CR，不修改 |
| Owner 端口 | Reporting/Payment/Inventory-Catalog 增加集合读取候选 | 只设计，不实现 |
| SQL/Mapper | 12 条查询可能保持或精确调整 | 只比较候选，不修改 |
| 索引/迁移 | 可能需要组合索引 | 必须独立 CR + 前向迁移，当前为0 |
| 资金/库存/租户 | 不允许变化 | 变化即停止 |
| Redis/连接池/长稳 | 属于 G10A-RES-P2-001 | 不准入 |

## 准备阶段退出标准

- 三项兼容性 CR、九项候选、三组批量端口均具备唯一机器记录；
- 150/501/501、12 查询摘要和 R2-R2-R1 不可变证据可追溯；
- 生产 SQL/Mapper/索引/数据库对象/迁移变化为 0；
- `G10A-SQL-P2-001 = OPEN`、`G10A-RES-P2-001 = PREPARED`；
- 治理双平台、范围、契约一致性与证据门禁通过；
- 外部执行为 0。

## 后续运行时独立验收

每一步都必须先让相应红测试稳定失败，再做最小修复；保存当前/候选计划、查询次数、实际行、
数据守恒、租户攻击、锁/并发、迁移和回退证据。禁止用墙钟波动、自动重跑或降低阈值判定通过。
