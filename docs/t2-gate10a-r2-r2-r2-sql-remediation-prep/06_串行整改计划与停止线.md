# 串行整改计划与停止线

后续仅在项目发起人确认启动后执行：

1. R0：逐项确认三个报表 CR，并把 12 个失败 seed 变成可执行红测试；
2. R1—R3：依次整改 Reporting 批量端口、RPT-SALES、RPT-INVENTORY、RPT-PAY-REC；
3. R4：Payment 批量端口与 PAY-FACTS；
4. R5：Inventory/Catalog 批量端口与 INV-EXPIRY；
5. R6：INV-FEFO 与 MBR-POINTS-FEFO 锁定计划；
6. R7：INV-PACKAGE 与 PRM-RULES；
7. R8：PRM-QUOTE-LINES、PUR-LINES、TRF-LINES 的 KEEP_SQL/索引证明；
8. R9：全部 10k/100k、获批趋势、权限攻击、完整 CI 和 Finding 关闭建议。

前一步独立 VERIFIED 前不得铺开下一步。索引/数据库对象只能在获批独立 CR 后用唯一前向迁移实现。

## 立即停止条件

- 需要改变 API/错误码/响应兼容但对应报表 CR 未批准；
- 需要改变金额、库存、租户、支付、同步、幂等、事件 Schema 或 Owner 语义；
- 需要修改任何已发布迁移；
- 候选导致锁顺序、结果摘要、逐字段守恒或租户隔离漂移；
- 出现内部 P0/P1、Flaky、证据不完整或必须依赖外部执行；
- 尝试提前进入 G10A-RES、R3、完整 Alpha 或生产发布。
