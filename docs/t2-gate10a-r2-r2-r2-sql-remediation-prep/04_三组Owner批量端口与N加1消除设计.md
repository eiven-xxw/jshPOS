# 三组 Owner 批量端口与 N+1 消除设计

## 1. ReportingBatchReadPort：150 → 目标 3

输入由服务端构造：可信租户、授权门店集合、三类报表、业务日范围、投影版本、筛选摘要和恢复游标。
冻结用例 50 门店在一个授权门店分块内，每类报表最多一次查询，因此目标不超过 3 次。输出为稳定排序、
有摘要和 next cursor 的流式分块。Reporting 只读自己的投影/正式端口，不查询其他 Owner 私有表。

## 2. PaymentFactBatchReadPort：501 → 目标 4

先按 tenant/provider/UTC 半开区间读取一次内部事实，再把 500 个引用按每块最多 200 个集合匹配，目标
`1 + ceil(500/200) = 4`。返回稳定的 reference→facts 映射和摘要。重复请求复用原 request hash；
支付 `UNKNOWN`、成功单调和“禁止自动二次扣款/退款”不变。

## 3. LotExpiryPolicyBatchReadPort：501 → 目标 2

Inventory 一次读取最多 500 个临期候选及其冻结策略键，Catalog 通过明确只读端口一次返回去重后的
策略版本，Inventory 合并形成带事实检查点的只读视图。门店业务时区、批次身份、过期禁售与临期阈值
由服务端冻结；不得用跨 Owner Mapper 直接关联 Catalog 私有表。

## 共同故障恢复

- 每次请求绑定稳定 idempotency key、内容摘要、tenant、数据范围、查询/投影版本和关联标识；
- ACK 丢失或进程重启复用原请求与游标；同键异内容拒绝；
- 分块输出必须可检测重复、缺口和乱序，恢复不得重新生成资金或库存命令；
- 缓存只可加速，不能成为报表、支付或库存唯一事实来源；跨租户游标/缓存键失败关闭。
