# Gate 4D / Sprint S8 范围、非目标与逐项准入

## 1. 正式准入

| Requirement ID | 范围 | 准入状态 |
|---|---|---|
| `T2-TRF-001` | 同租户基础调拨申请、提交、审批、整单发出、多次收货、在途账、差异处置、发出前取消、库存和成本闭环 | READY → IN_PROGRESS |

准入依据为商业方案 V3 3.8.4、详细设计 33 第 2、3、6、11、12、14 章和 ADR-026。编码前已冻结数据主权、状态、不变量、权限、审计、API、事件、Flyway、容量、回退和 CI。

## 2. 设计准备但禁止运行时

`T2-PRM-001`、`T2-PRM-002`、`T2-PRM-003` 只补充规则版本、候选/互斥/优先级、手工改价权限、整单折扣、抹零、成交快照、退款还原和稳定分摊设计。契约必须带 `x-runtime-allowed=false`；不得创建促销表、服务、Controller、计算引擎、任务或 POS 逻辑，RTM 保持 `DRAFT`。

## 3. 明确非目标

- 支付 Provider 网络、沙箱调用、生产密钥和真实资金；
- 跨租户、跨币种、多货主、批次、库位、序列号、越库、运输计费和复杂配送 WMS；
- 调拨预占、自动补货、路线优化、PDA 扫码与 Android 实机；
- 多发入账、无单收货、发出后直接取消、历史流水修改；
- 促销、会员、报表、应付、发票、总账、税务和批次成本运行时。

## 4. 准入门槛

- `T2-CST-001` 及 Gate 0—4C 既有依赖必须为 `ACCEPTED`；`T2-PAY-002` 必须保持 `BLOCKED`。
- 唯一不可变基线 tag、Gate 4C 封板提交和本分支祖先关系均通过机器校验。
- 所有 API 不接受 `tenant_id`；来源/目的门店和仓库均由服务端可信上下文与数据范围交叉验证。
- 发出与收货分别调用库存 Owner；任何成本失败必须回滚本次库存和调拨命令，不允许静默跳过。
- 本 Sprint 最高可到 `VERIFIED`；`ACCEPTED` 必须等待项目发起人确认。
