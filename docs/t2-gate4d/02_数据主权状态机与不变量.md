# Gate 4D 数据主权、状态机与不变量

## 1. 数据主权

| 数据 | 唯一写入 Owner | 其他模块权限 |
|---|---|---|
| 调拨单、行、命令、发出/收货事实 | `jshpos-transfer` | 只读端口/事件 |
| 在途流水与可重建在途投影 | `jshpos-transfer` | 只读对账 |
| 来源/目的仓数量流水与余额 | `jshpos-inventory` | 调拨只能调用受控端口 |
| 调拨发出/收货成本流水与余额 | `jshpos-costing` | 调拨只提供权威来源，不写成本表 |
| 原发出成本依据 | `jshpos-costing` | 通过 `TransferCostSourcePort` 与成本 Mapper 组合解析 |

`tenant_id` 只来自 `TrustedTenantContext`。API、命令 DTO、缓存、任务、导出和对象存储参数中的租户值均不构成授权依据。

## 2. 状态机

```text
DRAFT --submit--> SUBMITTED --approve--> APPROVED --dispatch--> IN_TRANSIT
  |                    |                    |
  +------cancel--------+---------cancel----+

IN_TRANSIT --partial receipt--> PARTIALLY_RECEIVED --full receipt--> CLOSED
IN_TRANSIT/PARTIALLY_RECEIVED --final short receipt--> DIFFERENCE_PENDING --resolve--> CLOSED
```

- `DRAFT/SUBMITTED/APPROVED` 可取消，终态 `CANCELLED`，不得产生库存或成本流水。
- `APPROVED` 只允许一次整单发出；来源仓扣减成功后进入 `IN_TRANSIT`。
- 多次收货累计不得超过已发出数量。全部收齐直接进入 `CLOSED`；最终少收进入 `DIFFERENCE_PENDING`。
- `DIFFERENCE_PENDING` 只能由有权限人员接受短少/破损/拒收差异并追加在途结清流水后进入 `CLOSED`。
- 发出后取消必须返回 `TRF-CANCEL-POSTED`；反向调拨属于新单据，不修改原单。

## 3. 核心不变量

1. 来源仓与目的仓不同，且均属于可信租户和调用者数据范围。
2. 每行数量为正、最多六位小数；同一调拨单 SKU/基础单位组合唯一；原申请单位、输入数量及分子/分母换算快照必须随行冻结。
3. `quantity_before + quantity_delta = quantity_after`；在途流水序号按调拨行严格递增且不得更新/删除。
4. `dispatched_qty = received_qty + open_transit_qty + approved_difference_qty`。
5. 发出与收货使用不同 `event_id`；同一命令重复同摘要返回原状态，同键异摘要拒绝。
6. 多收和未发先收失败关闭；部分收货不得隐式关闭剩余在途。
7. 来源 `TRANSFER_OUT` 保存成本快照；目的 `TRANSFER_IN` 必须引用同一调拨行的原发出成本。
8. 调拨、库存、成本、审计与 Outbox 在每个命令的本地数据库事务内一致；失败不得留下半完成命令。
9. 晚到命令按聚合版本和事实状态判定，不按请求到达时间覆盖新状态。
10. 历史发出、收货、差异和在途流水只能追加冲正/新单据，不得回写；差异在途流水必须逐行保存受控原因码。
11. 在线发出、收货、差异投影必须可由不可变在途流水重算核对；漂移只能告警并走受控前向修复，禁止查询时静默改账。

## 4. 差异范围

本 Gate 只准入 `SHORTAGE`、`DAMAGED`、`REJECTED`、`TRANSIT_LOSS` 四类少收处置，数量合计必须精确等于剩余在途。`OVERAGE` 只记录拒绝审计，不允许入库；多发与无单货物必须另建后续受控流程。
