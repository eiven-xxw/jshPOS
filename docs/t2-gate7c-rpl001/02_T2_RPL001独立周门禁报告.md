  Outbox；Inventory/Catalog/Procurement 只通过明确受控端口交付权威事实。

- 计算只使用 Inventory Owner 的在手、可用、预占、负库存策略、余额版本和最后流水

  上限，并同时满足最小订货量与订货倍数。
- 建议状态覆盖 `GENERATED/REVIEWED/APPROVED/REJECTED/STALE/PURCHASE_DRAFTED/FAILED`；
  库存或规则版本后移会显式使旧建议过期，不会静默继续执行。
- 转采购草稿只通过 Procurement Owner 正式应用端口，冻结原建议、供应商、仓库、
  SKU、采购单位和换算；审批前不产生采购承诺、收货、库存或成本效果。
- 同幂等键同内容返回原结果，同键异内容拒绝；重复、乱序、晚到、并发审批、重启恢复、
  失效供应商、换算冲突和跨租户/仓库访问均按冻结规则失败关闭或最终收敛。
- MySQL V62 只前进迁移包含中文 COMMENT、租户复合约束、唯一键、查询索引、只追加/
  冻结事实触发器和权限种子；已发布迁移未修改。
- Vue 补货工作台只调用正式 API，支持规则、生成、建议复核/审批/拒绝、过期和
  转采购草稿；前端不重算库存、在途量或建议数量。
- 24 个固定故障向量和两个虚构租户、多门店、多仓库、三业态合成数据已纳入回归；
