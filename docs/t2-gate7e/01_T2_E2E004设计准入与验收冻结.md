# T2-E2E-004 设计准入与验收冻结

## 2. 主权、状态和事务边界

- QA/Architecture 只拥有验收清单、固定向量、失败 seed、缺陷账、证据索引和签署结果；
  不拥有任何业务事实，也不新增业务表、迁移、API 或事件。
- 每个 Owner 继续只写自己的事实。跨模块只通过正式应用端口、版本化事件、Inbox/Outbox
  或显式只读端口；汇总器不得直接访问 Mapper 或业务表。
- `T2-E2E-004` 状态为 `DRAFT → IN_PROGRESS → VERIFIED → ACCEPTED`；任何必需组件、
  检查点、守恒、固定 seed、证据或 P0/P1 条件失败即保持 `IN_PROGRESS/NO-GO`。
- 汇总器没有跨 Owner 大事务。销售、同步、退货、库存、成本、日结等仍沿用已接受事务
  边界，并通过稳定 ID、摘要和检查点验证最终收敛。

## 3. 权限、审计、幂等和敏感边界

- `tenant_id`、门店、终端和员工只能来自可信上下文；两个虚构租户的跨租户/跨门店请求
  必须失败关闭。缓存、任务、临时文件、导出和对象存储继续使用租户命名空间。
- 汇总执行只保存合成标识、测试结果和摘要，不保存 Secret、真实 PII、商户号、终端证书
  或支付报文；日志与制品继续执行 Secret/PII 门禁。
- 同一 seed、旅程和 Owner 检查点必须具备稳定身份与内容摘要；同键同内容返回原结果，
  同键异内容拒绝。`UNKNOWN` 只能观察原命令收敛，禁止生成新资金或业务命令。
- 所有关键拒绝、恢复、差异、修复、日结签署和补打必须有既有 Owner 审计证据；汇总器
  只引用审计，不复制或篡改审计事实。

## 4. 正式三业态旅程

同一证据 Run 使用 `TENANT_A/TENANT_B`、至少两个组织、六个门店、六个终端：

1. 便利店：开店准备、普通条码、促销/会员价、人工优惠、挂取单、现金/部分现金、成交、
   同步、库存成本、补打、退货换货、补货、日结和异常处置；批次能力保持关闭。
2. 零食折扣店：行业模板、批量商品/价格、折扣与会员 BEST_PRICE、现金运营、库存补货、
   退款换货和日结；批次能力保持关闭。
3. 社区超市：行业模板、秤码、显式批次效期、FEFO、促销/会员价、销售退货、采购盘点
   调拨补货、临期预警、日结异常；不引入批次成本或复杂 WMS。

共同链路为：后台初始化/迁移/开店 → 商品价格/权益包发布 → POS 登录开班 → 扫码/秤码 →
报价与人工优惠 → 挂取单/现金与部分现金 → 成交与同步 → 库存/成本/报表 → 部分和最终
退货退款/换货 → 采购/盘点/调拨/补货 → 日结/异常处置 → 关班 → 备份恢复与合成升级。

## 5. 守恒与 Owner 检查点

- 订单：`gross - discount + surcharge = receivable`，订单行合计与头一致。
- 资金：现金与 Provider 无关份额合计等于应收；电子份额继续 `BLOCKED/UNAVAILABLE`；
  退款累计不超过原成功份额，`UNKNOWN` 不重扣不重退。
- 数量：库存只追加流水与可重建余额一致；批次 FEFO、退货归批、盘点、采购、调拨和补货
  不得直接覆盖余额。数量使用精确十进制。
- 成本：只消费库存/采购权威事实，成本流水只追加，投影可重建；调拨继承来源成本，禁止
  报表层或汇总器重算。
- 优惠与会员：优惠分摊金额守恒；退款读取原权益、会员价、促销及人工优惠快照。
- 日结：逐门店/业务日的订单、退款、现金、库存、成本和报表检查点可解释；晚到事实只形成
  更正版本，不覆盖已签署日结。

## 6. 故障、性能、恢复与 Go/No-Go

- 固定 16 个 seed 覆盖重复、乱序、ACK 丢失、`UNKNOWN`、磁盘失败、进程终止、业务日
  切换、跨租户/门店、同键异内容、旧包/坏包、快照/摘要篡改、部分 Owner 失败、投影
  重建、迁移中断、安全前向修复和外部边界伪装。
- 继续执行 `T2-PERF-001` 的 10k/100k 商品、10k 同步积压、1m 报表投影、扫码和结算
  固定合成趋势；正确性与完整性是硬门禁，墙钟时间不是商业 SLA。
- 备份恢复和合成升级只复用已接受 `T2-BAK-001/T2-UPG-001` 正式软件路径；生产 KMS、
  对象存储、PITR、真实 APK 与设备命令仍不在范围。
- P0/P1 必须为 0；任一开放即 `NO-GO`。完成后最高结论是
  `INTERNAL_V1_BUSINESS_COMPLETE_CANDIDATE`，等待项目发起人确认。
