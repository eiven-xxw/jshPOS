# T2-E2E-004 可重复运行手册

## 1. 目的与证据上限

本手册用于在同一 Git 提交、同一 GitHub Actions run 中复现商业 V1 内部汇总验收。最高证据等级仅为 `INTERNAL_V1_BUSINESS_COMPLETE_CANDIDATE`，不代表支付沙箱、真实设备/外设、设计伙伴、完整 Alpha、生产或商业验收。

## 2. 固定输入

- 基线：`feeecec5e1b438ba46f4225954e950d4e45ceb0c`
- 需求：`T2-E2E-004`
- 汇总向量：`contracts/t2/gate7e/internal-v1-business-complete-v1.json`
- 准入契约：`contracts/t2/gate7e/e2e004-admission.json`
- 性能参考：`contracts/t2/gate6h/performance-baseline-v1.json`
- 合成拓扑：两个虚构租户、六个门店、六个终端、三类业态
- 固定故障：`G7E-0001` 至 `G7E-0016`

禁止替换为真实 PII、支付凭据、生产密钥、真实商户数据或真实终端身份。

## 3. 本地源契约预检

在仓库根目录执行：

```powershell
python scripts/check_t0_structure.py
python scripts/check_rtm.py
python scripts/check_contracts.py
python scripts/check_t2_gate7e.py
python scripts/run_t2_gate7e_internal_v1_business_complete.py `
  --output artifacts/t2/gate7e/local/source-contract-report.json `
  --seed-ledger artifacts/t2/gate7e/local/failure-seed-ledger.json `
  --defect-ledger artifacts/t2/gate7e/local/defect-ledger.json
git diff --check
```

本地源契约结果只能为 `DESIGN_VALIDATED_ONLY`，不得冒充同次 CI 正式执行证据。

## 4. 完整 CI 复现

推送工作分支后运行 `.github/workflows/t2-gate7e.yml`。不得只重跑失败 job；任何失败都应先定位并修复后，以新提交重新执行整条流水线。

同一次 run 必须产生以下独立制品：

1. `governance-ubuntu`、`governance-windows`：RTM、契约、准入和状态边界；
2. `server`：模块化单体全量测试、覆盖率、可执行 JAR、SBOM 和许可证；
3. `mysql-runtime`：空库执行统一 V1—V80 前向迁移、重复执行和约束验证；
4. `web`：构建、Lint、类型、全量组件测试和依赖许可证；
5. `flutter-ubuntu`、`flutter-windows`：分析、全量测试、SQLite、覆盖率和依赖清单；Ubuntu 另编译 Kotlin 与 Android APK；
6. `runtime-stack`：正式 Server/Web/MySQL 同时启动，并执行 Flutter 文件 SQLite 正式运行旅程；
7. `internal-e2e`：六条三业态旅程守恒、16 个固定 seed、P0/P1 缺陷账；
8. `security`：Secret、依赖漏洞、SBOM、许可证和 workflow 配置门禁；
9. `evidence-index`：对上述原始文件生成逐文件 SHA-256 索引。

## 5. 判定规则

- Gate 7B—7D 实际获批的 14 项需求全部保持 `ACCEPTED`；
- `T2-E2E-004` 只能在同提交全部门禁通过后转为 `VERIFIED`；
- 六条旅程的订单、支付份额、退款、库存、成本、批次和日结逐字段守恒；
- 16 个 seed 必须全部映射到未跳过且成功的 Java 或 Dart 测试；
- P0/P1 为 0，Flaky 为 0，不允许自动重跑；
- 外部执行计数全部为 0；
- 任一制品缺失、摘要不一致或证据等级漂移均为 `NO-GO`。

## 6. 故障处理与前向修复

1. 保存失败日志、失败 seed、commit SHA 和执行器；
2. 将确定性失败写入缺陷账，不删除用例、不改 seed；
3. 数据库迁移只允许新增前向修复，不得修改 V1—V80 已发布迁移；
4. `UNKNOWN` 只能查询或观察原命令，不得生成替代资金或业务命令；
5. 修复完成后提交新 commit，从头运行完整工作流；
6. P0/P1 未归零时保持 `IN_PROGRESS/NO-GO`。

## 7. 清理与保留

- 本地 `artifacts/t2/gate7e/local` 可安全清理；
- CI 原始制品保留 30 天，内部 E2E 和证据索引保留 90 天；
- 不删除 Workflow Run、Git 提交、报告、日志或证据索引；
- 不得借清理动作改变任何 BLOCKED、DEFERRED、DRAFT 状态。
