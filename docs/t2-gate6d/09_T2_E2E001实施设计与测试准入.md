# T2-E2E-001 实施设计与测试准入

## 1. 证据模型

本需求采用“同提交组件执行证据 + 固定跨 Owner 旅程守恒”的组合式内部合成 E2E。它不建立第二套业务算法，不跨 Owner 写私表：CI 先运行正式 Flutter、Web、服务端应用服务与 MySQL 迁移测试，再由 E2E 编排器读取机器报告，并对同一份冻结旅程逐步骤核对身份、摘要、金额、库存、成本、报表和班次守恒。

证据等级固定为 `SYNTHETIC_E2E`。该方式验证内部产品能力能按正式契约组合，但不是已部署全栈、支付沙箱、真实设备、现场试点或完整 Alpha。

## 2. 冻结旅程

每个虚构租户各覆盖便利店、零食折扣店和社区超市，共六个门店/终端旅程：

`可信租户/门店/员工 → 商品价格与规则包 → 签名摘要安装 → 班次已开启 → 扫码购物篮 → 促销/人工优惠快照 → 挂取单组件证据 → SQLite 现金原子成交 → 原 Outbox 事件同步/ACK → 服务端订单 → 库存销售出库 → 冻结销售成本 → 报表投影核对 → 现金理论数与班次关闭`

所有 ID、业务日、金额、精确数量、包版本和事实摘要固定；同一事件重放必须返回原结果，同键异内容、跨租户包、金额篡改和报表反写必须拒绝。

## 3. Owner 与证据来源

- Foundation：组织、门店、业务日与可信范围应用服务测试。
- Catalog：商品、多单位、价格发布和租户命名空间数据包测试。
- POS：可信会话、包安装、挂取单、促销现金原子成交、打印预览和同步恢复的 Linux/Windows 机器报告。
- Order/Sync：促销快照绑定订单、Inbox 幂等、事件分发和 ACK 语义测试。
- Inventory/Costing：权威订单驱动不可变销售出库与冻结出库成本测试。
- Reporting：销售投影幂等、同键异内容拒绝和可信范围查询测试。
- MySQL/Web：完整已发布迁移与正式运营组件测试。

E2E 编排器仅读取这些机器证据并验证固定旅程，不直接更新任何 Owner 表，也不把组件失败掩盖为 E2E 成功。

## 4. 守恒与失败关闭

- `gross - discount + surcharge = receivable`，现金 `tendered - receivable = change`。
- 库存 `openingOnHand - saleOut = closingOnHand`，销售数量与订单冻结数量一致。
- 销售成本使用冻结单位成本乘精确数量；报表逐字段等于权威事实。
- 班次理论现金为备用金加现金实收，差异为实点减理论。
- 数据包必须绑定可信租户/门店且已验签；Outbox 使用原 event ID 并最终 ACK。
- 任一所需机器报告缺失、失败、跳过或字段不守恒，E2E 失败关闭。

## 5. 准入与非目标

`T2-ADM-001` 已由独立 Run `32361270390` 验证，因此 E2E-001 获准进入实现。本需求不新增商品、促销、订单、库存、成本或报表算法；不执行 Provider 网络、真实设备命令、真实打印、现场试点和完整 Alpha，也不改变任何外部 P0 状态。
