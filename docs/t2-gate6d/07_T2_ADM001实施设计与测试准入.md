# T2-ADM-001 实施设计与测试准入

## 1. 页面拓扑

- `/`：经营工作台，只读聚合当前会话可见组织、门店、商品、模板和最近审计，失败模块显示未知而不是 0。
- `/foundation`：组织、门店、业务日、行业模板、员工组织/门店数据范围和领域审计。
- `/system/user`、`/system/role`：复用 RuoYi-Vue-Plus 账号、角色、菜单权限和数据权限能力。
- `/catalog`：商品、条码、多单位、分类、品牌、价格版本、批量导入与安全回退。
- `/reporting`、`/terminal-registry`：只提供正式既有模块导航，不跨 Owner 读取私表。

## 2. 数据与权限边界

Vue 只调用 `@/api/foundation`、`@/api/catalog`、RuoYi 系统 API 及既有 Reporting/Terminal API。所有领域 API 由可信登录会话注入租户，页面、查询参数和表单均不得出现 `tenant_id/tenantId`。前端权限指令只用于交互隐藏，服务端必须继续做最终功能权限、数据范围和审计校验。

经营工作台只对 API 返回的可见列表计数，不计算销售额、库存、成本、优惠或对账事实；部分 API 失败时保持该卡片未知并显示告警，不以空数组伪造正常。

## 3. 商品运营不变量

- 商品必须且只能有一个主单位，最多 50 个销售单位；单位换算只提交正安全整数分子/分母。
- 同一商品输入中的单位 ID 与条码不得重复；服务端继续执行租户内全局条码唯一与正式数据主权校验。
- 金额只使用价格 API 的最小货币单位整数；前端不执行促销、价格覆盖或生效优先级算法。
- 导入必须先预检并展示逐行错误；仅 `PRECHECKED` 可发布，仅已发布批次显示安全回退入口。
- 价格簿草稿、价格项、未来生效时间、发布状态与内容摘要全部使用 Catalog Owner 返回值。

## 4. 员工范围不变量

账号与角色由 RuoYi 系统模块管理，鲸熵汇员工数据范围由 Foundation Owner 独占。范围替换只允许 `TENANT/ORG_SUBTREE/STORE`，组织或门店目标与范围类型必须一致；页面不自行推导组织树授权，服务端保存并审计完整替换事实。

## 5. 兼容、回退与错误

- 新增字段保持可选；未知状态或 API 失败不得导致跨模块写入。
- 前端静态制品可回退上一版本，服务端事实、价格版本和导入批次不随 Web 回退。
- 失败只展示安全业务信息；底层响应、Secret、PII 和租户内部标识不得进入控制台或页面。

## 6. 测试准入

- TypeScript 类型检查、ESLint、生产构建和依赖/许可证门禁必须通过。
- Vitest 覆盖工作台计数、多单位规范化、唯一主单位、重复单位/条码、非整数换算及页面边界。
- 静态页面契约验证首页不再包含框架 Demo，Foundation/Catalog 只经正式 API，且无客户端租户覆盖和直接 API URL。
- 两个虚构租户、多门店、三业态只在测试与 E2E 数据中体现；本需求不接触真实 PII。
