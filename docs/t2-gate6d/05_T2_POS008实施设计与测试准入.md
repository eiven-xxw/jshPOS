# T2-POS-008 实施设计与测试准入

## 1. 页面与 Owner 边界

收银页面只依赖 `PosSaleController`，控制器只依赖 `PosSessionService` 和 `PosSaleApplicationService`。宿主组合根负责把该端口绑定到已接受的 Catalog、Pricing、Promotion、Checkout、Sync 和 Print Task 应用能力；未绑定时使用 `LockedPosSaleApplicationService` 失败关闭。

禁止页面直接访问 SQLite、MethodChannel、`pos_device_adapter` 平台通道或任一 Owner 私有表；禁止页面构造订单、收款、促销快照或 Outbox 事实。页面提交条码、稳定商品引用、规范数量字符串、优惠动作、收款字符串和稳定幂等键，金额、报价版本、fingerprint、成交结果与同步状态均由应用端口返回。

## 2. 页面状态

`loading → ready ↔ busy → settled` 为正常路径；任何已知应用失败进入 `failed` 并保留上一份只读工作区，未知异常统一转为安全错误码。改变购物篮或成交事实的操作执行单航班，按钮在 `loading/busy` 时禁用。

成交失败后页面保留相同的 `saleRef + quoteFingerprint` 并生成相同现金幂等键；禁止创建第二个订单命令。成交成功后只有用户点击“下一单”才请求应用服务创建新工作区。

## 3. 用户旅程

1. 从可信会话壳进入当前班次工作区并恢复未完成购物篮与同步投影；
2. 扫码枪键盘注入或 F2 聚焦条码框，回车提交一次扫码意图；
3. 名称、SKU 或条码搜索只读取已发布数据包投影；
4. 改量、重新报价和人工优惠均整体替换 Owner 返回的工作区；
5. F4 挂单后由 Owner 生成新空篮，取单按稳定引用重新校验；
6. F9 现金结算，展示应收、实收、找零、快照摘要和 Outbox 引用；
7. 打印只展示任务预览与 `FAKE_DEVICE_ADAPTER` 证据，不调用真实打印；
8. 顶部持续展示在线、待同步、重试和死信隔离数量，不把“网络已恢复”等同于事件已 ACK。

## 4. 权限与审计

| 操作 | 本地权限防线 | Owner 审计要求 |
|---|---|---|
| 扫码/搜索/改量/报价/挂取单 | `pos:sale:operate` | 命令、员工、班次、终端、业务日与关联标识 |
| 人工优惠 | `pos:discount:manual` | 动作、限额、审批引用、原/新金额与规则包版本 |
| 现金结算 | `pos:cash:settle` | 稳定幂等键、成交快照、收款、班次现金效果与 Outbox |
| 同步查看 | `pos:sync:view` | 查询范围与异常修复入口 |
| 打印预览 | `pos:print:preview` | 任务引用、订单引用、预览人和时间；真实设备命令为 0 |

服务端和本地 Owner 仍须再次鉴权；页面权限不构成最终授权。

## 5. 离线、兼容与回退

- 离线允许读取已验证数据包、报价、挂取单和现金成交；在线专属操作由应用服务返回安全错误。
- 工作区契约只增加可选展示字段；未知字段忽略，状态码和金额字段不得重定义。
- UI 发布失败回退上一 APK；SQLite 与已发布事实不回退，恢复后继续读取原购物篮和 Outbox。
- Quote fingerprint、订单快照摘要或同步游标不一致时失败关闭，由 Owner 提供前向修复，不在页面重算。

## 6. 测试准入

- 18 个固定向量覆盖扫码、重复操作、搜索、改量、促销、人工优惠、挂取单、现金幂等、重启、离线、积压、打印预览、业务日和跨租户失败关闭。
- Controller 单元测试覆盖权限、单航班、错误收敛和全部应用端口。
- Widget 测试覆盖 1440×1000 大屏触控、键盘/扫码输入、弹窗、同步提示和失败关闭；布局不得出现 overflow。
- Gate 6D session/sale domain、application、infrastructure 目标覆盖率保持不低于 90%；presentation 由 Widget/语义测试单独约束。
- Provider 网络、真实终端命令、真实打印、真实资金、现场试点和完整 Alpha UAT 均须为 0。
