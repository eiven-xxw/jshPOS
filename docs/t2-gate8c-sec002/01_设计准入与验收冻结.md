# T2-SEC-002 设计准入与验收冻结

## 关闭矩阵

| Finding | 回归先行 | 最小实现 | 量化关闭标准 |
|---|---|---|---|
| G8C-SEC-P0-001 | 生产 YAML 与启动失败测试 | Secret 引用、默认关闭、启动校验 | 生产文件无静态默认凭据；缺任一必需 Secret 和已知默认值均启动失败 |
| G8C-SEC-P1-002 | 管理配置和拒绝审计契约测试 | 白名单、授权详情、独立 Basic | 只暴露 health/info/prometheus；`always`、`*` 和敏感端点均失败 |
| G8C-SEC-P1-003 | 超限前置拒绝、长度不符、摘要、清理和并发资源测试 | 64 KiB 缓冲流式暂存与对象上传 | `(0,10 MiB]`；正文不形成整包 `byte[]`；所有路径临时文件为零 |

## 不变量

- Secret、凭据、附件正文、Authorization 和真实 PII 不进入 Git、日志、CI 或普通制品。
- Service 上限为 10 MiB；客户端声明量与实际量必须一致。
- 对象存储键保持 `service/{trustedTenant}/tickets/{ticket}/attachments/{serverId}`。
- 不修改数据库迁移、业务状态机、API 路径、金额库存或租户事实。

## 验收顺序

`安全契约测试 → Service 单元/故障测试 → Server 全量 → Web/Flutter/Android → MySQL/SQLite → Secret/依赖/SBOM/许可证 → 证据聚合`。

任一失败必须固定并从新提交完整复跑；不得只重跑失败 Job。
