# Gate 10A-R2 串行整改计划

1. **R2-R1 可维护性**：先加入复杂度预算、19 类金标/白名单和 Owner 依赖环门禁，再按风险逐类
   拆分；第一批只处理最上游高风险类，保持事务和接口行为。
2. **R2-R2 SQL**：只有 R2-R1 独立 VERIFIED 并经确认后，才建立 12 个查询的 MySQL 8.4
   计划、分页和查询数回归；需要索引/迁移则停止申请 CR。
3. **R2-R3 资源**：只有 SQL 批次接受后，先执行 10 分钟冒烟，再单独执行 24 小时长稳；
   任何持续正斜率、数据丢失或不可解释死信均 `NO-GO`。

R2 完成不自动进入 R3。每项都需要独立周门禁报告和项目发起人确认。
