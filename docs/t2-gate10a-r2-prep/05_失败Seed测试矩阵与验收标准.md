# 失败 Seed、测试矩阵与验收标准

## 冻结红基线

| Seed | 当前观察 | 含义 |
|---|---|---|
| `G10A-R2-MTN-RED-001` | 19 个 Owner Java 文件≥400行 | 可维护性 Finding 仍开放 |
| `G10A-R2-SQL-RED-001` | MySQL EXPLAIN 回归文件为0 | SQL Finding 仍开放 |
| `G10A-R2-RES-RED-001` | 持续窗口仅120秒 | 资源 Finding 仍开放 |

红基线的存在是准备阶段 `PASS` 的必要条件，因为它证明没有用绿色占位伪造整改完成。

## 正式整改共同标准

- P0/P1 为 0，失败测试必须先于实现并保留 seed；
- API、错误码、状态机、事务、幂等、Owner、事件和数据守恒不变；
- 可信 tenant、门店/数据范围和权限攻击回归全绿；
- 无依赖漂移、无已发布迁移改写、无自动重跑掩盖 Flaky；
- 每项 Finding 独立 VERIFIED 并等待确认，不能一次关闭三项；
- 新索引/迁移、业务或语义变化触发独立 CR；
- 资源结果只标记内部合成长稳，不形成商业 SLA。
