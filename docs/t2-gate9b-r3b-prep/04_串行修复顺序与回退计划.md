# 串行修复顺序与回退计划

## 修复顺序

1. R0：先增加共享交互失败回归，冻结 `useControlledOperation` 的 FAILED/UNKNOWN、
   单航班和原幂等键语义；
2. R1：VUE-08 权限、状态与恢复；
3. R2：VUE-07 库存/成本/盘点；
4. R3：VUE-11 供应链，再验证其内嵌 VUE-10 补货；
5. R4：VUE-09 合成发布与灰度；
6. R5：VUE-06 促销、会员隐私与积分；
7. R6：VUE-05 迁移编排；
8. R7：VUE-12 日结；
9. R8：VUE-13 异常中心；
10. R9：VUE-14 批次效期；
11. R10：VUE-15 门店开通；
12. R11：11 页联合交互与完整 CI。

前一步独立交互测试未通过，后一步不得铺开。每一步先提交失败测试，再提交最小实现。

## 回退策略

- 页面改动只消费既有 API，不迁移数据；任一步失败可撤回该页组件与测试提交；
- 共享交互工具必须先保持既有页面兼容，出现跨页回归时优先回退共享变更；
- 不回退或覆盖任何 Owner 事实、数据库迁移或已接受 ADR；
- VUE-10 保持现有两级装配链，禁止通过新增菜单“修复”已纠正的审计误判；
- 外部能力始终失败关闭，回退不得把 `BLOCKED/UNAVAILABLE` 变成模拟成功。
