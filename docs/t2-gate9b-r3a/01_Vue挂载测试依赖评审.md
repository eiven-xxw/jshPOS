# Vue 挂载测试依赖评审

## 决策

G9A-R3A 增加以下**仅开发/测试**依赖并锁定精确版本：

| 组件 | 版本 | 用途 | 许可证 | 运行时装配 |
|---|---:|---|---|---|
| `@vue/test-utils` | `2.4.11` | 挂载 Vue 3 SFC，验证真实渲染后的权限、状态和交互 | MIT | 否 |
| `happy-dom` | `20.11.6` | 为 Vitest 提供 Node 24 兼容的 DOM 测试环境 | MIT | 否 |
| `glob`（传递依赖覆盖） | `10.5.0` | 修复 `js-beautify` 传递范围解析到的命令注入版本 | ISC | 否 |

## 必要性与替代分析

- 现有源码字符串断言无法证明组件挂载后的按钮禁用、权限裁剪、加载/空态、失败恢复和单航班，
  不满足 ADR-071 的直接交互证据要求。
- `@vue/test-utils` 是 Vue 3 的标准组件测试工具，复用现有 Vitest，不引入第二套测试运行器。
- `happy-dom` 相比 `jsdom` 依赖树更小且明确支持 Node `>=20`；浏览器 E2E 对本批四个页面过重，
  也不能替代组件级固定故障 seed。
- 自行编写 DOM/Vue 挂载器会重复制造测试基础设施并增加维护风险，因此不采用。

## 安全与供应链结论

- 两项直接依赖与一项传递覆盖均固定版本，许可证为 MIT/ISC，只进入开发测试依赖树，
  不进入商业 Web 运行时 bundle；
- 锁文件、`pnpm audit`、许可证清单、SBOM 与依赖差异审查必须纳入本批 CI；
- 若出现 High/Critical 漏洞、许可证漂移、生产 bundle 命中或 Node 24 不兼容，本批失败关闭。

首次候选 `@vue/test-utils 2.4.6 + happy-dom 20.8.3` 在 `pnpm audit --audit-level high`
发现 3 个 High 后已拒绝；升级后仍命中 `glob 10.4.5`，因此使用同主版本修复版 `10.5.0`
的精确 override。该失败记录不得删除，最终依赖组合必须重新审计为 0 个 High/Critical。
