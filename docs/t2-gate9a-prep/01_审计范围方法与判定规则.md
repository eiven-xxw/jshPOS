# 审计范围、方法与判定规则

## 1. 范围

基线为 `4ba20f8bb9bfdc36f4fee1b831ca35c7b54b9533`。审计覆盖：

- RTM 中当前 87 项 T2 `ACCEPTED` 需求；
- 22 个 `jshpos-*` 正式 Owner 模块；
- 20 个 Vue 业务页面/组件和 6 个 Flutter 正式业务页面/壳；
- 300 项服务端 Controller 操作、当前 OpenAPI、MySQL/SQLite、事件/Outbox、权限审计、测试和 CI；
- Gate 7E 三业态业务旅程、Gate 8B SaaS 运营旅程以及当前发布/迁移装配。

本阶段不修改运行时、迁移、依赖或业务页面。技术诊断页
`technical_baseline_page.dart` 不计入 26 个商业业务页面，但仍作为生产源树孤立页面在后续装配
批次复核是否移除。

## 2. 端到端链路

每项需求必须映射为：

`Requirement → 页面/N/A → Controller/OpenAPI → Application → Domain → Repository/Mapper →`
`MySQL/SQLite → Event/Outbox/N/A → 权限审计 → 测试 → CI`。

后端治理、性能或发布类需求允许页面、领域或 Outbox 为 `N/A_BY_REQUIREMENT_SCOPE`，但 Owner、
依据、测试和 CI 不得为空。矩阵由脚本从 RTM 和当前源树生成，避免人工把旧的 15 Owner 快照
继续当作当前事实。

## 3. 标记分类

审计扫描 `Fake/Mock/Stub/Locked/InMemory/TODO/FIXME/UnsupportedOperationException/UnimplementedError`，
但文本命中不直接判缺陷。只有满足明确路径和语义的以下情况才允许：

- 测试/合成专用 SQLite 内存构造器；
- 外部支付或硬件未解阻时的显式失败关闭适配器；
- `FAKE_TEST` 观察源的生产拒绝规则；
- Windows 不支持 POSIX 权限时的受控目录 ACL 兼容分支；
- 促销互斥锁定、批次锁定快照或 POS 会话 `LOCKED` 等正式业务状态。

其余未分类标记会令审计失败。测试目录不作为生产标记缺陷，但测试后门仍由范围和 API 门禁检查。

## 4. 结论规则

- 审计覆盖不完整、Owner/RTM 漂移、外部状态漂移或未分类生产标记：`NO_GO_AUDIT_INCOMPLETE`；
- 范围与证据完整，P0/P1 已如实登记但尚未修复：`CONDITIONAL_PASS_AUDIT_ONLY`；
- 只有后续独立修复批次关闭全部内部 P0/P1，才可申请新的内部候选结论。

`CONDITIONAL PASS` 只证明“问题清单可信”，不证明“产品没有问题”。
