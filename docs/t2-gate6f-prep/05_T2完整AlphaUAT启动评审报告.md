## 2. 环境拓扑与数据

完整 Alpha 获批后使用独立非生产环境：隔离的管理 Web/API/MySQL/Redis/对象存储/备份恢复域，授权支付沙箱出口与回调入口，登记主/兼容终端及外设，独立日志/指标/追踪与 Secret 系统。测试商户按两个以上租户、三业态、多个组织/门店/终端建立；默认合成数据，伙伴脱敏样本仅在授权范围内使用。

环境必须禁止生产路由、生产 KMS/密钥和未脱敏数据，具备按租户清除、证据封存、访问吊销与销毁证明。支付回调入口、设备网络和伙伴数据区分别使用最小权限与审计。

## 4. 缺陷、证据与签署

- P0：资金重复/丢失、跨租户泄漏、库存/成本不可重建、数据不可恢复、关键交易不可用或无法安全回退。任何 P0 立即 `NO-GO`。
- P1：核心旅程无替代、对账不守恒、主设备/支付不稳定、关键权限审计缺失或恢复目标不达标。完整 Alpha 接受前 P1 必须为 0。
- 外部结论必须分别使用 `SANDBOX`、`REAL_DEVICE`、`PARTNER_VERIFIED/PILOT` 证据，不得用 STATIC/FAKE/INTERNAL_ALPHA_CANDIDATE 替代。
- 签署至少包含项目发起人、产品、架构、QA、安全、SRE、支付、设备和伙伴责任人；材料提供人与独立验证人不得相同。

## 5. Go/No-Go 与回退

启动 `GO` 的必要条件：PAY/HWD/PAR 三轨分别达到 `VERIFIED_DOCUMENT`、独立执行准入获批、环境安全评审通过、无未关闭入口 P0、数据清除/销毁方案演练通过。当前条件不满足，因此保持 `DRAFT/NO-GO`。

任何一轨授权撤回、资料过期、Secret/PII 事件、环境连接生产、P0 缺陷或无法清除数据时，立即停止完整 Alpha，吊销访问，封存证据并回退到对应 `BLOCKED/DRAFT` 状态。
