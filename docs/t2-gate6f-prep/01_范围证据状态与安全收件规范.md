## 2. 证据状态机

| 状态 | 含义 | 可执行动作 |
|---|---|---|
| `MISSING` | 未收到材料 | 发送/交付统一 RFI，不能执行 |
| `RECEIVED_UNVERIFIED` | 已收到但来源、签署、范围或摘要未闭环 | 隔离保存并离线验真 |
| `VERIFIED_DOCUMENT` | 来源、授权、主体/型号、版本、范围、SHA-256、保管人、到期及删除/吊销均核验 | 只能提交独立执行准入评审 |
| `EXECUTION_APPROVED` | 项目发起人对该轨明确批准范围、时间和停止条件 | 只能执行批准矩阵 |
| `EXECUTED_EXTERNAL` | 在批准环境形成外部证据 | 仍需独立验收，不自动 ACCEPTED |

状态只能通过新证据向前提升；摘要、授权、范围或期限发生变化时生成新证据 ID，旧记录保留并标记过期/吊销。

## 3. 统一收件元数据

每份受控材料至少登记：

- 不透明材料 ID、轨道、文档类型、提供主体、授权签署人是否已核验；
- 适用 Provider 产品/商户权限，或设备厂商/精确型号/固件，或伙伴主体/门店范围；
- 文档/SDK/API 版本、发布日期、取得时间、适用环境与排除范围；
- SHA-256、字节数、保管人、受控位置引用、密级；
- 生效/到期、轮换、撤回、删除/吊销规则；
- 验真人、复核人、验真时间、结论与冲突项。

材料提供人、验真人和最终批准人必须职责分离。

## 4. 安全保管

- Git/CI 只保存不透明引用、非敏感摘要、状态和必要 SHA-256，不保存受控原文。
- 支付 Secret、私钥、证书、真实商户/终端标识进入批准的 Secret 系统；报告只引用 Secret ID。
- 样机序列号、设备证书和厂商授权包进入资产/受控文档系统；普通 Artifact 不得打包。
- 伙伴身份、联系方式、书面意愿、样本和删除证明进入 CRM/合同/隐私受控区；仓库只使用 `PAR-01..05`。
- 误收生产凭据或未脱敏数据时立即停止验真、隔离、通知安全负责人并要求轮换/删除，不测试其有效性。
