# T2-PAY-004 正式实现准入与切面

## 1. 准入结论

项目发起人于 2026-08-22 接受 `T2-EXG-001`，并仅授权 `T2-PAY-004`
进入 `IN_PROGRESS`。实现基线为 `2cc9f88b8ad2d0530a77a9341d396dd1a2fc1e5f`。

本批只实现 Provider 无关 TenderPlan、部分支付、部分现金以及原命令恢复。电子渠道
适配继续受 `T2-PAY-002` 阻断；正式装配不得提供电子成功实现。

## 2. 数据主权与事务

- Payment Owner 独占计划、份额、份额状态、观察、历史、审计和 Payment Outbox。
- Order/Shift Owner 独占部分现金事实、班次现金流水、订单绑定和对应审计/Outbox。
- Payment 应用服务通过 `TenderCashCollectionPort` 调用现金 Owner；禁止 Payment Mapper
  直接写 `ord_*` 或 `shf_*`。
- 同库模块化单体使用同一 Spring 事务保证现金份额与计划状态原子提交；任一写入失败
  整体回滚。

## 3. 状态与不变量

- Plan：`FROZEN → COLLECTING → PAID`，以及 `UNKNOWN/FAILED/CANCELLED/MANUAL_RECOVERY_REQUIRED`。
- Allocation：`PLANNED → PROCESSING → SUCCEEDED`，以及 `UNKNOWN/FAILED/CANCELLED`。
- 一个计划 2—8 份、同币种 CNY、金额逐分等于订单应收；现金最多一份且必须最后。
- `SUCCEEDED` 不回退；`PROCESSING/UNKNOWN` 占额并阻断后续份额和替代命令。
- 现金实收可高于冻结现金份额，找零等于实收减份额；班次净增加仅为冻结份额。
- 退款按原成功份额和原介质恢复；最后一笔合法退款吸收分摊余数。

## 4. 安全与恢复

可信 `tenant_id`、门店、终端和操作者来自服务端会话或 POS 可信绑定。所有 Mapper、
SQLite、缓存/任务契约和事件均显式带租户范围。同幂等键异内容拒绝；ACK 丢失、重启和
UNKNOWN 只复用原 plan/allocation/command 查询或观察。

电子 collect 在正式装配中固定返回 `PAYMENT_EXTERNAL_BLOCKED`。不新增 Provider SDK、
HTTP 客户端、回调端点、账单下载、凭据配置或测试成功适配器。

## 5. 迁移、容量与回退

MySQL V57/V58 与 SQLite V13 均为独立前向迁移，不修改已发布文件。计划最多八份，
查询使用租户、订单、状态和更新时间索引。回退只关闭新入口并观察已冻结计划收敛；
不得删除或回写资金、现金流水、历史、审计和事件。

## 6. 验收

固定向量覆盖金额、顺序、电子阻断、现金找零、重复/同键异内容、UNKNOWN、ACK 丢失、
跨租户、事务回滚、重放和按原介质退款。Java 与 Dart 对状态、错误码、金额和摘要必须
一致；`tender-golden-vectors-v1.json` 是两端共同读取的摘要金标，禁止各自复制预期值。
P0/P1 为 0 且完整 CI 全绿后，才可更新为 `VERIFIED` 并等待发起人确认。
