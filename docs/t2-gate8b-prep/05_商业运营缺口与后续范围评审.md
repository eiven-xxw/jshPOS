# 商业运营缺口与后续范围评审

## 已覆盖

- 商户申请、预检、独立审批、技术租户编排和商业生命周期。
- 版本化套餐权益、服务端授权、配额控制。
- 订阅激活、续期、宽限、到期、受控降级、提醒意图、保留和恢复。
- 版本化服务目录、实施检查、服务工单、责任流转、附件元数据和内部时间目标。

## 不作为缺陷、但商业落地前仍需决策的缺口

1. 真实合同/商业订单和计费系统：当前只保存外部引用，不准入扣款、发票或财务记账。
2. 真实通知渠道：当前只形成提醒/通知意图；短信、邮件和第三方客服仍无执行适配器。
3. 生产对象存储/KMS 与保留策略：接口和失败关闭已具备，生产配置与演练仍需独立执行准入。
4. 客服连接器与呼叫中心：非商业 V1 当前范围，如确有刚需须独立 CR。
5. 商业数据分析、计费对账和合同 SLA：均不得从内部时间目标推导，须单独产品及法务决策。

## 后续范围建议

优先关闭许可证和四项外部 P0，再启动完整 Alpha。若继续优先内部代码，下一批只建议做“商业运营汇总缺陷修复与运维可观测性收口”，不得新增计费、财务或连接器模块；任何新能力均需独立 CR、Requirement ID 和发起人确认。
