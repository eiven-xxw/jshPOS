# 范围、非目标与证据边界

## 1. 目标

Gate 8B-Prep 证明三个已接受商业运营 Owner 可以经正式 HTTP 契约装配为一条可重复的内部合成旅程，并把各自的 Requirement、Owner、API/事件、迁移和证据汇总到同一可审计入口。

## 2. 唯一范围

- 接受记录：把 `T2-SVC-001` 从 `VERIFIED` 更新为 `ACCEPTED`。
- 汇总：`T2-SAA-001`、`T2-SUB-001`、`T2-SVC-001`。
- 验证：正式 REST Controller 的请求路径、请求头、DTO、稳定身份、状态顺序和 Owner 调用。
- 审计：套餐权益、订阅访问模式、服务授权、可信租户、幂等、只追加历史和受控恢复。
- 决策：商业运营差距、许可证、外部 P0、完整 Alpha 与发布 Go/No-Go。

## 3. 非目标

- 不增加主代码、数据库表或迁移、Vue/Flutter 运行时页面及后台任务。
- 不实现计费、自动扣款、发票、应付、总账、税务、合同 SLA 或商业赔付。
- 不调用支付、设备、外设、伙伴或连接器外部边界。
- 不启动完整 Alpha、现场试点、生产部署或商业发布。

## 4. 证据等级

聚合 E2E 上限为 `INTERNAL_SYNTHETIC_API_JOURNEY`。测试中的应用服务替身只证明正式 HTTP 装配，不证明数据库或状态机执行；后者严格引用 SAA/SUB/SVC 已接受的单项测试、MySQL 与运行栈证据。禁止把两类证据混写成真实外部或生产结论。
