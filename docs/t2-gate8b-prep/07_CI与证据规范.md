# CI 与证据规范

## 门禁

1. Ubuntu/Windows：AGENTS、RTM、ADR、CR、契约、UTF-8、基线祖先和范围检查。
2. Formal API：执行 `CommercialSaasOperationsFormalApiE2ETest`，保存 Surefire XML。
3. Server/MySQL：完整模块回归、覆盖率、SBOM、许可证与 V1—V86 前向迁移。
4. Web/Flutter/Android：既有构建、静态检查、测试、SQLite 和 Kotlin/APK 回归。
5. Security：Secret/PII、依赖漏洞、许可证、工作流 IaC 与范围漂移检查。
6. Evidence：每类生产者独立归档，生成文件级 SHA-256 和不可变索引。

## 失败规则

任一平台、正式 API 旅程、迁移、安全、证据或外部零执行检查失败即 NO-GO。禁止自动重跑掩盖 Flaky、降低阈值、修改已发布迁移、删除失败证据或创建绿色占位。

## 证据等级

最终索引必须写明 `INTERNAL_SYNTHETIC_API_JOURNEY`，同时保留 PAY/HWD/PRN/PAR BLOCKED、UAT/REL DRAFT、LIC/JSH DEFERRED。索引不得出现 SANDBOX、REAL_DEVICE、PILOT、FULL_ALPHA、PRODUCTION 或 COMMERCIAL 成功结论。
