# T2-LIC-001 商业许可证关闭执行准入评审报告

## 1. 评审结论

`DEFERRED / OPEN 0/3 / NO-GO COMMERCIAL RELEASE`。本轨不阻止离线准备，但在商业发布前必须关闭。任何组件只能通过“替换并完成回归/SBOM”或“适用分发模式的书面法务批准”关闭，不能以暂时未调用或开发阶段忽略代替。

## 2. 逐组件计划

| 组件 | 优先路径 | Owner 角色 | 截止门禁 | 当前 |
|---|---|---|---|---|
| Aviator | 迁移到批准的自有受限 DSL/宽松许可证组件；否则书面法务批准 | 架构、法务 | `T2-REL-001 READY` 前 | `OPEN` |
| simple-http | 迁移到仓库既有受治理 HTTP 客户端；否则书面法务批准 | 架构、安全 | `T2-REL-001 READY` 前 | `OPEN` |
| MySQL Connector/J | 法务确认商业分发/部署模型、NOTICE/offer 义务；必要时调整分发模式 | 法务、发布 | `T2-REL-001 READY` 前 | `OPEN` |

## 3. 关闭证据

- 使用清单：模块、版本、传递依赖、打包位置和运行方式。
- 替换路径：ADR/变更、兼容测试、性能/安全/网络策略回归、旧依赖完全移除。
- 法务路径：适用版本、许可证、地域、部署/分发模型、NOTICE/源代码提供义务和批准人书面意见。
- 共同证据：最终 SBOM、许可证清单、发布 BOM、NOTICE、依赖扫描和联合签署。

## 4. Go/No-Go

三项全部 `CLOSED` 且最终 SBOM/许可证门禁通过后，才允许把本需求提交 `VERIFIED`；项目发起人确认前不得转 `ACCEPTED`。任一项 `OPEN`、Owner 未具名、意见不适用当前版本或回归缺失，都必须保持生产/商业发布 `NO-GO`。
