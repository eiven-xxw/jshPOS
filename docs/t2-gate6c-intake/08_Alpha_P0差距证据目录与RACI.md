## 3. RACI

| 工作 | A | R | C | I |
|---|---|---|---|---|
| 支付 Provider 选择与授权 | 项目发起人 | 商务/支付负责人 | 法务、安全、架构、QA | 产品、SRE |
| 支付材料技术验真 | 支付负责人 | 支付工程师、安全工程师 | Provider 具名技术联系人、QA | 项目发起人 |
| 主机/外设选型和样机 | 设备负责人 | 设备工程师、采购 | 厂商技术联系人、安全、QA | 产品、SRE |
| 伙伴招募与意愿 | 产品负责人 | 商务/客户成功 | 法务、隐私、QA | 项目发起人 |
| 样本授权与删除 | 隐私/安全负责人 | 数据保管人 | 伙伴授权人、QA、法务 | 项目发起人 |
| 独立准入与状态变更 | 项目发起人 | PM/QA | 架构、安全、对应轨负责人 | 全体 |

任何一人不得同时完成材料提供、验真和最终批准。具名联系人和责任日期在受控系统登记，不在公开仓库保存个人联系方式。

## 4. Go/No-Go 规则

- 单轨 `GO`：该轨完整受控包达到 `VERIFIED_DOCUMENT`、无 P0 缺口、测试方案/停止条件/回退明确，并由项目发起人单独确认。
- 单轨 `CONDITIONAL GO`：仅允许明确列出的非破坏性执行；任何条件超界立即停止。
- 单轨 `NO-GO`：资料缺失、授权不清、Secret/PII 不安全、无法回退或依赖未满足。
- 完整 Alpha `GO`：三条外部 P0 均经独立执行形成要求等级证据，内部门禁仍有效，P0/P1 缺陷清零，并另行评审 `T2-UAT-001/REL-001`。

本次三轨均为 `NO-GO`，因此不创建绿色占位、不变更 RTM 状态。
