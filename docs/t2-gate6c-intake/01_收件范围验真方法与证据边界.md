# Gate 6C 收件范围、验真方法与证据边界

## 1. 授权与基线

- 唯一起点：Gate 6C-Prep 封存提交 `74f5100b89a7cf98acd28622e5ccdc4beb7626b7`。
- 当前授权：公开官方资料收件、受控资料目录登记、离线来源/哈希/适用范围核验，以及三条独立执行准入报告。
- 当前禁止：Provider SDK/HTTP 调用、沙箱端点探测、真实终端安装/重启/固件/钱箱命令、现场试点、完整 Alpha UAT。
- 状态守恒：`T2-PAY-002/HWD-001/PAR-001=BLOCKED`，`T2-UAT-001/REL-001=DRAFT`。

## 2. 本次“首批收件”的两层模型

| 层级 | 允许材料 | 本次结果 | 可以证明 | 不能证明 |
|---|---|---|---|---|
| 公开官方层 | 官网产品页、开放平台、公开 API/SDK 文档 | 支付 9 份、硬件 7 份公开响应已登记 URL/哈希 | 候选存在、公开能力和待询问题 | 授权沙箱、合同、精确产品权限、样机兼容、伙伴意愿 |
| 受控外部层 | 授权函、测试商户/终端引用、版本化接口包、SDK 授权、样机清单、书面意愿 | 尚未收到完整包 | 达到 `VERIFIED_DOCUMENT` 后可申请执行准入 | 在发起人确认前仍不能执行网络、设备或试点 |

公开材料使用子标签 `PUBLIC_OFFICIAL_DOCUMENT`，不得直接把需求整体提升为 ADR-035 定义的 `VERIFIED_DOCUMENT`。只有执行所需受控材料全部完成来源、授权、版本、范围、摘要、保管人和到期核验后，独立报告才能建议 `GO`。

## 3. 离线验真步骤

1. 仅对公开官网执行普通 HTTPS GET，禁止访问页面中展示的测试/生产 API 地址。
2. 核对最终 URL 的机构官方域名；重定向到非官方或下载站时拒收或单独标记。
3. 保存原始响应到本地忽略目录，登记取得时间、字节数和 SHA-256；原始响应不提交 Git。
4. 从材料中抽取“公开声称”，同时登记适用产品、版本、地区与免责声明；不把示例凭据或端点视为授权。
5. 受控材料只在批准的文档/Secret 系统保存，Git 仅登记不透明引用和摘要。
6. 任一来源、授权、版本或适用范围无法确认时，将该项标为 `MISSING/RECEIVED_UNVERIFIED`，并保持 `NO-GO`。

## 4. 验真判定

| 判定 | 条件 | 后续 |
|---|---|---|
| `OFFICIAL_DOMAIN_HASHED` | 官方域名可达，响应已离线哈希 | 可进入 RFI 对照，不可执行 |
| `RECEIVED_UNVERIFIED` | 收到受控文件但授权、签署、版本或摘要未闭环 | 隔离、补件 |
| `VERIFIED_DOCUMENT` | 执行必需受控包完整，来源/授权/版本/范围/保管/摘要均通过 | 只允许提交独立执行准入评审 |
| `EXECUTED_EXTERNAL` | 经另行批准后在指定沙箱/样机/伙伴执行并封存证据 | 仅支持对应轨结论 |

## 5. 安全与版权

- 仓库不保存公开网页全文，只保存事实摘要、URL 与响应哈希；引用以必要事实为限。
- 不记录 Secret 值、证书私钥、真实手机号、银行卡、商户号、终端号、设备序列号或门店原始数据。
- RFI 回件若含敏感内容，先由安全负责人分类和隔离；生成脱敏元数据后才允许进入评审。
- 公开页面后续变化时重新取得并生成新证据 ID，不覆盖旧记录。
