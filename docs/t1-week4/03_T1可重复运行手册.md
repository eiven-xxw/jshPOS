# T1 可重复运行手册

## 1. 目的与边界

本手册用于在干净环境复跑 T1 Week 1—3 的内部 `STATIC/FAKE` 风险证据，并比较 Ubuntu/Windows 的归一化语义摘要。它不执行支付沙箱、真实网络、Android 实机、物理断电、外设或门店试点。

## 2. 前置条件

- Git 完整历史和 annotated tag `t0-baseline-2026-08-16`；
- Python 3.12；T1 PoC 只使用 Python 标准库；
- 当前提交必须继承 T0 tag；
- 不设置支付、设备或生产 Secret；不需要外部账号；
- 输出目录必须位于被 Git 忽略的 `artifacts/`。

## 3. 本地静态门禁

Windows PowerShell 或 POSIX Shell 均可逐条执行：

```text
python scripts/check_t0_structure.py
python scripts/check_rtm.py
python scripts/check_contracts.py
python scripts/check_t1_prep.py
python scripts/check_t1_week1.py
python scripts/check_t1_week2.py --output artifacts/t1/week2/static-recheck.json
python scripts/check_t1_week3.py --output artifacts/t1/week3/static-recheck.json
python scripts/check_t1_week4.py --output artifacts/t1/week4/static-audit.json
```

任何命令非零退出都必须停止。不得使用 `|| true`、`continue-on-error`、跳过测试或降低 HIGH/CRITICAL 阈值。

## 4. 单平台完整复跑

Ubuntu：

```text
python scripts/run_t1_reproducibility.py --platform ubuntu --output-dir artifacts/t1/week4/ubuntu
```

Windows：

```text
python scripts/run_t1_reproducibility.py --platform windows --output-dir artifacts/t1/week4/windows
```

每个平台输出：

- Week 1、2、3 原始 FAKE 证据及各自 SHA-256；
- `normalized-evidence.json`；
- `reproducibility-summary.json`；
- 输入 Git blob 树摘要和失败 seed 总账摘要；
- 原始执行时长，仅作趋势参考。

## 5. 跨平台比较

将两个平台制品放入对应目录后执行：

```text
python scripts/compare_t1_reproducibility.py --ubuntu-dir artifacts/t1/week4/ubuntu --windows-dir artifacts/t1/week4/windows --output artifacts/t1/week4/reproducibility-comparison.json
python scripts/check_t1_week4.py --validate-comparison artifacts/t1/week4/reproducibility-comparison.json --output artifacts/t1/week4/static-audit-with-comparison.json
```

比较必须同时满足：

- `commitSha` 一致；
- Git 输入树摘要和输入文件数量一致；
- 失败 seed 总账摘要一致且未跟踪失败为 0；
- Week 1—3 结果数、断言数、迭代数一致；
- 两份 `normalized-evidence.json` 字节 SHA-256 一致。

## 6. 归一化规则

原始证据不可修改。跨平台语义摘要只排除：

- `generatedAt`；
- metrics 内名称包含 `second`、`duration`、`p95`、`memory`、`mib`、`ratio` 或 `peak` 的性能趋势字段。

结果、状态、断言、迭代、fixture digest、不变量指标、提交号、限制声明和失败 seed 均保留。若这些稳定字段不一致，比较门禁必须失败。

## 7. SBOM、许可证和安全摘要

```text
python scripts/build_t1_poc_inventory.py --output-dir artifacts/t1/week4/inventory
```

输出 T1 PoC CycloneDX SBOM、许可证/CI 工具清单和安全摘要。T1 没有第三方 Python 运行依赖；商业产品依赖继续以 T0 聚合 SBOM、ADR-015 和全仓库 CI 为准。

GitHub CI 另外执行 Trivy HIGH/CRITICAL 漏洞、Secret 和 Workflow 配置扫描。STATIC 结果不得替代 `SANDBOX` 或 `REAL_DEVICE`。

## 8. 故障处理

1. 保存失败平台、提交、原始证据、固定 seed 和日志；
2. 新失败 seed 先写入 `observedFailedSeeds`，不得删除夹具；
3. 定位是平台差异、非确定性、产品不变量缺陷还是证据归一化错误；
4. 先补回归，再修复；修复通过后写入 `fixedFailedSeeds`；
5. 两个平台全部重新运行，不允许只重跑绿色平台；
6. 若存在未修复 P0/P1、摘要不一致或证据分级污染，Week 4 判定 `NO-GO`。

## 9. 外部证据提醒

实机、外设、支付沙箱和设计伙伴资料仍为 `BLOCKED`。获得真实资料后必须建立独立 `SANDBOX`、`REAL_DEVICE` 或 `PILOT` 轨道，不能覆盖或改名复用本手册的 Fake 制品。
