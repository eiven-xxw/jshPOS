# T2-EXC-001 设计准入与验收冻结

## 1. 范围与非目标

本需求提供同步、数据包、支付/退款、库存、成本、报表与日结异常的统一案件、认领、
转派、处置计划、Owner 命令观察、独立复核、关闭、重开和审计工作台。它不拥有来源
事实，不重算或改写任何资金、库存、成本、投影或日结事实，不执行 Provider 网络或设备
命令。外部阻断只显示 `BLOCKED/UNAVAILABLE`。

## 2. 数据主权与访问策略

Operations 独占 `ops_exception_case`、`ops_exception_observation`、`ops_exception_lease_event`、
`ops_exception_action_plan`、`ops_exception_repair_command`、`ops_exception_review`、
`ops_exception_state_event`、`ops_exception_audit_event` 与 `ops_exception_outbox`。

| 表 | 访问策略 | SQL | 说明 |
|---|---|---|---|
| case / action_plan / repair_command | CONTROLLED_WRITE | XML | 仅具名条件迁移与乐观锁 |
| observation / lease_event / review / state_event / audit / outbox | APPEND_ONLY | XML | 禁止 UPDATE/DELETE |
| 列表与详情组合 | READ_PROJECTION | XML | 显式列、可信 tenant/store 条件 |

所有 Owner 读取与修复只经版本化事件或显式应用端口；禁止跨 Owner Mapper、任意 SQL、
前端拼装来源事实或直接修改 Owner 表。

## 3. 稳定身份、状态与不变量

- 身份绑定可信 `tenant_id/store_id`、`source_owner/type/fact/event/sequence/sha256`、
  `dedup_key`、首次/最近观察时间和关联标识。
- 同来源同摘要幂等；同来源异摘要只追加观察并进入显式冲突，禁止覆盖。
- 状态为 `OPEN → CLAIMED → IN_PROGRESS → WAITING_OWNER/RESOLVED → CLOSED`，并支持
  `FAILED`、`REOPENED`；所有迁移写只追加历史。
- 认领为有期限租约，使用可信用户、UTC 到期时间和乐观锁。转派、批量操作、复核与关闭
  必须具备独立权限；关闭复核人与当前认领人不得相同。
- 修复命令绑定稳定幂等键、请求摘要和来源观察；同键异内容拒绝。超时、重启或 ACK 丢失
  只能观察原命令，不得重新生成资金或业务命令。
- 支付/退款 UNKNOWN 只允许 Provider 无关观察，PAY-002 未解阻时保持 WAITING_OWNER。

## 4. API、页面与错误

OpenAPI 冻结在 `contracts/t2/gate7d-exc001/openapi-exception-center-v1.yaml`。Vue 工作台只
调用正式 API，支持可信门店筛选、来源/严重级别队列、血缘、认领、转派、计划、修复
状态、独立复核、关闭/重开和审计时间线。批量上限 100，查询上限 100；页面不计算
Owner 结果。错误码前缀 `OPS-EXC-*`，冲突返回 409，权限 403，不可见 404，Owner 不可用 503。

## 5. 迁移、容量、兼容与回退

V73 建立异常控制面与只追加事实，V74 建立权限菜单；均为只前进迁移。案件 ID、观察 ID、
命令 ID 使用 ULID；摘要使用小写 SHA-256。列表索引按租户、门店、状态、严重级别、观察
时间设计。单租户百万开放案件只做合成索引趋势，不形成 SLA。失败采用前向修复；已写
观察、状态、审计和命令引用不得删除，回退应用时保留为不可见兼容数据。

## 6. 量化验收

1. 八类状态、租约过期、并发认领、职责分离和非法迁移全覆盖；
2. 七类 Owner 来源均可形成权威观察，外部未解阻路径明确 `BLOCKED/UNAVAILABLE`；
3. 重复、乱序、晚到、同键异内容、超时、ACK 丢失、重启和重新出现可收敛；
4. 两虚构租户、多门店攻击，所有 Mapper/XML/API/缓存/导出路径零越权；
5. MySQL 8.4 实迁移、约束、只追加触发器、百万合成趋势和前向修复通过；
6. Server、Web、Flutter 双平台、SQLite、Android/Kotlin、安全、SBOM、许可证、覆盖率和
   Gate 0—7D 既有回归全绿；P0/P1 缺陷为零后只更新为 `VERIFIED`。
