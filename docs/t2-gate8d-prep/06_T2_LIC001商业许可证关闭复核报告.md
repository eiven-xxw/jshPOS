# T2-LIC-001 商业许可证关闭复核报告

## 1. 独立结论

`DEFERRED / OPEN 0/3 / NO_GO COMMERCIAL RELEASE`。本轮只复核仓库声明和既有发布证据；
未收到适用于精确版本、地域和分发模式的书面法务意见，也未完成替换后的全量回归与最终
发布 SBOM。因此任何组件都不能标记 `CLOSED`。

## 3. 可接受的关闭路径

1. **替换路径**：精确使用清单 → ADR/变更准入 → 删除或替换 → 功能/性能/安全/兼容/全 Gate
   回归 → JAR/Web/APK/容器最终 SBOM 和许可证清单确认旧组件为 0 → 发布 Owner 与法务签署。
2. **法务路径**：固定坐标、版本、地域、部署/分发/客户交付方式 → 书面意见或商业许可 →
   NOTICE/源代码 offer/归属等履约清单 → 最终 SBOM/发布 BOM 一致 → 法务与发布联合签署。

## 4. 逐项建议

- Aviator：先证明是否有实际业务运行时引用；若只剩依赖管理声明，优先通过独立技术 CR 移除，
  再以最终 SBOM 和全量回归关闭技术路径。
- simple-http：先从完整 Maven 依赖树、JAR 内容和 CycloneDX SBOM 证明三栈均为 0；若为 0，
  仍需发布/法务角色签署“无需履约”的关闭证据。
- MySQL Connector/J：商业 V1 仍需要 MySQL，优先由法务对部署/分发模型给出书面结论；若不能
  接受，则单独评估驱动和交付模式，禁止在本准备阶段仓促替换。

## 5. Go/No-Go

`T2-LIC-001` 继续 `DEFERRED`，不阻断内部准备，但在 `T2-REL-001 READY` 和任何商业发布前
必须 3/3 `CLOSED`。当前商业发布固定 `NO_GO`。
