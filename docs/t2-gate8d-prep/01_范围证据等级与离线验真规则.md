# Gate 8D-Prep 范围、证据等级与离线验真规则

## 1. 授权范围

允许：受控材料元数据核验、来源/授权/版本/范围/摘要/保管/生命周期检查、许可证证据复核、
UAT/REL 入口冻结、治理与 CI。禁止：Provider 网络、真实资金、安装/重启/控制设备、调用
真实外设、联系伙伴或门店、完整 Alpha、生产部署、商业 tag、商业声明和 SLA。

## 2. 材料保管边界

仓库只能保存以下非敏感字段：不透明 ID、受控位置引用、来源主体、授权签署角色、适用产品/
型号和版本、允许范围、原文 SHA-256、保管角色、到期、轮换、删除、吊销和验真时间。以下内容
不得进入 Git、普通日志、CI 或普通 Artifact：受控原文、Secret、商户号、终端号、证书私钥、
设备序列号、联系人身份、真实 PII 和未脱敏商户数据。

## 3. 证据等级

| 等级 | 含义 | 能否授权执行 |
|---|---|---|
| MISSING | 未提供真实不透明引用或必要元数据 | 否 |
| RECEIVED_UNVERIFIED | 已登记但来源、授权、摘要或范围未完成核验 | 否 |
| VERIFIED_DOCUMENT | 整包材料完整且逐项离线验真通过 | 否，仍须独立批准 |
| EXECUTION_APPROVED | 项目发起人对单一轨道明确批准执行 | 仅批准范围内 |
| EXECUTION_VERIFIED | 获批执行完成且证据达标 | 不能自动形成商业批准 |

公开网页、型号系列、Fake、合成数据、内部候选和历史模板最高只能作为线索或内部软件证据，
不得提升为 `VERIFIED_DOCUMENT`。

## 4. 逐项验真算法

1. 解析不透明引用，不在普通输出中展开敏感值；
2. 核验来源和签署人对适用主体、产品/型号、环境和用例具有授权；
3. 核验版本、范围、有效期、轮换、删除和吊销规则互相一致；
4. 在受控位置计算或核对 SHA-256，禁止复制原文到工作区；
5. 核验保管人、最小访问和审计；
6. 任一必需项缺失、摘要漂移、授权不明或过期则整包失败关闭；
7. 达到 `VERIFIED_DOCUMENT` 后只生成独立执行准入报告，等待项目发起人确认。
