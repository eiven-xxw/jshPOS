# 文档说明

## 1. 编写目的

本文给出商业 V1 从治理、架构、研发、运维、隐私、等保、支付边界、备份、灾难恢复和事件响应到验收证据的实施方案。它不是单纯的安全口号清单，而是每个控制项的责任人、技术措施、运行频率、证据和验收门槛。

## 2. 法律与标准基线

- 适用 2026 年 1 月 1 日起施行的修正版《中华人民共和国网络安全法》：[中国人大网修法决定](https://www.npc.gov.cn/npc/c1773/c1848/c21114/wlaqfxz/wlaqfxz002/202511/t20251103_449242.html)。
- 个人信息处理遵循合法、正当、必要、诚信和最小范围原则，并落实个人权利、敏感信息、影响评估和处理者义务：[《个人信息保护法》](https://www.npc.gov.cn/WZWSREL25wYy9jMi9jMzA4MzQvMjAyMTA4L3QyMDIxMDgyMF8zMTMwODguaHRtbD9yZWY9aW1i)。
- 数据分类分级和数据安全责任遵循《数据安全法》：[工业和信息化部转载全文](https://www.miit.gov.cn/zwgk/zcwj/flfg/art/2022/art_284b390b84484f10b0e43eeafaad0f6d.html)。
- 《网络数据安全管理条例》自 2025 年 1 月 1 日施行，明确在等保基础上采取加密、备份、访问控制、安全认证等措施：[国家行政法规库](https://xzfg.moj.gov.cn/front/law/detail?LawID=1734)。
- 等保建设以现行 GB/T 22239-2019 基本要求、GB/T 25058-2019 实施指南、GB/T 25070-2019 安全设计、GB/T 28448-2019 测评要求等为基线：[国家标准全文公开系统](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=BAFB47E8874764186BDB7865E8344DAF)。
- 应用安全验证采用 OWASP ASVS 5.0.0 的适用控制作为工程基线：[OWASP ASVS](https://owasp.org/www-project-application-security-verification-standard/)。
- 如系统存储、处理、传输持卡人数据或能影响持卡人数据环境，应按 PCI DSS 4.0.1 正式定界和评估；本方案优先通过持证支付 SDK/终端和令牌化缩小范围：[PCI SSC](https://www.pcisecuritystandards.org/standards/pci-dss/)。

本文不是法律意见或正式等保定级结论。生产上线前应由法务、隐私负责人、主管部门及合格测评/支付评估机构确认适用范围。

## 3. 安全目标

- 交易事实不丢失、不重复、不被未授权修改；
- tenant_id 隔离贯穿身份、SQL、缓存、消息、对象存储和日志；
- 资金、库存、优惠、会员和结算变更可追溯；
- POS 离线时仍受设备、时间、额度和签名约束；
- 外部接口最小权限、可吊销、可限流；
- 个人信息最小化、可查、可更正、可删除或依法保留；
- 安全事件可发现、可止损、可取证、可恢复；
- 单组件故障、可用区故障和区域灾难有分层恢复方案。

- 到期自动重新评审。
- 合规强制项不能用风险接受替代。

# 二、等保实施路线

## 2.1 建议定级

建议把“连接器型商业收银经营平台生产系统”作为一个候选定级对象评估，商业 V1 按第二级基线建设。以下情况需重点评估第三级：

- 服务大量跨区域门店并造成较大社会影响；
- 承载重要数据或被行业主管部门认定重要系统；
- 进入大型集团、政府、国企或关基供应链；
- 业务中断对公共利益或经济运行影响显著；
- 客户合同明确要求三级。

最终定级应结合业务影响分析、系统边界、主管部门意见和专业机构建议。

## 2.2 工作阶段

1. 定级对象边界梳理。
2. 专家评审/主管部门确认。
3. 公安机关备案。
4. 差距分析。
5. 安全建设整改。
6. 等保测评。
7. 问题整改和复核。
8. 持续监测、年度复审/按要求测评。
9. 重大变更重新评估。

## 2.3 对象边界

纳入候选边界：

- API Gateway/WAF；
- RuoYi-Vue-Plus SaaS 管理与业务服务；
- 开放平台、连接器 Gateway/Runtime；
- MySQL、Redis、MQ/任务、对象存储；
- 身份、密钥、日志、监控；
- CI/CD 生产发布链；
- 生产运维入口；
- POS 设备管理和同步云端。

Android POS 是外部/边缘终端，但其身份、证书、离线数据和同步协议属于整体安全控制。

## 2.4 控制域

对照等保技术与管理要求至少覆盖：

- 安全物理环境；
- 安全通信网络；
- 安全区域边界；
- 安全计算环境；
- 安全管理中心；
- 安全管理制度；
- 安全管理机构；
- 安全管理人员；
- 安全建设管理；

- 云计算、移动互联等适用扩展。

| 类别 | 示例 |

## 3.2 数据分级

| 级别 | 示例 | 控制 |
|---|---|---|
| L1 公开 | 公开商品宣传信息 | 完整性和发布控制 |

## 3.3 个人信息目录

- 员工身份、排班、操作记录；

- 售后证据；

# 四、多租户安全

## 4.1 tenant_id

- tenant_id 为 VARCHAR(20)，由认证上下文注入。
- 订单、支付、退款、设备、命令和事件等领域标识使用 ULID，避免终端离线申请主键并保持全链路可追踪。
- 客户端 tenant_id 只作一致性校验。
- 所有租户业务表包含 tenant_id。
- 唯一索引、查询、缓存、Outbox/Inbox、对象路径包含租户范围。
- 平台级表和租户级表明确区分。

## 4.2 防越权

- Repository 默认租户拦截。
- 关键查询同时校验数据范围。
- 禁止拼接 SQL 绕过插件。
- 异步线程显式传播不可伪造的 TenantContext。
- 定时任务分租户执行并清理上下文。
- 导入导出二次校验。
- 对象存储预签名 URL 绑定租户、对象和短时 TTL。
- 全局管理员使用独立身份、JIT 授权和完整审计。

## 4.3 测试

- 每个开放/内部 API 有跨租户负向测试。
- 基于随机 tenant_id 的属性测试。
- SQL 日志/静态规则检查缺失 tenant 条件。
- 缓存键冲突测试。
- 消息篡改 tenant_id 测试。
- 运维导出、备份恢复和数据迁移隔离测试。

跨租户读写属于 P0。

# 五、身份与访问

## 5.1 身份

- 管理用户；
- 门店员工；
- 平台运维；
- Android 设备；
- 开放应用；
- 连接器实例；
- 服务身份。

不同主体使用不同 credential，不共享“超级 API Key”。

## 5.2 认证

- 管理后台支持 MFA，平台管理员强制 MFA。
- 密码使用现代自适应哈希 Argon2id/bcrypt，参数可升级。
- 防撞库、限速、异常登录和会话撤销。
- 设备使用证书/密钥与短期 token。
- 服务间使用短期工作负载身份、mTLS 或签名 token。
- 开放平台按 POS-DD-038。
- 连接器密钥按 POS-DD-037。

## 5.3 授权

RBAC + data_scope + 业务守卫：

- 角色控制菜单/动作；
- 数据范围控制租户、组织、门店、仓；
- 业务守卫控制金额、状态、班次和职责分离；
- 字段级控制敏感信息；
- 条件访问控制设备、网络、风险和时间。

## 5.4 高风险动作

- 退款；
- 无原单退货；
- 储值/积分调整；
- 手工库存/成本调整；
- 促销发布；
- 密钥查看/轮换；
- 批量导出；
- 跨租户运维；
- 备份恢复；
- 审计关闭。

使用 MFA/step-up、审批、双人复核、原因、证据和不可变审计。

## 5.5 权限生命周期

- 入职最小权限。
- 转岗当日复核。
- 离职即时禁用。
- 临时权限自动到期。
- 高权限每月复核，普通权限每季度。
- 90 天未用账号处理。
- 服务账号无交互登录。
- Break-glass 双人启用、短时、全程告警和事后复核。

# 六、密码与密钥

## 6.1 密钥类型

- TLS；
- JWT/JWKS；
- 设备证书；
- Webhook 签名；
- 数据包签名；
- 数据库/字段加密；
- 对象存储；
- 备份；
- 支付/连接器凭证；
- CI/CD 签名。

## 6.2 管理

- 密钥存 KMS/HSM/Vault，不写源码、配置库、镜像或日志。
- 应用只保存 secret_ref。
- 每个环境、租户/伙伴和用途隔离。
- key_id/version 明确。
- 支持双密钥验证窗口和无停机轮换。
- 访问由工作负载身份和最小权限控制。
- 密钥导出、轮换、吊销和失败告警。
- 备份密钥与数据备份分开保管。

## 6.3 轮换

| 类型 | 建议 |
|---|---|
| 短期访问 token | 分钟级 |
| 数据库密码/服务 secret | 90 天或自动轮换 |
| Webhook/连接器密钥 | 90—180 天 |
| TLS 证书 | 自动续期，短周期优先 |
| 数据加密主密钥 | 年度/风险触发 |
| 包签名密钥 | 年度并保留验证历史 |

泄漏时立即吊销，不等待常规周期。

# 七、数据加密与脱敏

## 7.1 传输

- 外部和内部敏感链路 TLS 1.2+，优先 1.3。
- 禁用弱协议和套件。
- 数据库、Redis、MQ、对象存储启用 TLS。
- 管理/运维入口 VPN/ZTNA + MFA。
- POS、Edge Agent、Webhook 可使用 mTLS/消息签名。

## 7.2 存储

- 云盘/数据库/对象存储服务端加密。
- L4 字段使用应用层字段加密或令牌化。
- 密钥与数据分离。
- 本地 POS 数据库按设备能力加密，私钥在 Android Keystore。
- 备份全程加密。
- 测试环境不使用未经脱敏生产数据。

## 7.3 展示

- 手机号、地址、姓名、证件、银行卡标识默认掩码。
- 根据业务目的临时解密。
- 查看明文属于敏感动作并审计。
- 导出进一步脱敏/水印。
- 日志使用 ID/hash，不写完整值。

## 7.4 密码学

- 使用成熟库和合规算法。
- 不自创加密。
- AEAD 优先，例如 AES-GCM。
- nonce/IV 不复用。
- Hash 用 SHA-256 或更强。
- 口令哈希加盐并自适应。
- 算法可替换，禁止写死不可迁移格式。

# 八、支付安全边界

## 8.1 最小范围

- 二维码支付只保存平台交易号、金额、状态和脱敏渠道信息。
- 银行卡通过独立持证终端/SDK，POS 不采集 PIN、磁道、CVV。
- 不在服务端日志、数据库或小票保存完整 PAN。
- 支付密钥由支付模块/密钥服务持有。
- 回调验签、金额/币种/商户校验。
- 支付 UNKNOWN 查询，不盲目重扣。

## 8.2 PCI

若任何组件存储、处理、传输 CHD/SAD 或可影响 CDE：

- 由 QSA/收单机构正式定界；
- 采用 PCI DSS 4.0.1；
- 网络分段；
- 安全日志、漏洞扫描、渗透和访问控制；
- SAQ/ROC 资格不能自行假定；
- 终端和 SDK 需满足适用 PCI PTS/MPoC/软件标准。

产品路线优先保持“无卡数据/令牌化/外置支付终端”。

# 九、应用与 API 安全

## 9.1 安全开发

- 威胁建模：订单、支付、退款、库存、离线、连接器、开放 API。
- 安全需求进入 Backlog 和验收。
- 代码评审和 CODEOWNERS。
- SAST、SCA、Secret、IaC、容器扫描。
- 单元/集成安全测试。
- DAST 与渗透。
- SBOM、制品签名和 provenance。
- 生产变更审批和回滚。

## 9.2 ASVS

商业 V1：

- 普通管理与开放 API 以 ASVS L2 适用项为基线。
- 身份、支付、储值、退款、密钥和平台运维按更高风险强化。
- 每个适用控制映射到测试和证据。
- 不把“扫描无高危”视为 ASVS 通过。

## 9.3 输入与输出

- DTO Schema 验证；
- 长度、类型、枚举、Decimal 精度；
- 参数化 SQL；
- 输出编码；
- HTML/Markdown 清洗；
- 文件类型/大小/病毒扫描；
- SSRF URL allowlist/解析后 IP 校验；
- 解压缩大小限制；
- JSON 深度/节点限制；
- 防 Mass Assignment。

## 9.4 API

- OAuth/Scope/Data Scope；
- BOLA/BFLA；
- Idempotency-Key；
- ETag/If-Match；
- 限流和业务滥用；
- RFC 9457 脱敏错误；
- API Inventory 与版本退役；
- Webhook RFC 9421/9530 签名；
- 外部响应不可信。

# 十、POS 与设备安全

## 10.1 应用

- Release 签名、完整性和官方分发。
- 禁止生产调试、明文网络和 WebView 不安全桥。
- Root/模拟器/Hook 风险按策略告警或限制。
- Android Keystore。
- 数据库和日志保护。
- 截屏、剪贴板、外部存储按敏感页面限制。
- 后台任务与导出授权。

## 10.2 Kiosk

- Fully Managed + DPC/EMM。
- Lock task allowlist。
- 禁用 USB 调试、未知来源、非授权 App。
- 远程锁定、擦除和证书吊销。
- 系统补丁/固件 SLA。
- 设备退役先同步、吊销和受控擦除。

## 10.3 离线

- 离线授权期限；
- SKU/金额/储值/券额度；
- 规则包签名与有效期；
- Outbox 不可删除；
- 相同 event_id 不同 hash 阻断；
- 设备克隆检测；
- 时间漂移；
- 未同步交易换机流程。

# 十一、基础设施与网络

## 11.1 分区

建议：

- Internet/WAF/Gateway；
- Application；
- Data；
- Management；
- Security/Logging；
- Build；
- Backup/DR。

默认拒绝，按端口、身份和方向最小开放。

## 11.2 边界

- WAF、DDoS、防 Bot。
- 管理端不直接暴露公网。
- 数据库/Redis/MQ 无公网。
- 出站代理/域名 allowlist，连接器隔离。
- 云安全组、网络 ACL 与主机防火墙。
- 流量和 DNS 日志。
- SSRF 到元数据地址阻断。

## 11.3 主机/容器

- 最小镜像、非 root。
- 只读文件系统和最小 capabilities。
- 漏洞基线与补丁。
- EDR/运行时防护按环境。
- 禁止共享宿主机敏感目录。
- 资源 limits/requests。
- 镜像签名和准入。
- 不在镜像写 secret。

## 11.4 数据库

- 独立账号和最小权限。
- 应用无 DDL/超级权限。
- TLS、审计和慢查询。
- tenant_id 索引和拦截。
- PITR/备份。
- 高可用主备。
- 禁止生产人工直改交易表。
- Break-glass SQL 双人审批和留痕。

## 11.5 Redis/MQ

- 私网、认证/TLS。
- tenant_id 缓存键。
- Redis 不是交易事实。
- 消息 ACL、Inbox/Outbox。
- DLQ 和积压告警。
- 不在消息头放 secret/PII。

# 十三、隐私治理

## 13.1 处理原则

- 明确目的；
- 最小必要；
- 公开透明；
- 准确；
- 保留最短；
- 安全；
- 可问责。

## 13.2 告知与同意

- 租户/商户是处理者或受托处理角色需合同明确。
- 会员注册、营销、定位、画像、跨主体共享分开评估。
- 敏感个人信息满足特定目的、充分必要和严格保护，并履行单独同意等适用要求。
- 不把拒绝非必要同意作为基础收银服务前提。
- 同意有版本、时间、渠道和撤回。

## 13.3 权利请求

支持：

- 知情/查阅；
- 复制；
- 更正/补充；
- 删除；
- 撤回同意；
- 注销；
- 解释自动化决策。

工单需核验身份、计算范围、排除他人信息、记录响应时间和结果。交易/财务依法保留的数据可限制删除，但应说明并限制用途。

## 13.4 PIPIA

以下场景进行个人信息保护影响评估：

- 敏感个人信息；
- 自动化决策；
- 委托、共享/提供；
- 公开；
- 跨境；
- 大规模监控/画像；
- 新连接器/会员能力；
- 重大技术变更。

报告记录目的、影响、风险、措施和结论，并按法律要求保存。

## 13.5 委托与第三方

- 数据处理协议；
- 目的、期限、方式、种类、保护措施；
- 子处理者；
- 安全事件通知；
- 删除/返还；
- 审计权；
- 数据位置；
- 终止机制。

## 13.6 跨境

商业 V1 默认中国境内存储和处理境内生产个人信息，不默认跨境。发生跨境前：

- 完成数据地图和必要性；
- 确认适用途径和阈值；
- 履行告知/单独同意等；
- 完成影响评估；
- 采用适用安全评估、标准合同或认证；
- 合同和持续监督；
- 不把开发日志或海外监控当作“小量无风险”。

# 十五、漏洞管理

## 15.1 来源

- 自动扫描；
- 渗透；
- 厂商通告；
- CVE/SBOM；
- Bug bounty/客户；
- 日志与事件；
- 等保测评。

## 15.2 SLA

建议：

| 级别 | 处置 |
|---|---|
| Critical/在利用 | 24 小时内缓解，72 小时内修复或管理层批准 |
| High | 7 天 |
| Medium | 30 天 |
| Low | 90 天 |

结合暴露面、数据、可利用性调整。无法及时修复时实施 WAF、关闭能力、隔离、轮换密钥等补偿。

- 每年至少一次；
- 重大架构/支付/开放平台变更后；
- 覆盖 Web、API、Android、租户隔离、连接器、Webhook；
- 修复后复测；
- 报告脱敏和严格访问。

# 十六、备份策略

## 16.1 目标

采用 3-2-1-1-0 思路：

- 至少 3 份数据；
- 2 种介质/独立故障域；
- 1 份异地；
- 1 份不可变/离线；
- 通过恢复验证达到 0 个未解决错误。

## 16.2 备份对象

- MySQL 全量、增量/binlog；
- 对象存储；
- 配置、Schema、迁移脚本；
- 密钥元数据与独立密钥恢复材料；
- 审计日志；
- CI/CD 和 IaC；
- 连接器映射/原文；
- 设备/应用注册；
- 业务报表定义。

Redis 缓存不作为恢复事实，但其配置和必要持久化策略记录。

## 16.3 频率

| 对象 | 建议 |
|---|---|
| MySQL PITR | 连续 binlog，RPO 5 分钟内 |
| MySQL 全量 | 每日 |
| 对象存储 | 版本化 + 跨域复制 |
| 配置/IaC | 每次变更 + 每日快照 |
| 审计日志 | 实时集中 + 不可变归档 |
| 密钥恢复材料 | 每次轮换 + 双人保管 |

## 16.4 保护

- 加密；
- 备份账号独立；
- 生产删除权限不能删除不可变备份；
- 保留锁；
- 跨账号/跨区域；
- 恶意软件扫描；
- 备份清单和哈希；
- 到期受控销毁。

## 16.5 恢复验证

- 每月抽样恢复。
- 每季度数据库完整恢复。
- 每半年跨区域灾备演练。
- 恢复后执行业务对账、租户隔离和安全校验。
- 记录实际 RTO/RPO。
- 不能恢复的备份等同备份失败。

# 十七、高可用与灾备

## 17.1 故障层级

| 层级 | 示例 | 策略 |
|---|---|---|
| 组件 | 单实例、进程 | 多实例/自动重启 |
| 节点 | VM/宿主机 | 跨节点调度 |
| 可用区 | AZ 故障 | 多 AZ 应用和数据库主备 |
| 区域 | 云 Region | 异地备份/冷暖备恢复 |
| 逻辑 | 误删、勒索、坏发布 | PITR、不可变备份、回滚 |
| 终端网络 | 门店断网 | POS 离线营业 |

## 17.2 服务等级

| 等级 | 系统 | 同区域 RTO/RPO | 区域灾难 RTO/RPO |
|---|---|---|---|
| T0 | 订单、支付引用、退款、同步 | 30 分钟 / 5 分钟 | 4 小时 / 1 小时 |
| T1 | 库存、价格、促销、会员权益 | 1 小时 / 15 分钟 | 8 小时 / 4 小时 |
| T2 | 后台、报表、连接器非交易任务 | 4 小时 / 1 小时 | 24 小时 / 24 小时 |
| T3 | 历史分析/低优先辅助 | 24 小时 / 24 小时 | 72 小时 / 24 小时 |

合同如更严，基础设施和成本需对应升级。RTO/RPO 只有在演练通过后才能对外承诺。

## 17.3 同区域高可用

- Gateway/应用多实例；
- 无状态会话或可恢复会话；
- MySQL 同区域多 AZ 主备；
- Redis 高可用但缓存可重建；
- MQ/任务高可用；
- 对象存储多副本；
- 健康检查、熔断、限流；
- 部署跨故障域；
- 容量预留 N+1。

## 17.4 区域灾难

商业 V1 建议暖备/可编排冷备：

- IaC 可在备用区域重建；
- 加密跨区域备份；
- 域名/DNS/证书预案；
- 密钥和 secret 可恢复；
- 外部支付/连接器 IP 白名单预先规划；
- 数据恢复顺序；
- 人工 Go 决策；
- 回切方案。

不建议 V1 直接承诺跨区域双活交易，复杂度会显著增加资金/库存一致性风险。

## 17.5 恢复顺序

1. 安全与身份/KMS。
2. 网络、DNS、Gateway。
3. MySQL 权威数据。
4. Order/Payment/Refund/Sync。
5. Inventory/Pricing/Promotion/Member。
6. Open API/Connector。
7. 报表和低优先任务。
8. 对账与积压追赶。

恢复期间 POS 依据离线能力矩阵营业。

# 十九、事件响应

## 19.1 级别

| 级别 | 示例 | 响应 |
|---|---|---|
| P0 | 跨租户、大规模数据泄漏、重复扣款、核心不可恢复 | 立即启动最高级响应 |
| P1 | 高危攻击、核心中断、密钥泄漏、备份不可用 | 15 分钟内响应 |
| P2 | 局部功能、单租户重大异常 | 30 分钟内响应 |
| P3 | 低影响安全缺陷 | 工作时间处理 |

## 19.2 流程

准备 → 发现 → 分析 → 遏制 → 根除 → 恢复 → 通知 → 复盘。

## 19.3 现场

- 不擅自删除证据。
- 记录时间线、操作人和命令。
- 保护日志、快照和哈希。
- 密钥轮换和隔离。
- 评估 tenant/个人/资金影响。
- 法务与隐私负责人判断通知义务和时限。
- 对客户事实透明但不未经批准推测。

## 19.4 复盘

- 5 Whys/系统性原因；
- 检测为何未提前发现；
- 控制和测试缺口；
- 行动项、负责人和截止；
- 文档/Runbook/培训更新；
- 验证不会重现；
- 不以追责个人替代系统改进。

# 二十三、商业 V1 决策摘要

1. 建议按等保二级基线建设、保留三级增强能力；正式定级由主管部门/测评机构确认。
2. 适用 2026 年修正版《网络安全法》及《个保法》《数据安全法》《网络数据安全管理条例》。
3. tenant_id 使用 VARCHAR(20)，租户隔离覆盖所有存储和异步链路。
4. 管理高权限强制 MFA，高风险业务使用 step-up、审批和职责分离。
5. 生产 secret 进入 KMS/Vault，数据、终端和备份分层加密。
6. 通过持证支付终端/SDK 和令牌化缩小 PCI 范围；范围由专业机构确认。
7. 应用安全以 OWASP ASVS 5.0 L2 适用项为工程基线。
8. 个人信息以目的、最小化、权利请求、PIPIA、第三方和跨境治理闭环。
9. T0 同区域目标 RTO 30 分钟/RPO 5 分钟，区域灾难 RTO 4 小时/RPO 1 小时，必须经演练才能承诺。
10. 商业发布前必须完成真实恢复、跨租户、支付、离线、渗透和事件响应验收。

本方案批准后，安全门禁、数据分级、身份密钥、备份、RTO/RPO、事件级别和证据要求成为商业 V1 强制基线；任何例外需要有期限的正式风险接受。
