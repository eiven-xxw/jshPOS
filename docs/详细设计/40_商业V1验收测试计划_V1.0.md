# 文档说明

## 1. 编写目的

本文把“功能做完”转换为“可以对真实商户收费、上线、持续运营”的可验证条件。计划覆盖需求追踪、功能、领域不变量、离线、硬件、连接器、开放 API、安全、隐私、性能、灾备、迁移、实施、试营业、可观测性和商业运营准备度。

## 2. 验收原则

- 按风险和业务事实验收，不按页面数量验收。
- 资金、库存、租户、离线、优惠分摊和恢复是最高优先级。
- 每项通过都必须有可复核证据。
- 不以“无法复现”直接关闭缺陷。
- 生产能力必须在接近生产的环境、真实硬件和真实故障中验证。
- RTO/RPO、容量和 SLA 未演练通过不得写入销售承诺。
- AI 生成代码与人工代码执行相同质量门禁。

## 3. 适用角色

- 产品、架构、研发、QA；
- 安全、隐私、SRE/运维、DBA；
- 实施、培训、售后、客户成功；
- 财务、支付运营、连接器运营；
- 试点商户业务代表；
- 管理层 Go/No-Go 委员会。

# 三、准入与退出

## 3.1 测试准入

- 需求和规格已基线化；
- API/事件/Schema 可用；
- 数据库迁移可部署/回滚；
- 单元和模块集成通过；
- SAST/SCA/Secret 无未接受 Critical；
- 测试环境和数据准备；
- 真实硬件和外部沙箱可用；
- 监控日志开启；
- 缺陷基线清晰；
- 构建可追溯、制品已签名。

## 3.2 商业退出

必须同时满足：

- 必选需求 100% 有测试与结果；
- P0/P1 为 0；
- P2 无影响资金、租户、数据完整、核心营业和恢复的遗留；
- 自动化核心回归 100% 通过；
- 资金/库存/优惠/离线不变量 100% 通过；
- 性能、长稳、灾备达到批准目标；
- 安全高危为 0，渗透已复测；
- 隐私/等保准备和合同材料可用；
- 试营业连续达到门槛；
- Runbook、支持、值班和回滚就绪；
- 所有有期限风险接受经批准。

## 3.3 暂停条件

- 出现跨租户；
- 重复扣款/退款；
- 订单或库存静默丢失；
- 账本不可重建；
- 备份不可恢复；
- 生产密钥泄漏；
- 核心机型长稳失败；
- 未知支付被当失败后重扣；
- 离线同步产生重复订单；
- 无法解释经营/渠道对账差异。

# 二十八、商业 V1 决策摘要

1. 商业验收是功能、数据、资金、离线、硬件、安全、灾备、实施和运营的联合门禁。
2. P0/P1 必须为 0，跨租户、重复资金、丢单和备份不可恢复一票否决。
3. POS-DD-031 至 039 的每个强制约束都进入 RTM 和证据包。
4. 核心状态机、金额/库存/分摊不变量和错误码必须 100% 覆盖。
5. Android 主推硬件至少达到 L2，完成 7 天长稳。
6. 离线至少完成 8 小时真实营业和 10 万 Outbox 恢复压力。
7. 性能目标必须绑定实际部署规格和报告，不能脱离硬件销售。
8. T0 RTO/RPO 必须通过真实恢复演练。
9. 上线前进行 2—5 家代表门店 7—14 天试营业和每日对账。
10. 只有产品、架构、QA、安全、运维、实施、客户和管理层共同签署才可商业发布。

本计划批准后，退出门槛、P0/P1 定义、强制证据、试营业指标和 Go/No-Go 决策表成为商业 V1 发布准绳。任何降低门槛的请求必须以正式范围变更或管理层风险接受记录处理，且不得突破法律、租户隔离和资金安全底线。
