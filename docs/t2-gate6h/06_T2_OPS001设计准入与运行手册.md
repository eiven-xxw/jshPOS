# T2-OPS-001 设计准入与运行手册

## 1. 边界

本项收口内部部署配置、日志指标、诊断、备份恢复、升级回退和故障处置。只允许虚构租户、合成密钥、GitHub 执行器和本地容器；生产 KMS、对象存储、PITR、跨区域灾备、真实终端命令和商业 SLA 继续 `BLOCKED/ASSUMPTION`。

## 2. 配置与启动

1. 复制 `infra/compose/.env.example` 到不入库的 `.env`，替换所有占位秘密。
2. `docker compose -f infra/compose/compose.yaml config` 必须先通过；镜像必须固定 digest，禁止 `privileged`、host network 和默认口令。
3. 启动 MySQL/Redis 后等待健康检查，导入 RuoYi 基表，再由正式 JAR 的 Flyway 只前进迁移领域表。
4. 服务端加载 `infra/internal-rc/application-internal-rc.yml`；数据库、Redis、监控口令只从受控环境注入，缺失即启动失败。
5. Web 使用 CI 构建制品；POS 仍为虚构终端和 Fake Device Adapter，不执行实机命令。

## 3. 可观测与告警

所有请求和事件保留 correlation ID、可信 tenant/store/device 范围、Owner、事件 ID、幂等键摘要和错误码；禁止记录凭据、完整令牌、会员密文、支付敏感字段或正文。内部暴露端点仅为 `health/info/metrics/logfile`，详细健康信息只对授权角色开放。

P0 告警包括：服务不可用、Flyway 失败、跨租户拒绝、资金 `UNKNOWN` 异常增长、事实守恒失败、备份/恢复失败。P1 包括：Outbox 积压、死信、同步游标停滞、冷启动或报表趋势显著退化、磁盘容量预警。

## 4. 诊断包

`collect_t2_gate6h_diagnostics.py` 只输出文件元数据、SHA-256、行数和错误计数，不复制原日志正文。输入发现 Secret/令牌/私钥/疑似 PII 时立即失败关闭。诊断清单保留 7 天，到期受审计清理；对象路径必须绑定环境和租户命名空间。

## 5. 备份恢复与升级回退

- 复用 `T2-BAK-001` 的六类恢复集合、AES-GCM、空环境恢复、Flyway validate、投影重建和逐租户/业务日守恒。RPO≤15 分钟、RTO≤60 分钟仍仅是 `SYNTHETIC_RESTORE` 内部目标。
- 复用 `T2-UPG-001` 的摘要/签名、兼容窗口、灰度、营业保护、健康检查、失败暂停和安全前向修复；Schema 不回退，应用失败优先回退兼容版本或前向修复。

## 6. 故障处置

1. 值班人员记录 incident ID、UTC、环境、版本、相关 correlation ID 与影响范围。
2. 先隔离写入和外部边界，禁止重复生成资金或业务命令。
3. 查询原幂等键、Inbox/Outbox、Owner 审计和权威事实；报表不能覆盖事实。
4. 需要恢复时只向空隔离目标执行；任何摘要、范围、密钥、迁移或守恒失败均 NO-GO。
5. 发布失败按发布状态机暂停；已发布迁移不得修改，形成受审计前向修复。
6. 关闭事件前记录根因、修复提交、回归 seed、证据摘要和清理结果。
