# T2-PERF-001 设计准入

## 目标与证据边界

在 GitHub 干净执行器上运行正式代码路径，以固定合成数据记录容量、并发、服务端冷启动、POS 扫码与结算、同步积压和报表投影趋势。正确性、守恒、完整性和缺失测量是硬门禁；墙钟时间只用于同规格执行器的趋势比较，不承诺生产容量、真实 Android 性能或商业 SLA。

## 固定负载

- 商品导入 10k/100k，终端登记 100k。
- 报表投影 1,000,000 行，内部支付/退款对账 100k。
- POS 扫码 1,000 次、现金结算 200 次，同步积压 10k 事件。
- 服务端冷启动必须运行正式 `ruoyi-admin.jar`，并在 MySQL/Redis 合成环境下通过健康检查。
- 并发验证必须使用稳定幂等键，检查重复、同键异内容、余额/金额守恒和无跨租户污染。

## 测量与退化规则

每项记录 commit、执行器、工具版本、数据规模、耗时、吞吐和通过状态。首个干净执行器结果建立基线；后续同环境对比。性能时间暂不设置脆弱的商业阈值，但数据规模不足、测试失败、指标缺失、守恒失败、进程崩溃、超时或跨租户污染均直接失败。

## 安全和非目标

只使用两个虚构租户与三业态合成数据；Provider 网络、真实资金、真实设备、伙伴联系、现场试点和生产部署均为零。不得通过测试后门直接写事实，不得自动重跑掩盖 Flaky。
