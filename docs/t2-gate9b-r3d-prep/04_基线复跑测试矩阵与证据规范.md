# 基线复跑测试矩阵与证据规范

## 1. 必跑门禁

| 生产者 | 执行内容 | 证明范围 |
|---|---|---|
| governance-ubuntu/windows | 结构、RTM、契约、范围守恒、26页来源摘要和旅程覆盖 | 治理与跨平台编码一致 |
| scope-integrity | 从 `f5909b...` 比较依赖和运行时目录 | 运行时/API/依赖/数据库变化为0 |
| web-baseline | production build、ESLint、typecheck、全部 Vitest | 20个Vue页现有直接交互和全量Web回归 |
| flutter-ubuntu/windows | pub get、format、analyze、全部 Widget/单测与覆盖率 | 6个Flutter页及POS全量回归 |
| evidence | 下载并摘要全部生产者证据 | 来源、commit和结果可追踪 |

## 2. 证据规则

- 失败 Job 和失败 seed 必须保留；禁止自动重跑或以重跑掩盖 Flaky；
- Web 与 Flutter 必须从干净执行器安装冻结依赖；
- 页面测试日志、JUnit/机器日志、覆盖率摘要、dist 摘要与供应链清单必须进入 Artifact；
- Vue/Flutter 的跨客户端拼接只标记 `INTERNAL_UI_EVIDENCE_CHAIN`；
- 任一来源摘要漂移、页面缺失、测试失败、P0 或未经解释的新 P1 均为 `NO-GO`。

## 3. 退出标准

准备阶段只有在 6 个证据生产者全部成功、26页/3旅程/3 seed 机器契约一致、运行时变更为0、
外部状态守恒时，才可建议 `CONDITIONAL PASS` 并请求正式 R3D 准入。
