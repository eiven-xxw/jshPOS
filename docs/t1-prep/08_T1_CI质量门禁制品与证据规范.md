# T1 CI 质量门禁、制品与证据规范

> 文档编号：JSH-POS-T1P-008
> 版本：1.0
> 状态：启动评审候选（当前只规定门禁，不在 T1-Prep 开发 PoC 流水线）
> 需求：`T1-CI-001`、`T1-SEC-001`
> 依据：技术规范 11—12、ADR-013—017

## 1. 目标

使每个 T1 结论可以回答：由哪个 commit、哪个依赖和构建环境、在什么设备/沙箱、用哪个 seed、执行哪些故障、产生什么结果、由谁复核。CI 不只是“编译绿灯”，而是 T1 的证据生产线。

## 2. 触发与权限

| 触发 | 自动执行 | 禁止访问 | 合并资格 |
|---|---|---|---|
| 任意 PR（含 fork） | 治理、静态、单元、Fake、SBOM、漏洞、许可证、Secret/IaC | 沙箱 Secret、实机执行器 | 所有必需 Job 通过且人工评审 |
| 主仓库受信 PR 标签/环境批准 | 支付沙箱 smoke/矩阵 | 生产 Secret/真实资金 | 只生成 `SANDBOX` 证据，不单独决定合并 |
| 主仓库受保护手工调度 | 实机/外设/物理恢复 | 生产数据、非登记设备 | 生成 `REAL_DEVICE` 证据，需执行人和复核人 |
| main 每夜 | 长故障矩阵、10k/100k 数据、重复 seed | 外部 Secret 默认关闭 | 作为周门禁证据 |
| T1 候选提交 | 三次干净全量、制品、摘要和证据索引 | 任何临时绕过 | 供退出评审，不自动进 T2 |

支付与实机 Job 必须使用受保护 Environment、并发锁和人工批准；来自 fork 的代码不得获得 Secret。T1 只使用测试签名 APK 和沙箱凭据。

## 3. 逻辑 Job 与硬门槛

### 3.1 `governance`

- 校验 AGENTS、ADR、change-log、T1-Prep 文档清单和内部链接；
- RTM 列、唯一 ID、状态、必填字段、阶段、证据引用；
- 禁止 `BLOCKED/DEFERRED` 需求关联业务实现；
- 禁止 T1 探针出现未经准入的正式领域模块/表名；
- `git diff --check`、文档编码和敏感占位符扫描。

门槛：全部 0 错误；T1 文档中 `BLOCKED`/`ASSUMPTION` 不得被“已支持/已验收”措辞覆盖。

### 3.2 `server-poc`

- 固定 JDK/Maven/上游依赖基线；
- 编译、单元、契约、租户攻击、Inbox/幂等、Payment Fake、数据包测试；
- 禁止跳过测试、空测试套件和 `continue-on-error`；
- 报告测试数、失败、跳过、时长和 flaky 复跑次数。

门槛：失败 0；P0 用例跳过 0；不稳定复跑 0；所有失败让 Job 非零退出。

### 3.3 `flutter-pos-poc`

- 固定 Flutter/Dart/Gradle/Android SDK/JDK；
- format check、analyze、unit/widget、SQLite/Outbox/包/升级 Fake 矩阵；
- 构建 T1 probe APK；验证 manifest、minSdk 28、ABI、exported/backup/network 配置；
- APK 只用测试签名，包名/版本明显标记 `.poc`，不能被误装成生产应用。

门槛：analyze 0 error/warning（允许项必须基线审查）；测试失败/跳过 P0 0；APK 可安装到隔离模拟器。

### 3.4 `android-device-contract`

- Dart/Kotlin 双侧契约、Fake 故障、MethodChannel 序列化兼容；
- Kotlin lint/test/assemble；AAR/JAR/SDK checksum 和 ABI/许可审查；
- Flutter UI/业务层不得直接调用厂商 MethodChannel；厂商名称只在插件注册/profile。

门槛：契约 100% 通过；核心层厂商条件分支 0；未批准 SDK/二进制 0。

### 3.5 `fault-matrix`

- 进程 kill、网络延迟/丢包/重复/乱序、磁盘/包/迁移损坏；
- 保存 seed 和 fault timeline；
- PR 运行小矩阵，nightly/候选运行文档 07 完整规模。

门槛：适用 P0 不变量 100%；运行失败不可由自动 rerun 隐藏。

### 3.6 `tenant-security`

- 两虚构租户 API/Mapper/Job/Cache/Export/Object/Logs 攻击矩阵；
- SAST、Secret、PII、IaC、Android 配置；
- 错误响应和日志泄漏检查。

门槛：跨租户/敏感泄漏 0；新增 High/Critical 0；误报只可由安全负责人基于证据抑制且有到期日。

### 3.7 `supply-chain`

- 生成 Maven/npm/pub/Gradle/APK 聚合 SBOM；
- Trivy/生态 audit、许可证清单、受限组件精确匹配；
- 运行仓库自有 dependency diff，沿用 ADR-016 补偿控制；
- 新依赖记录用途、固定版本、来源、许可证、漏洞、替代和所有者。

门槛：可利用 HIGH/CRITICAL 0；新增未批准受限/未知许可证 0；SBOM 组件和制品可关联。既有三项延期问题继续在报告展示，不因 T1 隐藏。

### 3.8 `payment-sandbox`（受保护）

- 环境批准后注入短期沙箱 Secret；
- 官方签名向量、smoke、UNKNOWN/查询/回调/退款/对账矩阵；
- 回调使用临时受控域名和并发锁；运行后吊销/清理。

门槛：文档 07 沙箱项全部通过；真实资金 0；Secret/原始付款码进入日志 0。无沙箱时 Job 标记 `BLOCKED/not-run`，不可绿色 Fake 替代。

### 3.9 `real-device`（受保护自托管执行器）

- 校验登记设备指纹/固件/外设组合；
- 安装测试签名 Probe APK；执行打印/扫码/秤/钱箱/客显、进程/服务/物理恢复；
- 采集脱敏系统信息、测试报告和人工抽检表。

门槛：文档 07 实机项通过；运行设备与选型 profile 完全匹配。模拟器结果不可上传到 `REAL_DEVICE` 路径。

### 3.10 `evidence-seal`

- 汇总前述报告、制品、SBOM、许可证、扫描、元数据和人工签字；
- 生成文件清单和 SHA-256；校验证据等级和必填字段；
- 对 APK、容器、SBOM、测试报告和 commit 建立一一映射。

门槛：清单缺失/摘要不符/等级冒充/敏感数据任一即失败。

## 4. 分层流水线

| 层 | 目标时长 | Job | 阻断 |
|---|---:|---|---|
| PR Fast | ≤15 分钟 | governance、增量 server/flutter/device、Secret、dependency diff | 阻断合并 |
| PR Full | ≤30 分钟 | 全量单元/契约、租户小矩阵、SBOM/漏洞/许可、Fake fault | 阻断合并 |
| Nightly | ≤4 小时 | 10k/100k、20 seeds、升级矩阵、完整 SCA | 阻断候选，不必阻塞普通开发队列 |
| Protected External | 按调度 | payment-sandbox、real-device | 阻断对应真实结论 |
| Candidate Seal | 3 次全量 | 所有适用 Job + evidence-seal | 阻断 T1 退出评审 |

时长目标不能成为跳过测试的理由。超时应拆分/并行，不降低规模。

## 5. 证据元数据 Schema

每个 `run-metadata.json` 至少包含：

```json
{
  "schemaVersion": "1.0",
  "runId": "t1-<utc>-<shortSha>-<job>",
  "requirementIds": ["T1-SYN-001"],
  "evidenceLevel": "FAKE",
  "repository": "github/eiven-xxw/jshPOS",
  "commitSha": "40-hex",
  "baselineTag": "t0-baseline-2026-08-16",
  "workflowRunUrl": "https://github.com/.../actions/runs/...",
  "toolchain": {"jdk": "fixed", "flutter": "fixed", "androidApi": 36},
  "environment": "ci-linux",
  "deviceProfileRef": null,
  "providerProfileRef": null,
  "seed": "reproducible-seed",
  "startedAt": "RFC3339 UTC",
  "finishedAt": "RFC3339 UTC",
  "result": "PASS",
  "tests": {"total": 0, "passed": 0, "failed": 0, "skipped": 0},
  "redactionCheck": "PASS",
  "producer": "job-or-person-id",
  "reviewer": "independent-person-id"
}
```

`deviceProfileRef` 只有 `REAL_DEVICE` 必填；`providerProfileRef` 只有 `SANDBOX` 必填。值使用受控档案引用，不能放完整序列号、商户号或终端号。

## 7. 必交制品

- T1 probe APK（测试签名）及 SHA-256、versionName/versionCode、manifest 摘要；
- 服务端最小探针构建物或容器 digest；
- 全生态 CycloneDX SBOM；
- 许可证清单、受限/未知组件结果；
- 单元、契约、故障、租户、安全测试报告；
- 五家 Provider Profile 版本与真实沙箱脱敏结果（若执行）；
- 主机/外设 profile 和实机脱敏结果（若执行）；
- RTM 快照、风险/缺陷快照、独立复核；
- 所有文件 SHA-256 和 CI Run URL。

## 8. 证据保留和敏感信息

- 普通 T1 证据建议在受控制品库保留 180 天；GitHub Artifact 按套餐允许的最大合理期限配置，仓库只保留摘要/索引，不提交大制品；
- 沙箱原始报文不进入常规制品，临时加密隔离数据最多 7 天，问题关闭后销毁；长期只保留脱敏字段/摘要；
- 实机完整序列号、MAC、IMEI 不进入报告，使用受控资产 ID 或哈希；
- 任何 Secret 泄漏：停止 Job、撤销/轮换、删除可删除制品、保留安全事件证据，并重新执行受影响结论；
- 人工截图必须裁剪并二次脱敏，能用结构化结果时不使用截图代替。

## 9. GitHub 不升级下的补偿治理

项目决定不升级套餐。继续执行以下控制：

1. 正式工作只通过 PR，不直接向 main 推送；
2. 由仓库流程/评审清单强制至少一名非作者复核 P0/P1；
3. 仓库自有 dependency diff + SBOM + ecosystem audit + 许可证门禁替代不可用的原生 Dependency Review；
4. 失败 Job 不允许手工标绿，补偿控制本身也由测试覆盖；
5. 合并后验证 main commit 与 PR head、CI Run、制品摘要；
6. 候选证据另存不可变摘要，防止无 Branch Protection 时发生静默覆盖；
7. main 出现未评审提交时立即停止候选封板，追溯并重新跑完整门禁；
8. 不以“套餐不支持”为由降低漏洞、许可证或测试阈值。

这些是流程补偿，不等同于平台强制保护；剩余人为绕过风险需在每次门禁报告中显式展示。

## 10. 禁止做法

- `skipTests`、排除失败测试、降低安全阈值、用 rerun 掩盖 flaky；
- `continue-on-error` 后把 Job 作为通过；
- 未执行的实机/沙箱 Job 输出绿色占位；
- 把 Fake 文件复制到 `sandbox`/`real-device` 路径；
- 上传 Secret、原始支付报文、未脱敏商户数据或完整设备标识；
- 仅用截图证明状态机/幂等/租户不变量；
- 手工修改测试报告或 SHA-256；
- 为了 T1 指标引入正式业务实现。

## 11. T1-Prep 与执行边界

当前只批准本文规范和本地文档校验。新增 T1 工作流、探针 Job、受保护环境、自托管实机执行器或支付 Secret，必须在项目发起人确认 T1 PoC 启动后进行，并关联 `T1-CI-001`。这可避免在启动评审前以“搭 CI”为名进入 PoC 编码。
