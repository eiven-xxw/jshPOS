# T1 四周迭代计划与 RACI

> 文档编号：JSH-POS-T1P-006
> 版本：1.0
> 状态：启动评审候选
> 周期：项目发起人确认 T1 PoC 启动后的 4 个工作周

## 1. 计划原则

- 周期固定、范围可减：第四周结束必须给结论，不以“再写一点”无限延期。
- 先契约和故障，后正常路径；先 Fake 形成可重复矩阵，再接实机/沙箱。
- 设备、支付外部资料走关键路径；未解除阻断不伪造实证。
- 七类 PoC 可并行，但共用 RTM、证据格式和每日风险同步。
- 任何正式业务需求立即移回 T2 Backlog，不占用 T1 容量。

## 4. 四周执行计划

### 第 1 周：契约、夹具与可复现故障

目标：让七类风险都能在自动化中“被故意打坏”，形成失败基线。

| 工作包 | 主要任务 | 周末证据 |
|---|---|---|
| WP1 设备 | 冻结设备能力/错误/超时契约；Kotlin/Dart Fake 注入；主机 SDK 独立样例（若解阻） | 契约测试、Fake 故障清单、设备资料缺口 |
| WP2 支付 | 十家 Provider Profile v0；评选五家；统一状态/命令/回调契约与 Fake Provider | 十家候选表、五家差异/契约测试、沙箱准入结果 |
| WP3/4 离线同步 | SQLite 合成模型、注入点；网络故障代理、Inbox/Outbox 测试夹具 | 事务/重复/乱序失败基线与 seed |
| WP5 租户 | 两个虚构租户、角色和攻击矩阵；旁路清单 | 越权用例清单、可自动化入口 |
| WP6 数据包 | manifest/schema、签名向量、10k/100k 合成数据集 | 数据包契约与正常/损坏夹具 |
| WP7 升级 | A/B APK/DB/协议矩阵；迁移失败夹具 | 版本矩阵和最小升级演练脚本设计 |
| CI | T1 分级 Job、证据 metadata、Secret/PII 检查设计实现 | PR 门禁绿，FAKE 证据包样例 |

周门槛：所有进入实现的需求已从 `READY` 合法转为 `IN_PROGRESS`；测试能在无外部设备时稳定复现已设计故障；无业务域扩张。

### 第 2 周：核心不变量与首轮外部实证

目标：先把资金、租户、本地事实、重复效果四条红线跑通。

- WP3：逐事务边界杀进程，验证 0/0/0 或 1/1/1；磁盘满/损坏进入安全状态；
- WP4：重复、乱序、丢 ACK、同 ID 不同 payload、游标中断；
- WP5：API、Mapper/XML/原生 SQL、后台任务、缓存、导出/对象存储攻击；
- WP2：五家 Fake 全部运行契约；若沙箱解阻，先跑签名/查询/回调 smoke；
- WP1：若实机解阻，完成能力探测和两条打印/扫码/秤最小 smoke；
- WP6：10k/100k 全量与增量，弱网断点、损坏拒收和原子切换；
- WP7：A→B 正常升级、迁移中杀进程和安全阻断；
- QA：形成首轮缺陷、最小复现和门槛差距；P0 当日停止相关合并。

周门槛：四条红线自动化 100% 通过；未通过则第 3 周优先修复，不进入功能扩展。

### 第 3 周：恢复、交叉故障与稳定性

目标：验证正常组件叠加故障时仍满足边界。

- 设备：连续打印/扫码/称重，缺纸/断连/服务重启/App 重启恢复；
- 支付：超时→UNKNOWN→查询/回调收敛，重复/乱序回调，退款 UNKNOWN，对账差异；
- 离线：上传到达但 ACK 丢失、进程重启+网络抖动、队列积压恢复；
- 数据包：下载中断+进程重启、切换中杀进程、旧包重放、跨租户包；
- 升级：待同步探针+升级、迁移失败+回退、旧客户端/新服务端兼容；
- 安全：Secret/PII、依赖/许可证、日志与证据二次检查；
- QA：固定回归集合，失败 seed 自动加入回归。

周门槛：量化指标达到文档 07 阈值；真实输入仍缺失的项保持 `BLOCKED`，不得用 Fake 填补列。

### 第 4 周：重复验证、清理与退出评审

目标：证明结果可重现，删除临时捷径，形成管理决策。

1. 在干净环境/第二台执行器重新构建并复跑所有自动化；
2. 实机/沙箱关键矩阵由非实现者复跑；
3. P0/P1 清零，P2 逐项评估是否影响架构结论；
4. 生成制品、SBOM、许可证、安全扫描和证据摘要；
5. 更新 RTM 的实现、证据、状态；
6. 更新 ADR/风险/成本和对 T2 的建议；
7. 删除/隔离探针中的临时 Secret、测试账号和数据；
8. 提交 T1 退出评审：Go、Conditional Go、No-Go 或重选方案。

T1 退出后仍不得自动进入 T2。

## 6. 节奏与报告

- 每日 15 分钟风险站会：只报昨天证据、今天假设、阻断和红线；
- 每日结束更新 RTM/缺陷/风险，不用聊天结论替代仓库记录；
- 每周一次 45 分钟门禁评审：对照量化阈值，不按完成百分比粉饰；
- P0：立即停止相关工作、1 小时内通知 SP/AR/QA/SE；
- P1：当日建立最小复现和负责人，下一门禁前关闭；
- 外部阻断超过 2 个工作日：PM 提交替代顺序/范围影响，不自动延长四周。

## 7. 关键路径

```text
T1 启动确认
  ├─ 设备资料 + SDK + 样机 ─ Vendor sample ─ Kotlin adapter ─ 实机矩阵
  ├─ 支付授权 + 沙箱资料 ─ 签名/回调 smoke ─ UNKNOWN/退款/对账矩阵
  └─ 内部契约冻结 ─ Fake/故障夹具 ─ 七类自动化 ─ 重复验证
                                                     └─ T1 退出评审
```

主机和支付两条外部路径必须在第 1 周前半段解除阻断，才能合理完成第 3 周的稳定性验证；否则 T1 可以完成内部架构证据，但整体只能得 `CONDITIONAL/INCONCLUSIVE`，不能声称七类全通过。
