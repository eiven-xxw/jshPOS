> 注意：本文件的 Go 仅指 T1 风险 PoC，不代表 T2 或商业上线。

## 1. 术语与规则

- 风险：尚未发生、可能影响目标的不确定事件；有概率、影响、缓解和触发器。
- 阻断：继续该需求会缺少授权、输入或安全条件；对应 RTM 必须为 `BLOCKED`。
- 假设：为了设计方案暂时采用、尚未实证的条件；必须有验证日期和失败替代。
- 延后：经项目发起人批准不在本阶段解决；仍保留责任和后续硬门禁。
- 缺陷：已执行的实现/测试不符合要求；不能用 `BLOCKED` 隐藏。

Fake 只能解除“内部契约不可测”的风险，不能解除厂商 SDK、实机、沙箱、试点或商业合规阻断。

## 5. T1 启动 Go/No-Go

### 5.1 内部 Fake PoC 的 Go 条件

必须同时满足：

- 项目发起人确认本启动评审；
- T0 tag 指向/签名信息可验证，T1 分支无正式业务改动；
- T1 RTM、七类方案、测试、CI/证据、风险和四周计划批准；
- PM/AR/QA/安全及各工作包负责人实名；
- `READY` 需求逐项通过准入清单；
- 合成数据、测试环境和秘密管理方案就绪；
- 无生产 Secret、真实支付或未脱敏数据。

满足后只允许 `READY` 的 `FAKE/STATIC` 工作。当前仍缺最后一项“项目发起人确认”，所以是 `NO-GO pending review`。

### 5.2 实机 PoC 的额外 Go 条件

- B-01—B-05 解除；
- 主机/外设 profile、SDK 许可/安全审查、样机资产和厂商联系人齐备；
- 物理断电/钱箱/打印测试场地有安全操作和恢复预案；
- `REAL_DEVICE` 执行器隔离且设备指纹校验通过。

### 5.3 支付沙箱 PoC 的额外 Go 条件

- B-06 解除；
- 沙箱不发生真实资金；测试商户/终端/密钥为专用且可吊销；
- 回调/出网/Secret/日志脱敏经过安全批准；
- 支付负责人和技术联系人确认 UNKNOWN、查询、退款、回调、对账验收。

### 5.4 强制 No-Go

- 要求使用生产密钥、真实资金或未脱敏商户数据；
- 外部授权/SDK 许可不清；
- 需求无 ID、验收不可执行或范围实际进入正式业务；
- P0 不变量失败或绕过质量门禁；
- 设备/支付 Fake 被要求当实证；
- 无独立 QA/安全复核；
- 基线 commit 不可验证或 main 存在未审计覆盖；
- 工作量明显超过四周且拒绝减范围。

## 6. T1 退出 Go/No-Go

| 决策 | 条件 | 后续 |
|---|---|---|
| `GO` | 七类全部 PASS；实机和真实沙箱齐备；P0/P1=0；证据完整；风险可接受 | 只允许制定下一阶段计划，仍需项目发起人独立启动 T2 |
| `CONDITIONAL GO` | 内部不变量 PASS，但明确外部项 BLOCKED 或有期限 P2 | 只推进不依赖阻断项的设计；解除条件前不得商业实现/宣称支持 |
| `REDESIGN` | 核心假设失败但有可行替代 | 新 ADR、时间/成本评估、重新 PoC；不进入 T2 |
| `NO-GO` | P0/P1 未解决、证据不可复核、外部授权/成本不可接受 | 停止该路线，保留证据和失败结论 |

`INCONCLUSIVE` 默认按 `NO-GO`，除非项目发起人基于书面条件批准 `CONDITIONAL GO`。

## 7. 回退方案

### 7.1 T1-Prep 未获批准

- 不合并/关闭 T1-Prep PR；
- 分支可保留供审计或归档；
- 工作树回到 `t0-baseline-2026-08-16`；
- 不删除已封板 T0 tag，不改写 main 历史；
- 记录退回原因和所需修改。

### 7.2 PoC 代码回退

- 所有探针使用独立模块/构建变体/路由和 `poc/synthetic` Schema，可整体禁用/删除；
- 不把 PoC 数据库迁移加入正式迁移链；若必须运行共享环境，使用独立数据库/schema 和账号；
- 失败 commit 通过新 revert commit 回退，不 reset/重写共享历史；
- 保留失败测试、seed、日志摘要和 ADR，不删证据掩盖路线失败。

### 7.3 设备回退

- Probe APK 与测试配置可卸载；恢复登记固件/系统设置须按厂商 Runbook；
- 外设断电、拔线、打印/钱箱测试先停止任务并保存诊断；
- 厂商插件失败时退回 Fake/标准协议或重选主机，不在核心层打补丁；
- 样机测试数据清除并记录，禁止恢复出厂导致资产/证据失联。

### 7.4 支付回退

- 停止回调和沙箱 Job，撤销测试密钥/证书/白名单/账号；
- 查询所有测试交易到官方终态，确认无真实资金；
- 清理临时公网入口和原始报文，保留脱敏结果/摘要；
- adapter 不满足统一语义时隔离该 provider，不能修改核心把 UNKNOWN 当失败。

### 7.5 数据与升级回退

- 合成活动数据使用版本指针切回上一个完整包；损坏包进入隔离，不覆盖旧包；
- 应用回退必须先检查 DB 兼容；不兼容则阻断旧应用，走前向修复；
- SQLite 失败不清空/重建来“恢复”；先只读隔离、备份、诊断；
- CI/证据已泄漏 Secret 时先吊销，再删除可删除副本和重建证据。

## 8. 当前建议

建议本次启动评审给出：

> `CONDITIONAL GO` 建议——项目发起人确认后可进入四周 T1，但起步只允许 `READY` 的内部 Fake/Static PoC；实机和支付沙箱工作分别在 B-01—B-06 解除后开始。若第 1 周截止仍未解除，整体 T1 不得判全量 GO。

这不是当前授权。项目发起人尚需明确确认；在确认前所有 T1 编码保持 `NO-GO`。
