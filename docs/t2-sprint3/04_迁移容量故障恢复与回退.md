# S3 迁移、容量、故障恢复与回退

## 1. MySQL 前向迁移

- V7：设备同步注册、Sync Inbox、结果、Change Feed、ACK、游标、冲突/修复审计；
- V8：六个 S3 权限点；
- tenant_id 为 `VARCHAR(20)` 并与 Gate 0 主权表字符集一致；所有设备、门店、Inbox、游标关系使用复合租户约束；
- Inbox 与审计事实不可物理删除/覆盖；结果只允许受控状态推进；
- MySQL 8.4 clean migrate→repeat migrate→validate，历史 V1—V6 checksum 不变。

## 2. SQLite V2 前向迁移

不修改 `Gate2Schema.v1`。V2 为 Outbox 增加租约、下次重试、ACK、结果和错误字段，新增 `local_sync_inbox`、`local_sync_cursor`、`local_sync_dead_letter` 与 `local_sync_attempt`。`local_schema_history` 分别保存 V1/V2 SHA-256，`user_version=2`。

V1→V2 在独占启动事务执行；失败整体回滚并保持 V1 可读。回退 App 必须声明兼容 V2；不执行破坏性 down migration。

## 3. 容量与退避

- Push 单批最多 100 条、未压缩最多 2 MiB、单事件最多 256 KiB；
- 默认自动重试预算 12 次，1 秒起步、5 分钟上限，使用确定性 seed + 抖动；
- 100k Outbox 使用分页/索引，不一次加载；优先订单/班次，避免惊群；
- ACKED 只按保留策略归档，S3 不实现自动删除；
- 指标：pending/retry/sending/blocked 数、oldest age、push latency、duplicate、gap、hash mismatch、cursor error。

## 4. 故障恢复

| 故障 | 必须结果 |
|---|---|
| 出队前进程终止 | 保持 PENDING |
| 已置 SENDING 后终止 | 租约超时后原事件转 RETRY |
| 服务端已持久 Inbox 但 ACK 丢失 | 原事件重发并返回 DUPLICATE/原结果 |
| 批次部分结果 | 逐事件原子更新，未返回项保留并重试 |
| 429/503/网络超时 | 遵循 Retry-After/退避，不重建事件 |
| cursor 损坏/回退/过期 | 阻断该流，保留 Inbox，走快照/人工恢复 |
| 同 ID 异 hash | 两端 BLOCKED，禁止自动修复 |
| 迁移失败 | 事务回滚，保留旧 Schema，前向修复 |
| 积压 100k | 分页恢复并最终收敛，无静默丢失 |

## 5. 灰度与回退

按虚构租户→单门店→多门店启用同步能力开关；任何 P0/P1、积压不收敛、跨租户、哈希冲突或游标倒退立即停止扩张。回退只回应用到兼容 Schema 的版本，保留数据库和证据；禁止直接 SQL 改交易、Inbox 或 Outbox。
