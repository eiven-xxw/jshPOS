# S3 同步数据主权、状态与不变量

## 1. 数据主权

| 数据 | 唯一 Owner | 可写者 | 禁止做法 |
|---|---|---|---|
| POS 交易事实与本地 Outbox | POS Local Store | 已准入本地领域事务 | Sync Worker 生成第二订单或修改事件身份 |
| 设备授权范围 | Device Registry | 服务端受控管理流程 | 相信消息体/Header tenant_id |
| 云端 Sync Inbox/结果 | Sync | Sync Gateway/Consumer | 未持久 Inbox 先返回成功 |
| 订单/班次/现金事实 | Order | Order 应用端口 | Sync Mapper 直接改订单金额或状态 |
| 下行 Change Feed/游标 | Sync | 服务端发布器 | 客户端解析或自行递增 cursor |
| POS Local Inbox/游标 | POS Sync | Inbox 原子应用事务 | 事件失败仍推进 cursor |

## 2. Outbox 状态机

`PENDING → SENDING → ACKED`；网络/超时分支 `SENDING → RETRY → SENDING`；永久业务拒绝 `SENDING → FINAL_REJECTED`。`ACKED` 和 `FINAL_REJECTED` 不自动回退。超过租约的 `SENDING` 使用原 event_id、payload、hash 转 `RETRY`。

重试预算不是删除预算。达到自动尝试上限后事件进入人工隔离，仍保留原始事实、错误码、证据和恢复动作。

## 3. 云端 Inbox 状态机

`RECEIVED → PROCESSING → APPLIED`；依赖/版本缺口进入 `PENDING_GAP`；可重试错误进入 `RETRYABLE`；领域冲突进入 `CONFLICT`；永久不兼容进入 `FINAL_REJECTED`；哈希冲突进入 `SECURITY_BLOCKED` 并阻断设备。状态只能单向推进，重复请求返回原结果。

## 4. 下行 Inbox 与游标

- 唯一键：`tenant_id + device_id + event_id`；
- 同 ID 同 hash 返回既有结果，同 ID 异 hash 使设备 `BLOCKED`；
- `aggregate_version=current+1` 应用，旧版本同效果视为重复，更高版本进入 GAP；
- cursor 是服务端签发的不透明 token，按 `tenant + device + stream` 单调推进；
- 只有批内事件全部应用完成，才在同一 SQLite 事务写 next_cursor；
- `CURSOR_EXPIRED/CURSOR_INVALID/CURSOR_ROLLBACK` 停止该流并请求权威恢复，禁止猜测。

## 5. 强制不变量

1. 一个 event_id 最多形成一次业务效果；
2. 相同 event_id 永远绑定同一 payload SHA-256；
3. ACK 丢失不改变事件身份；
4. 未 ACK 事件不得因退出、解绑、升级或缓存清理消失；
5. tenant_id 只来自可信主体与注册表交集；
6. 不同聚合可乱序，同一聚合按版本收敛且不采用最后写入覆盖；
7. 客户端时间只作事实字段，不作为授权或唯一排序依据；
8. HTTP 200 只代表信封已处理，每个事件必须读取独立 result；
9. 支付 UNKNOWN 不在本 Sprint 运行时出现，任何支付事件只能作为未实现契约被拒绝；
10. 所有人工修复保留操作者、原因、证据、前后状态和原事件。
