# S3 测试矩阵、CI 与证据

## 1. 测试矩阵

| 层级 | 内容 | 门槛 |
|---|---|---|
| Java 单元/属性 | Inbox 防重、hash、状态、版本、设备范围、游标 | Sync 核心 line≥90%、branch≥85%；0 skipped |
| MySQL 8.4 | V1—V8、重复迁移、复合租户约束、Inbox 不可变、cursor 单调 | 0 failure/skipped |
| Flutter/SQLite | V1→V2、租约、退避、逐项 ACK、Inbox+cursor 原子性 | Sync 核心 line≥90%；0 skipped |
| Loopback 网络 | Push/Result/Pull/Ack、超时、断连、部分响应、429/503 | 不使用外网、Secret 或 Fake 解除外部阻断 |
| 故障收敛 | 重复、乱序、ACK 丢失、双重重启、固定 seed、100k 积压 | 最终业务效果唯一、未 ACK 丢失 0 |
| 租户安全 | 两租户、多门店/终端、HTTP/Mapper/任务/缓存/导出/对象键 | 越权成功 0 |
| 兼容迁移 | 旧客户端/新服务端、新客户端/Schema N-1、失败迁移 | 安全拒绝或前向修复 |
| 供应链 | Secret、依赖、SBOM、许可证、IaC | HIGH/CRITICAL 0；未批准许可证 0 |

## 2. 固定故障 seed

使用 `20260816`、`310031`、`ACK-LOSS-17` 三组固定 seed，覆盖批次乱序、响应截断、进程终止、服务端已收未 ACK、租约恢复和积压分页。新发现失败 seed 必须加入总账，禁止只重跑随机成功样本。

## 3. CI Job

`governance`、`server`、`mysql-migration`、`sync-fault`、`tenant-security`、`pos-linux`、`pos-windows`、`admin-web`、`security-sbom-license`、`evidence`。禁止 `continue-on-error`、自动 retry、阈值降低、测试跳过和绿色占位。

## 4. 退出标准

- `T2-SYN-001=VERIFIED`，待项目发起人确认后才能 `ACCEPTED`；
- Gate 0—2 已确认项保持 `ACCEPTED`；Gate 3 准备项保持 `DRAFT`，支付沙箱保持 `BLOCKED`；
- 同一候选 SHA 的十个 Job 全绿，并形成测试、覆盖率、迁移、安全、SBOM、许可证和证据索引；
- 正式支付/退款/库存/促销运行时和外部网络支付调用为 0；
- `sandbox=0`、`realDevice=0`、`pilot=0`，不得宣称 Alpha、试点或商用。
