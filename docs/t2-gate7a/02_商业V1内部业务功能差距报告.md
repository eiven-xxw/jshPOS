# 商业 V1 内部业务功能差距报告

## 1. 结论

审计确认 18 项原子差距。它们已登记为 `DRAFT`，只证明“当前未被既有 ACCEPTED 能力完整覆盖”，不表示已经设计准入、实现或验收。Gate 7A 不把任何新需求转为 `READY/IN_PROGRESS`。

## 2. Gate 7B：POS 交易运营

| ID | 差距 | 关键仓库事实 | 首要不变量 |
|---|---|---|---|
| `T2-POS-010` | 备用金之外的现金收入、支出、抽大钞、存现与钱箱事件 | `local_cash_ledger.movement_type` 只允许 `SALE_RECEIPT` | 现金流水只追加；每笔关联班次、原因、权限和审计 |
| `T2-POS-011` | 小票模板版本、打印任务状态和补打审计 | `local_print_job` 每单唯一且没有 reprint 事实 | 订单成功不依赖打印；补打生成新事实并明确标识 |
| `T2-ORD-004` | 未结交易取消、支付未知时关闭、成交后反向处置 | SQLite 预留 `CANCELLED`，但没有正式取消应用服务 | 成交事实不可作废覆盖；完成后只能走原单退货退款 |
| `T2-EXG-001` | 换货关联 | 生产路径不存在 exchange 运行时；`DEC-04` 明确后置 | 换货=原单退货+新销售；两者均保持独立幂等事实 |
| `T2-PAY-004` | Provider 无关组合/部分支付 | POS 只支持一次现金结算 | 各支付份额之和等于应收；UNKNOWN 份额禁止重新生成命令 |

`T2-EXG-001` 在独立 CR 获批前不得进入 READY。`T2-PAY-004` 的电子份额即使完成内部核心，仍不得解除 `T2-PAY-002`。

## 3. Gate 7C：商品门店供应与社区超市条件能力

| ID | 差距 | 关键仓库事实 | 首要不变量 |
|---|---|---|---|
| `T2-PRD-005` | 秤码/金额码解析和计量快照 | Catalog 有 WEIGHT 类型；POS 仍按完整条码精确查询 | 编码模板版本化；数量/金额精确且成交时冻结 |
| `T2-LBL-001` | 价签任务、换签异常、打印预览 | 无正式价签任务或未换签清单 | 任务引用已发布价格版本；不直接改价格 |
| `T2-RPL-001` | 最低/最高库存、缺货预警、建议转采购草稿 | 库存有余额但无补货建议运行时 | 建议可解释；审批前不产生采购或库存效果 |
| `T2-DMT-001` | 开业业务资料迁移与切换 | 现有 MIG/DAT 只覆盖 Schema 与合成种子 | 预检、幂等批次、错误明细、期初双人确认和回退 |
| `T2-ONB-001` | 门店克隆和开店检查 | 有模板/门店 CRUD；无克隆/里程碑状态机 | 只复制配置引用，不复制核心事实和历史 |
| `T2-LOT-001` | 社区超市批次、效期、临期 | `DEC-08` 为条件能力；正式库存维度未启用 | 仅条件模板；不含批次成本、库位、波次或 WMS |

`T2-RPL-001` 是规则化建议，不是预测式“智能补货”。电子秤、价签机和真实打印继续由 `T2-HWD-001/PRN-001` 阻断。

## 4. Gate 7D：日结、异常、会员权益与商业运营

| ID | 差距 | 关键仓库事实 | 首要不变量 |
|---|---|---|---|
| `T2-CLS-001` | 门店业务日日结与签署 | 已有班次关闭和逐日报表；无门店日结状态 | 日结只汇总权威事实；差异不能由报表覆盖 |
| `T2-EXC-001` | 统一异常认领、修复、关闭工作台 | 同步/库存/成本/支付差异分散存在 | 只记录处置任务；Owner 事实只能由 Owner 修复 |
| `T2-MEM-003` | 等级权益、会员价与成交快照 | 有等级事实，无会员价/权益联动 | 权益版本和快照冻结；历史不随等级变化重算 |
| `T2-SAA-001` | 标准商户开户和套餐权益 Owner | RuoYi 只有通用租户套餐菜单/到期字段 | 复用认证平台但商业权益不得写入 `ruoyi-system` |
| `T2-SUB-001` | 续期、宽限、到期和降级 | 无订阅合同生命周期 | 到期不删除业务事实；降级必须可审计、可恢复 |
| `T2-SVC-001` | 标准实施清单和服务工单 | 无实施/工单 Owner | 不保存 Secret/真实敏感材料；不形成商业 SLA |

后三项属于原规划 T3—T5 的商业 V1 能力；若提前进入 Gate 7D，必须先用 CR 明确付费客户、复用率、工时、质量风险和替代方案。

## 5. Gate 7E：汇总验收差距

`T2-E2E-004` 用于组合 Gate 7 实际获批并完成的功能，形成 `INTERNAL_V1_BUSINESS_COMPLETE_CANDIDATE`。它不更新 `T2-UAT-001`，不接受真实支付、真实硬件、伙伴试点、连接器或商业许可证，也不允许把未实施的 DRAFT 项用绿色占位纳入候选。

## 6. 未形成新需求的候选

- 三业态展示与导航差异：已由 `T2-CFG-001/T2-UX-001` 覆盖。
- 复杂优惠券、储值、发票、应付、总账、复杂 WMS、AI：明确非目标，不分配 T2 实现 ID。
- 真实支付、硬件、打印、伙伴和鲸熵汇：沿用现有 `BLOCKED/DEFERRED` ID，不创建替代 ID。

机器清单见 `contracts/t2/gate7a/v1-gap-register.csv`。
