一、三项共同要求：

1. 先冻结用户旅程、数据主权、状态机、冻结点、金额不变量、权限、数据范围、审计、错误码、幂等键、事务、API/事件、MySQL/SQLite 前向迁移、容量、兼容、回退和测试准入；
2. 复用既有 Order/POS/Return/Payment/Device/Audit Owner，不得创建平行订单、现金、退款或打印 Owner，不得跨 Owner Mapper 直写；
3. 金额使用最小货币单位整数并保存币种；现金流水和成交事实只追加，禁止物理删除或覆盖历史；
4. Flutter 只能调用正式应用服务、Repository 和设备适配端口，禁止 UI 直连 SQLite 或 MethodChannel；Vue 如新增工作台只调用正式 API；
5. tenant_id、门店、终端、员工、班次和业务日必须来自可信上下文并形成不可变快照；
6. 核心状态、实体、应用服务、事务边界和复杂 SQL 保留有效中文注释；继续执行 MyBatis-Plus/XML 双边界和已发布迁移不可修改规则。

二、`T2-POS-010` 特殊要求：

- 现金存入、取出、缴款/投库和非销售开钱箱使用具名类型、原因、授权人与稳定幂等键；
- 现金影响、班次预期现金、审计和 Outbox 在同一 SQLite 事务内原子提交；任一失败整体回滚；
- 非销售开钱箱不得伪造成现金余额变化；权限拒绝、金额越界、班次关闭、业务日切换、重复提交和同键异内容必须失败关闭；
- 暂不执行真实钱箱脉冲，设备端口返回明确 `BLOCKED/UNAVAILABLE`，不得模拟真实成功。

三、`T2-POS-011` 特殊要求：

- 模板、成交打印任务、补打请求和设备执行观察分别明确 Owner 与不可变关系；
- 原始打印任务不得因补打被覆盖，补打必须关联原订单/原任务、模板版本、内容摘要、次数、原因、操作者和授权；
- 防止跨租户补打、模板替换、内容篡改、无限补打、重复点击与重启丢任务；
- 本 Sprint 只允许预览和 Fake Device Adapter 的软件验证，`T2-PRN-001` 继续 BLOCKED，不形成 REAL_DEVICE 证据。

四、`T2-ORD-004` 特殊要求：

- 明确购物篮取消、挂单取消、未完成本地订单作废、已同步未完成订单取消请求和已完成订单反向处置的边界；
- 已完成成交、支付、库存、成本、促销和审计事实不得回退为未发生；只能走原单退货退款、资金冲正观察或显式补偿；
- UNKNOWN 资金结果不得用取消命令或重生成业务命令掩盖；
- 覆盖重复/乱序、ACK 丢失、客户端未知、部分 Owner 失败、跨租户、业务日切换和全量重放收敛。

五、测试与 CI：

- 使用两个虚构租户、多门店、多终端、三业态和现金/Provider 无关合成边界；
- 覆盖金额边界、现金短溢、权限拒绝、幂等冲突、磁盘失败、事务中断、同步重放、补打篡改、取消时序和跨租户攻击；
- Java/Dart 对共享状态、错误码、金额和摘要逐字段一致；
- CI 继续包含治理、服务端、Web、Flutter Linux/Windows、Android/Kotlin、MySQL、SQLite、跨端向量、交易故障、租户权限、Secret、依赖、SBOM、许可证、覆盖率及 Gate 0—7A 回归；不得降低阈值、跳过失败测试或用自动重跑掩盖 Flaky。

- Gate 7C—7E、储值、复杂优惠券、发票、应付、总账、复杂 WMS、连接器和 AI 功能；
- Provider 网络、真实资金、真实设备/外设命令、伙伴现场执行、完整 Alpha、生产部署和商业声明；
- 改变现有 `BLOCKED/DEFERRED/DRAFT` 外部证据状态。
