# 测试矩阵、CI 与量化验收

## 1. 合成数据

使用两个虚构租户、三业态、多组织、多门店、多终端和虚构员工；开户前使用独立虚构申请域。
不使用真实客户资料、真实 PII、商户号、设备证书或生产 Secret。

## 2. 测试矩阵

| 维度 | 核心覆盖 |
|---|---|
| SaaS | 重复开户、同键异内容、并发审批、服务端 tenant 分配、套餐切换、配额边界、暂停/恢复/注销 |
| Subscription | 激活、续期、宽限、到期、降级、恢复、时区、时钟偏移、任务重复/乱序/重启 |
| Service | 实施检查、认领租约、转派竞态、独立关闭、重开、附件越权、到期清理 |
| 安全 | 跨租户/门店、权限绕过、缓存/任务/导出/对象存储污染、Secret/PII 泄漏 |
| 数据 | 前向迁移、重复执行、中断、版本不兼容、内容摘要冲突、归档和恢复 |

固定向量见 `contracts/t2/gate8a-prep/test-vectors.json`。准备阶段至少 40 条用例，本次冻结
46 条；正式开发需将这些设计向量转换为领域、应用、Mapper/XML、API、Web 和跨端测试。

## 3. 量化验收

- 三项 Requirement 均保持 DRAFT，外部 BLOCKED/DEFERRED/DRAFT 状态零漂移。
- 运行时、迁移文件、Controller、Vue/Flutter 业务页面、后台任务和依赖变更均为 0。
- 三个 CR、ADR、OpenAPI、事件、错误码、迁移登记、旅程和测试向量可机器校验。
- 可信 tenant、Owner 主权、服务端权益检查、只追加历史和受控恢复不变量全部存在。
- 固定向量 ID 唯一，SAA/SUB/SVC 每项均覆盖正常、冲突、并发、跨租户和恢复路径。
- Ubuntu/Windows 治理门禁、范围/Secret 门禁和证据聚合全部绿色，无跳过和自动重跑。

## 4. CI 准备

专用工作流执行治理结构、RTM、契约、Python 编译、Gate 7F 基线状态、Gate 8A 准入检查、
依赖差异、运行时目录零变化、Secret/PII 扫描和证据摘要。正式 SAA 运行时获批后再增量加入
Server、MySQL、Web、状态机、并发、对象存储、覆盖率、SBOM 与许可证实测，不用准备阶段的
静态绿色替代运行时质量证据。

## 5. No-Go

出现运行时文件、状态提升、跨 Owner 写入设计、客户端 tenant 权威、物理删除历史、真实资金/
设备/伙伴执行、Secret/PII 或任何 P0/P1 设计缺陷时，Gate 8A-Prep 为 `NO-GO`。
