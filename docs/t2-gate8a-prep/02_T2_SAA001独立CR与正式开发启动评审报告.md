# T2-SAA-001 独立 CR 与正式开发启动评审报告

## 1. 评审结论

- Requirement：`T2-SAA-001`
- 当前状态：`DRAFT`
- 证据：`STATIC_DESIGN_AND_CONTRACT_PREP`
- 建议：`CONDITIONAL GO，等待项目发起人确认`
- 运行时实现：`0`

标准开户、套餐权益和商业租户生命周期是把内部候选转为可实施 SaaS 产品的必要能力，并且
是 SUB、SVC 的前置依赖。建议纳入商业 V1，但只能在本报告被确认后单独启动。

## 2. 范围与非目标

范围包含商户申请、资料预检、独立审批、技术租户创建编排、初始化检查点、激活、暂停、
停用、受控恢复、逻辑注销申请，以及版本化套餐权益和门店/终端/员工/存储/导出/API 配额。

不包含真实订阅收费、自动扣费、发票、应付、总账、税务、储值、真实客户开户、商业 SLA、
连接器或生产部署。

## 3. 准入冻结

- Owner：计划独立 `jshpos-saas`；不得把商业规则写入 `ruoyi-system`。
- 主权：SaaS 写商业申请/套餐/权益/生命周期；Foundation 写技术租户、组织、IAM/RBAC。
- 状态：采用契约中的商户申请、租户生命周期和权益版本状态机。
- 权限：申请提交、预检、审批、强制补偿、暂停、恢复、注销分别授权，审批人与申请人分离。
- 幂等：创建、审批、Provision、激活、暂停、恢复均绑定命令 ID、内容摘要和预期版本。
- 审计：记录来源、操作者、理由、前后状态、计划/权益版本、关联标识和结果摘要。
- 失败补偿：跨 Owner 采用可恢复 Saga；不得声称跨模块数据库大事务。
- 租户：申请阶段无 tenant_id；技术租户只由 Foundation 服务端分配且不可复用。
- 回退：已发布迁移只前进；商业状态通过新版本或补偿事实修正，禁止回写历史。

## 4. 依赖与影响

复用 Gate 0 的可信上下文、组织、RBAC、审计、迁移和观察能力；只通过端口影响 Terminal、
Reporting、Backup、Migration 与业务 Owner 的入口授权。既有 Owner 表和状态机保持不变。

主要风险是商业状态误停全部经营能力、配额竞态、越权开户、租户标识伪造和商业规则侵入
平台模块。对应控制是受控恢复能力白名单、服务端权益检查、乐观锁、配额原子检查、职责分离、
稳定幂等和失败关闭。
