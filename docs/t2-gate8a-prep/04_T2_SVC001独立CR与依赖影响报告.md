# T2-SVC-001 独立 CR 与依赖影响报告

## 1. 当前结论

标准实施检查单和服务工单对商业交付有价值，但必须建立在已稳定的 SaaS 租户生命周期和
Subscription 状态之上。当前保持 `DRAFT / DEPENDENCY BLOCKED`，不创建运行时。

## 2. 领域边界

计划独立 `jshpos-service` Owner，独占服务目录版本、实施项目、检查项、工单、认领租约、
转派、处理记录、附件引用、内部时间目标、审计和 Outbox。它只能读取 SAA/SUB 快照，不能
激活/停用租户、切换套餐、安装设备、执行支付或批准生产变更。

实施项目覆盖 `DRAFT、PREFLIGHTING、PREFLIGHT_FAILED、READY、IN_PROGRESS、BLOCKED、
READY_TO_HANDOVER、HANDED_OVER、CANCELLED`；工单覆盖 `OPEN、ASSIGNED、IN_PROGRESS、
WAITING_INPUT、RESOLVED、CLOSED、REOPENED、CANCELLED`。必选检查未完成不得移交；关闭和
重开只追加历史，高风险关闭执行职责分离。

## 3. 附件、安全与依赖

附件正文存放于租户命名空间对象存储，数据库只保存不透明对象引用、SHA-256、媒体类型、
大小、上传人、保留和清理状态。每次下载重新校验租户、门店范围和权限，短期签名链接到期
失效；缓存、任务、导出和临时文件使用相同命名空间。

服务目标只用于内部告警，不构成合同 SLA 或赔付。工单不得替代设计伙伴授权、真实设备/
外设执行准入或生产变更审批。

## 4. 后续 Go/No-Go

只有 `T2-SAA-001` 和 `T2-SUB-001` 均独立 ACCEPTED，且服务目录、附件、权限、租约、审计和
故障用例再次评审通过，才可启动 SVC 正式开发。
